# 架構總覽

- 文件版本：1.6
- 文件狀態：已實作
- 現行系統版本：0.4.118
- 首次實作版本：0.1.61
- 最後核對日期：2026/10/08

## 文件目的

說明本專案的整體分層、各專案職責、依賴方向、啟動流程，以及 DI 容器中註冊的主要服務，協助新進開發者快速建立心智模型。

---

## 1. 解決方案組成

方案檔：`src/MeetingRecord/MeetingRecord.slnx`（採新版 `.slnx` 格式）。共 7 個專案，採典型的分層架構：

| 專案 | 主要職責 | 依賴方向 |
|------|----------|----------|
| `MeetingRecord.Web` | Blazor Server 宿主、Razor 元件、Web API、登入、本地化、靜態資源 | 依賴所有其他專案 |
| `MeetingRecord.Business` | 商業邏輯：Service、Repository、AutoMapper Profile、Helper | → AccessDatas、Models、Dtos、Share |
| `MeetingRecord.AccessDatas` | EF Core `DbContext`、Entity、Migration | → 無外部專案相依 |
| `MeetingRecord.Models` | AdapterModel、System 設定模型、共用領域模型 | → 無外部專案相依 |
| `MeetingRecord.Dtos` | API 對外 DTO：`ApiResult<T>`、`PagedResult<T>`、模組 DTO | → 無外部專案相依 |
| `MeetingRecord.Share` | 跨層共用 Helper、Extension（純工具） | → 無外部專案相依 |

> 依賴方向永遠由「上層」指向「下層」，不可反向引用。Web 不應跳過 Business 直接操作 `BackendDBContext`，但 Web 內的 API Controller 為了輕量化，使用 `Repository`（仍位於 Business 專案）。

## 2. 啟動流程（`MeetingRecord.Web/Program.cs`）

啟動主檔位於 [`src/MeetingRecord/MeetingRecord.Web/Program.cs`](../../src/MeetingRecord/MeetingRecord.Web/Program.cs)。整體流程：

1. **建立 `WebApplicationBuilder`**（`Program.Main` 開頭的 `WebApplication.CreateBuilder(args)`），緊接著以 `StartupSafetyValidator.Validate` 做 Production 設定檢查。
2. **NLog 設定**（`Program.Main` 的 `#region NLog 相關設定`）：
   - 從 `NLog:BasePath` 讀取根目錄，於其下建立 `MeetingRecord.Web` 子目錄。
   - 清除預設 logger provider，改由 `UseNLog()` 接管。
   - `app.Build()` 之後才取得 `ILogger<Program>` 寫入啟動日誌。
3. **核心服務註冊**（`Program.Main` 的 `#region 系統使用服務`）：
   - `AddRazorComponents().AddInteractiveServerComponents()`：Blazor Server 互動式渲染（SignalR `MaximumReceiveMessageSize` 提高為 10 MB）。
   - `AddControllers()`（掛 `ApiExceptionFilterAttribute`）、`AddSwaggerGen()`：傳統 Web API + Swagger。
   - `AddAntDesign()`；`AddConfiguredLocalization()`（`Extensions/ServiceCollectionExtensions.cs`）：`AddLocalization()`、`RequestLocalizationOptions` 支援 `zh-TW` / `en-US`（採 `AcceptLanguageHeaderRequestCultureProvider`），並以 `LocaleProvider.SetLocale("zh-TW", AntDesignLocaleFactory.Create("zh-TW"))` 套用本地化字串。
   - `AddConfiguredOptions`、`AddConfiguredCors`、`AddConfiguredRateLimiting`、`AddConfiguredHealthChecks`、`AddConfiguredCache`（皆在 `ServiceCollectionExtensions`）。
4. **認證**（`Program.Main` 的 `#region 加入使用 Cookie & JWT 認證需要的宣告`）：
   - Cookie 政策：`CheckConsentNeeded = true`、`MinimumSameSitePolicy = None`。
   - `AddAuthentication(MagicObjectHelper.CookieScheme).AddCookie(...)`：登入 / 登出 / 拒絕路徑均指向 `/Auths/Login` 系列；`AddJwtBearer(...)` 供 Web API 使用。
   - Google OAuth 僅在 `GoogleOAuthSettings.IsConfigured` 時註冊。
   - `AddAuthorization()`。
5. **AutoMapper**（`Program.Main` 的 `#region AutoMapper 使用的宣告`）：載入 `AutoMapping` Profile，可選擇套用 LicenseKey。
6. **強型別設定**：`AddConfiguredOptions` 綁定 `SystemSettings`、`SecuritySettings`、`CorsSettings`、`SwaggerSettings`、`CacheSettings`、`MediaSettings`（0.4.27，FFmpeg 路徑）與 `ExportSettings`；`Program.Main` 的 `#region 加入設定強型別注入宣告` 另以 `AddOptions<T>().Bind(...).ValidateDataAnnotations().ValidateOnStart()` 綁定 `LlmSettings`（語音轉錄與文字生成供應商設定）與 `ExchangeRateSettings`（0.4.88，用量金額換算顯示幣別）。
7. **外部目錄準備**（`#region 系統使用的目錄準備`）：依 `SystemSettings.ExternalFileSystem` 各路徑呼叫區域函式 `EnsureDirectoryExists`，缺少時自動建立（`DatabasePath`、`DownloadPath`、`UploadPath`、`ProjectFilePath`、`MeetingMediaPath`、`MeetingTranscriptPath`、`AiChatPath`）。
8. **EF Core**：由 `ServiceCollectionExtensions.AddConfiguredDatabase` 固定以 `UseSqlite` 註冊 `BackendDBContext`；連線字串由 `MagicObjectHelper.GetSQLiteConnectionString` 結合 `SystemSettings.ExternalFileSystem.DatabasePath` 動態產生。
9. **客製服務**（`#region 客製服務註冊`）：`AddApplicationServices()` 註冊 Service / Repository（除 `SystemStartupState` 外皆 `Scoped`）；`AddTranscriptionServices()`（0.4.27）、`AddTextGenerationServices()`（0.4.31）與 `AddExchangeRateServices()`（0.4.88）另註冊佇列、進度通知器、快取等 **Singleton**、背景 worker（**HostedService**）與具名 `HttpClient`，見第 3 節。
10. **資料庫初始化**（`#region 資料庫的 Migration`，於 `app.Build()` 之後）：
    - 若有 Migration 則 `Database.Migrate()`，否則 `EnsureCreated()`。
    - 預設角色（`DefaultRoleSeeder.RunAsync`，0.4.101 起）：確保「一般使用者」角色（`MagicObjectHelper.預設角色`）存在；只在剛建立或剛從舊名改名時把權限設成業務頁那一組，之後以角色管理頁為準；**不動任何帳號的角色**（0.4.98～0.4.100 的「全員收斂成一般使用者」已拿掉）。
    - Seed 預設 `MyUser`（`BootstrapSettings.SupportAccount`），密碼以 PBKDF2 雜湊，標記為 `IsAdmin`；沒有角色時才掛上一般使用者角色。
    - RBAC 回填（`IRbacBackfillService`，失敗不中止啟動）。
    - 團隊轉換（`TeamConversionService.RunAsync`，0.4.102，冪等、失敗不中止啟動）：舊專案成員轉成同名團隊、補主責團隊、舊會議補上傳者。
    - **轉錄狀態修復**（0.4.27）與**草稿生成狀態修復**：把殘留在「待處理」或「處理中」的 `Meeting` 改判為「失敗」——兩條佇列都不持久化，重啟後沒有 worker 會接手。
11. **中介軟體管線**（`#region 註冊中介軟體`）：
    - 非 Development 時 `UseExceptionHandler("/Error")`、`UseHsts()`。
    - `UseConfiguredForwardedHeaders`、`UseConfiguredSwagger`、`UseHttpRequestLogging<Program>`（自訂 middleware 紀錄每筆 HTTP 請求耗時與例外），皆在 `Extensions/ApplicationBuilderExtensions.cs`。
    - `UseStatusCodePagesWithReExecute("/not-found")`、`UseHttpsRedirection`、`UseConfiguredLocalization`（`UseRequestLocalization`）、`UseConfiguredCors`、`UseRateLimiter`、`UseAntiforgery`。
    - `MapStaticAssets`、`UseConfiguredDownloadStaticFiles` 將 `DownloadPath` 對應為 `/UploadFiles`。
    - `UseAuthentication` → `UseAuthorization`。
    - `MapControllers`、`MapHealthChecks("/health/live")`、`MapHealthChecks("/health/ready")`、`MapRazorComponents<App>().AddInteractiveServerRenderMode()`。
    - `/system-health`（「系統健康度」）由 Razor 元件提供巡檢頁：系統管理選單、頁面權限「系統健康度」（預設僅管理員），頁尾原始日誌固定只給管理員（0.4.93）。

## 3. 已註冊的 Scoped 服務

於 `ServiceCollectionExtensions.AddApplicationServices()` 一次列出，便於對照：

```
AuthenticationStateHelper      // 驗證登入狀態、載入 CurrentUser、回傳認證檢查結果
CurrentUserService             // 全局保存目前登入使用者（含角色 / 權限）
MyUserServiceLogin             // 登入專用驗證流程（密碼比對、驗證碼）
SidebarMenuService             // 載入 Menu.json 並依角色過濾
RolePermissionService          // 角色權限樹（GetRoleListPermissionAllName 等）
RoleViewService                // 角色檢視（RoleView Entity）CRUD
MyUserService                  // 使用者 CRUD
ProjectService / ProjectRepository
CategoryService / CategoryRepository
TeamService / TeamRepository
PromptTemplateService / PromptTemplateRepository   // 會議紀錄提示詞範本
MeetingService / MeetingRepository                 // 會議紀錄（含影音上傳與轉錄入列）
TodoService / TodoRepository                       // 待辦事項（0.4.32）
MeetingFileStore               // 會議影音檔與逐字稿的實體檔案存取
DashboardService               // 儀表板統計聚合（0.4.54；0.4.97 起全公司彙總、刻意不套團隊過濾、不放明細）
AiUsageRecorder                // AI 用量帳本（0.4.80）：每次 AI 呼叫寫一筆 AiUsageLog，依 LlmSettings 定價與 ExchangeRateCache 匯率補金額
AiUsageAnalysisService         // 「AI 用量分析」頁的讀取層（金額一律撈進記憶體再加總，不在 SQL 端 SUM）
IPdfRenderer → HeadlessBrowserPdfRenderer  // 以 Edge／Chrome 無頭列印把 HTML 轉成 PDF（會議紀錄與 AI 問答匯出共用）
IRecordAccessScopeProvider → RecordAccessScopeProvider  // 解析目前使用者的存取範圍（Blazor／API 兩種情境）
ProjectAccessService           // 資料可見範圍的單一入口：專案主責＋協作團隊與使用者團隊有交集才看得到（0.4.99／0.4.102）
DefaultRoleSeeder              // 啟動時確保「一般使用者」預設角色存在（冪等，不動帳號角色）
TeamConversionService          // 啟動時把舊資料轉成「主責＋協作團隊」並補舊會議上傳者（冪等）
SystemHealthService            // 彙整健康檢查、加權分數、紅黃綠燈號與日誌 tail
HealthLogReader                // 讀取 NLog 今日日誌檔最後 100 筆紀錄
SystemStartupState             // Singleton，記錄啟動時間（「關於」對話窗與健康度使用）
```

> 不經 DI 的純函式／靜態類別：`ProjectTeamWriter`（`Business/Services/Other`，把 `ProjectAccess.ResolveProjectTeams` 的結果寫進 `ProjectTeam`，畫面 `ProjectService` 與 API `ProjectRepository` 共用，0.4.102）；`MeetingDocumentExporter`、`AiChatDocumentExporter`（`Business/Services/Export`，把會議紀錄／AI 問答對話組成可列印的 HTML 與安全檔名，不碰 IO，實際列印交給 `IPdfRenderer`）。

轉錄管線另外註冊於 `AddTranscriptionServices()`（0.4.27）：

```
IJobCancellationRegistry → JobCancellationRegistry // Singleton，轉錄與草稿生成共用的取消登記處
ITranscriptionQueue → TranscriptionQueue           // Singleton，行程內 Channel<int>
ITranscriptionProgressNotifier                     // Singleton，行程內進度狀態（0.4.36），不進資料庫
TranscriptionBackgroundService                     // HostedService，單一 worker
IMediaConverter → FfmpegMediaConverter             // Scoped，外部 FFmpeg 轉檔切段
ITranscriptionProvider → AzureOpenAiTranscriptionProvider  // Scoped，換廠商的擴充點
TranscriptionJobRunner                             // Scoped，單筆轉錄工作流程
HttpClient("AzureOpenAiTranscription")             // 具名 client，逾時 10 分鐘
```

文字生成管線另外註冊於 `AddTextGenerationServices()`（0.4.31），形狀與轉錄軌道對稱但刻意獨立，避免長音檔的轉錄把草稿生成堵住；AI 問答與待辦擷取也在這裡註冊，複用同一個 `ITextGenerationProvider`，但屬於使用者等在畫面前的同步互動，不走佇列：

```
IMeetingDraftQueue → MeetingDraftQueue             // Singleton，行程內 Channel<int>
IMeetingDraftProgressNotifier                      // Singleton，行程內進度狀態（0.4.38），不進資料庫
MeetingDraftBackgroundService                      // HostedService，單一 worker
ITextGenerationProvider → AzureOpenAiTextGenerationProvider  // Scoped，換廠商的擴充點
MeetingDraftJobRunner                              // Scoped，單筆草稿生成工作流程
AttachmentTextExtractor                            // Scoped，AI 問答讀附件文字（PDF／docx／txt／md／csv）
AiChatStore                                        // Singleton，AI 問答對話檔（.jsonl，AiChatPath）存取，持有依對話檔的寫入鎖
AiChatService                                      // Scoped，以專案或單一會議為範圍的 AI 問答（0.4.51）
TodoExtractionService                              // Scoped，從會議紀錄草稿抽出待辦候選
HttpClient("AzureOpenAiTextGeneration")            // 具名 client，逾時 10 分鐘
```

匯率換算另外註冊於 `AddExchangeRateServices()`（0.4.88）：

```
ExchangeRateCache                                  // Singleton，目前生效匯率；刻意只有同步欄位讀取，記帳路徑不得 await HTTP
ExchangeRateFetcher                                // Scoped，抓一次匯率；失敗回 null 不擲例外，只給背景服務呼叫
ExchangeRateBackgroundService                      // HostedService，啟動時以用量帳本最後一筆匯率當種子，之後定期抓匯率寫進快取
HttpClient(ExchangeRateFetcher.HttpClientName)     // 具名 client，逾時 15 秒
```

> Repository 用於 Web API（`Controllers/`），Service 用於 Razor 元件 / Page；兩者目前並存。
>
> 背景 worker 不能直接注入 Scoped 服務，因此 `TranscriptionBackgroundService` 對每筆工作用 `IServiceScopeFactory.CreateScope()` 取得自己的 `TranscriptionJobRunner`（內含 Scoped 的 `BackendDBContext`）。

## 4. 請求生命週期

### 4.1 Razor 元件請求（Blazor Server）

```
Browser ─► UseAuthentication ─► UseAuthorization ─► MapRazorComponents
                                                         │
                                                         ▼
                                         Layout.razor + Page.razor
                                                         │
                                                         ▼
                                       View 元件 ──► Service ──► DbContext
```

`AuthenticationStateHelper.Check(...)` 會在進入受保護頁面時讀取 `ClaimsPrincipal`、由 `Sid` 對應到 `MyUser`，檢查使用者狀態、強制改密碼需求與角色權限資料。檢查結果會以 `AuthenticationCheckResult` 回傳；Layout、NavMenu 或 Page 會依 `Succeeded`、`Unauthenticated`、`InvalidUser`、`RequiresPasswordChange` 決定是否繼續載入、停止載入或交由 Helper 導向登出與 `/ChangePassword`。

### 4.2 Web API 請求

```
Browser ─► UseRateLimiter ─► UseAuthentication ─► UseAuthorization ─► MapControllers
                                                         │
                                                         ▼
                                       Controller ──► Repository ──► DbContext
                                                         │
                                                         ▼
                                       回傳 ApiResult<T> 或 PagedResult<T>
```

詳見 [Web API 設計慣例](Web%20API%20設計慣例.md)。

API Controller 目前同時支援 `/api/{controller}` 與 `/api/v1/{controller}`；新用戶端應優先使用 `/api/v1/...`。

## 5. 程式碼分層慣例

| 慣例 | 說明 |
|------|------|
| 命名對齊 | `XxxPage` / `XxxView` / `XxxService` / `XxxRepository` / `XxxAdapterModel` / `XxxDto` |
| UI 不直接觸 DbContext | Razor 只呼叫 Service / Repository，不直接 `using` `BackendDBContext`。 |
| Edit 前先 Clone | 表格列被編輯前要 `Clone()` 隔離，避免雙向綁定污染來源。 |
| EF 追蹤清理 | Update / Delete 前以 `CleanTrackingHelper` 清除追蹤實體。 |
| 通知統一走 AntDesign | 成功 / 失敗一律經 `NotificationService` / `MessageService`。 |
| API 回應統一 | 任何 Controller 一律回傳 `ApiResult<T>`，分頁則包 `PagedResult<T>`。 |

詳細模板請見 [建立一個新 CRUD 操作網頁說明](../guides/建立一個新%20CRUD%20操作網頁說明.md)。
