## 1. 分層與依賴方向 ⚠️

依賴方向一律向上，**不得反向相依**：

```
MeetingRecord.Web ──► MeetingRecord.Business ──► MeetingRecord.AccessDatas
       │                  │
       └──► MeetingRecord.Dtos / MeetingRecord.Models / MeetingRecord.Share
```

- `MeetingRecord.Share`、`MeetingRecord.Models`、`MeetingRecord.Dtos`：不得相依其他專案。
- UI（Razor）**不得直接 `using` `BackendDBContext`**，只能呼叫 Service / Repository。
- 細節見 [架構總覽](架構總覽.md)。

## 2. 模型變更要產生 Migration ⚠️

本專案**只支援 SQLite**（0.4.24 起移除 SQL Server 支援），migration 一律放在單一組件：

- SQLite：`src/MeetingRecord/MeetingRecord.AccessDatas/Migrations/`

**任何 Entity／欄位變更都要產一次 migration**，否則程式碼與資料庫 schema 會不一致。指令見 [EFCore 指令備忘](../guides/EFCore.md)。

> 資料庫連線一律由 `ServiceCollectionExtensions.AddConfiguredDatabase` 以 `UseSqlite` 註冊，連線字串由 `MagicObjectHelper.GetSQLiteConnectionString` 結合 `SystemSettings.ExternalFileSystem.DatabasePath` 產生；`appsettings.json` 已無 `DatabaseProvider` 設定。

⚠️ **測試抓不到漏掉的 migration**（0.4.80 前）：所有測試 fixture 都用
`Database.EnsureCreatedAsync()`（照目前的模型**直接建表、繞過 migration**），而正式啟動走
`Database.Migrate()`。所以忘了產 migration 時整套測試會全綠，直到有人跑 App 才在啟動時被
EF 10 的 `PendingModelChangesWarning` 擋下來——而那時多半已經 commit 出去了。
0.4.80 新增 `MigrationSnapshotTests` 補這個缺口：它比對模型與 `BackendDBContextModelSnapshot`，
不一致就變紅並印出缺少的操作與該下的指令。

⚠️ **SQLite 把 `decimal` 存成 TEXT**：`ORDER BY` 是字典序（`"10.0" < "9.0"`）、`WHERE > 1` 同理。
金額之類的 decimal 欄位**只能撈進記憶體再加總**，絕不可在 SQL 端 `SUM`／`ORDER BY`／比較大小
（見 `AiUsageAnalysisService`）。

## 3. EF 追蹤與編輯隔離 ⚠️

- 表格列被編輯前要先 `Clone()` 隔離，避免雙向綁定污染來源資料。
- Update / Delete 前以 `CleanTrackingHelper`（`src/MeetingRecord/MeetingRecord.Business/Helpers/CleanTrackingHelper.cs`）清除追蹤實體，避免 EF 追蹤衝突。
- 附件「資料表紀錄」由 EF Core Cascade 處理，但**實體檔案**仍須由 Service 層在刪除前後手動移除。見 [檔案上傳機制](../features/檔案上傳機制.md)。
- `Meeting` 的影音檔／逐字稿是**內嵌欄位而非子表**，連 Cascade 都沒有：刪除時 Service 與 Controller 都要自行呼叫 `MeetingFileStore` 清實體檔案。

## 4. Web API 回應一律包信封 ⚠️

- 任何 Controller 一律回傳 `ApiResult<T>`；分頁則包 `PagedResult<T>`（定義於 `MeetingRecord.Dtos`）。
- UI 用 Cookie 認證（`MagicObjectHelper.CookieScheme`）、API 用 JWT Bearer，兩套 scheme 互不干擾。
- CRUD API 預設需要 Bearer token；login / refresh 允許匿名。未授權／禁止存取的回應也包成 `ApiResult`。
- 除驗證身分外，受保護 CRUD **每個動作**另以 `[HasPermission("resource:action")]`（`HasPermissionAttribute` + `IPermissionChecker`）做**動作級授權**，無權限回 **403**（維持 `ApiResult`）；管理員短路。
- 平行路由：保留 `/api/...`，新用戶端優先用 `/api/v1/...`。
- 見 [Web API 設計慣例](Web%20API%20設計慣例.md)、[API Versioning 策略](API%20Versioning%20策略.md)、[認證授權與權限機制](../security/認證授權與權限機制.md)。

## 4.1 紀錄分類/團隊標籤與團隊權控 ⚠️

- PromptTemplate 與 Meeting 的 `Categories`/`Teams` 為**多值標籤**，以換行分隔字串儲存；務必透過 `TagStringHelper`（`ToStored`/`ToList`）轉換，AutoMapper 已以 `ForMember` 處理 List↔字串。**Project 的這兩個欄位已於 0.4.39 移除、Todo 的已於 0.4.66 移除**。
- **團隊行級權控**只在 **Blazor 服務層**：清單 `GetAsync` 對非管理員套 `BuildTeamAccessPredicate`，單筆 `GetAsync(id)`／檔案下載以 `IsTeamAccessible` 守門。非管理員僅見「無團隊（公開）或與其角色團隊交集」的紀錄。透過 `IRecordAccessScopeProvider` 取得範圍。
- 使用者**有效團隊**由 `IEffectiveTeamResolver` 計算＝直接綁使用者的 `UserTeam` ∪ 其角色 `RoleView.DefaultTeamsJson`（聯集去重）；登入時載入 `CurrentUser.TeamList`（見 `AuthenticationStateHelper.Check`），API/檔案下載走 `RecordAccessScopeProvider`。此設計讓「團隊綁使用者」與「團隊綁角色」並存，達成個別使用者差異化授權。
- Web API（repository 路徑）目前**不**做行級過濾（與母專案一致）。

## 5. 權限與選單對應（已改為宣告式，非位置索引）

側邊選單以**選單 Id → 權限鍵**的宣告式對應決定顯示，**重排 Menu.json 不會錯位**（已移除舊的位置索引耦合）：

- `src/MeetingRecord/MeetingRecord.Web/Datas/Menu.json` — Sidebar 結構（含各項 `id`）。
- `SidebarMenuService.MenuPermissionMap`（`src/MeetingRecord/MeetingRecord.Web/Components/Layout/SidebarMenuService.cs`）— `Id → 權限鍵` 對應，權限鍵取自 `MagicObjectHelper` 常數。
- `MagicObjectHelper`（`src/MeetingRecord/MeetingRecord.Share/Helpers/MagicObjectHelper.cs`）— 權限鍵常數。

新增受權限控管的頁面時：於 `MagicObjectHelper` 新增權限鍵常數、於 `Menu.json` 新增項目（給定唯一 `id`）、於 `MenuPermissionMap` 加入 `id → 權限鍵`、於 `RolePermissionService` 權限矩陣加入該頁、於 `MenuIconTests.AllowedIcons` 加入新圖示、於 `_Imports.razor` 加 `@using`、於 `ServiceCollectionExtensions` 註冊 Service 與 Repository。**共七處，漏掉多半不會編譯失敗**（`_Imports` 例外），但功能會壞。

⚠️ **圖示必須是 classic Material Icons。** `App.razor` 載的是 `Material+Icons+Outlined`，
用 Material Symbols 專有名稱（`monitoring`、`query_stats`…）會渲染成**破圖**。
`MenuIconTests.AllowedIcons` 擋得了「沒加白名單」，但**擋不了「名稱在白名單卻不存在於字型」**——
加新圖示時要實際渲染確認。

⚠️ **`dashboard-*` 那套 CSS 借不到。** 它們定義在 `DashboardView.razor.css` 裡是 **scoped** 的
（會被編成 `[b-xxxxx]`），在別的元件完全不生效，而且**沒有任何錯誤訊息**——
卡片會靜靜地變成一張一列。scoped CSS 沒有共用元件，照既有現況複製一份到自己的 `.razor.css`。
工具列那 14 行 `.xxx-toolbar` 也是同樣的情況（七個清單頁各有一份）。

### 5.1 側邊欄分區（0.4.33 起）⚠️

- `Menu.json` 的**頂層節點**以 `section` 欄位宣告所屬區塊（目前為「核心功能」與「功能選單」）。未標註者歸入預設區塊。加新區塊只改 JSON，不用改程式。
- **`SidebarMenuItemModel.CloneWith` 必須複製 `Section`** —— `ApplyPermissionStructure` 與 `FilterAuthorizedMenuItems` 各 Clone 一次，漏掉會讓分區靜默失效且沒有任何錯誤訊息。
- **分區只影響渲染，不影響選取狀態的鍵值**：`SidebarMenuSectionBuilder` 回傳的每個項目都帶著它在**完整清單**中的原始索引，`NavMenu` 一律以 `root-{原始索引}` 當 key。若分組後各區塊各自從 0 重新編號，`TryFindActiveMenuPath` 算出的高亮與自動展開會全部錯位。
- **選單結構與權限矩陣是獨立的兩件事**：`Menu.json` 已扁平化（移除「專案管理」「會議管理」兩個只有單一子項的群組節點），但 `RolePermissionService` 的權限矩陣**仍保留這兩個群組**。原因是矩陣中每個內層清單的 `[0]` 是群組（只有開關）、`Skip(1)` 才是帶 view/create/edit/delete 的葉節點——拆掉群組會讓專案項目、會議紀錄、待辦事項全部失去動作級權限。
- 改完 `Menu.json` **必須重啟**：選單經 `ICacheService` 快取（key `sidebar:menu:raw`，預設 30 分鐘），不重啟會看到舊選單而誤判成沒生效。

補充現況（RBAC 已落地）：
- **權限粒度到動作級**：`view/create/edit/delete/export`（見 `PermissionKeys.cs`），可做「可看不可改」；裸頁面鍵＝該頁全動作（向後相容）。
- **一使用者多角色**：`UserRole` 多對多，權限取**聯集**；團隊直綁使用者（`UserTeam`）。
- **UI 與 API 共用單一權威來源** `IPermissionChecker`（RBAC 關聯表）：登入時 `AuthenticationStateHelper.Check` 以 `GetEffectivePermissionKeysAsync` 一次載入有效權限鍵（含多角色聯集）到 `CurrentUser.RoleList`，供選單/`CheckAccessPage`/`CheckAccessAction` 同步比對；`TabViewJson` 退為角色編輯回填用的相容欄位。

> 權限判定的權威來源為 RBAC 關聯表（見 [認證授權與權限機制](../security/認證授權與權限機制.md)）；完整路線見 [權限授權現況評估與改善路線](../security/權限授權現況評估與改善路線.md)。

## 6.1 UI 慣例 ⚠️

**按鈕的文字規則分兩類，看有沒有外框。**（0.4.62 起；0.4.57～0.4.61 是「全站一律有文字」）

**有外框的按鈕（工具列、對話框）一律要有可見文字。**
用途只寫在 `Tooltip` 或 `title` 是不夠的——**這兩者在觸控裝置上叫不出來**。
共用樣式是 `wwwroot/app.css` 的 `.btn-icon-label`：

```razor
<Button Type="ButtonType.Default" OnClick="...">
    <span class="btn-icon-label">
        <MaterialIcon Theme="MaterialIcon.Themes.Outlined" Kind="add" /><span>新增</span>
    </span>
</Button>
```

**無外框的按鈕只放圖示，說明靠 `Tooltip`。** 清單「操作」欄一律用共用元件
`CrudActionButton`（`Title` ＋ `Icon`），不要自己刻：`Title` 同時是 Tooltip 內容
與 clip 隱藏的無障礙標籤（畫面上看不到但螢幕閱讀器讀得到，**不要因此刪掉它**）。
理由是專案頁一列最多 6 顆，帶文字會把 `Fixed="Right"` 的欄位撐到 500px 以上。

例外是**右下角的背景工作進度面板**：四顆鈕雖然無外框，但仍保留文字——同一列的
「取消」（真的中止工作）與「關閉」（只移除通知）行為完全不同，只留圖示會誤按。

另外三處純圖示是「圖示即設計」而非省略標籤：側邊欄收合鈕、
收合態的側邊欄選單觸發鈕、使用者選單的下拉箭頭（`aria-hidden` 裝飾）。

**第三類：狀態膠囊本身就是控制項**（0.4.64 起，目前只有提示詞清單的「啟用狀態」）。
它同時有文字**又有** 1px 外框，上述兩類都不適用。規則：

- 有對應動作權限時才渲染成 `<button>`，**沒權限就渲染回 `<span>`**，不要用 `<button disabled>`
  ——disabled 的按鈕不可 focus，掛在上面的 `aria-label` 狀態說明會讀不到。
- 可見文字講**狀態**、`aria-label` 與 `title` 講**動作**。把「啟用」直接當按鈕的可及名稱
  會被讀成命令，語意與實際相反。
- 原生 `<button>` **不繼承字型**，改成按鈕後要補 `font: inherit` 與 `cursor: pointer`
  （見 `PromptTemplateViewView.razor.css`）。這裡不需要 `::deep`，button 是自己寫的元素。
- **會寫入資料的膠囊**一定要有二次確認（`ConfirmAsync`）：膠囊比按鈕更容易誤觸。**非破壞性的那一向不套
  `Danger`**（啟用不套、停用才套）。⚠️ 0.4.85 之前這條寫的是「一定要有二次確認」，已限縮——
  只切換檢視的膠囊見下面的變體。

**只切換檢視的膠囊不要二次確認**（0.4.85 起，目前只有待辦頁負責人面板的四顆狀態膠囊）。
它只改檢視狀態、可逆、不碰資料庫，套確認等於每看一次清單就問一次。與上面幾點的差異：

- **要 `aria-pressed`**：這是 toggle 不是 action。⚠️ 必須給**字串** `"true"`／`"false"`——
  Blazor 對 `bool` 屬性的規則是「true 只渲染屬性名、false 整個略掉」，給 bool 會渲染成空值而無效。
- **0 筆的膠囊渲染回 `<span>`**，理由與上面「沒權限渲染回 `<span>`」同一條，另外也從源頭消滅
  「點了得到空清單」。⚠️ 隨之而來的不變式：**作用中的篩選，畫面上一定要有一顆可以點掉它的膠囊**
  ——0 筆的膠囊點不掉，篩選若留著就會變成「空清單，而且畫面上沒有任何東西可以按掉它」。
  待辦頁用 `TodoOwnerFilter.Clamp` 在每條重載路徑尾端收斂，見 [待辦事項 PRD](../prd/待辦事項-prd.md)。
- 原生 `<button>` 的 `font: inherit` 會把 `font-size` **一起重設**，膠囊要把 `12px` 補回來。
- 要讓使用者看得出「現在有篩選」需要**兩層**：選中那顆加內框與粗體，**其餘膠囊 `opacity: .5`**
  ——只有選中那顆變粗，四顆並排時看不出來。

**圖示一律用 `MaterialIcon`，不要用 emoji**——emoji 的字體、大小與基線由作業系統決定，
跟旁邊的文字對不齊。

### ⚠️ scoped CSS 選不到子元件

樣式掛在 AntDesign 元件的 `Class` 上時，**Blazor CSS 隔離的 scope 屬性不會傳進子元件**，
`.foo {}` 會被編成 `.foo[b-xxxxx]` 而永遠選不到——這類規則不會報錯，只是靜靜地不生效
（0.4.56 與 0.4.57 各查出一批這樣的死規則）。

解法是從**自己 `.razor` 裡寫的元素**用 `::deep` 選進去：

```css
.my-own-wrapper ::deep .ant-component-class { ... }
```

要確認有沒有生效，直接看產出的樣式包
`obj/Debug/net10.0/scopedcss/bundle/MeetingRecord.Web.styles.css`——
scope 屬性要落在自己的容器上，子選擇器不帶屬性才是對的形狀。

跨多個元件共用的樣式（如 `.btn-icon-label`）放 `wwwroot/app.css`，
不受 scope 限制，也不必抄很多份。

### ⚠️ AntDesign 的 CSS 比 app.css 晚載入

`App.razor` 裡 `app.css` 在第 12 行、AntDesign 在第 22 行。要覆寫 `.ant-*` 樣式，
選擇器一律加 `body` 前綴把特異度墊高一級，否則會被蓋回去（見 `app.css` 的奶茶色區塊）。

## 6.2 清單頁分頁：其餘六頁仍是壞的 ⚠️

八支 `*Service.GetAsync(DataRequest)` 原本都是這個寫法：

```csharp
dataSource = dataSource.Skip((dataRequest.CurrentPage - 1) * dataRequest.PageSize);
if (dataRequest.Take != 0)          // ← 呼叫端一律傳 Take = 0
{
    dataSource = dataSource.Take(dataRequest.PageSize);
}
```

而**八個清單頁全部傳 `Take = 0`**，所以 `Take` 從來沒被套用過——第 1 頁會列出全部資料，第 N 頁會列出「第 N 頁以後的全部」。`result.Count` 是在 `Skip`／`Take` 之前算的，所以分頁器的總數與頁數一直是對的，只有內容沒被切，因此不容易被發現。

**0.4.64 修了 `PromptTemplateService`、0.4.85 修了 `TodoService`**（都是把 `Take` 從條件裡拉出來）。
其餘六支（`Category` / `Meeting` / `MyUser` / `Project` / `RoleView` / `Team`）維持原樣，
所以目前**只有提示詞清單與待辦清單真的分頁**。要修其餘六支的話：

- 每支各一行，寫法完全相同；`DataRequest.Take` 不能刪（那六支還在讀它）。
- 現有測試不會變紅（三處建 `DataRequest` 的測試都是 `PageSize = 50` 配個位數種子資料）。
- **但每一頁都要一併補頁碼夾住**，否則會浮出另一個被掩蓋的問題：`_pageIndex` 從來不會被
  夾回範圍內，停在第 2 頁時把該頁唯一一筆刪掉就會 `Skip` 掉全部資料而顯示空白表格。
  做法見 `PromptTemplateViewView.razor.cs` 或 `TodoViewView.razor.cs` 的 `ReloadAsync` 尾端。
  ⚠️ 夾出來的頁碼要 `Math.Max(1, ...)`：AntDesign 1.6.0 在 `PageIndex < 1` 時**不觸發** `OnChange`，夾出 0 會卡死。
- 0.4.85 另外浮出一處：`OnTableChange` 要補 `_pageSize = args.PageSize;`。分頁沒作用時
  「使用者改每頁筆數」根本不可能被觀察到，修好之後它第一次真的會動；而目前唯一讓它能動的是
  `@bind-PageSize` 與 AntDesign 內部 callback 的**觸發順序**，是沒有文件保證的第三方實作細節。
- 頁大小若要與共用值不同，**不要動 `MagicObjectHelper.PageSize`（8）**——那是八個清單頁共用的。
  待辦頁 0.4.85 先改成 view 內的具名常數 5，0.4.86／0.4.87 又改成量畫面算出來的（見下一節）。

### 清單頁要「剛好吃滿一個畫面」時 ⚠️（0.4.86 起，0.4.87 重做，目前只有待辦頁）

量測只有 DOM 做得到，但**決策一律留在 C#**（`TodoAutoFit.Decide`）——
本專案沒有 bUnit，放進 JS 的判斷就永遠測不到，與 `text-editor.js` 同一條界線。

⚠️ ⭐ **不要用「可用高度 ÷ 列高」去預測。** 0.4.86 就是這樣寫的，結果實測表格底部
永遠離畫面底 76～177px（而右邊面板永遠只差 51px），使用者看到的就是「只顯示幾列、底下一大片空白」。
原因是**列高不是固定的**——待辦頁的截止日欄會把「逾期 N 天」折到第二行，實測 63.75px 對 81px。
估保守就少排列，估樂觀就撐出捲軸，而且無條件捨去還會再吃掉一列。

**改成回授**（0.4.87）：量「表格區塊（含分頁器）底部離畫面底還剩多少」，
夠塞一列就補（用最高的列估，寧可少補）、負數就縮（用最矮的列估並進位，一次拿夠），
剩餘空間連最矮的一列都放不下就是吃滿了。不需要猜列高到底多少。

- ⚠️ **調整完一定要主動再量一次**（JS 端要開一支 `remeasure`）。`ResizeObserver` 只看寬度，
  而改列數只會改高度——少了這一步，列數只會被調整一次，永遠停在第一次估的值。
- ⚠️ **要記下「已知放不下的列數」當上限**，否則補進來的那一列比估的高而撐出捲軸、
  縮回去之後剩餘空間又看起來夠補……如此反覆，每跳一次都打一輪查詢。
  上限只會往下壓、列數又有上下界，所以一定會停。
- ⚠️ **`rect` 是視窗座標**，要加 `window.scrollY` 換成文件座標，
  否則進頁面時剛好捲在半路就會算錯。標題列是 `sticky`（仍佔著流），換算後正好等於「沒捲動時的視窗座標」。
- ⚠️ **底部要多留 2px，面板高度上限用 `Math.floor` 不要 `Math.round`**：
  `scrollHeight` 是整數、版面高度是小數，剛好算滿時進位會多出 1px——而 1px 也是一條捲軸。
- ⚠️ **判斷「換了版面寬度」的容差不能用 0**：收斂過程中整頁捲軸會短暫出現，
  容器寬度跟著差一個捲軸寬（約 15px），用 0 會讓上限被自己造成的捲軸清掉。
  24px 大於任何常見捲軸寬，又遠小於側邊欄收合的 236px。

還有兩件跟版面無關但一定要處理的：

- **使用者自己改過每頁筆數就停止自動調整**，否則他選了 20 筆會立刻被蓋回去，看起來像選單壞了。
- **會多打一兩次查詢**：載入時先用回退值撈一頁，之後每調整一次再撈一次。
  要省掉就得先算繪一個沒有資料的空表格來量，為了幾次查詢把載入流程整個翻掉不划算。

⚠️ 實跑驗證時 **CDP 的 `Emulation.setDeviceMetricsOverride` 不會在頁面裡派送 `resize` 事件**
（真實瀏覽器拉視窗一定會派），腳本要自己補一發；而且判定要**等到狀態連續兩次相同**，
不要用固定 sleep——量測→查詢→重繪最多兩輪，固定等 2.8 秒會抓到過渡態，看起來就像沒收斂。

## 6.3 會產生外部 API 費用的動作一律二次確認 ⚠️（0.4.65 起）

全站只有兩個類別實際打付費 API：`AzureOpenAiTranscriptionProvider.TranscribeAsync` 與
`AzureOpenAiTextGenerationProvider.GenerateAsync`。任何最終會走到它們的 UI 入口，**都要有
`ConfirmAsync` 二次確認，且標題要寫出「（會產生費用）」**。目前有五條路徑，四條加了確認。

### 確認要放在「真正觸發 API 的那一步」之前

抽出待辦是反例，也是最容易做錯的形狀：`TodoExtractionModal` 的 `OnParametersSetAsync`
一開啟就呼叫 `ExtractAsync`，**Modal 顯示出來的那一刻 API 已經打出去了**。所以確認必須放在
開啟 Modal 的那顆按鈕上，不能放進 Modal 裡。開啟 Modal 的方法若是 `void`，**必須改成
`async Task`** 並改掉 razor 的 lambda——在 `void` 裡 `await` 確認等於 fire-and-forget，
視窗會照開照計費。

上傳影音檔的確認位置也有講究：它掛在 AntDesign `Modal` 的 `OnOk` 上，而**視窗會自己關掉**，
所以取消時一定要 `modalVisible = true`，否則使用者填的整張表單會消失。位置要在驗證通過之後、
主資料存檔之前——放在存檔之後按取消，會留下一筆存好卻沒有音檔的紀錄。

### 文案：講成本動因，不要講「幾次 API 呼叫」

轉錄的段數要等 FFmpeg 切完才知道，畫面上只有檔案大小，而位元率在語音備忘錄與含影軌的
MP4 之間差十倍以上；生成的段數算得出來但要每次點按都讀一次逐字稿檔，而 `TranscriptChunker`
優先在段落邊界斷句，`ceil(字數/上限)` 只是下界。**講錯數字比不講更糟**——「系統說 3 次、
帳單是 5 次」會變成客訴。只寫免費且精確的事實（上傳時的檔名與檔案大小是最強的防誤觸訊號），
其餘用質性描述（「音檔越長費用越高」）。

### Danger 跟「覆蓋」走，不跟「花錢」走

沿用 §6.1 的規則（非破壞性不套 Danger）。花錢不等於破壞性，所以紅色確認鈕只在會刪掉或
覆蓋既有資料時出現：重新轉錄且已有逐字稿、上傳且已有音檔、生成且已有草稿。首次執行、
失敗重跑、取消後重跑都不套；抽出待辦**永不**套（只產生候選，勾選儲存前什麼都沒寫）。

### 取消／中止類動作刻意不加確認

進度面板的「取消」**不要加確認**。取消是省錢的方向（`TranscriptionJobRunner` 每段開頭檢查
取消旗標，還在排隊就被取消的會整個跳過並註明「不要浪費一次 API 呼叫」）。對省錢方向加上
與花錢方向同等的阻力，等於訓練使用者把兩邊都無腦按掉。誤觸防護改用另一種方式：進度面板
是 §6.1 禁用純圖示按鈕的明文例外，正因為「取消」與「關閉」易混淆，兩顆都保留可見文字。

⚠️ **這一條只管背景工作的中止，不管表單的取消。**表單按取消會丟掉使用者打好的字，
那是相反的方向，0.4.84 起一律要確認——判準與完整規則見 §6.10。

**但這個決定的前提是「取消之後真的能重跑」**——所以取消後的狀態一定要留有出口。
`MeetingAdapterModel.CanRetryTranscription` 在 0.4.65 之前是列舉式且漏了 `Cancelled`，
取消過的紀錄根本不會出現重新轉錄鈕，取消等於死路。這類「能不能再送一次付費工作」的旗標
**一律寫成排除式**（列出不能送的狀態），不要寫成列舉式——新增 enum 值時列舉式會默默漏掉。

### 防連點要靠早退，不要只靠 Loading

`isGenerating` 這類旗標在 enqueue 回來後的 `finally` 立刻歸零，`Loading` 只覆蓋毫秒。
真正的防連點是方法開頭的早退，以及服務層擋掉 `Pending`（不只 `Processing`）——後者才是
最後一道防線，因為確認框擋不住「使用者確認兩次」。`CrudActionButton` 沒有 `Loading` 參數，
要用 `Disabled` ＋ 一個 per-row 的 id 欄位（比照 `exportingMeetingId`）。

## 6.4 堆疊層級（z-index）⚠️（0.4.68 起）

全站外框（頁首、側邊欄、側邊欄收合鈕）的 `z-index` **一律用 `app.css` 的三個變數**，不要自己挑數字：

```css
--z-app-header: 100;          /* .top-row（三個 layout 共用） */
--z-app-sidebar-toggle: 101;  /* 側邊欄收合鈕 */
--z-app-sidebar: 102;         /* 收合態側邊欄（其彈出選單在內部用 40） */
```

取值的依據是 AntDesign 1.6.0 **實際用到的值**（從 `ant-design-blazor.css` 查出來，不是憑印象）：

| AntDesign 元件 | z-index |
| --- | --- |
| `.ant-table-cell-fix-left` / `-right` / `.ant-table-summary` | 2 |
| `th.ant-table-selection-column.ant-table-cell-fix-left` | 3 |
| `.ant-affix` | 10 |
| `.ant-table-resizable .ant-table-resizing` | 99 |
| `.ant-modal-mask` / `.ant-modal-wrap` | 1000 |
| `.ant-message` / `.ant-notification` | 1010 |
| `.ant-dropdown` / `.ant-select-dropdown` / `.ant-picker-dropdown` | 1050 |

所以外框要 **> 99**（壓過所有表格內部圖層）且 **< 1000**（對話框、通知、下拉選單仍要蓋在外框之上）。我方的浮動面板（背景工作進度、`#blazor-error-ui`）刻意放在 1000，與 modal 同層。

### ⚠️ 父層的 z-index 會困住子層

這是 0.4.68 修掉的實際 bug：頁首 `.top-row` 原本是 `z-index: 1`，裡面的使用者選單雖然寫 `z-index: 20`，**但它逃不出頁首建立的那個堆疊脈絡**。結果清單頁表格的固定欄（`.ant-table-cell-fix-right`，z-index 2）直接蓋過整個頁首與選單——畫面上看到操作欄的圖示浮在頁首上、下拉選單被表頭切一半。

**子層寫再大都沒用，要改的是建立堆疊脈絡的那個父層。** 任何 `position` 非 `static` 且設了 `z-index` 的元素都會建立堆疊脈絡；新增這類容器時，先確認它的值高於它內部要彈出的東西所需要越過的所有圖層。

### `Fixed` 欄位要配 `ScrollX` 才會生效

`<ActionColumn Fixed="ColumnFixPlacement.Right">` 在沒有 `ScrollX` 的表格上是 **no-op**——全站 9 個清單頁都這樣寫，但只有待辦事項頁（0.4.66 起設了 `ScrollX="1020px"`）真的 sticky。要開 `ScrollX` 前先確認頁首的層級正確，否則就會重現上面那個 bug。

## 6.5 對話框的版面 ⚠️（0.4.69 起，0.4.82 重整）

**所有 Modal 外框樣式一律寫在 `Components/Commons/FormModalHelper.razor` 的全域 `<style>`**，不要寫在頁面的 `.razor.css`。原因是 Blazor 的 CSS isolation 會替選擇器加上 `[b-xxxxx]`，而 `.ant-modal-*` 是 `Modal` 元件渲染的 portal DOM，拿不到本元件的 scope 屬性，寫在 scoped CSS 裡**永遠選不到**。

⚠️ **`FormModalHelper` 掛在 `MainLayout`，全站每一頁都吃得到——不要在頁面裡再掛一個。**
0.4.69 之前 `MainLayout` 沒有 render 它（所以「變更密碼」的 `.change-password-modal` 從來沒生效過），
各頁面就自己補了 8 個，結果同一段 `<style>` 在 DOM 裡出現 9 次。0.4.82 把那 8 個移除、只留 layout 這一個。

### 兩層：基準線 ＋ 分級

**基準線**（`.ant-modal*`，0.4.82）套用到**每一個**對話框，包含唯讀檢視、清單、chat 與 `ConfirmAsync` 的確認框：

```css
.ant-modal         { top: 4vh; padding-bottom: 0; max-width: 94vw; }
.ant-modal-content { display: flex; flex-direction: column; max-height: 92vh; overflow: hidden; }
.ant-modal-header  { flex-shrink: 0; padding: 12px 20px; }
.ant-modal-footer  { flex-shrink: 0; padding: 10px 20px; }
.ant-modal-body    { flex: 1 1 auto; min-height: 0; overflow-y: auto; padding: 16px 20px; }
```

所以**新的對話框什麼都不做就已經是對的**：外框不捲、標題與按鈕永遠看得到、只有內容區捲動。

⚠️ `min-height: 0` 不可省。flex 子項的預設最小高度是內容高度，少了它 `overflow-y` 根本不會生效。

⚠️ **刻意不覆寫 `.ant-modal-wrap` 的 `overflow: auto`。** 它是「整頁在捲」的**現場**但不是**原因**：
wrap 會捲是因為 `.ant-modal` 比視窗高。把「4vh ＋ 最多 92vh ＝ 96vh」做成事實之後它根本沒東西可捲。
留著 `auto` 是**唯一的退路**——萬一日後有人加上更大的 `max-height`，`auto` 的結果是「可以捲到底，難看但救得回來」，
`hidden` 的結果是「底部連同按鈕被永久裁掉，使用者既操作不到也看不出來」。

**分級只負責寬度**（刻意不是一律滿版：3 個欄位的表單撐成整個螢幕寬，欄位會漂在一片空白中間）：

| class | 寬度 | 適用 |
| --- | --- | --- |
| `.form-modal-compact` | 680px | 3～4 個欄位、唯讀短清單（分類、團隊、變更密碼、關於、AI 轉會議紀錄、歸屬到專案）|
| `.form-modal-standard` | 880px | 5～8 個欄位、清單型（待辦、提示詞、使用者、專案附件、抽出待辦、唯讀檢視會議紀錄）|
| `.form-modal-wide` | 1080px | 左右分欄的對話式內容（AI 問答）|
| `.form-modal-large` | 90vw | 權限矩陣、多份清單（角色、專案）|
| `.meeting-view-modal` | 96vw（`top: 2vh`、`max-height: 96vh`）| 影音上傳、左右分欄編輯器 |

⚠️ **掛了尺寸 class 就不要再設 `Width`。** 這裡的 `width` 是 author-important，依 CSS 串聯順序
**贏過 `Width` 產生的 inline style**——參數會靜默失效，留著只會讓下一個人以為調它有用。
`MeetingRecord.Tests/ModalSizeClassTests.cs` 會擋這件事，也會擋「Modal 沒有任何尺寸 class」。

⚠️ 高度一律用 `max-height` 不用固定 `height`：固定高會讓短內容硬撐成整個螢幕高、中間空一大片
（0.4.82 之前 `.form-modal-large` 就是這樣，新增專案時三個清單都空著最明顯）。

⚠️ **自繪按鈕列（`Footer="null"`）的對話框要自己處理按鈕不被捲走。** 基準線的 `flex-shrink: 0`
只保護 `.ant-modal-footer`；按鈕放在 body 裡的話，會被上面佔滿高度的內容擠出捲動區——
視窗看起來正常，但「儲存」永遠按不到。作法見 `.markdown-editor-modal .ant-modal-body`
（把 body 變成 flex column，內容 `flex: 1 1 auto`、按鈕列 `flex-shrink: 0`）。

### ⚠️ Razor 註解的兩個坑（都編譯得過，只有開畫面才看得到）

**一、不要在元件標籤的屬性之間寫註解。**
註解夾在兩個屬性中間時，Razor 會把整段註解當成**屬性名稱**傳給元件，
執行期丟 `InvalidOperationException: does not have a property matching the name`、整頁空白。
註解要寫在標籤**外面**。

**二、註解內文不可以出現註解的結束符號。**
Razor 的註解**不能巢狀**，它看到第一個結束符號就收工，後面的文字會變成一般 markup
**直接渲染到畫面上**。0.4.82 就是這樣讓一段開發者註解外洩到會議紀錄頁的底部：
那段註解本身是在警告第一個坑，內文引用了符號，結果自己把自己關掉了。

⚠️ **包在反引號裡也沒用**——Razor 不看 Markdown，它只認符號序列。
要提到那組符號時用文字敘述（「註解的開始／結束符號」），不要把符號本身打出來。

平衡計數（開幾個關幾個）**抓不到這個缺陷**：上面那個案例正好是開 2 關 2。
`MeetingRecord.Tests/RazorMarkupTests.cs` 改照 Razor 的規則掃——從每個開始符號找到**第一個**
結束符號，檢查那段內文裡有沒有再出現開始符號——所以這個坑現在會在測試階段就紅。

### 短欄位一行兩欄

把 `FormItem` 包進 `<div class="form-modal-grid">`，要跨整列的加 `Class="form-modal-full"`：

```razor
<AntDesign.Form ... Layout="FormLayout.Vertical">
    <div class="form-modal-grid">
        <FormItem Label="名稱" Required>…</FormItem>
        <FormItem Label="代號">…</FormItem>
        <FormItem Label="描述" Class="form-modal-full">…</FormItem>
    </div>
</AntDesign.Form>
```

分欄原則：**單行輸入（Input／Select／DatePicker／Switch／Checkbox）併排；多行或寬內容（TextArea／檔案清單／Slider／權限矩陣／很長的 placeholder）跨整列**。768px 以下自動退回單欄。

⚠️ `.form-modal-grid` 的子項選擇器用 `>`，所以 `FormItem` 必須是 grid 的**直接子元素**。包在 `@if` 裡沒問題（Razor 的條件式不產生 DOM 節點），但多包一層 `<div>` 就會壞掉。

⚠️ 全站**沒有**用 AntDesign 的 `<Row>`／`<Col>`，兩欄一律是這個 CSS grid。

## 6.6 Markdown 渲染一律走 `MarkdownRenderer` ⚠️（0.4.70 起）

任何要把 Markdown 變成 HTML 的地方——畫面上的 AI 回答、會議紀錄草稿檢視、匯出 PDF——**一律呼叫 `MeetingRecord.Business.Helpers.MarkdownRenderer.ToHtml`**。

**不要再開第二條 Markdig pipeline。** 兩個理由：

1. **PDF 那條不比畫面安全，反而更危險。** `HeadlessBrowserPdfRenderer` 是叫無頭瀏覽器去讀 `file://` 的 HTML，**瀏覽器會執行 script**，而且是本機檔案來源。注入到會議紀錄草稿（使用者可自由編修）的內容會在**伺服器上**跑起來。
2. 兩條管線必然走鐘，出事時很難判斷是哪一條的行為。

### 管線刻意排除的擴充

`MarkdownRenderer` **明列**要啟用的擴充而不是用 `UseAdvancedExtensions()`：

⚠️ `UseAdvancedExtensions()` 的官方定義是「**除了** BootStrap、Emoji、SmartyPants 與軟換行外全部啟用」，也就是**包含 `GenericAttributes`**。`## 標題 {onclick="alert(1)"}` 會直接產出 `onclick` 屬性，而 `DisableHtml()` **擋不到它**（那是屬性，不是 HTML 區塊）。同理排除 `MediaLinks` 與 `Diagrams`（會產生 iframe 或外連資源）。

反過來，**表格一定要留**：提示詞範本由使用者自行撰寫、系統不規範 LLM 的輸出格式，實務上很常出現表格。少了它會原封不動印成 `|---|---|`。

`UseCjkFriendlyEmphasis()` 也一定要留：CommonMark 的 right-flanking 判定對中文不友善，`**備註：**兩份紀錄…` 結尾的 `**` 後面直接接中文字時不算 emphasis，會原樣印出來。

### 連結淨化走 AST 走訪

`Markdown.Parse` 之後走訪 `document.Descendants()`，把 `LinkInline` 與 `AutolinkInline` 的 `Url` 過白名單（`http`／`https`／`mailto`，相對位址與 `#錨點` 放行），再 `Markdown.ToHtml(document, pipeline)`。

⚠️ **`AutolinkInline` 不能漏**：`<javascript:alert(1)>` 是合法的 CommonMark autolink，走的不是 `LinkInline`。
⚠️ **判斷通訊協定前要先丟掉控制字元**，瀏覽器就是這樣做的——不先丟的話 `java<TAB>script:` 可以直接繞過白名單。
⚠️ **`#錨點` 一定要放行**，否則註腳與自動標題 id 全斷。

### `DisableHtml()` 是逸出不是丟棄

`<img src=x onerror=…>` 的輸出是 `&lt;img src=x onerror=&quot;…`。寫測試時要斷言**有沒有產生元素**（`DoesNotContain("<img")`），不是文字裡有沒有那串字——後者兩種行為都會過，等於沒驗到。

### 塞進 Blazor 的注意事項

- 用 `@((MarkupString)MarkdownRenderer.ToHtml(x))`，容器用 `<div>` 不要用 `<pre>`（`<pre>` 自帶等寬字型與 `white-space: pre`）
- ⚠️ 容器**不能**有 `white-space: pre-wrap`：Markdig 產出的標籤之間本來就有換行，保留下來每個區塊之間會多一行
- ⚠️ 內文樣式一定要用 `::deep`：`MarkupString` 產生的子節點拿不到 `[b-xxxxx]` scope 屬性（同 §6.1 的坑）
- Bootstrap 的預設 `code` 是粉紅色，要 `color: inherit` 蓋掉

## 6.7 幫既有實體加欄位時的三條寫入路徑 ⚠️（0.4.71 起）

以 `Project` 為例。加一個欄位要動的**不只是 AutoMapping**，有三條互不相干的寫入路徑，漏掉任何一條都會靜默失效：

| 路徑 | 機制 | 要做什麼 |
| --- | --- | --- |
| `ProjectService.AddAsync` | `Mapper.Map<Project>(paraObject)` | 加 `ForMember` 即可 |
| `ProjectService.UpdateAsync` | **手抄每個欄位，完全不走 Mapper** | **必須補一行賦值** |
| `ProjectRepository.UpdateAsync`（Web API） | `context.Entry(x).CurrentValues.SetValues(project)` | 見下 |

⚠️ 只改 AutoMapping 的症狀是「**新增存得進去、修改存不進去**」，而且畫面上看起來像存成功了。

⚠️ **`SetValues` 會覆寫所有純量欄位。** controller 傳進去的是 `mapper.Map<Project>(dto)` 產生的**全新實體**，DTO 沒帶到的欄位一律是 null——舊版客戶端一次 PUT 就會把新欄位清光。同一個方法裡 `project.CreatedAt = existingProject.CreatedAt;` 就是這個坑的前例。處理方式有二：把欄位加進 `ProjectCreateUpdateDto`，或在 repository 用 `??=` 保留（「傳 null 視為沒有要改」）。0.4.71 兩個都做了。

> 其他實體的服務不一定是這個形狀（多數走 Mapper），但**動手前一定要實際讀一次 `UpdateAsync`**，不要假設它跟 `AddAsync` 對稱。

### 多值欄位一律用 `TagStringHelper`

儲存格式是換行包夾字串（`"\nA\nB\n"`），`ToStored` / `ToList` 負責 trim、捨棄空項、忽略大小寫去重、保留原順序、全空回 null。AutoMapping 兩個方向都要 `ForMember`（範例見 `PromptTemplate` 與 `Project` 兩個 region）。

⚠️ AdapterModel 加了 `List<T>` 之後，**`Clone()` 必須深複製**。`MemberwiseClone` 是淺的，編輯對話框是「先 Clone 再改」，不深複製的話按「取消」也已經改到清單資料列上了。

## 6.8 中文輸入法與 Blazor Server ⚠️（0.4.71 起）

**不要用 AntDesign `Select` 的 `SelectMode.Tags` 讓使用者輸入中文。**

0.4.71 實測（用 CDP 的 `Input.imeSetComposition` 真實模擬注音組字，不是 `dispatchEvent` 假造）：

| 元件 | 輸入「艾琪」的結果 |
| --- | --- |
| 普通 `<Input>`（change 事件回寫） | `艾琪` ✅ |
| `<Select EnableSearch>`（單選、從清單挑） | `艾琪` ✅ |
| **`<Select Mode="SelectMode.Tags">`** | **組字內容殘留**，畫面上出現 `艾ㄑ－艾琪` 這種半成品 |

元件內部**有** IME 處理（`SelectContent.IsComposing`），但擋不住 Blazor Server 逐鍵回傳伺服器的時間差——組字中途的注音被伺服器回寫進欄位，定案的字再接在後面。

⚠️ **這個症狀在本機無頭瀏覽器上重現不出來**（延遲太低），所以「調參數看看能不能修好」這條路沒有辦法驗證，只能丟給使用者試錯。直接換成結構上不會有問題的輸入方式比較誠實。

### 讓使用者自由輸入多值時的做法

用**普通 `<Input>` ＋「新增」按鈕**，標籤外觀自己畫（範例見 `ProjectViewView.razor` 的「常用名詞」「常用與會人員」與 `.project-view-tag-*` 樣式）。

兩個實作細節，都是實跑才發現的：

- ⚠️ **「新增」鈕不要依輸入框內容停用。** `<Input>` 是 change（失焦）才回寫，按鈕會一直停用到失焦為止——而**點一顆停用的按鈕不會觸發它的 click**，使用者得點兩次才加得進去。空值交給 handler 自己擋。
- ⚠️ **這裡的「新增」鈕不要綁 Enter。** 中文輸入法用 Enter 確認候選字，綁在按鈕上一定誤觸。
  （0.4.77 起表單本身可以 Enter 送出了，但那是另一回事——見下一節，關鍵在於**判斷式要看 `IsComposing`**。）

### 表單的 Enter 送出：一律走 `FormKeyboardHelper`（0.4.77 起）

0.4.77 之前，多數編輯對話框的 `EditForm` 掛 `@onkeydown="OnModalKeyDownAsync"`，而那個 handler
只比對 `args.Key == "Enter"`——**七個 handler 沒有一個做輸入法防護**。使用者按 Enter 多半只是要
確認輸入法的候選字，結果整個對話框就存檔關掉了。

現在一律改用共用判斷（`Components/Commons/FormKeyboardHelper.cs`）：

```csharp
if (FormKeyboardHelper.IsSubmit(args)) { … }      // Enter，且非組字中、無修飾鍵
else if (FormKeyboardHelper.IsCancel(args)) { … } // Escape / Esc
```

三個關鍵：

- ⚠️ **`KeyboardEventArgs.IsComposing` 是唯一的輸入法途徑。** `KeyboardEventArgs` 沒有 `KeyCode`，
  所以「檢查 229」在 Blazor 端做不到。這個屬性 .NET 9 才加，本專案 0.4.77 才開始用。
- **Shift+Enter 在多行欄位換行**：`IsSubmit` 回 false，瀏覽器的原生行為就會換行，不必寫程式碼。
- ⚠️ **`await Task.Delay(200)` 不是可以省的**：AntDesign `Input` 預設 change／blur 才回寫繫結值，
  Enter 送出時焦點還在欄位裡，不等就會拿到舊值。

`ProjectViewView` 的兩個多值輸入區仍然保留 `@onkeydown:stopPropagation`——那裡擋的是
「新增標籤」這種按鈕級的 Enter，與表單送出是兩件事。

### 刻意不綁 Enter 的地方

| 對象 | 理由 |
| --- | --- |
| **19 個 `ConfirmAsync` 二次確認框** | 那道手續正是 0.4.65 為了付費與破壞性動作加的；綁 Enter 等於送出表單的 Enter 還沒鬆手、確認框就被按掉了 |
| **編修會議紀錄的左欄 textarea** | 那是在改一份多段落的長文件，不是輸入一句話送出。0.4.82 起同一個視窗**上方的搜尋框**反而有綁：Enter = 下一筆（`IsSubmit`）、Shift+Enter = 上一筆（`IsReverseSubmit`），兩者都擋組字中的 Enter。「編修逐字稿」已隨功能移除 |
| 登入頁 | 靜態 SSR 原生表單，Enter 早就能送出，而且原生表單天生 IME 安全 |

### `Select` 其他兩個已知的坑（多選、從清單挑的情境仍會用到）

- **`@bind-Values` 編譯不過**：`ValuesChanged` 是 `EventCallback<IEnumerable<TItemValue>>`，與 `List<string>` 屬性型別對不上。用 `Values="..."` ＋ `OnSelectedItemsChanged="..."`。
- **Modal 不是條件渲染，元件實例會跨次開啟殘留**：本專案的編輯對話框都只靠 `@bind-Visible` 開關，而 `SelectBase.OnValuesChangeAsync` 開頭有「沒有選項就直接 return」。換一筆資料時舊的選取會留在畫面上。要給一個**每次開啟都會變的 `@key`**（例如開啟次數計數器）；⚠️ **用資料的 Id 當 key 沒有用**——同一筆資料重開時 Id 不變。

> 這些坑**單元測試全部抓不到**（bUnit 測不了 overlay 與 JS interop），只能實際打字驗。

## 6.9 把必填參數放寬成可空時 ⚠️（0.4.73 起）

把 `int` 參數改成 `int?`（例如 `RequestDraftAsync` 的 `projectId`）**會靜默改變既有判斷式的語意，而且編譯器不會警告**。改之前先把所有用到那個參數的判斷式列出來，逐一問「傳 null 時這條會怎麼走」。

0.4.73 實際踩到的兩個：

### 相等比較會把 null 當成「不一樣的值」

```csharp
// 原意：這筆已經歸屬別的專案 → 拒絕
if (meeting.ProjectId is not null && meeting.ProjectId != projectId)
```

`projectId` 變成 `int?` 之後，「已屬 A ＋ 傳 null（不指定）」會因為 `A != null` 為 true 被判成衝突而**整筆拒絕**。要補上 `projectId is not null &&`。

### EF 的 lifted comparison 在 null 時恆為 false

```csharp
// projectId 是 null 時，這行查不到任何列 → 誤報「找不到指定的專案項目」
var project = await context.Project.FirstOrDefaultAsync(x => x.Id == projectId);
```

`int` 與 `int?` 的比較在 SQL 端是 `= NULL`，永遠不成立。存在性檢查要整段包在 `if (id is not null)` 裡。

> 好消息是**呼叫端不必改**：`int → int?` 是隱含轉換，既有呼叫與既有測試都照舊編譯。這也正是危險的地方——**沒有任何紅字提醒你去檢查語意**，所以每一種 null 組合都要有測試釘住。

## 6.10 表單的取消要確認，背景工作的取消不要 ⚠️（0.4.84 起）

判準只有一句：**這個動作會不會讓使用者失去自己輸入的東西？**

| | 會不會丟掉輸入 | 要不要確認 |
|---|---|---|
| 表單的「取消」（新增／修改視窗）| **會**——打了半天的字直接消失 | **要** |
| 背景工作的「取消」（進度面板）| 不會，只是不做一件會花錢的事 | **不要**（見 §6.3）|

⚠️ 兩件事都叫「取消」，但方向相反，不要混。§6.3 那條「取消／中止類動作刻意不加確認」
講的是**背景工作的中止**，是省錢方向；表單取消失去的是使用者花時間打的字。

### 規則

- **只有真的改過才問。**對沒改過的表單也問，正是 §6.3 警告的「訓練使用者無腦按掉」。
- dirty 判斷一律走 `Components/Commons/FormDirtyHelper`：開表單時 `Capture(...)` 拍一份
  JSON 快照，取消時 `IsDirty(...)` 比對。確認框文案走同一支 helper，全站一種說法。
- ⚠️ **不要用 `EditContext.IsModified()`。**`InputWatcher` 撈到的是**外層 `EditForm`** 的
  EditContext，而欄位住在**內層 `AntDesign.Form`** 底下，欄位變更的通知打不到外層，永遠回 false。
  （`Validate()` 能用，是因為它驗的是同一個 model 實例，不依賴 field-change 通知。）

### 三個一定會踩到的坑

**一、`@bind-Visible` 是雙向的。**
AntDesign 在呼叫 `OnCancel` **之前**就把視窗關掉了，在 handler 裡 `return` 留不住它。
使用者選「繼續編修」時必須 `modalVisible = true` 把它開回來，否則整張表單反而會消失——
正好是我們要修的問題的反面。（`TodoExtractionModal` / `MarkdownEditorModal` 用單向
`Visible=`，那種**不可以**寫 `Visible = true`，直接 `return` 就留得住。）

**二、Esc 會走兩條路。**
AntDesign Modal 的 `Keyboard="true"` 與表單上的 `@onkeydown` 都會呼叫同一個 cancel handler。
0.4.84 之前兩次都只是 `modalVisible = false`，冪等所以沒人發現；**加了確認框之後會疊出兩個**。
每個表單都要一個 `isDiscardConfirming` 旗標擋重入。

**三、不在 model 上的暫存狀態也算「改過」。**
待上傳的檔案（`pendingMediaFile`、`pendingUploadFiles`）不在 model 裡，要透過
`Capture` 的 extras 一起比。⚠️ **不可以把 `IBrowserFile` 丟進去**——它身上帶著 Stream，
序列化出來的結果與使用者選了哪個檔案無關，所有檔案都長得一樣。用「檔名:大小」的字串。

### 刻意**不**加確認的視窗（不是漏掉）

| 視窗 | 理由 |
|---|---|
| 專案附件（唯讀清單）| 只有下載鈕，沒有任何輸入 |
| 待辦詳情、關於 | 唯讀 |
| AI 轉會議紀錄、歸屬到專案 | 只有選取沒有輸入；且取消是「不花錢」方向，依 §6.3 不加阻力 |

### 已知且接受的誤判（都只會多問一次，不會漏問）

- `TodoAdapterModel.OverdueDays` 依賴 `DateTime.Today`：開著視窗跨過午夜會誤判。
- `RolePermissionNode.Actions` 是字典，勾了再取消勾會多出一個 `"edit": false` 的 key。

兩者都不值得為它們改既有程式碼。`FormDirtyHelper` 的設計原則是**所有不確定都往「多問一次」倒**：
漏問會靜默吃掉使用者的輸入，多問只是多按一下。`IsDirty(null, ...)` 一律回 true 也是同一個理由
（代表開表單時忘了拍快照，症狀是「每次取消都問」，一試就發現）。

## 8.1 外部相依與長時間工作（0.4.27 起，0.4.31 補充生成軌道）⚠️

- **FFmpeg 是外部執行檔相依**：語音轉錄前一律以 FFmpeg 把影音檔轉成 mp3 並固定切成 15 分鐘分段。路徑由 `MediaSettings:FfmpegPath` 設定（預設 `ffmpeg`，走 PATH），沒安裝就沒有轉錄功能。**一律切段**是刻意的——轉錄 API 有單檔 25MB 上限，固定路徑讓長會議與短錄音共用同一套邏輯。
- **FFmpeg 存在性在啟動時就檢查（0.4.29 起）**：判斷一律走 `FfmpegPathResolver.Exists`（純檔名會沿 `PATH` + `PATHEXT` 搜尋，與 `Process.Start` 一致），別自己寫 `File.Exists`——那會把 `ffmpeg` 這種正確設定誤判成不存在。Production 找不到就中止啟動，其他環境只記 WARN 照常啟動（沒在用轉錄的開發者不該被擋）。
- **對外 HTTP 一律走 `IHttpClientFactory`**：`AddTranscriptionServices` 與 `AddTextGenerationServices` 各自註冊具名 client（逾時皆 10 分鐘）。
- **AI 供應商設定一律走 `IOptions<LlmSettings>` / `IOptions<MediaSettings>`**，禁止直接讀 `IConfiguration`。換廠商的擴充點是 `ITranscriptionProvider`（轉錄）與 `ITextGenerationProvider`（生成），兩者形狀刻意對稱。
- **長時間工作不得阻塞 Blazor circuit**：轉錄與草稿生成各走一條行程內 `Channel<T>` 佇列 + 單一 worker `BackgroundService`，每筆工作自建 DI scope。佇列**不持久化**（單一實例假設），因此 `Program.cs` 啟動時會把殘留的「處理中」／「生成中」改判為「失敗」，由 UI 重新觸發。
- **兩條背景軌道刻意不共用 worker** ⚠️：轉錄一筆可能跑數十分鐘，共用單一 worker 會讓草稿生成被長音檔堵在後面。新增第三種背景工作時請比照開新軌道，不要塞進既有佇列。
- **UI 舊複本不得覆寫背景寫入的狀態** ⚠️：`MeetingService.UpdateAsync` 與 `MeetingRepository.UpdateAsync` 都一律沿用資料庫既有的媒體、轉錄與 AI 草稿欄位。日後再有背景工作寫回主表時，請比照辦理——漏掉的話畫面上的舊複本存檔就會把背景寫入的結果清空。
- **停掉正在跑的實例一律先用 `netstat` 由埠找 PID** ⚠️：`netstat -ano | Select-String ":5189.*LISTENING"` → `tasklist /FI "PID eq <PID>"` 確認 → `taskkill /PID <PID> /F`。**絕對不要用 `taskkill /IM MeetingRecord.Web.exe`**——Visual Studio 偵錯中的宿主行程會匹配到同樣的映像名稱，本專案曾因此連帶砍掉開發者的 VS。完整流程見 [啟動與停止系統](../operations/啟動與停止系統.md)。
