# 稽核事件擴充：使用者 / 角色 / 權限異動（0.4.23）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.4.23
- 首次實作版本：0.4.23
- 最後核對日期：2026/07/14

## 目的

稽核表 `AuditLog` 與 `IAuditLogService` 原本只在登入流程寫入（`Login.*`）。本次補齊**使用者、角色與權限異動**的留痕，消除合規落差（誰在何時新增/修改/刪除了哪個帳號或角色、改了哪些權限、指派了哪些角色/團隊）。

**無模型變更（`AuditLog` 表已存在）→ 不需 migration。**

## 變更範圍

- **`MyUserService`**（`MeetingRecord.Business/Services/DataAccess/`）：建構子注入 `IAuditLogService` + `CurrentUserService`；`AddAsync`/`UpdateAsync`/`DeleteAsync` 成功時寫 `User.Create`/`User.Update`/`User.Delete`，`TargetType=MyUser`、`TargetId=使用者 Id`、`Detail` 含帳號與角色/團隊指派摘要（`account=…; roleIds=[…]; teams=[…]`）。
- **`RoleViewService`**：同樣注入稽核 + CurrentUser；`AddAsync`/`UpdateAsync`/`DeleteAsync` 成功時寫 `Role.Create`/`Role.Update`/`Role.Delete`，`TargetType=RoleView`、`Detail` 含角色名稱與權限鍵數。因這兩服務內部已呼叫 `SyncAssignmentsAsync`／`SyncRolePermissionsAsync`（角色/團隊指派、權限矩陣雙寫），在此層記錄即涵蓋**權限異動**。
- Actor 由 `CurrentUserService.CurrentUser` 取得（UI 登入時經 `AuthenticationStateHelper.Check` 填入）；`Id==0`（未登入）時 `ActorUserId` 傳 null。

## 設計重點

- **不動 `RbacWriteService`**：維持其為純資料層、不引入 actor 依賴；稽核放在有 `VerifyRecordResult`（判成敗）與可取 actor 的服務層。
- **僅記錄成功異動**：合規留痕核心；一般表單驗證失敗價值低、避免噪音（與登入失敗屬攻擊訊號不同）。
- 沿用既有容錯 `IAuditLogService.WriteAsync`（寫入失敗只記 NLog、不中斷主流程），放在各方法自身 `SaveChanges` 成功後、`return` 前。
- Action 沿用 `名詞.動作` 點分命名。

## 驗證

- 單元測試：新增 `AuditEventsTests`（6 例，涵蓋 User/Role 的 Create/Update/Delete 與未登入 actor=null），共 **135 測試全綠**。
- 建置：`dotnet build` 綠燈。
- 實跑（SQLite/Development，瀏覽器實際操作 + Python 查 `AuditLog` 表）：以 `support` 登入，於 /myusers 新增/編輯/刪除帳號、於 /roleviews 新增/刪除角色 → `AuditLog` 出現對應 `User.*`/`Role.*` 事件，`ActorAccount=support`、`ActorUserId=1`、`Success=1`、`TargetType`/`TargetId`/`Detail`（含中文）正確。

## 注意事項

- 密碼變更事件（`ChangeOwnPasswordAsync` 等）本次未納入，留待需要時另補。
- 這些管理功能目前僅 Blazor UI 入口；若日後新增管理 API，actor 取得可比照 `RecordAccessScopeProvider` 用 `ClaimTypes.Sid`。
- `appsettings.json` `SystemVersion` 0.4.22 → 0.4.23。
