# 移除工作項目、會議記錄與 SQL Server 支援，新增「關於」對話窗（0.4.24）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.4.24
- 首次實作版本：0.4.24
- 最後核對日期：2026/08/17

## 目的

將腳手架收斂到更小、更一致的核心：

1. 「工作項目」與「會議記錄」不再是本系統需要的作業，且與「專案項目」高度雷同，留著只是三份幾乎相同的樣板程式碼與文件維護成本。
2. SQL Server 軌道實際上是**空殼**：`MeetingRecord.AccessDatas.SqlServerMigrations` 只有一個 marker 類別、`Migrations\` 資料夾是空的。更糟的是 `appsettings.Production.json` 預設 `DatabaseProvider=SqlServer`，而該 provider 下 `GetMigrations()` 為空會靜默落入 `EnsureCreated()`，產生沒有 migration 歷史表的 schema。此次把資料庫收斂為單一 SQLite 軌道，讓程式碼、設定與文件三者一致，並順帶修掉這個既有缺陷。
3. 系統原本沒有任何地方向使用者顯示版本（`SystemVersion` 只出現在管理員專屬健康監控頁的一句 evidence 字串），因此在右上角使用者選單新增「關於」對話窗。

## 變更範圍

### 一、移除工作項目（MyTask）與會議記錄（Meeting）

- **刪除 30 個功能專屬檔案**：頁面／檢視（`MyTasPage.razor`、`MeetingPage.razor`、`MyTasViewView.*`、`MeetingViewView.*`）、Controller（`MyTaskController`、`MeetingController`）、Service／Repository（`MyTasService`、`MeetingService`、`MyTaskRepository`、`MeetingRepository`）、Entity（`MyTask`、`MyTasFile`、`Meeting`、`MeetingFile`）、AdapterModel／上傳輸入、DTO（Dto／CreateUpdateDto／SearchRequestDto）。
- **共用檔案清理**：`BackendDBContext`（4 個 DbSet + 2 段 cascade 設定）、`AutoMapping`（`#region MyTas` 與 `#region Meeting` 共 16 個 `CreateMap`）、`MagicObjectHelper`（`角色_工作項目`、`角色_會議項目`）、`RolePermissionService`、`SidebarMenuService.MenuPermissionMap`（`[22]`、`[23]`）、`Menu.json`（id 22／23）、`ServiceCollectionExtensions`（4 筆 `AddScoped`）、`Program.cs`（2 筆 `EnsureDirectoryExists`）、`SystemSettings.ExternalFileSystem`（`TaskFilePath`／`MeetingFilePath`）、`appsettings.json`、`SystemHealthService.CheckFileSystem`、`FormModalHelper.razor`。
- **Migration**：新增 `20260817031712_RemoveTaskAndMeeting`，`Up()` 依序 `DROP` `MeetingFile`、`MyTasFile`、`Meeting`、`MyTas`（子表先於主表）。

> `Project` 原本就**沒有**指向 `MyTask`／`Meeting` 的導覽屬性，兩者之間也毫無關聯，因此移除為單向乾淨切割，不影響專案項目。

### 二、移除 SQL Server 支援

- 刪除整個 `MeetingRecord.AccessDatas.SqlServerMigrations` 專案，並從 `MeetingRecord.slnx` 與 `MeetingRecord.Web.csproj`（`ProjectReference` + `Microsoft.EntityFrameworkCore.SqlServer` 套件）移除參考。
- `AddConfiguredDatabase` 的 provider `switch` 簡化為直接 `options.UseSqlite(...)`。
- `SystemSettings` 移除 `DatabaseProvider` 屬性、`GetDatabaseProvider()`、`DatabaseProvider` 列舉與 `ConnectionStrings.DefaultConnection`。
- `appsettings.json` 移除 `DatabaseProvider`／`DefaultConnection`；`appsettings.Production.json` 移除整段 `SystemSettings`（原本只放這兩個鍵）。
- `SystemHealthService` 三處資料庫訊息改為固定字樣 `SQLite`；移除 `ApiIntegrationTests` 的 `SystemSettings_ShouldResolveDatabaseProvider` `[Theory]`。

### 三、新增「關於」對話窗

- `MainLayout.razor` 使用者下拉選單於「設定 API 密碼」與「登出」之間新增「關於」；沿用既有「變更密碼」的模式（內嵌 AntDesign `Modal` + `bool` 開關），不新增元件、不使用 `ModalService`。
- `MainLayout.razor.cs` 新增注入 `IOptions<SystemSettings>`、`IWebHostEnvironment` 與 Singleton `SystemStartupState`，`OnAboutClick` 於**點擊當下**組出七列資訊：系統名稱、系統描述、系統版本、執行環境、.NET 版本、啟動時間、已運作時間。
- 對話窗寬度以 `Width="520"` 直接指定 —— `MainLayout` 並未渲染 `FormModalHelper`，不能依賴其 CSS class。

## 注意事項

- **既有資料庫**：啟動時會自動套用 `RemoveTaskAndMeeting`，四張表及其資料一併消失。升級前如需保留舊資料請自行備份。
- **附件實體檔案不會被自動刪除**：`TaskFilePath`／`MeetingFilePath` 目錄下的檔案仍留在磁碟上，需自行清理。
- **權限殘留刻意不處理**：以既有 DB 實測升級後，RBAC `Permission` 表仍留有 `工作項目`／`會議項目` 兩列，`RolePermissionMap` 亦仍有 2 列指向它們；`RoleView.TabViewJson` 則因啟動 Seed 會重寫而已不含這兩個鍵。權限是以**名稱**比對（`RolePermissionService.SetPermissionInput` 用 `HashSet<string>`）而非位置索引，這些殘留不會被任何頁面或 API 使用，也不會造成既有角色設定錯位，故讓其自然失效。
- **已知殘留**：`BackendDBContext.OnModelCreating` 仍保留 `UseCollation("Chinese_Taiwan_Stroke_CI_AS")`。這是 SQL Server 概念、SQLite 會忽略；移除會產生額外的模型差異與 migration 雜訊，故刻意保留。
- **側邊選單**：「專案管理」群組保留，底下只剩「專案項目」，`角色_專案管理` 權限鍵與 id:2 結構不變。
- 測試中原本把「工作項目」當作泛用權限字串的兩處（`PermissionCheckerTests`、`RbacWriteServiceTests`）已改用仍存在的「分類清單」。
