## 目的

系統已於 0.4.25 由通用 Blazor 腳手架就地轉為「會議紀錄系統」的開發基底，但當時是**純更名**，沒有任何會議紀錄領域功能。本次加入第一個領域能力：讓使用者先把「產生會議紀錄要下給模型的指令」管理起來。

最終目標流程是「上傳會議語音檔 → 轉錄 → 套用提示詞 → 產出會議紀錄」。本次刻意只切下最前面、最獨立、風險最低的一段：

1. **提示詞範本的 CRUD**（含分類／團隊標籤與團隊列級權控）。
2. **provider-aware 的 `LlmSettings` 強型別設定骨架**，讓日後串接轉錄與生成時不必再動架構。

**本次不呼叫任何外部 API**：沒有音檔上傳、沒有語音轉錄、沒有 LLM 呼叫、沒有會議紀錄 Entity。完整流程與未決議題另立一份規劃中 PRD。

### 二、提示詞變數

固定支援三個變數：`{{transcript}}`、`{{meetingTitle}}`、`{{meetingDate}}`（大括號內允許空白、變數名比對不分大小寫）。

儲存時掃描 `{{...}}`，出現清單外的變數會發出警告並列出未知變數與支援清單，**但不阻擋儲存**。理由：範本作者常會先寫下尚未支援的佔位符再逐步調整，硬擋會打斷正常編輯流程。因此這段判斷刻意放在 UI 的 `NotifyUnknownVariables()`，**不進 Service 的 `BeforeAddCheckAsync`／`BeforeUpdateCheckAsync` 驗證流程**；判斷邏輯抽在 `PromptVariableHelper` 以便單元測試。

### 三、LLM 設定區段

`appsettings.json` 新增頂層 `LlmSettings`，以 `Providers` 字典依供應商名稱分組，`DefaultProvider` 指定預設供應商：

```json
"LlmSettings": {
  "DefaultProvider": "AzureOpenAI",
  "Providers": {
    "AzureOpenAI": {
      "Endpoint": "https://your-resource.openai.azure.com/",
      "ApiKey": "DevelopmentOnly-ChangeThisLlmApiKey",
      "Model": "gpt-4o-mini",
      "ApiVersion": "2024-10-21"
    }
  }
}
```

用字典而非陣列的理由：唯有字典才讓 `LlmSettings__Providers__AzureOpenAI__ApiKey` 這種環境變數覆寫成立（陣列是 `__0__`，插入新廠商就整組錯位）；未來加第二家只是多一個物件，既有設定鍵一個都不用動。

新增 `MeetingRecord.Models/Systems/LlmSettings.cs`（放 Models 而非 Web，因為下一階段的呼叫端會在 Business，而分層依賴是 Web → Business 單向），`Program.cs` 以先前保留的空 region 綁定 `IOptions<LlmSettings>` 並 `ValidateOnStart`。驗證用 `IValidatableObject` 實作——`ValidateDataAnnotations()` **不會遞迴進 Dictionary 的 value**，把 `[Required]` 掛在 `LlmProviderSettings` 屬性上永遠不會被驗到。

`appsettings.Production.json` 清空 `DefaultProvider` 與 `ApiKey`：正式環境預設「未啟用 LLM」，要用必須顯式以環境變數指定，既安全又不會擋住不使用 LLM 的部署。`StartupSafetyValidator` 加上 Production 檢查（指定 `DefaultProvider` 後 `ApiKey` 不可留空或沿用開發預設值、`Endpoint` 不可留空或含 `your-resource`）。

新增測試 `LlmSettingsTests.cs`、`StartupSafetyValidatorTests.cs`（後者為本 repo 首份針對啟動安全檢查的測試）。

### 四、權限

新增頁面權限鍵「提示詞清單」與四個動作鍵 `提示詞清單:view/create/edit/delete`。權限種子由 `RbacBackfillService` 於啟動時自動回填，不需 SQL 或 migration。

- 清單頁的新增／修改／刪除按鈕以 `CheckAccessAction` 依權限隱藏（比照 `ProjectViewView`，較 `CategoryViewView` 多此一層）。
- 團隊列級權控只在 Blazor Service 層生效（`BuildTeamAccessPredicate` + `IsTeamAccessible`）；Web API 的 repository 路徑不做列級過濾，與 `ProjectController` 一致。

## 注意事項

- **本版不會呼叫任何 LLM 或轉錄 API**。`LlmSettings` 填了值也不會產生任何外部請求，`Endpoint`／`ApiKey` 目前沒有任何消費者。
- **既有自訂角色需重新勾選**新權限。`support`（管理員）短路後立即可見；掛「預設角色」者需**重啟一次**應用程式；掛自訂角色者需由管理員到 `/roleviews` 手動勾選。RBAC 回填失敗只記 log 不中止啟動，選單沒出現時請先看 log。
- **`MenuIconTests.AllowedIcons` 未加新 icon 會使整套測試失敗**。本次選 `article`（有效的 classic Material Icons 名稱）；不可用 Material Symbols 專屬名稱，否則側邊欄破圖。
- **本頁 Enter 不送出表單**（只有 Esc 關閉 Modal）。這與 `CategoryViewView`／`ProjectViewView` 不同，是刻意偏離：`Content` 是 14 列多行輸入，Enter 必須留給換行。
- **名稱唯一性是全域、可見性是團隊範圍**：B 團隊建立的提示詞，A 團隊使用者看不到，但用同名新增時仍會撞名。這是沿用分類／團隊清單的既有語意。
- **Web API 路徑無列級權控**：持有有效 JWT 與 `提示詞清單:view` 的用戶端可經 API 讀到跨團隊資料。此為既有設計界線（見 `開發慣例與限制速查.md` §4.1），非本次引入。
- **測試全綠不代表 migration 存在**：測試 fixture 以 `EnsureCreatedAsync` 從模型直接建表、繞過 migration。
- `LlmSettings.Providers` 字典以 `StringComparer.OrdinalIgnoreCase` 初始化，`Providers["azureopenai"]` 亦可查得。
- `readme.md` 仍以「Blazor 開發啟動範本」自述（0.4.25 已載明整份重新定位屬另一次異動），本次僅補功能列表、設定檔表與文件索引。
- **`readme.md` 的 `git diff` 行數會被放大，非整檔重寫**。實際內容差異只有 4 處（`git diff --ignore-cr-at-eol readme.md` → 6 insertions / 2 deletions；以原始位元組比對，第一個差異點就落在本次新增的功能列表那行）。放大的原因有兩個：
  - repo 設定 `core.autocrlf=true`，但既有 blob 內存的是 CRLF，diff 時每一行都會被視為變更。
  - HEAD 版 `readme.md` 的第 9 節「變更紀錄」有兩處既有換行瑕疵——0.4.24 那行結尾是 `\r\r\n`、0.4.25 那行結尾是裸 `\n` 接 `\r\n`（推測由先前以 PowerShell 追加內容時產生）。本次新增的 0.4.26 條目正好插在該區塊，兩處一併正規化為標準 CRLF，全檔現為 285 個 CRLF、0 個裸 CR／裸 LF。
- `readme.md`、`CLAUDE.md`、`AGENTS.md` 位於 repo 根目錄，**不在 `scripts/Test-DocsEncoding.ps1` 的檢查範圍**（該腳本只遞迴 `docs/`），且本來就無 BOM；本次未變更其 BOM 狀態。
