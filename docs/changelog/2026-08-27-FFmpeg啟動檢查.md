# FFmpeg 啟動期檢查與設定改走 PATH（0.4.29）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.4.29
- 首次實作版本：0.4.29
- 最後核對日期：2026/08/27

## 變更目的

開發機沒安裝 FFmpeg 時，使用者要等到「上傳影音 → 背景轉錄工作跑起來 → 失敗」才會知道，而且失敗訊息只留在該筆會議紀錄上：

```
System.InvalidOperationException: 無法啟動 FFmpeg（MediaSettings:FfmpegPath = C:\ffmpeg\bin\ffmpeg.exe）
---> Win32Exception (2): 系統找不到指定的檔案。
```

本次讓「FFmpeg 路徑指到不存在的檔案」在**啟動時**就被指出來，並把 `appsettings.json` 的預設值改成走 PATH，不再綁死在某台機器的安裝路徑上。

## 根因

`MediaSettings:FfmpegPath` 的既有檢查有兩個缺口：

1. `StartupSafetyValidator` 一開頭就對非 Production 直接 `return`，所以 Development 完全不檢查。
2. Production 的規則只檢查**留空**。路徑有填、但檔案不存在（正是本次情況）兩道都穿過去。

`FfmpegMediaConverter` 也沒有任何執行前的存在性檢查——它把設定值直接交給 `ProcessStartInfo.FileName`，要等 `Process.Start()` 擲出 `Win32Exception` 才知道啟不起來。

另外 `MeetingService.UploadMediaAsync` 是無條件入列的，所以在沒裝 FFmpeg 的機器上，**每一次上傳都保證失敗**。

## 本次修改

- **新增** `Business/Services/Transcription/FfmpegPathResolver.cs`
  - `Exists(string?)`：判斷設定值是否指向實際存在的執行檔。
  - 帶目錄資訊（rooted 或含分隔字元）→ 直接 `File.Exists`；純檔名 → 沿 `PATH` 逐目錄搭配 `PATHEXT` 搜尋。
  - **PATH 分支不可省**：`FfmpegPath` 本來就允許只填 `ffmpeg`，只做 `File.Exists` 會把正確設定誤判成不存在。解析方式對齊 `Process.Start`（`UseShellExecute = false`），讓「檢查通過」等同「真的啟得起來」。
- `Web/Configuration/StartupSafetyValidator.cs`
  - 抽出私有 `GetTranscriptionContext(IConfiguration)`，集中「兩種都算已啟用轉錄」的判斷，供 `Validate` 與新方法共用。
  - `Validate` 新增選填參數 `Func<string, bool>? ffmpegExists`（預設 `FfmpegPathResolver.Exists`），讓測試不必依賴執行機器上真的裝了 FFmpeg。
  - Production 的 FFmpeg 規則由「不可留空」擴充為「不可留空**或指向不存在的檔案**」，維持中止啟動。
  - **新增** `GetDevelopmentWarnings(IConfiguration, Func<string, bool>?)`：轉錄已啟用但 FFmpeg 找不到時回傳提醒訊息，**不擲例外**。未啟用轉錄則回空集合。
- `Web/Program.cs`
  - `app` 建好、logger 可用之後，非 Production 時將 `GetDevelopmentWarnings` 的內容逐則 `LogWarning`。
  - 之所以不併進 `Validate`：`Validate` 在 `Main` 第二行就執行，早於 NLog 接管，當下記不了 log。
- `appsettings.json`
  - `MediaSettings.FfmpegPath`：`C:\ffmpeg\bin\ffmpeg.exe` → `ffmpeg`（走 PATH，升級 FFmpeg 不必再改設定）。
  - `SystemVersion` `0.4.28 → 0.4.29`。
- 測試
  - **新增** `FfmpegPathResolverTests.cs`：空白／rooted 存在／rooted 不存在／PATH 上的純檔名／PATH 上沒有的純檔名／相對路徑不回退搜尋 PATH。
  - `StartupSafetyValidatorTests.cs`：既有案例改為明確傳入 `FfmpegInstalled`／`FfmpegMissing` 存根，讓「這個案例不是在測 FFmpeg」顯性化；新增 Production 路徑不存在應中止、以及四個 `GetDevelopmentWarnings` 案例。

`appsettings.Production.json` 的 `FfmpegPath: ""` **維持不動**——正式機必須明確指定，留空由啟動檢查擋下，這是刻意設計。未變更 `FfmpegMediaConverter` 的執行期行為、轉檔參數、上傳流程或任何 API。

## 部署注意事項

- 正式環境仍須自行安裝 FFmpeg 並在 `MediaSettings:FfmpegPath` 指定**完整路徑**（服務帳戶的 PATH 未必包含它）。
- 升級後若該路徑不存在，Production 會在啟動時中止並指名設定鍵——這是預期行為，不是回歸。

## 驗證

```powershell
cd src/MeetingRecord
dotnet build                            # 0 錯誤
dotnet test                             # 254 通過、0 失敗
pwsh ../../scripts/Test-DocsEncoding.ps1
```

啟動期防呆兩個方向都已實測：

- `FfmpegPath` = `ffmpeg`（已安裝）→ 啟動日誌無 FFmpeg 警告。
- `FfmpegPath` = 不存在的路徑 → 啟動日誌出現一則 `Startup configuration warning.` 指名 `MediaSettings:FfmpegPath`，且應用程式仍正常啟動。
