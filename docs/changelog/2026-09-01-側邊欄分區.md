# 側邊欄分區與選單扁平化（0.4.33）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.4.33
- 首次實作版本：0.4.33
- 最後核對日期：2026/09/01

## 變更目的

使用者在 0.4.32 之後看實際畫面，指出「跟當時的 wireframe 差很多」。追查後其中一個主因是：[會議記錄流程 Wireframe 設計規格](../superpowers/specs/2026-08-31-meeting-flow-wireframe-design.md) 畫的是「三個核心功能置頂」，但**側邊欄從未重整**——0.4.31 的範圍只有 AI 生成與 `/projects` 改版，`Menu.json` 一行都沒動，而這個落差當時沒有主動說明。

此外「專案管理」與「會議管理」兩個群組各自只有一個子項，多包一層純屬多餘。

## 變更內容

### 一、選單扁平化與分區

移除 id=2「專案管理」與 id=6「會議管理」兩個群組節點，把底下的 21／22／61 提升為頂層（**id 保持不變**，`MenuPermissionMap` 才對得上）。新結構：

```
核心功能        會議紀錄 ｜ 專案項目 ｜ 待辦事項
功能選單        首頁 ｜ 系統管理(群組) ｜ 資料定義(群組) ｜ 登出
```

區塊由 `Menu.json` 頂層節點的 **`section` 欄位宣告**，`SidebarMenuItemModel` 新增對應屬性。日後要加第三個區塊只改 JSON，不用改程式。

### 二、選單結構與權限矩陣刻意脫鉤

**`RolePermissionService` 的權限矩陣完全沒動**，仍保留「專案管理功能」與「會議管理功能」兩個群組。

原因是矩陣的資料結構有硬性限制：`InitializePermissionSetting()` 把每個內層清單的 `[0]` 當成群組（只有 `Enable` 布林），`Skip(1)` 才是帶 `view/create/edit/delete/export` 的葉節點。**拆掉群組會讓專案項目、會議紀錄、待辦事項全部失去動作級權限**，`CheckAccessAction(角色_專案項目, Create)` 之類的判斷會直接壞掉。

兩者本來就是獨立的：`Menu.json` 管顯示，權限矩陣管授權，靠 `MenuPermissionMap` 的 id→權限鍵對應橋接。因此可以只扁平化選單。

`MenuPermissionMap` 移除已不存在的 `[2]` 與 `[6]` 兩筆。

### 三、分區不影響選取狀態的鍵值

選單的選取高亮與自動展開靠 `root-{index}` 這種鍵值，而 `index` 是 `TryFindActiveMenuPath` 對**完整清單**遞迴算出來的。若分組後各區塊各自從 0 重新編號，鍵值會碰撞、高亮與展開全部錯位。

作法是把分組抽成純函式 `SidebarMenuSectionBuilder.Build`，**回傳的每個項目都帶著它在完整清單中的原始索引**，`NavMenu` 渲染時一律用該索引當 key。結果是 `TryFindActiveMenuPath`、`GetAncestorKeys`、`SidebarMenuNode` **一行都不用改**。

抽成純函式也讓這段邏輯可以單元測試——與 `TranscriptChunker.Split`、`AzureOpenAiTextGenerationProvider.BuildRequestUri` 同一個慣例。

### 四、修正既有的權限鍵不一致

`ProjectViewView.OnInitializedAsync` 原本用 `CheckAccessPage(角色_專案管理)`（**群組鍵**），但同一頁的工具列與操作鈕用的是 `角色_專案項目`（葉節點鍵）。`MeetingViewView` 一直是用葉節點鍵——所以 `ProjectViewView` 是全站唯一的例外（已 grep 全 repo 確認）。

群組節點從選單移除後更沒有理由用群組鍵，改為 `角色_專案項目`。這個改動只會**放寬**存取（原本只被授予葉節點鍵的角色現在進得去），不會收緊。

### 五、樣式

第二個以後的區塊標題加上分隔線與間距。收合態下 `.nav-section-title` 本來就被 CSS 隱藏，兩區之間會失去視覺分隔，因此另加 `.collapsed-section-divider`。

## 已知限制

- **`Menu.json` 有快取**：`ICacheService` key `sidebar:menu:raw`，預設 30 分鐘。改完必須重啟，否則會看到舊選單而誤判成沒生效。
- **權限矩陣仍有兩個群組沒有對應的選單項**。這是刻意的（見上），但在「角色管理」畫面上，這兩個群組看起來會像是沒有頁面的空分類。
- **`Permission` 表中的舊鍵不受影響**：矩陣沒動，所以沒有孤兒鍵產生。
