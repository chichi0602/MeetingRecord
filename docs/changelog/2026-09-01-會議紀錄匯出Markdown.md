## 變更目的

使用者要能把 AI 產生的會議紀錄帶出系統（例如寄給與會者）。

## 為什麼是 Markdown 而不是 PDF

需求原本是 PDF，也考慮過「先產 md 再轉 pdf」。但 MD → PDF 那一步仍然需要真正繪製 PDF 的元件，需求與直接產 PDF 完全相同，不會因為中間多一個 md 而省掉；而中文 PDF 必須把 CJK 字型嵌進檔案（TrueType subsetting、CID font、CMap 對應表），自己寫是數週工程，引套件則牽涉授權與 10–20MB 字型檔進版控。

相對地，**`Meeting.DraftContent` 本身就是 Markdown**——LLM 依提示詞範本產出 `##` 標題與條列。寫成 `.md` 檔等於直接輸出欄位：零新套件、零字型問題、零授權風險。使用者拿到 `.md` 後可用 VSCode、Typora、Word 等任何工具轉 PDF。

日後若要補伺服器端 PDF，本次建立的下載管道可直接複用。

## 前提：這個專案原本沒有任何可運作的下載機制

實作前盤點發現：

- 全 repo **0 處 JS interop、0 個自寫 js 檔**
- 所有 API controller 都是 `[Authorize(AuthenticationSchemes = JwtBearerDefaults.AuthenticationScheme)]`，而瀏覽器導航帶的是 Cookie ——`<a href>` 下載**一定 401**。既有那條壞掉的 `/api/project-files/{id}/download` 就是這樣壞的
- 唯一現成的對外檔案路徑 `/UploadFiles` 掛在 `UseAuthentication` 之前，**完全無授權**，不適合放會議紀錄

所以本次的主要工作其實是**建立下載管道**。

## 變更內容

### 一、下載管道（本專案第一支 JS interop）

| 檔案 | 內容 |
|------|------|
| `wwwroot/js/download.js` | 新增。`DotNetStreamReference` → `Blob` → `<a download>` → `revokeObjectURL` |
| `Components/App.razor` | 加一行 `<script src="@Assets["js/download.js"]"></script>`，與既有 `@Assets` 慣例一致 |
| `Services/FileDownloadInterop.cs` | 新增。包裝 `IJSRuntime`，提供 `SaveTextAsync` 與 `SaveBytesAsync` |

**選擇 JS interop 而非新開 HTTP 端點**是刻意的：檔案完全不落地，不新增對外的檔案輸出面。這與文件反覆宣示的立場一致——「少一個 HTTP 檔案輸出面就少一處要顧的授權」（見 `docs/features/檔案上傳機制.md`）。

輸出的 `.md` 是 **UTF-8 含 BOM**，理由與 `MeetingFileStore.SaveTranscriptAsync` 相同：Windows 記事本開沒有 BOM 的 UTF-8 中文檔案會是亂碼。

### 二、匯出內容

`Business/Services/Export/MeetingMarkdownExporter.cs`，比照 `TranscriptChunker` 的純函式慣例（可單元測試、不碰 IO）：

```markdown
# 會議紀錄：需求確認會議

- 專案：Q3 產品改版專案
- 會議：需求確認會議
- 會議日期：2026/08/28
- 使用提示詞：標準會議紀錄
- 產生時間：2026/09/01 11:22

---

（DraftContent 原文，不做任何轉換）
```

**不含逐字稿**——高敏感內容，且一小時會議就數千字。

檔名為 `會議紀錄_{標題}_{產生日}.md`。會議標題常常本身就是上傳的影音檔名，所以會先去掉影音副檔名（`.m4a`、`.mp4` 等 16 種），再濾除檔名非法字元、把連續空白壓成單一底線、截斷過長標題（60 字）。

### 三、UI 與權限

`/projects` 歷史會議紀錄清單，每列（草稿已完成時）新增一顆「匯出 Markdown」按鈕（icon `download`）。

**權限用 `PermissionActions.Export`** —— 角色權限矩陣一直有 view/create/edit/delete/**export** 五個動作，但 `export` **從未被任何程式使用過**。匯出正是它天生的用途：匯出代表資料離開系統，值得與「檢視」分開控管。

## ⚠️ 已知的權限副作用

現有角色**都沒有勾過 `export`**，而管理員短路一切權限。所以升級後：

- **管理員**：看得到匯出鈕
- **一般角色**：**看不到**，需要到「角色管理」把「專案項目」那一列的「匯出」勾起來

這是刻意的設計，不是 bug。

## 實作備註（給後續維護）

- `@Assets` 的 static assets manifest 是**編譯期**產生的。新增 `wwwroot` 下的檔案後必須重新建置，否則 `@Assets["js/xxx.js"]` 抓不到。
- `Components/_Imports.razor` 的 `@using` **不會套用到 code-behind 的 `.cs` 檔**，`ProjectViewView.razor.cs` 需自行 `using Microsoft.JSInterop;`。
- 測試中若要斷言「字串不含某控制字元」，必須用 `string.IndexOf(char)`（序數比對）。xunit 的 `Assert.DoesNotContain(string, string)` 是**文化相關**比對，`\0` 之類的可忽略字元會在任何字串中都「找得到」，導致假失敗。
