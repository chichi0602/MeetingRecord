## 變更目的

專案累積了 14 份 PRD、7 份架構文件、25 篇 changelog，但**沒有任何一份把它們串成一條敘事**。接手者（或幾週後回頭看的自己）無法快速知道「這個系統在做什麼、資料怎麼流、每個頁面在整條流程裡扮演什麼角色、哪裡會卡」。

盤點確認這是文件庫的空白：`grep 操作手冊|使用說明|操作流程|功能總覽` 全 repo 零命中於任何功能導向文件。`docs/planning/07-MeetingInk-產品分析與自建藍圖.md` 也早就把這類文件列為待補缺口。

## 變更內容

新增 `docs/architecture/系統功能總覽.md`，與既有的《架構總覽》互補——那份寫「技術怎麼組起來」，這份寫「功能面有什麼、怎麼串起來」。

八個章節：系統定位、端到端流程、側邊選單逐項介紹、不在選單裡的頁面、兩個核心觀念、權限與背景工作與已知問題、規劃中項目、延伸閱讀。

### 誠實記錄的已知問題

文件第六節列出實際查證過的現況，包含：首頁與專案項目渲染同一個元件；專案附件下載端點根本不存在（且 API 全為 JWT-only，瀏覽器 `<a href>` 帶 Cookie 必定 401）；分類與團隊以名稱字串儲存且刪除無使用中檢查，改團隊名會讓可見性當場斷掉；帳號鎖定無後台解鎖介面且計數器到期不歸零；雙因素驗證只有欄位未實作；稽核日誌無任何查看介面且涵蓋範圍僅登入與使用者／角色管理；逐字稿外送 Azure OpenAI 且無保留期限與成本控管。

這些不是新產生的問題，而是原本散落在各處或根本沒被記錄下來的現況。接手者最需要知道的就是這些。
