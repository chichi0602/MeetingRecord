- 文件版本：1.0
- 文件狀態：已實作

- 首次實作版本：0.4.39

## 變更目的

兩件事：

1. **修正重啟後「待處理」永遠卡住的問題**（0.4.38 的 changelog 記為既有問題，本次處理）。
2. **把描述、優先級、分類、團隊四個欄位從專案中完全移除**——0.4.37 只從表單拿掉，這一版才是徹底移除，連資料庫欄位一起刪。

## 一、修正 Pending 永遠卡住

`Program.cs` 的啟動復原原本只掃 `Processing`：

```csharp
.Where(x => x.TranscriptionStatus == TranscriptionStatus.Processing)
```

但**佇列不持久化**，`Pending`（已入列、還沒被 worker 撿走）在重啟後同樣沒有人會接手，卻不會被復原邏輯掃到，會永遠停在「待處理」。轉錄與草稿生成兩條軌道都有這個問題。

改成同時涵蓋兩種狀態：

```csharp
// Pending 也要一併復原：佇列不持久化，重啟後「已入列但還沒被 worker 撿走」的
// 紀錄同樣沒有人會接手，只掃 Processing 會讓它們永遠卡在「待處理」。
.Where(x => x.TranscriptionStatus == TranscriptionStatus.Processing
         || x.TranscriptionStatus == TranscriptionStatus.Pending)
```

錯誤訊息也一併調整為「應用程式重啟導致轉錄中斷（排隊中或處理中），請重新執行轉錄。」

理論上有個極小的競爭視窗：`RequestDraftAsync` 先設 `Pending` 才 `EnqueueAsync`，兩者不在同一交易。但復原只在**啟動當下**執行，那時程序才剛起來、不可能有進行中的請求，實務上安全。

## 二、四個欄位徹底移除

### 設計理由

使用者的定位：**角色權限只決定「能做什麼功能」，不決定「能看到哪些資料」**。因此專案的列級可見性機制整組拿掉，存取改為純粹的功能級 RBAC。

### 移除範圍

| 層 | 內容 |
|---|---|
| 實體／模型 | `Project`、`ProjectAdapterModel` 四個欄位（含 `PriorityOptions`、`CategoriesText`、`TeamsText`） |
| DTO | `ProjectCreateUpdateDto` 四欄、`ProjectSearchRequestDto.Priority` |
| AutoMapper | Project 的兩組 `ForMember`（`TagStringHelper` 轉換），變成裸的 `CreateMap` |
| ProjectService | 關鍵字搜尋、分類／團隊過濾、優先級排序、優先級驗證、`UpdateAsync` 逐欄寫入，以及 **4 處團隊權限判斷**（清單、單筆、附件下載守門、`GetSelectableAsync`） |
| 其他 service | `MeetingService.RequestDraftAsync` 與 `TodoService.BeforeAddCheckAsync` 的**專案**團隊守門 |
| API | `ProjectRepository` 搜尋與排序、`ProjectController` log 參數、`CombinedSearchHelper` 排序 arm |
| UI | `ProjectViewView.OnAddAsync` 的 `Priority` 預設值 |
| 資料庫 | migration `20260902075848_RemoveProjectDescriptionPriorityCategoriesTeams`（四個 `DropColumn`） |

### 連鎖移除

- **`ProjectService` 的 `IRecordAccessScopeProvider accessScope` 注入**：4 處權限判斷是它唯一的用途，移除後成為死欄位，建構式參數一併拿掉（DI 註冊仍保留，另外三個 service 與進度面板還在用）。
- **`GetFileDownloadAsync` 的 `parent` 區域變數**：唯一用途是餵給團隊判斷，一併刪除。

### 刻意保留

`Meeting`、`PromptTemplate`、`Todo` 各自的 `Categories`／`Teams` 與其列級權限判斷完全不動——**`MeetingService.RequestDraftAsync` 對逐字稿與提示詞的兩處守門仍在**，只拿掉中間那段對專案的檢查。另外 `TagStringHelper`、`DataRequest.CategoryFilters/TeamFilters`、`IRecordAccessScopeProvider` 的 DI 註冊、**專案附件功能**都保留。

### 測試異動

- **`ProjectServiceTeamAccessTests.cs` 整檔刪除**（5 個測試）：全部是團隊權控測試，移除機制後語意上不再成立。
- **`TodoServiceTests.BeforeAddCheckAsync_ShouldFail_WhenProjectIsOutOfTeamScope` 刪除**（1 個）：測的正是被移除的專案守門。同檔的專案存在性檢查測試保留。
- 三個 fixture（`MeetingServiceTests`、`TodoServiceTests` 的 `AddProjectAsync`）拿掉 `Priority`/`Teams` 設定。
- `ApiIntegrationTests` 拿掉送出的 `Description`/`Priority`。

## 實作備註（給後續維護）

- SQLite 不支援真正的 `DROP COLUMN`，EF Core 會走 **table-rebuild**（建暫存表 → `INSERT…SELECT` → drop → rename），過程中會出現 `PRAGMA foreign_keys = 0` 無法在交易中執行的警告，這是預期行為。`Project` 有三個子表外鍵（ProjectFile／Meeting／Todo），rebuild 後外鍵仍指向 `Project` 表名，不受影響。
- 用 `sed -i '/pattern/d'` 跨多檔刪行時要極度小心：本次因此誤刪了 `AddMeetingAsync`／`AddCompletedMeetingAsync`／`AddPromptTemplateAsync`／`AddTodoAsync` 四個 fixture 中的 `Teams` 設定（那些是 Meeting／PromptTemplate／Todo 自己的，不該動），造成 11 個無關測試失敗。刪除前應先確認 pattern 的唯一性，或改用帶上下文的多行取代。
- 同樣地，`sed -i '起,迄d'` 刪連續區塊時每刪一次行號就位移，本次也因此吃掉過一個測試方法的結尾大括號。
