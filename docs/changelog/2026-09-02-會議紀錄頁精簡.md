# 會議紀錄頁移除分類／團隊、會議日期自動帶入（0.4.35）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.4.35
- 首次實作版本：0.4.35
- 最後核對日期：2026/09/02

## 變更目的

使用者對 `/meetings` 提出兩件事：

1. 移除「分類」「團隊」欄位——「這邊只需要產出會議記錄，到專案項目那邊再選擇對應專案、負責人就好」。
2. 會議日期沒填就自動帶入上傳音檔的日期，填錯再人工編輯。

第一項把會議紀錄頁的定位收斂成「上傳音檔 → 產出逐字稿」；歸屬與分類是專案項目頁的職責。

## 一、移除分類／團隊

三處一起拿掉：

| 位置 | 移除內容 |
|------|----------|
| 表格欄位 | `CategoriesText`、`TeamsText` 兩個 `<Column>` |
| 工具列 | 分類過濾、團隊過濾兩個多選 `<Select>`（保留關鍵字搜尋） |
| 新增／編輯表單 | 分類、團隊兩個 `<FormItem>` |

`MeetingViewView.razor.cs` 一併清掉**因此變成孤兒**的成員：`availableCategories`／`availableTeams`／`selectedCategoryFilters`／`selectedTeamFilters` 四個欄位、建構式注入的 `CategoryService`／`TeamService`、`OnInitializedAsync` 載入選項的兩行、`ReloadAsync` 傳入的兩個 Filter，以及四個 handler。

**刻意不動**：`Meeting.Categories`／`Meeting.Teams` 資料庫欄位、`MeetingService` 的過濾與權限程式碼、`TagStringHelper`、`MeetingAdapterModel` 的兩個屬性與 `Clone()` 深拷貝、AutoMapper 設定、`DataRequest.CategoryFilters/TeamFilters`（專案項目、提示詞、待辦共用）。**沒有 migration。**

## ⚠️ 已知的權限副作用（刻意為之，非 bug）

**`Meeting.Teams` 是會議唯一的列權限來源**——沒有 owner 欄位，`ProjectId` 可為空無法替代，`MeetingService` 有 11 處用它做行級過濾（含逐字稿預覽）。

而 `TagStringHelper.ToStored([])` 回傳 `null`，predicate 把 `null` 視為公開，所以：

- **0.4.35 之後新建的會議一律公開**，任何有「會議紀錄」頁權限的人都看得到，**包含逐字稿預覽**。
- 0.4.35 之前已標團隊的舊資料**維持原可見範圍**——DB 欄位與 11 處判斷都沒動。

這個副作用在動工前已明確告知使用者，使用者仍選擇整組移除。保留 DB 欄位與服務層邏輯是刻意的：要把控管收回來，只需把表單的團隊 `Select` 加回 `MeetingViewView.razor`，服務層一行都不必改。

## 二、會議日期自動帶入上傳日

唯一改動點是 `MeetingService.SaveMediaAsync`：

```csharp
// 會議日期沒填就帶入上傳當天；已填的不覆蓋，要更正仍可從畫面編輯。
meeting.MeetingDate ??= DateTime.Today;
```

選這個位置的理由：它是**唯一**同時涵蓋三種情形的地方——新增後首次上傳、換檔重傳、先建立空會議之後才補檔案，而且實體已載入且被追蹤。

用 `DateTime.Today` 而非 `DateTime.Now`：這是日期語意，清單與匯出都以 `yyyy/MM/dd` 呈現。

Web API 路徑（`MeetingRepository`）不碰檔案、沒有「上傳日」可言，不加這條規則。

`MeetingService.UpdateAsync` 的「沿用資料庫既有值」清單**刻意不加 `MeetingDate`**——使用者要能從畫面改，與 `ProjectId` 的處理一致。

## 實作備註（給後續維護）

- 使用者若正以 Visual Studio 執行本專案，`MeetingRecord.Web.exe` 會鎖住 `bin/Debug` 下的 DLL 讓建置失敗。**不要用 `IMAGENAME` 過濾去砍行程**（會連使用者的實例一起殺掉）；改用 `dotnet build -p:BaseOutputPath=<暫存目錄>` 把輸出導到別處即可，不必停掉任何行程。
- 但 `-p:BaseIntermediateOutputPath` **不能**一起改，否則專案參照解析會報 MSB4006 循環相依。
- 幾個註冊測試會從 `AppContext.BaseDirectory` 往上找 `MeetingRecord.Web/Datas/Menu.json`。輸出目錄一旦被導走，這個往上找的動作就會失敗（6 個測試報 `FileNotFoundException`）——把 `Menu.json` 複製到暫存輸出目錄下對應位置即可，不是真的迴歸。
