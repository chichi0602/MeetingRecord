# 會議紀錄匯出改為 PDF（0.4.40）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.4.40
- 首次實作版本：0.4.40
- 最後核對日期：2026/09/03

## 變更目的

使用者要求專案頁的匯出**直接下載 PDF**，不要再自己把 Markdown 轉檔。

## ⚠️ 這推翻了 0.4.34 的決議

[會議紀錄匯出 Markdown（0.4.34）](2026-09-01-會議紀錄匯出Markdown.md) 有一整節「為什麼是 Markdown 而不是 PDF」，當時的結論是：

> 中文 PDF 必須把 CJK 字型嵌進檔案（TrueType subsetting、CID font、CMap 對應表），自己寫是數週工程，引套件則牽涉授權與 10–20MB 字型檔進版控。

**那個評估是對的，但範圍不完整**——它只比較了「自己寫」與「引 .NET PDF 套件」兩條路，漏掉了第三條：**把 HTML 交給系統既有的瀏覽器無頭列印**。這條路把當初列出的三個阻礙全部消掉：

| 0.4.34 的阻礙 | 這次怎麼解決 |
|---|---|
| CJK 字型嵌入是數週工程 | 瀏覽器的排版引擎本來就會做 |
| 字型檔 10–20MB 進版控 | 用系統字型，**專案不放任何字型檔** |
| PDF 套件的商業授權 | 不引 PDF 套件 |

代價是**依賴機器上裝有 Edge 或 Chrome**。本專案的部署假設是 Windows 單機內部系統（見 [正式部署與安全檢查清單](../operations/正式部署與安全檢查清單.md)），Windows 內建 Edge，所以這個代價在現況下幾乎為零。

## 為什麼一定要支援表格

盤點時發現一件會決定成敗的事：**提示詞範本沒有任何 seed，`Content` 完全由使用者自行撰寫，而 `SystemPrompt` 也沒有規範輸出格式**。也就是說系統無法保證 LLM 產出的 Markdown 語法範圍，而 GPT 系模型很愛用表格列決議／負責人／期限。

若渲染器不支援表格，使用者拿到的 PDF 會直接印出 `|---|---|`。因此 Markdown → HTML 用 **Markdig 並啟用 `UseAdvancedExtensions()`**（表格支援在這裡面），而不是自己寫簡易轉換。

## 變更內容

### 一、`MeetingDocumentExporter`（由 `MeetingMarkdownExporter` 改寫）

檔名邏輯**完全沿用**——去影音副檔名、濾非法字元、壓縮空白、截斷過長標題、日期取 `DraftCompletedAt ?? UpdatedAt`，只有副檔名從 `.md` 變 `.pdf`。

`BuildDocument` 改為 `BuildHtml`：表頭（專案／會議／會議日期／使用提示詞／產生時間）以 `<dl>` 呈現，內文經 Markdig 轉 HTML，外層包上完整文件與內嵌列印樣式（`@page` A4、中文字型堆疊、表格框線、標題不落頁尾、表格列不被切半）。

**表頭欄位一律 HTML 逸出**——會議標題是使用者輸入（常常就是上傳的檔名）。內文走 Markdig，由該套件處理。

### 二、`HeadlessBrowserPdfRenderer`

結構比照 `FfmpegMediaConverter`：暫存工作目錄 → 組參數 → 跑外部程序 → 收 stderr → 檢查離開碼 → `finally` 清理。逾時 2 分鐘。

```
--headless=new --disable-gpu --no-first-run --no-default-browser-check
--disable-extensions "--user-data-dir=<暫存>" --no-pdf-header-footer
"--print-to-pdf=<輸出>" "file:///<輸入>"
```

⚠️ **`--user-data-dir` 指向獨立暫存目錄是必要的**，不是可有可無的保險：使用者的 Edge 通常正開著，不隔離 profile 的話新程序會直接附掛到既有實例，然後**什麼都不印就結束，而且離開碼還是 0**。因此除了檢查離開碼，**還要驗證輸出檔存在且非空**。

### 三、設定與啟動檢查

新增 `ExportSettings:BrowserPath`（**留空即自動偵測** Edge／Chrome 的四個常見安裝位置）。設定值優先且不回退——填錯要讓人看見，不靜默改用別的瀏覽器。

`FfmpegPathResolver` 的 PATH 搜尋核心抽成 **`ExecutablePathResolver`**，`FfmpegPathResolver` 保留為薄包裝，既有呼叫點與 6 個測試完全不動。

`StartupSafetyValidator.GetDevelopmentWarnings` 加上瀏覽器檢查。**與轉錄不同，這條一律檢查**——匯出 PDF 只要有草稿就能用，與轉錄是否啟用無關。既有 4 個測試改為明確傳入 `BrowserInstalled`，避免斷言結果隨執行機器上有沒有 Edge 而改變。

### 四、下載管道（最小改動）

`download.js` 的 MIME 從寫死的 `text/markdown` 改為參數；`FileDownloadInterop.SaveBytesAsync` 多收一個 `contentType`。`SaveTextAsync` 隨 Markdown 匯出一併移除。JS interop 管道本身不變——所有 API controller 都是 JWT Bearer，瀏覽器導航帶 Cookie 必定 401，這個限制沒有改變。

### 五、UI

按鈕改「匯出 PDF」，產生期間顯示「匯出中…」並停用。這是必要的：PDF 要啟動外部程序、耗時數秒，原本的匯出是同步無回饋的，不擋會讓使用者連點而啟動多個瀏覽器程序。

## 實作備註（給後續維護）

- Markdig 的 `UseAdvancedExtensions()` 會啟用 **AutoIdentifiers**，產出的是 `<h2 id="…">` 而非 `<h2>`。寫斷言時不要假設沒有屬性。
- 用 `perl -0pi -e` 做取代時，**`$"` 是 perl 的特殊變數**，C# 的內插字串 `$"…"` 會被吃掉只剩 `"…"`。這次踩了兩次（`BuildFileName` 的回傳、`NotifyError` 的訊息），都是靠編譯錯誤才發現。這類取代改用 `sed` 或 Edit 工具比較安全。
- 以 awk／sed 切分檔案重組方法時，注意舊方法的結尾大括號會不會被一起帶進來。
