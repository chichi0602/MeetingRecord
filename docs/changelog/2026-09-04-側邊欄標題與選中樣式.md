# 側邊欄標題區重排、選中樣式改淡色、收合鈕移到欄外（0.4.44）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.4.44
- 首次實作版本：0.4.44
- 最後核對日期：2026/09/04

## 變更目的

使用者回報側邊選單「標題排版不太好看」「展開後選中項的背景是黑色的，有點違和」。

查證後發現裡面有**兩個真的壞掉**的問題，不只是美感。

---

## 一、選中項的文字是藍色——父層的 `!important` 蓋不到子元素

0.4.41 換色時把選中背景設成 `--oat-ink`（#43362C）並宣告 `color: var(--oat-50) !important`。

但 `MenuItem RouterLink` 渲染出來的是 `<a>`，而 AntDesign 自己的 `.ant-menu-item-selected a` 帶主色藍。

**`!important` 只在「同一個元素上的宣告互相競爭」時勝出。** 子元素身上有自己的 `color` 宣告時，它用的是自己的值，根本不會去繼承父層——父層寫再多 `!important` 也無效。所以選中列一直是**藍字壓在深棕底上**。

修法是直接對 `<a>` 下 `inherit`：

```css
.sidebar-menu-shell ::deep .ant-menu-item a,
.sidebar-menu-shell ::deep .ant-menu-item a:hover,
.sidebar-menu-shell ::deep .ant-menu-item-selected a {
    color: inherit !important;
}
```

同時關掉 AntDesign inline 選單畫在右緣的那條主色藍指示線（`.ant-menu-item::after`）——截圖裡選中列右邊那一小條藍線就是它。

## 二、選中項的圖示是隱形的

同一份 CSS 把**選中態的圖示**設成 `var(--oat-ink)`，而背景也正好是 `var(--oat-ink)`。同色。

所以那一列從來就看不到圖示，只是因為背景夠深、沒人發現圖示其實在那裡。

**這個問題因為選中底色改成淡色而自然消失**，`var(--oat-ink)` 在淡底上是正確值，不需要另外改。

## 三、選中樣式：深棕整塊 → 淡奶油底＋左側色條

使用者的說法是「黑色有點違和」。改為後台側邊欄更常見的做法：

```css
.sidebar-menu-shell ::deep .ant-menu-item-selected,
.sidebar-menu-shell ::deep .ant-menu-submenu-selected > .ant-menu-submenu-title,
.sidebar-menu-shell ::deep .ant-menu-submenu-open > .ant-menu-submenu-title {
    background: var(--oat-50) !important;
    box-shadow: inset 3px 0 0 0 var(--oat-ink);
    color: var(--oat-ink) !important;
    font-weight: 600;
}
```

左側色條用 **inset `box-shadow` 而不是 `::before`**：AntDesign 已經在用 `::after`，少碰它的偽元素就少一處相衝的可能；而且 inset 陰影會自動跟著 `border-radius: 14px` 的圓角走。

深棕文字壓在 `#EEE5DE` 上是 **9.4:1**，遠高於 WCAG AA 的 4.5:1。

收合態的圖示按鈕（`.collapsed-menu-trigger` 的 hover 與 `-active`，原本也是整顆深棕方塊）套用同一套，兩種狀態視覺一致。

## 四、標題區：產品標誌＋產品名，收合鈕移到欄外

### 被裁切是算得出來的

側邊欄 300px，扣掉 padding 32px、漢堡鈕 44px、品牌圖示 48px、兩個 0.9rem 間距（28.8px），只剩約 147px；而「MeetingRecord.Web」在 1.15rem 下約需 155px。

而且那是**專案組件名，不是產品名**。

### 改法

- **收合鈕移出側邊欄**（見下節），省下 44px + 一個間距。
- **標誌**改用登入頁那份三橢圓「AI」線稿（也是 `wwwroot/favicon.svg`），以 `currentColor` 描邊。原本是通用的 `dashboard_customize` 包在深棕方塊裡——**兩顆深色方塊並排正是標題區看起來沉重的主因**，線稿本身已有造型，不再套底色方塊。
- **名稱**改讀 `SystemSettings.SystemInformation.SystemName`（「AI 會議記錄小助手」）。`NavMenu.razor.cs` 注入 `IOptions<SystemSettings>`，比照 `MainLayout.razor.cs` 的既有寫法。**不寫死字串**——系統名稱與版本號都以設定檔為單一來源。
- 字級 1.15rem → 0.98rem 並允許換行，長系統名也不會被切。
- **收合態改成只留標誌**。原本是 `display: none` 把整個品牌區藏掉、只留漢堡鈕；漢堡鈕搬走後若沿用就會變成一列空白。

## 五、收合鈕為什麼要放到 `.sidebar` 外面

`.sidebar` 有 `overflow: hidden`，按鈕擺在裡面就**沒辦法跨出邊界**——絕對定位往外推只會被裁掉。

所以改由 `MainLayout.razor` 渲染，當 `.sidebar` 的兄弟節點，直接呼叫既有的 `ToggleSidebar()`，不再繞 `OnSidebarToggle` 這個 EventCallback。

```css
@media (min-width: 641px) {
    .sidebar-toggle-edge {
        left: var(--sidebar-width);
        position: fixed;
        top: 50%;
        transform: translate(-50%, -50%);
        transition: left 0.28s ease, …;
    }
}
```

兩個關鍵：

- **`left: var(--sidebar-width)`**：這個變數定義在 `.page` 上（展開 300px、收合 64px），按鈕是其子節點所以取得到。按鈕中心正好落在側邊欄右邊界上，且收合／展開時會跟著滑動——`transition` 的時間與 `.sidebar` 的 `width` 相同（0.28s），兩者同步。
- **用 `fixed` 而不是 `absolute`**：`.sidebar` 是 `position: sticky` + `height: 100vh`，要對齊的是**視窗**中間而不是整頁中間；頁面很長時 `absolute` 會把按鈕留在文件上緣附近。`fixed` 同時也繞開了 `overflow: hidden`。

手機（<641px）`--sidebar-width` 是 `100%` 且版面直向堆疊，貼右邊界會跑出畫面，因此該斷點沿用 `position: absolute` 的左上角位置（`.page` 已有 `position: relative`）。CSS 以手機優先撰寫，桌機斷點才覆寫成浮動。

圖示由 `menu`／`menu_open` 改為 `chevron_left`／`chevron_right`，更能表達「收合／展開」這個方向性動作。

**孤兒清除**：`NavMenu` 的 `OnSidebarToggle` 參數與 `ToggleSidebar()` 方法在按鈕搬走後沒有呼叫端，一併移除。

## 六、順手收掉同源的殘留

這兩處與本次是同一個成因（0.4.41 換色時漏掉），不是無關的順手改：

| 位置 | 原本 | 改為 |
|---|---|---|
| `MainLayout.razor.css` 的 `.sidebar` 背景 | 舊藍灰漸層 `#f5f6f8 → #eef1f4 → #e7ebf0` | 奶茶色階，與 `NavMenu` 的 `.top-row` 接得上 |

側邊欄底色是冷灰、上緣標題列卻是暖奶茶——這是「違和」的另一半。

## 實作備註（給後續維護）

- **`!important` 不會讓子元素繼承父層的值**。子元素身上只要有自己的 `color`（AntDesign 的 `a` 就是），父層寫什麼都沒用，必須直接對子元素下規則。這次的藍字就是這樣來的。
- 想讓元素跨出 `.sidebar` 的邊界，得把它放到 `.sidebar` **外面**——那個容器有 `overflow: hidden`。
- 要對齊 `position: sticky` + `100vh` 的側邊欄中線，用 `position: fixed` + `top: 50%`；`absolute` 對齊的是整份文件，頁面一長就跑掉。
- 跟著側邊欄寬度移動的元素，直接吃 `.page` 上的 `--sidebar-width` 並複製同一組 `transition` 時間，比另外算數值可靠。
