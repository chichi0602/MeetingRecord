## 變更目的

使用者在編輯專案時放了合約類的附件，問「我要在哪查看」。查證後發現問題比提問本身嚴重：

1. **專案頁主畫面完全沒有附件入口**，只有「修改專案」視窗裡列得出來。
2. **那個視窗裡的下載連結本身就是壞的**，而且從第一天就不可能會動。

另外回報「AI 轉會議紀錄」按鈕沒有與旁邊的下拉選單對齊。

---

## 一、下載為什麼一直是壞的

`ProjectViewView` 產生的連結指向 `/api/project-files/{id}/download`，但：

- **這個端點從來沒有存在過**。`Controllers/` 底下沒有任何 `ProjectFile` 相關的 controller，所以點下去是 404。
- **就算補上 controller 也還是不會動**。所有 API controller 都是 `[Authorize(AuthenticationSchemes = JwtBearerDefaults.AuthenticationScheme)]`，而瀏覽器 `<a href>` 導航帶的是 Cookie ——一定 401。

`ProjectService.GetFileDownloadAsync` 因此一直是**零呼叫端**的死程式碼。

這件事在 [系統功能總覽](../architecture/系統功能總覽.md) 的「已知問題」早有記載，[會議紀錄匯出 Markdown（0.4.34）](2026-09-01-會議紀錄匯出Markdown.md) 也把它當成反例引用過。

### 修法：沿用 0.4.34 建好的管道

0.4.34 為了匯出會議紀錄，已經建立了一條可用的下載管道——`FileDownloadInterop` 走 JS interop（`DotNetStreamReference` → `Blob` → `<a download>`），**不開對外端點**。這次直接沿用，理由與當時相同：少一個 HTTP 檔案輸出面就少一處要顧的授權。

### 為什麼要多一個 `SaveStreamAsync`

`FileDownloadInterop` 原本只有 `SaveBytesAsync`。**專案附件的上限是 1GB**，把整份讀成 `byte[]` 會在伺服器端吃掉等量記憶體。

而 `wwwroot/js/download.js` 收的本來就是 `DotNetStreamReference`，`SaveBytesAsync` 只是先包一層 `MemoryStream`。所以新增 `SaveStreamAsync` 把 `FileStream` 直接傳進去，並讓 `SaveBytesAsync` 改為呼叫它——邏輯只有一份。

```csharp
public async Task SaveStreamAsync(string fileName, Stream content, string contentType, CancellationToken ct = default)
```

`SaveBytesAsync` 保留：PDF 匯出（0.4.40）本來就是在記憶體裡現產 `byte[]`，沒有檔案可串。

> 註：瀏覽器端仍會 `arrayBuffer()` 整份收下來，那是這條管道的先天限制。本次只消掉**伺服器端**那份多餘的複本，沒有改 JS。

### 權限

`GetFileDownloadAsync` 只依檔案 Id 查、**沒有**團隊權控守門——`專案項目-prd.md` 先前記載「具團隊權控守門」是錯的，本次一併更正。

不補檢查是刻意的：0.4.39 已把專案的列級權控整組移除（「角色權限只管功能，不管資料可見範圍」），這裡再單獨加一道會與該決策矛盾；且檔案 Id 只可能來自使用者已載入的專案附件清單。

## 二、附件查看入口

使用者選擇「摘要列加一格，點開彈視窗」而非常駐卡片——專案頁已經有摘要列、AI 區塊、歷史會議紀錄三塊，再加一塊常駐卡片會過擠。

- 摘要列新增「附件 N 份」。**0 份時不做成可點的**——點開空清單沒有意義。
- 點下去開附件視窗，每列顯示檔名、大小（沿用同檔既有的 `FormatFileSize`）、上傳時間，右側一顆下載鈕。
- 視窗形狀比照同檔既有的三個 Modal（草稿檢視／草稿編輯／逐字稿預覽）：`Footer="null"`、`Keyboard="true"`。

### 附件資料是另外撈的

`SelectedProject.Files` 原本**永遠是空的**——專案選擇器用的 `GetSelectableAsync()` 沒有 `.Include(x => x.Files)`。

改在 `ReloadProjectContextAsync` 裡以現成的 `projectService.GetAsync(selectedProjectId)`（它已經 Include 了附件）取得，比照既有的 `projectMeetings` 模式。

**刻意不動 `GetSelectableAsync`**：在那裡加 Include 會替**每一個**專案都撈附件，而畫面一次只顯示一個。

### 編輯視窗

那條壞掉的 `<a href>` 換成呼叫同一個下載處理方法。`GetProjectFileDownloadUrl` 隨之成為本次變更造成的孤兒，一併移除。

## 三、AI 按鈕對齊

這裡其實有**兩個獨立的問題**，第二個才是根本。

### 3-1 按鈕與下拉的頂緣沒對齊

原本是 `.project-view-cta { margin-top: 22px; }` ——用一個魔術數字硬推按鈕去對齊旁邊的下拉。但欄位標籤的實際高度是 `0.82rem` 字級加上 `gap: 6px`，約 17.5px，所以按鈕低了約 4.5px。

改成讓按鈕走**與兩個下拉完全相同的堆疊**：外面包一層 `.project-view-ai-field`，上面墊一個 `aria-hidden` 的佔位標籤。這樣頂緣由同一組 `font-size` 與 `gap` 決定，**日後改標籤字級也不會再跑掉**。

### 3-2 ⚠️ 掛在元件上的 `Class` 選不到——scoped CSS 從頭到尾沒生效

按鈕內的圖示比文字大一截。查下去發現真正的原因不是尺寸沒設，而是：

**Blazor CSS isolation 的 scope 屬性只會加在「本檔 `.razor` 裡自己寫的 HTML 元素」上，不會傳進子元件。**

這件事有生成碼可證。`ProjectViewView_razor.g.cs` 裡，自己寫的 `<span>`：

```csharp
__builder2.OpenElement(215, "span");
__builder2.AddAttribute(216, "class", "project-view-cta");
__builder2.AddAttribute(217, "b-jwhvaz7ric");   // ← 有 scope
```

而 `<Button Class="...">` 從 `OpenComponent<AntDesign.Button>` 到 `CloseComponent` 之間**完全沒有** `AddAttribute(n, "b-jwhvaz7ric")`。`Class` 只是被當成一般元件參數傳進去。

於是 `.project-view-cta` 這個選擇器被編譯成 `.project-view-cta[b-jwhvaz7ric]`，而那顆 `<button>` 身上根本沒有這個屬性——**規則從一開始就沒有生效過**，連 `display: inline-flex; gap: 6px` 也沒有。

修法是把內容包進一層自己寫的 `<span class="project-view-cta">`，再用 `::deep` 設圖示字級：

```css
.project-view-cta ::deep .material-icons-outlined {
    font-size: 1rem;   /* 預設 24px，會比 14px 的按鈕文字大一截 */
    line-height: 1;
}
```

### ⚠️ 同一個坑還有三處（本次未動）

用同樣的方式檢查，`ProjectViewView.razor.css` 裡還有三條規則掛在元件的 `Class` 上，**同樣選不到**：

| 選擇器 | 掛在哪 | 原本想做什麼 |
|---|---|---|
| `.project-view-icon-button` | `<Button>` | 寬 36px、無 padding、置中 |
| `.project-view-icon-button-danger:hover` | `<Button>` | 刪除鈕的紅色 hover |
| `.project-view-project-select` | `<Select>` | `min-width: 260px` |

這三處是**既有問題、與本次變更無關**，所以沒有一併改（畫面目前靠 AntDesign 的預設樣式也還能看）。要修的話手法相同：包一層自己的元素，或改用 `::deep` 從上層容器選進去。

## 實作備註（給後續維護）

- 專案頁要顯示附件時，記得 `GetSelectableAsync()` **不帶** `Files`。想拿附件請走 `GetAsync(int id)`。
- `GetFileDownloadAsync` 回傳的 `Content` 是**開著的 `FileStream`**，呼叫端必須 `await using` 收掉，否則檔案控制代碼會一直被佔住。
- 頁面裡要做「看起來像連結、但實際是開 Modal」的元素時用 `<button>` 而非 `<a>`——`<a>` 沒有 `href` 時不可用鍵盤聚焦，有 `href="#"` 又會動到網址列。
- **要用 scoped CSS 調 AntDesign 元件的外觀，不能只給它 `Class`**——scope 屬性不會傳進子元件，那條規則會靜靜失效（不報錯、不警告）。作法是包一層自己寫的 HTML 元素，再從那層用 `::deep` 選進去。懷疑某條 scoped 規則沒生效時，用
  `dotnet build -p:EmitCompilerGeneratedFiles=true` 產生 `obj/.../generated/**/<元件>_razor.g.cs`，看該元素有沒有 `AddAttribute(n, "b-xxxxx")` 就知道了。
