# 移除「首頁」頁面、側邊欄選中樣式定案與版面補正（0.4.45～0.4.49）

- 文件版本：1.4
- 文件狀態：已實作
- 現行系統版本：0.4.49
- 首次實作版本：0.4.45
- 最後核對日期：2026/09/04

## 變更目的

1. **「首頁」與「專案項目」是同一個畫面**——`HomeAuthed.razor` 只有一行 `<ProjectViewView/>`，選單裡兩個項目點下去內容完全相同，只有網址與頁首標題不同。使用者要求移除。
2. 側邊欄選中樣式在 0.4.41～0.4.44 之間改了三版都不對，使用者提供參考圖後定案。

---

## 一、選中樣式定案：比底色深一階的圓角色塊

三版的演進與被否決的理由：

| 版本 | 樣式 | 問題 |
|---|---|---|
| 0.4.41 | 深棕整塊（`--oat-ink`）＋奶油字 | 使用者：「黑色有點違和」。而且**藍字＋隱形圖示**兩個 bug（見 0.4.44） |
| 0.4.44 | 淡奶油底（`--oat-50`）＋左側深棕色條 | 標記感太弱，色條是多餘的裝飾 |
| **0.4.45** | **`--oat-300`（#D4BDA8）圓角色塊，無色條、無陰影** | 定案 |

```css
.sidebar-menu-shell ::deep .ant-menu-item-selected,
.sidebar-menu-shell ::deep .ant-menu-submenu-selected > .ant-menu-submenu-title,
.sidebar-menu-shell ::deep .ant-menu-submenu-open > .ant-menu-submenu-title {
    background: var(--oat-300) !important;
    box-shadow: none;
    color: var(--oat-ink) !important;
    font-weight: 600;
}
```

深棕字壓在 `#D4BDA8` 上是 **6.4:1**，過 WCAG AA（4.5:1）。

**hover 必須跟著改成 `--oat-200`**：它原本就是 `--oat-300`，若不動就會與選中態同色、兩者分不出來。這是改選中色的必然連動，不是順手改。

收合態的圖示按鈕套同一組（hover `--oat-200`、選中 `--oat-300`），並把原本混在一起的 hover 與 active 拆成兩條規則——原本它們共用一條，選中與滑過長得一樣。

> 0.4.44 修掉的兩個 bug（AntDesign 的 `<a>` 藍色連結色、右緣 `::after` 藍線）在本版**維持修正狀態**，那兩條規則沒有動。

### 降落點改為 `/meetings`

`/App` 是登入後的降落點，**共有 6 處**指向它：

| 檔案 | 情境 |
|---|---|
| `Components/Auths/Login.razor.cs:119` | 帳密登入成功且無 returnUrl |

> ⚠️ **最後那一處差點被漏掉**：`SplashView` 寫的是**小寫** `/app`，用 `"/App"` 搜尋抓不到。漏了它會讓「打根網址進系統」直接 404。日後再改路由時，路徑比對一律用不分大小寫的搜尋。

### ⚠️ 既有資料庫會留下一列孤兒權限

`RbacBackfillService` 是**只增不減**的：它會把權限目錄裡的鍵補進資料庫，但**不會刪除目錄中已消失的鍵**。

所以升級後：

- 既有 `Permission` 表仍有 `Key = "首頁"` 的一列，勾過它的角色也仍有 `RolePermission` 連結。
- 但它**完全不會有任何作用**——沒有頁面使用這個權限鍵，選單對應表也沒有它。
- 角色管理的權限矩陣由 `RolePermissionService` 驅動，該列已移除，所以**畫面上根本不會顯示**，使用者也無從勾選或取消。

**本次刻意不加清除邏輯**：刪除權限是破壞性操作，為了一列惰性資料在 RBAC 這種安全敏感的服務裡新增刪除路徑，風險大於收益。要清的話直接對資料庫下兩行 SQL 即可（先刪 `RolePermission` 再刪 `Permission`）。

### 沒有一併處理的部分

`MainLayout.razor.cs` 的 `DefaultPageTitle = "系統首頁"` **維持不動**。它是「目前網址不在選單中」時的頁首備用標題（例如 `/Profile`、`/system-health`），與被移除的 `/App` 頁面無關。

## 三、0.4.46 補正：收合態的標題列過高、第一顆圖示貼著標題

實跑後回報兩個收合態的版面問題。

### 標題列被看不見的文字撐長

收合時 `.sidebar-brand-text` 用的是：

```css
opacity: 0;
pointer-events: none;
width: 0;
```

**文字看不見了，但它的「高度」還在。** 元素仍在版面流裡，兩行（系統名稱＋副標）的高度照樣把 flex 列撐開，所以收合後的標題列比 logo 本身高出一大截。

改成 `display: none` —— 要讓元素不佔空間，只有把它移出版面流。`opacity` 與 `width` 都做不到這件事（`width: 0` 只收掉水平方向）。

### 第一顆圖示與標題列之間沒有縫隙

展開態的間距其實是 `.nav-section-title` 的 `padding: 0.25rem 1.5rem 1rem` 撐出來的，但**收合態把區塊標題設成 `display: none`**，於是第一個項目直接貼著標題列。

`.sidebar-menu-shell` 本身是 `padding: 0 1rem 1rem`（**沒有 top**），收合態的覆寫也只動了左右，所以補上 `padding-top: 0.85rem`。

## 四、0.4.47 補正：頁首對齊與標誌尺寸

### 側邊欄頁首與內容區頁首沒有切齊

兩邊各自寫死高度，數字不一樣：

| | 高度 | 底線 |
|---|---|---|
| `MainLayout` 的 `.top-row`（內容區） | `min-height: 4.5rem` | 1px `rgba(67,54,44,.10)` |
| `NavMenu` 的 `.top-row`（側邊欄） | `min-height: 5rem` ＋ 上下 padding | **無** |

所以兩條邊界既不等高、也接不成一條線。

側邊欄那邊改為與內容區完全一致：`min-height: 4.5rem`、加上同一條底線，並把垂直 padding 拿掉（改靠既有的 `align-items: center` 置中），高度就只由 `min-height` 決定，不會再被 padding 悄悄墊高。**收合態不覆寫高度**——收合時同樣要跟內容區切齊。

連帶要改的還有 `.nav-scrollable` 的 `height: calc(100vh - 5rem)`：那個 `5rem` 就是舊的頁首高度，不跟著改會多出一段死空間或提早出現捲軸。已改為 `calc(100vh - 4.5rem - 1px)`。

### 標誌尺寸（0.4.47～0.4.49 調了三輪）

標誌原本是 2.5rem（收合態 2rem），而選單圖示只有 1rem（收合態 1.25rem）——**2.5 倍的落差**，看起來很突兀。

0.4.47 依「與選單圖示等大」改成 1rem／1.25rem，實跑後反而過小；0.4.48 調到 1.5rem／1.75rem 仍偏小。**0.4.49 定案**：

| 狀態 | 選單圖示 | 標誌 |
|---|---|---|
| 展開 | 1rem | **2rem** |
| 收合 | 1.25rem | **2.5rem** |

**標誌不必與選單圖示等大**——它是品牌識別而不是選單項目，等大反而顯得單薄。展開態 2rem 約與標題兩行文字等高，視覺上成組；收合態欄寬 64px 扣掉左右 padding 只剩約 53px，2.5rem（40px）能填滿大部分寬度。

### SVG 自己也帶著一圈空白

同一輪還發現：標誌的 `viewBox="0 0 120 120"`，但**圖形實際只佔到 5～115**（三橢圓含 6px stroke，加上四個 r=8 的圓點），四周各留了一圈約 4% 的空白。

在小尺寸下這圈空白很有感——同樣的 `width`，圖看起來就是比別的圖示小一號。viewBox 收緊為 `5 5 110 110`，圖形不變但填滿度提高。

> 登入頁用的是同一份線稿，但那裡的標誌有 96px，那圈空白不影響觀感，**未一併更動**。

> 標誌 SVG 裡的「AI」字樣在 viewBox 中只佔約 30% 高度，所以標誌越小那兩個字越難辨識；2rem（32px）時約 10px，勉強可讀。

## 實作備註（給後續維護）

- **改路由時要用不分大小寫搜尋**。Blazor 路由本身不分大小寫，程式裡寫 `/App` 或 `/app` 都能運作，所以區分大小寫的搜尋一定會漏。
- **改選中色時必須同時檢查 hover 色**。兩者本來就相鄰，只改一個會讓它們撞色。
- `RbacBackfillService` **只增不減**。從權限目錄移除鍵不會清掉資料庫裡的既有列，只會讓它變成惰性資料。
- **要讓元素不佔版面空間，只有 `display: none`**。`opacity: 0` 與 `width: 0` 都只是讓它看不見／收掉寬度，高度仍會撐開父層。
- 側邊欄的縱向間距**有一部分是靠 `.nav-section-title` 的 padding 撐的**。任何隱藏區塊標題的狀態（例如收合態）都要自己補回 `padding-top`。
- **側邊欄頁首與內容區頁首是兩個各自寫死高度的 `.top-row`**（分屬 `NavMenu` 與 `MainLayout` 兩份 scoped CSS，名字一樣但互不影響）。動其中一個的高度就必須同步另一個，還要一併檢查 `.nav-scrollable` 那條 `calc(100vh - ...)`。
- 要讓元素高度「只由 `min-height` 決定」，就別再給它垂直 padding——用 `align-items: center` 置中內容即可，否則兩個數字會互相疊加。
