# AI 問答：專案層級與單一會議（0.4.51～0.4.53）

- 文件版本：1.2
- 文件狀態：已實作
- 現行系統版本：0.4.53
- 首次實作版本：0.4.51
- 最後核對日期：2026/09/08

## 變更目的

補上待辦清單裡最大的一項——[系統功能總覽](../architecture/系統功能總覽.md) 第七節的
「AI 依專案附件與會議紀錄回答提問」。這是 0.4.43 使用者要求列入待辦、當時先不做的項目，
也是當初堅持保留專案附件功能的原始動機。

兩個入口：

| 入口 | 位置 | 讀什麼 |
|---|---|---|
| 專案層級 | 專案選擇列的工具列 | 本專案**所有會議紀錄 ＋ 附件** |
| 單一會議 | `歷史會議紀錄` 每一列的操作欄 | 該會議的**會議紀錄 ＋ 逐字稿** |

## 一、Azure OpenAI 連線是複用的，不是新接的

`ITextGenerationProvider` 早就在服務轉錄與會議紀錄生成，0.4.42 還改成了串流。
問答直接走同一個供應商實作、同一組 `LlmSettings` 設定，**沒有新增第二條到 Azure OpenAI 的路徑**。

差別只在：問答沒有佇列與背景 worker。它是使用者等在畫面前的同步互動，不是背景工作。

### 前置改動：串流回呼要能傳「文字」

`GenerateAsync` 的回呼原本是 `Action<int>? onCharactersGenerated`——**只有字數，沒有文字**。
0.4.42 當時只需要進度百分比，所以夠用；但聊天室要邊生成邊顯示就拿不到內容。

改為 `Action<string>? onDelta`，傳**增量**而非累積全文：

- 累積會讓每個片段都配置一次完整長度的字串（3000 字的回答約 500 次 delta ≈ 750KB 無謂配置）
- 兩種呼叫端要的東西不同——生成只要長度（自己累加），問答要文字。**傳增量兩者都拿得到**

`MeetingDraftJobRunner` 因此自己累加長度後再回報，**進度行為完全不變**。

## 二、附件文字擷取（新增兩個套件）

專案原本沒有任何 PDF／Word 讀取能力——`Markdig` 是 markdown→HTML，
`HeadlessBrowserPdfRenderer` 是**輸出** PDF。

新增 `Services/AiChat/AttachmentTextExtractor.cs`：

| 副檔名 | 做法 |
|---|---|
| `.pdf` | **PdfPig** 0.1.16（Apache-2.0） |
| `.docx` | **DocumentFormat.OpenXml** 3.5.1（MIT） |
| `.txt` `.md` `.csv` | 直接讀文字 |
| 其他 | 跳過 |

**刻意避開 iText**——它是 AGPL，用在非開源專案有授權問題。

### ⚠️ 掃描檔 PDF 讀不到，而且會被明確標示

掃描檔 PDF 有頁面但沒有文字層，PdfPig 擷取出來是空字串。這種情況與「格式不支援」
一併回 null，並在畫面上列進「無法讀取」。

**這一點不能省略**：如果默默當成沒有內容，使用者會以為 AI 讀過合約了卻答不出來，
反而更難排查。

### 沒有做快取（刻意）

每次提問都重新擷取一次。原本規劃用既有的 `ICacheService`，但**它在 Web 層
（`MeetingRecord.Web/Caching`），Business 層取用不到**——分層是 Web → Business，不能反向相依。

為了快取另引一套快取套件不划算。代價是上百頁的 PDF 每問一句就重新解析一次；
若日後成為瓶頸，正確的解法是把擷取結果存進資料庫欄位（上傳時做一次），而不是加快取。

## 三、脈絡組裝：絕不無聲截斷

新增 `Services/AiChat/ChatContextBuilder.cs`，比照 `TranscriptChunker`、
`TranscriptionNoiseFilter` 的純函式慣例。

- 預算 `DefaultMaxChars = 60000`。gpt-4o 系列脈絡 128k token，中文約 1～1.5 字元/token，
  60000 字元約當 40～60k token，其餘留給系統提示詞、對話歷史與回答本身。
- **傳入順序就是優先權**：會議紀錄（短、已整理過）排在逐字稿與附件（長）前面。
- 空間不足時截尾並在脈絡裡插入「已截斷」提示，讓**模型自己也知道**看到的不是全文。
- 回傳 `UsedLabels`／`TruncatedLabels`／`SkippedLabels` 三份清單，**畫面一定會顯示**。

## 四、對話歷史落庫

新增資料表 `AiChatMessage`（migration `AddAiChatMessage`，SQLite）：

| 欄位 | 說明 |
|---|---|
| `ProjectId` / `MeetingId` | **恰有一個非 null**，決定這則訊息屬於哪一段對話。兩者皆 Cascade |
| `Role` | `user`／`assistant` |
| `Content` | 訊息內容 |
| `AskedBy` | 提問者顯示名稱**快照** |
| `CreatedAt` | |

`AskedBy` **刻意不做 FK 到 MyUser**：使用者改名、停用或刪除都不該讓歷史紀錄跟著變動或消失。

`Meeting → Project` 本來就是 `SetNull`（刪專案不刪會議），所以會議層級的對話
不會因為專案被刪就消失。

### 對話是共用的，不是每人一份

同一個專案／會議底下所有人看到同一段對話。專案自 0.4.39 起已無列級權控，
團隊成員看得到彼此問過什麼可以避免重複詢問。日後若要改成個人私有，
加一個 `MyUserId` 過濾即可，**不必改結構**。

### 只有最近 6 輪會送進模型

更早的對話仍留在資料庫供畫面翻閱，但不再進提示詞。脈絡本身就吃掉大量長度，
歷史無上限累積會讓**每一次提問都比上一次更貴**。

## 五、UI

新增 `Components/Views/Projects/AiChatModal.razor`，兩種範圍共用同一個元件
（差別只在 `Scope` 與 `TargetId`）。

- 回答**邊生成邊顯示**（串流回呼由 HTTP 讀取執行緒觸發，必須 `InvokeAsync` 切回 UI 執行緒）
- 頂部顯示這次讀了幾份資料、哪些被截斷、哪些無法讀取
- Enter 送出、Shift+Enter 換行
- 提問先樂觀顯示；失敗時收回，不留下沒有回應的問題

**權限**：兩顆按鈕都不加額外的動作檢查，與同列的「檢視會議紀錄」一致
（只有編修要 `Edit`、匯出要 `Export`）。專案層級的按鈕刻意放在工具列而不是
下方的 AI 生成區塊——那一整塊需要 `Edit` 權限，而問答是唯讀操作。

## ⚠️ 需要知道的取捨與風險

- **完全不做成本控管**（既有的已知限制：不計 token、不設配額）。問答是一個
  **由使用者主動觸發、可以無限重複**的成本面，比生成更容易失控。本輪不做配額。
- **合約內容會外送 Azure OpenAI**。與現有的轉錄／生成同一個租戶，但這是新的資料外送面
  ——先前只有音檔與逐字稿會離開系統，現在附件全文也會。
- 專案的附件很多或很大時，**每次提問都要重新解析所有附件**（見第二節）。

## 六、0.4.52 補正：送出按鈕在打字時沒有啟用

實跑回報：輸入文字後送出按鈕仍是停用樣式，**要點到輸入框外面才會亮**。

根因不是 CSS，是綁定時機。AntDesign 的 `Input<T>.BindOnInput`（官方說明
*Whether to change value on input*）**預設不開**，所以 `@bind-Value` 只在
**change（失焦）** 時才把值寫回：

```razor
<TextArea @bind-Value="question" … />          <!-- 打字期間 question 恆為空字串 -->
…
Disabled="@(isAsking || string.IsNullOrWhiteSpace(question))"   <!-- 於是一直算出 true -->
```

「點一下輸入框外面就會亮」這個症狀，正好對得上 change 事件的觸發時機。

修法是加上 `BindOnInput="true"`，**只有這一行**——停用條件本身是對的，
CSS 也不必動（AntDesign 的 primary 按鈕停用是灰色、啟用是主色，本來就分得出來）。

### `DebounceMilliseconds` 當時維持預設 250ms —— **這個判斷是錯的，見 0.4.53**

## 七、0.4.53 補正：送出後輸入框沒有清空

實跑回報：問題送出後，文字仍留在輸入框裡。有**兩個獨立成因**，都與 0.4.52 的 debounce 判斷有關。

### 成因一：Enter 的預設行為會插入換行，而我們攔不掉

`<textarea>` 按 Enter 本來就會插入換行。要阻止必須 `@onkeydown:preventDefault`，
但那是 **Razor 的編譯期指示詞，只能用在原生 HTML 元素上**；AntDesign 的 `OnkeyDown`
是一個 `EventCallback` 參數，**拿不到 preventDefault**。

所以流程是：keydown → 我們的處理器清空 `question` → 瀏覽器插入換行 →
input 事件把換行寫回 `question` → 輸入框看起來「沒清掉」。

修法：在 `finally` 裡**再清一次**。這不是多餘的重複——第一次清是為了讓使用者
按下 Enter 當下就看到框空了，第二次清是為了抹掉那個晚到的換行。

### 成因二：250ms debounce 讓 Enter 讀到舊值

0.4.52 為了省伺服器往返而保留預設的 250ms debounce。這在「打完字停下來再按 Enter」時沒問題，
但**打完立刻按 Enter 時計時器還沒觸發**，`OnAskAsync` 讀到的 `question` 會是舊值甚至空字串：

- 空字串 → `OnAskAsync` 直接 return，**根本沒送出**
- 舊值 → **送出的問題被截斷**

然後計時器才把完整文字寫回輸入框——這正是「送出後文字還在」的另一半。

改為 `DebounceMilliseconds="0"`。代價是逐鍵一次伺服器往返，但**正確性優先於那點往返**：
一個會偶爾送出截斷問題的輸入框，省再多往返也沒有意義。

## 實作備註（給後續維護）

- `dotnet ef migrations add` 會建置啟動專案，**應用程式正在跑的時候 Debug 輸出被鎖住會失敗**。
  加 `--configuration Release` 即可繞開，不必去關使用者的程式。
- 測試字串包含關係要小心前綴：`"問題10"` 本身就含有 `"問題1"`，
  用 `DoesNotContain("問題1", …)` 驗「只保留最近幾輪」永遠會失敗。斷言要挑不互為前綴的邊界值。
- Business 層**取用不到** `ICacheService`（它在 Web 層）。需要跨層的基礎設施時，
  要嘛下沉到 Business，要嘛換個做法——不要為了它把相依方向反過來。
- **AntDesign 的輸入元件預設只在失焦時才更新繫結值**。凡是「打字當下就要反應」的
  UI（送出鈕啟用、即時字數、即時驗證），一律要加 `BindOnInput="true"`，
  否則值在打字期間不會變，畫面看起來就像壞掉。
- **`BindOnInput` 搭配鍵盤快捷鍵時，`DebounceMilliseconds` 一定要設 0**。
  只要處理器會「讀取當下的繫結值」（Enter 送出就是），debounce 就會讓它讀到舊值。
  省往返是次要的，讀到舊值等於功能壞掉。
- **AntDesign 元件的鍵盤事件參數攔不掉瀏覽器預設行為**。`@onkeydown:preventDefault`
  是編譯期指示詞、只能用在原生元素上；掛在元件的 `OnkeyDown` 參數上沒有等價寫法。
  用 Enter 送出多行輸入框時，換行一定會被插進去，只能在動作結束後把值清乾淨。
