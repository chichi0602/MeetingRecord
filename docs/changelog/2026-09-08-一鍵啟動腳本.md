## 變更目的

每次啟動系統都要從 `readme.md` 複製這一串，還得先 `cd` 到正確的目錄：

```
dotnet run --project MeetingRecord.Web/MeetingRecord.Web.csproj --launch-profile http
```

倉庫根目錄本來沒有任何啟動腳本（`scripts/` 下只有建立模組與檢查編碼的工具）。

## 用法

```powershell
.\run          # http  → http://localhost:5189（預設，會自動開瀏覽器）
.\run https    # https → https://localhost:7044
```

也可以在檔案總管按兩下 `run.cmd`。

腳本以 `pushd "%~dp0"` 切到自己所在的目錄，所以**從哪裡呼叫都可以**，不必先 `cd`。
沒帶參數時預設 `http`（`launchSettings.json` 的第一個 profile，`launchBrowser: true`）。

## 兩個刻意的設計

**啟動失敗時 `pause` 讓視窗停住。** 從檔案總管按兩下時，失敗訊息會隨視窗關閉一閃而過，
根本來不及看。成功啟動時不 pause（`dotnet run` 本來就會一直佔住視窗）。

**腳本內容全部是 ASCII，註解用英文。** `cmd.exe` 是依「當下主控台代碼頁」逐位元組
解析批次檔的，非 ASCII 位元組在代碼頁不同的機器上可能被拆成奇怪的字元而破壞解析。
中文說明放在 `readme.md`，不放在 `.cmd` 裡。

## 與 Visual Studio 的關係

**用 VS 的話直接按 F5，不需要這個腳本。** 兩者不能同時用——VS 已經佔住 port 5189，
而且會鎖住 `bin\Debug`，讓 `dotnet run` 連編譯都過不了。`run.cmd` 在非零結束碼時
會提示這個可能性，這是本專案反覆遇到的情況。

## 驗證

把 `dotnet run` 換成 `echo` 做成探針腳本，**從 `C:\` 呼叫**，確認：

- 無參數 → `--launch-profile http`
- 帶 `https` → `--launch-profile https`
- 專案路徑正確組成（`src\MeetingRecord\MeetingRecord.Web\MeetingRecord.Web.csproj`）

沒有實際跑起來——使用者的實例當時正佔用 port 5189（`netstat` 確認 PID 14272），
另起一個會撞埠，而且會與其共用同一個 SQLite 檔案。
