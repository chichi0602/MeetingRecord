## 變更目的

使用者問「現在要開啟專案的完整流程」，才發現這件事的資訊是散的：

- `readme.md` §5 講的是**第一次**建置（`restore` / `build` / `run`）
- 0.4.58 的 `run.cmd` 只在 readme 補了一小段
- **如何安全停掉正在跑的實例，整個 repo 完全沒有寫**

最後那一項最要緊：本專案曾因為用**映像名稱**砍行程，
**連帶砍掉開發者正在使用的 Visual Studio**（VS 偵錯中的宿主行程會匹配到同樣的映像名稱）。
這條規則先前只存在於對話慣例裡，沒有落在文件上——換一個人接手就會再踩一次。

## 新增 `docs/operations/啟動與停止系統.md`

六節：

1. **先確認有沒有已經在跑的實例**——`netstat` 查 5189。有就直接開瀏覽器，
   不要啟第二個（兩個實例共用同一個 SQLite 檔）
2. **需要停掉時**——優先 `Ctrl+C`；用 PID 時一律
   `netstat` 找 PID → `tasklist` 確認 → `taskkill /PID`。
   附上「絕對不要用 `/IM`」的警告與原因
3. **啟動三選一**——`run.cmd` / Visual Studio F5 / 手動 `dotnet run`，
   含兩個 launch profile 的網址；說明 A 與 B 為什麼不能同時用，
   以及要並存建置時的 `-p:BaseOutputPath=./.tmp-build-out/`
   （**要放在倉庫樹內**，放 `%TEMP%` 會讓 6 筆測試假性失敗）
4. **登入**——`support` / `support`
5. **什麼時候一定要重新編譯**——`.cs`／`.razor` 要重編（新 `@page` 路由尤其），
   但 `Menu.json` 與 `appsettings.json` 走 `ContentRootPath` 讀原始檔、改了立刻生效。
   **這個落差在 0.4.54 造成過一次誤判**（選單出現了但頁面 Not Found）
6. **啟動失敗的常見原因**——埠佔用、DLL 被鎖、FFmpeg 找不到、user-secrets 沒設
