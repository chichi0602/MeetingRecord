## 變更目的

專案項目頁的「歷史會議紀錄」每一列多一顆「抽出待辦」，用 AI 從那份會議紀錄找出
行動項目，並在確認視窗讓使用者挑哪些要真的加進待辦清單。

這是待辦清單上掛了很久的項目——`Todo.MeetingId` 外鍵**早就備妥但恆為 null**
（`系統功能總覽.md` 第七節記著「等這個功能才會有值」），`TodoAdapterModel.SourceText`
也早就寫好了「手動新增 vs 來源會議」的顯示邏輯。這一版把那條路接起來。

## 一、只讀會議紀錄草稿，不讀逐字稿

`TodoExtractionService.ExtractAsync` 只讀 `Meeting.DraftContent`。

草稿已經是 AI 整理過的結構化內容，「待辦事項」通常已經被列出來了——抽取準確度高、
長度短、便宜。逐字稿雖然有草稿沒寫進去的細節，但雜訊多，會抽出一堆「其實只是閒聊」
的東西讓使用者逐條去勾掉，反而更累。

因此按鈕的出現條件是 `context.HasDraft`，與同列的「檢視會議紀錄」「匯出 PDF」一致：
**沒有草稿就沒有東西可抽**。

權限鍵刻意是 **`角色_待辦事項` 的 Create**，不是專案項目的——這顆鈕真正做的事是新增待辦。

## 二、⚠️ 解析 LLM 輸出是這個功能唯一真正脆弱的地方

模型不保證回乾淨的 JSON，而且它歪掉的方式每次都不一樣。
`TodoExtractionParser` 把這些全部吸收掉：

| 狀況 | 處理 |
|------|------|
| 包在 ```json 圍籬裡 | 取第一個 `[` 到最後一個 `]`，順便解決下面兩種 |
| 前面加「好的，以下是我抽出的待辦：」 | 同上 |
| 後面補一段說明 | 同上 |
| 完全不是 JSON、空字串、回的是物件不是陣列 | **回空清單，不拋例外** |
| `dueDate` 是「下週五」「ASAP」 | 留 null |
| `priority` 是 `High`／`緊急`／沒填 | 正規化到 低／中／高，不認得就給「中」 |
| 標題超過 200 字、負責人超過 50 字 | 截斷到 `TodoAdapterModel` 的 `StringLength` 上限 |
| 沒有標題 | 整條丟掉 |

### 兩個刻意的判斷

**相對日期一律留 null，不去推算。** 算錯一個截止日比留白更糟——留白使用者一眼看得出
要補，算錯了他不會發現。提示詞那端也已經要求模型只輸出 `yyyy-MM-dd`，並把**會議日期**
放進提示詞當作換算基準（不是今天——會議可能是兩週前開的）。

**不認得的優先度一律給「中」。** 寧可全部落在中間讓使用者自己調，也不要亂猜成「高」。

**`Status` 不讓 AI 決定**，一律是「待辦」——剛抽出來的東西不可能已完成。

### 「抽不到」不是錯誤

`Parse` 任何解析不出來的情況都回空清單。對使用者來說「這份紀錄沒有待辦」與
「模型今天回了奇怪的東西」是同一件事：畫面顯示中性提示，而不是一個紅色錯誤。

## 三、確認視窗

`TodoExtractionModal`（擺在 `AiChatModal` 旁邊）。抽出來的東西**一律要人看過才寫入**——
模型會把人名聽錯、把討論當成行動項目，直接落庫的話使用者得一條條進待辦頁去刪，
比自己打還累。

每一列可改**標題、負責人、截止日、優先度**；描述唯讀顯示（AI 抽的描述通常是原文摘錄，
真要改的人會進待辦頁改）。預設全部勾選，沒勾的列淡化顯示，一眼看得出哪些不會被加進去。

**重複加入只提示不阻擋**：載入時查這場會議已有幾條待辦，大於 0 就在上方顯示
「這場會議先前已加入 N 條待辦」。不阻擋是因為開完後續會議再抽一次新決議是合理的用法。

**部分失敗要講清楚**：逐條呼叫 `TodoService.BeforeAddCheckAsync` → `AddAsync`，
有失敗的就回報「已加入 N 條，其餘未加入：…」並列出是哪幾條，不要只丟一句「失敗」。

## 四、沒有資料庫變更

`Todo.MeetingId` 早就存在（0.4.32 就加了），**不需要 migration**。
待辦清單的「來源」欄從此會顯示來源會議標題，而不是一律「— 手動新增」。

## 五、測試

新增 `TodoExtractionParserTests` 38 筆（既有 497 → **535 全綠**），
全部集中在「模型輸出歪掉」這件事上：

- 三種外層包裝（乾淨／圍籬／前後客套話）都要解析得出來
- 六種無法使用的輸出都回空清單且不拋例外
- 四種絕對日期格式接受；相對日期與缺欄位一律 null
- 六種優先度正規化；四種不認得的落到「中」
- 沒標題的丟掉、超長截斷、空字串轉 null、前後空白 trim
- `ToAdapterModel` 一律是「待辦」狀態且填上 `MeetingId`
- `BuildUserPrompt` 含草稿與會議日期

## 六、待實跑驗證

1. 已產生會議紀錄的列出現「抽出待辦」，沒草稿的列不出現
2. 點下去轉圈，然後列出候選
3. 取消勾選幾條、改負責人與截止日，加入後到待辦頁確認
   **「來源」欄顯示的是那場會議的標題**
4. 再點一次同一場會議，上方出現「先前已加入 N 條待辦」
5. 拿一份沒有明確待辦的會議紀錄試，顯示中性提示而不是錯誤
