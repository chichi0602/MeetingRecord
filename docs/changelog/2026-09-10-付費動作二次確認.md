# 付費動作一律二次確認，並修掉重複計費缺陷（0.4.65）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.4.65
- 首次實作版本：0.4.65

## 變更目的

使用者指出「重新轉錄」按下去沒有任何提示，而它會重跑一次完整的轉錄、產生實際費用。要求掃描全系統，把所有按下去會產生**多餘 API 費用**的入口都補上確認對話框。

盤點結果：**全系統只有兩個類別實際打付費 API**——`AzureOpenAiTranscriptionProvider.TranscribeAsync` 與 `AzureOpenAiTextGenerationProvider.GenerateAsync`。Web API Controller 完全沒有能觸發它們的端點，背景服務不重試、重啟也不重跑（`Program.cs` 的啟動修復把殘留的待處理與處理中一律標成失敗）。所以付費路徑只有五條，全部從 Blazor UI 觸發：

| 入口 | 改動前的確認 | 改動前的防連點 |
| --- | --- | --- |
| 重新轉錄 | 無 | **完全沒有** |
| 上傳影音檔（自動排入轉錄）| 無 | `isUploading` |
| AI 轉會議紀錄 | **僅已有草稿時**，且文案只講覆蓋不提費用 | `isGenerating`（只覆蓋毫秒）|
| 抽出待辦 | 無（Modal 一開就打，可無限重抽）| 無 |
| AI 問答送出 | 無 | 最完整 |

盤點時另外找到一個**真正的重複計費缺陷**與一個讓取消變成死路的既有 bug，一併修掉。

## 一、重複計費缺陷（確認框擋不住這個）

確認框只能減少誤觸；使用者確認兩次就真的跑兩趟。根因在服務層與按鈕顯示條件：

`RequeueTranscriptionAsync` 與 `RequestDraftAsync` 原本**只擋 `Processing`、不擋 `Pending`**。第一次點完狀態就變 `Pending`、按鈕還在、服務層又放行 → **入列兩次，被單一 worker 依序跑兩趟完整轉錄**。而進度面板以 `$"{Kind}-{MeetingId}"` 為 key，兩筆會收成一列——**畫面上完全看不出跑了兩趟，只有帳單看得出來**。兩支都改成 `is Processing or Pending`。

`ProjectViewView` 的「AI 轉會議紀錄」按鈕的 `Disabled` 原本只看兩個下拉選了沒，沒有用 `CanGenerateDraft`（該旗標本來就排除了 `Pending`）。改為新增 `SelectedTranscript` 與 `CanSubmitDraft` 兩個計算屬性後綁上去。

### 連帶修掉：取消過的轉錄沒有出口

`MeetingAdapterModel.CanRetryTranscription` 是**列舉式**的 `Pending or Failed or Completed`——**漏了 `Cancelled`**。所以取消過的轉錄根本不會出現「重新轉錄」鈕（服務層其實允許），唯一的出路是重新上傳檔案。如果只把 `Pending` 拿掉而不補 `Cancelled`，可重試的狀態會只剩兩個，取消依然是死路。

改成**排除式**，與 `CanGenerateDraft` 對稱：

```csharp
public bool CanRetryTranscription =>
    HasMedia
    && TranscriptionStatus is not (TranscriptionStatus.Pending or TranscriptionStatus.Processing);
```

這類「能不能再送一次付費工作」的旗標一律寫成排除式——列舉式在新增 enum 值時會默默漏掉，這次就是這樣漏的。

這個修正也是「進度面板的取消鈕不加確認」這個決定能成立的前提：取消必須是可回復的。順手把取消訊息從「已由使用者取消。」改成「已由使用者取消，可從清單重新轉錄。」／「⋯可重新產生會議紀錄。」，讓結果可讀。

**已驗證重啟路徑沒有被擋死**：`Program.cs` 的兩個啟動修復區塊本來就同時掃 `Pending` 與 `Processing`（註解明寫「佇列不持久化，重啟後已入列但還沒被 worker 撿走的紀錄同樣沒有人會接手」），一律改判為 `Failed`，而 `Failed` 仍可重試。執行期也不會卡在 `Pending`：兩個背景服務的單筆處理都包在只記 log 的 `catch` 裡。

## 二、四個確認框

### 文案刻意不講「幾次 API 呼叫」

- **轉錄算不出來**：段數要等 FFmpeg 切完才知道，畫面上只有檔案大小，而位元率在語音備忘錄與含影軌的 MP4 之間差十倍以上，換算出來的數字是雜訊不是估算。
- **生成算得出來但要付代價**：逐字稿在磁碟不在 adapter model，每次點按都讀一次檔只為了算數字，而 `TranscriptChunker` 優先在段落邊界斷句，`ceil(字數/上限)` 只是下界。
- 講錯數字比不講更糟（「系統說 3 次、帳單是 5 次」）。

所以只寫**免費且精確**的事實——上傳時的檔名與檔案大小（最強的防誤觸訊號）、抽出待辦的「每次固定一次呼叫」（唯一真的固定的）——其餘用質性描述。轉錄文案的分鐘數從 `FfmpegMediaConverter.SegmentSeconds` 算出來，不寫死，否則改常數時文案會偷偷過期。

### Danger 跟「覆蓋」走，不跟「花錢」走

沿用既有慣例（非破壞性不套 Danger）。花錢不等於破壞性：

| 確認框 | 紅色確認鈕 |
| --- | --- |
| 重新轉錄，已完成 | **是**（會刪掉現有逐字稿）|
| 重新轉錄，失敗／已取消 | 否 |
| 上傳影音檔，已有音檔 | **是**（舊音檔與逐字稿一併刪）|
| 上傳影音檔，首次 | 否 |
| AI 轉會議紀錄，已有草稿 | **是**（覆蓋人工編修過的內容）|
| AI 轉會議紀錄，首次／失敗／已取消 | 否 |
| 抽出待辦 | **永不**（只產生候選，勾選儲存前不寫入任何資料）|

### 三個位置陷阱

1. **上傳確認掛在 AntDesign `Modal` 的 `OnOk` 上，而視窗會自己關掉**——取消時一定要 `modalVisible = true`，否則使用者填的整張表單會消失。位置在驗證通過之後、主資料存檔之前：放在存檔之後按取消，會留下一筆存好卻沒有音檔的紀錄，而且「修改成功」已經跳過了。
2. **抽出待辦的確認必須放按鈕、不能放 Modal**：`TodoExtractionModal` 的 `OnParametersSetAsync` 一開啟就呼叫 `ExtractAsync`，Modal 顯示出來的那一刻 API 已經打出去了。而 `OpenTodoExtraction` 原本是 `void`，在 `void` 裡 `await` 確認等於 fire-and-forget、視窗照開照計費 → 改成 `async Task OpenTodoExtractionAsync` 並改掉 razor 的 lambda。`loadedMeetingId` / `CloseAsync` 刻意不動：入口有了確認之後，「關掉再開＝刻意重抽」正是那段註解原本的意思，文案也寫明了會再計費一次。
3. **`isGenerating` 不是防連點**：它在 enqueue 回來後的 `finally` 立刻歸零，`Loading` 只覆蓋毫秒。改為在方法開頭早退。`CrudActionButton` 沒有 `Loading` 參數，重新轉錄改用 `Disabled` ＋ `requeueingMeetingId`（比照既有的 `exportingMeetingId`）。

## 三、AI 問答：不加確認，改常駐提示

一次提問正好一次 API 呼叫，而提問本身就是這個功能的主要動作——每句都跳確認會讓功能不能用。它也是現在防連點最完整的一條路徑（`isAsking` 早退 ＋ `Loading` ＋ `Disabled` ＋ TextArea disabled）。改在輸入框上方加一行常駐提示（錢是在那裡花的，不放頂端跟既有的來源說明打架）。

## 四、進度面板的「取消」：刻意不加確認

取消是**省錢**的方向：`TranscriptionJobRunner` 每段開頭檢查取消旗標，還在排隊就被取消的會整個跳過並註明「不要浪費一次 API 呼叫」。對省錢方向加上與花錢方向同等的阻力，等於訓練使用者把兩邊都無腦按掉。誤觸防護用另一種方式解決：進度面板是「禁用純圖示按鈕」的明文例外，正因為「取消」與「關閉」易混淆，兩顆都保留可見文字。

### 待實跑驗證

1. 已完成的會議按「重新轉錄」→ 紅色確認、文案提到覆蓋逐字稿與費用；取消則什麼都沒發生
2. 失敗的會議按「重新轉錄」→ 文案改成「上次轉錄失敗」、確認鈕**不是**紅色
3. **取消一筆轉錄 → 該筆應出現「重新轉錄」鈕**（0.4.65 之前沒有）
4. 連按「重新轉錄」兩次 → 第二次被拒（「已排入轉錄，請稍候。」），只跑一趟
5. 上傳新音檔 → 確認框顯示檔名與檔案大小；取消 → **編輯表單仍在、資料沒存**
6. 首次生成 → 非紅色確認；已有草稿再生成 → 紅色且提到覆蓋人工編修
7. 抽出待辦 → 先跳確認才開 Modal；取消 → Modal 不開、**沒有任何 API 呼叫**
8. AI 問答 → 輸入框上方有常駐費用提示、送出**不跳**確認
9. 進度面板「取消」→ 不跳確認，訊息顯示「可從清單重新轉錄」
