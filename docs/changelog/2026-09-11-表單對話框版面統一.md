# 表單對話框版面統一（0.4.68 → 0.4.69）

使用者指出待辦事項的新增對話框內容過高、要捲動才看得完，要求**全站這類 dialog 都比照「會議紀錄新增」那一個**：盡量不捲動就顯示完整內容，較短的欄位一行放兩欄。

會議紀錄那個之所以不同，是 0.4.28 就單獨做過這件事（見 [會議紀錄對話框近滿版與雙欄](2026-08-27-會議紀錄對話框近滿版與雙欄.md)）。這次把當時只對一頁生效的做法抽成全站共用機制。

## 根因

`Modal` 預設 `Width` 是 **520**，而 `.ant-modal-body` 預設**沒有** `max-height`、**沒有** `overflow`（由 `ant-design-blazor.css` 實查，不是憑印象）。內容一高，整個 `.ant-modal` 跟著長高，捲動發生在 `.ant-modal-wrap`——也就是整個遮罩層——於是標題列與確認按鈕一起被捲出視窗。

## 做法

### 一、尺寸分四級，不是一律滿版

96vw 對只有 3 個欄位的分類清單是荒謬的。依內容高度分級：

| class | 尺寸 | 套用 |
| --- | --- | --- |
| `.form-modal-compact` | 680px、**高度自適應** | 分類、團隊、變更密碼 |
| `.form-modal-standard` | 880px、`max-height: 88vh` | 待辦、提示詞、使用者管理 |
| `.form-modal-large` | 90vw / 90vh | 角色管理、專案項目 |
| `.meeting-view-modal` | 96vw / 96vh | 會議紀錄（含影音上傳） |

⚠️ **compact 級刻意不設 `height`、也不設 `overflow`**。設 `height: 90vh` 會讓 3 個欄位的表單硬撐成整個螢幕高、中間空一大片。高度一律用 `max-height`：短表單自適應，長表單才捲。

使用者管理原本在 90vw/90vh 那組，改成兩欄後只剩 5 列，維持固定 90vh 會空掉半個螢幕，因此降到 standard。

### 二、兩欄 grid 從 meeting 專屬改成共用

原本的 `.meeting-view-form-grid` / `.meeting-view-form-full` 只對會議紀錄生效。改名為 `.form-modal-grid` / `.form-modal-full` 並由全站共用，**舊的兩條同時刪除**——同一件事不留兩套寫法。

分欄原則：單行輸入（Input／Select／DatePicker／Switch／Checkbox）併排；多行或寬內容（TextArea／檔案清單／Slider／權限矩陣／很長的 placeholder）跨整列。768px 以下退回單欄。

提示詞的兩個 TextArea 一併壓低（內容 14→10 列、描述 3→2 列），否則 880px 下仍會超出視窗。

### 三、順手修掉一條死 CSS

`.change-password-modal { width: 480px }` 寫在 `FormModalHelper.razor`，但 `MainLayout.razor` **沒有** render `<FormModalHelper />`（只有 8 個 `*ViewView` 有），所以那條規則從來沒作用過——與 0.4.67 那條 `.xxx-search-input` 同類的問題。這次在 `MainLayout` 補上 `<FormModalHelper />`，並讓變更密碼改用 `.form-modal-compact`（三個密碼欄併排會太擠，維持單欄）。

## 實跑量測

⚠️ 這批是 100% 的視覺改動，**單元測試完全證明不了**（579 筆全綠只代表沒改壞邏輯）。前幾批已連續出現「邏輯上想得通但實際沒生效」，所以這次用 CDP 驅動實際瀏覽器逐一開啟對話框量測，而不是靠推理交付。

判準是 `.ant-modal-body` 的 `scrollHeight ≤ clientHeight`（＝不需捲動），以及同一列兩個 `.ant-form-item` 的 `offsetTop` 相同（＝真的併排）。視窗 1574×900：

| 對話框 | 寬 | body 捲動 | 版面 |
| --- | --- | --- | --- |
| 待辦事項 | 880 | 404 / 404 不需捲動 | 3 列雙欄 ＋ 描述跨列 |
| 提示詞清單 | 880 | 603 / 603 不需捲動 | 2 列雙欄 ＋ 描述、內容跨列 |
| 分類清單 | 680 | 270 / 270 不需捲動 | 1 列雙欄 ＋ 描述跨列 |
| 團隊清單 | 680 | 348 / 348 不需捲動 | 名稱｜代號、啟用狀態、描述跨列 |
| 會議紀錄 | 1511 | 756 / 756 不需捲動 | 標題｜日期 ＋ 描述、影音檔跨列 |
| 專案項目 | 1417 | 702 / 702 不需捲動 | 3 列雙欄 ＋ 附件跨列 |
| 使用者管理 | 880 | 408 / 408 不需捲動 | 3 列雙欄 ＋ 團隊跨列 ＋ 啟用｜管理員 |
| 角色管理 | 1417 | 702 / 702 不需捲動 | 名稱｜預設團隊 ＋ 權限矩陣跨列 |
| 變更密碼 | 680 | 88 / 88 不需捲動 | 單欄（刻意）|

縮到 700px 寬時團隊對話框的 4 個欄位各佔一列，確認 `@media` 退回單欄有效。

量測用的是另外編到 `.tmp-build-out` 並開在 5289 埠的執行個體，沒有動到使用者自己跑在 5189 的那個。全程只開對話框與按取消，日誌確認沒有任何轉錄或草稿工作被背景服務撿走，**沒有產生任何 API 費用**。

## 順帶補驗前三批

0.4.66～0.4.68 一直沒有實跑驗收，這次一併量測，結果都正確：

- 側邊欄收合鈕四個邊都點得到（`z-index: 102`，沒被側邊欄蓋住）
- 使用者選單展開後上到下都可點（`elementFromPoint` 全部落在選單內），沒被表格固定欄切掉
- 待辦工具列所有元件的 `getBoundingClientRect().top` 相同，確實排成一列

## 影響範圍

9 個表單對話框的版面；沒有任何行為或資料變更。測試 579 筆全綠（與基準相同，本批不增減）。
