# 專案常用名詞與與會人員名冊，餵給 AI 校正聽錯的人名（0.4.70 → 0.4.71）

語音轉錄常把人名與專有名詞聽成同音字。使用者要在專案項目裡維護名單，並在「AI 轉會議紀錄」時餵給模型，讓它把明顯是誤認的寫法改回正確名稱。

確認過的六個決定：

1. **兩份分開的清單**——「常用名詞」（術語、產品名）與「常用與會人員」（人名）。分開才能跟模型說「這些是人名，發言者標示要用這些」
2. 都存在**專案項目**上，在專案的新增／編輯對話框維護
3. **提示詞下拉的左邊**多一個選擇器，從專案名冊勾選這場會議實際到的人（每次生成可以不一樣）
4. **只做生成階段，不動語音轉錄**
5. 標籤輸入（**原本用 `SelectMode.Tags`，實跑後改成「輸入框 ＋ 新增鈕」**，見下方雷 3）
6. 名單**直接附加在提示詞前面，不走 `{{}}` 佔位符**

## 為什麼轉錄階段不做

影音檔在會議紀錄頁上傳時就排進轉錄佇列，而**那個時間點 `Meeting.ProjectId` 還是 null**——專案是等到按「AI 轉會議紀錄」時才寫進去的。所以轉錄工作跑的時候根本不知道這份錄音屬於哪個專案，拿不到名單。

要做就得在上傳表單多一個「所屬專案」下拉，等於動到「逐字稿按生成時才歸屬專案」這個既有模型。使用者選擇這次先跳過。

## 為什麼不走 `{{}}` 佔位符

現有 5 個內建範本與所有使用者自訂範本都沒有寫佔位符。只加變數的話這個功能會**完全不生效，而且不會報錯**——未知變數在本專案的規則是「原樣保留」。所以改成程式自己把名單區塊接在提示詞前面，**所有現有範本自動生效，一個都不用改**。

## ⚠️ 四個實查確認的雷

### 1. 專案的寫入路徑有三條

`ProjectService.UpdateAsync` **手抄 7 個欄位、完全不走 Mapper**，而 `AddAsync` 是 `Mapper.Map<Project>(...)`。只改 AutoMapping 的結果是「**新增存得進去、修改存不進去**」，而且不會報錯。

| 路徑 | 機制 | 做了什麼 |
|---|---|---|
| `ProjectService.AddAsync` | `Mapper.Map` | 加 `ForMember` |
| `ProjectService.UpdateAsync` | **手抄欄位** | **補兩行賦值** |
| `ProjectRepository.UpdateAsync` | `CurrentValues.SetValues` | 見下 |

### 2. Web API 的 PUT 會把新欄位靜默清成 null

`ProjectController` 用 `mapper.Map<Project>(dto)` 造一個**全新實體**交給 `CurrentValues.SetValues`，那會覆寫所有純量欄位。舊版客戶端一次不含名單的 PUT 就會把使用者建好的名詞表清光。

> `CreatedAt` 之所以沒事，是因為那個方法裡特地手動保留（`project.CreatedAt = existingProject.CreatedAt;`）。**同一個坑的前例就在同一段程式碼裡。**

修法是同一條規則：`GlossaryTerms ??= existing`、`Participants ??= existing`。傳 null 視為「沒有要改」。代價是 **API 清不掉名單**——但畫面走的是 `ProjectService.UpdateAsync` 那條，清得掉。

### 3. ⚠️ AntDesign 的 Tags 模式在中文輸入法下會殘留組字內容（最後放棄這個元件）

第一版用 `SelectMode.Tags` 做標籤輸入。使用者實際用注音打字時出現 `艾ㄑ－艾琪` 這種半成品——組字中途的注音被留在欄位裡，定案的字再接在後面。

用 CDP 的 `Input.imeSetComposition` 真實模擬組字量測過三種欄位：

| 元件 | 輸入「艾琪」的結果 |
| --- | --- |
| 普通 `<Input>`（change 事件回寫） | `艾琪` ✅ |
| `<Select EnableSearch>`（單選、從清單挑） | `艾琪` ✅ |
| **`<Select Mode="SelectMode.Tags">`** | **殘留** |

元件內部**有** IME 處理（`SelectContent.IsComposing`），但擋不住 Blazor Server 逐鍵回傳伺服器的時間差。

⚠️ **關鍵在於這個症狀在本機無頭瀏覽器上重現不出來**（延遲太低）。也就是說「調 `AutoClearSearchValue` 之類的參數看看」這條路**無法驗證**，只能丟給使用者試錯。與其交付一個自己沒把握的修補，不如換成結構上不會有問題的輸入方式。

**最後的做法：普通 `<Input>` ＋「新增」按鈕，標籤外觀自己畫**（`.project-view-tag-*`）。兩個實跑才發現的細節：

- **「新增」鈕不能依輸入框內容停用**：`<Input>` 是 change（失焦）才回寫，按鈕會一直停用到失焦為止——而點一顆停用的按鈕不會觸發 click，使用者得**點兩次**才加得進去。空值交給 handler 擋。
- **Enter 不綁任何動作**：中文輸入法用 Enter 確認候選字，綁了一定誤觸。

順帶一提，換掉 Tags 之後，原本為了它而加的兩個東西就不需要了：`TrySetDefaultValuesAsync` 不會為既有值生標籤所以要把清單餵回去當選項、以及用開啟次數當 `@key` 避免元件實例殘留。兩者都已移除（規則仍記在 [開發慣例與限制速查 §6.8](../architecture/開發慣例與限制速查.md)，多選情境還是會用到）。

### 4. ⚠️ 表單按 Enter 會存檔並關閉對話框

專案對話框的 `EditForm` 有 `@onkeydown="OnModalKeyDownAsync"`，而那個 handler 把 **Enter 當成「確定並關閉」**。使用者按 Enter 多半只是要確認輸入法的候選字，結果整個對話框就存檔關掉了。

這個雷在 Tags 版本更致命（打字後按 Enter 是建立標籤的唯一方式，等於每加一個就存檔關閉一次），換成按鈕之後仍然要處理——否則使用者確認候選字時對話框會無預警關掉。

修法：輸入區包一層 `<div @onkeydown:stopPropagation="true">`，**包在 `FormItem` 內部**（包在外面會破壞 `.form-modal-grid` 的兩欄格線）。

> 追這個雷花了不少時間，因為症狀很迷惑：自動化連打四個標籤只剩最後一個，而且「按取消」之後資料還是進了資料庫。一度以為是 `Clone()` 沒深複製或取消存了檔，最後才確認是**每一次 Enter 都送出了一次表單**。

> 這個雷**推理不出來**，也沒有任何單元測試抓得到——只有實際打字才會遇到。

## 資料層

| 位置 | 欄位 | 語意 |
|---|---|---|
| `Project.GlossaryTerms` | `string?` | 常用名詞 |
| `Project.Participants` | `string?` | 常用與會人員名冊 |
| `Meeting.DraftAttendees` | `string?` | 本次生成勾選的實到者快照 |

三欄都走 `TagStringHelper` 的換行包夾格式（`"\nA\nB\n"`）。migration 是三個純 `AddColumn`（nullable TEXT），SQLite 只做 `ALTER TABLE ADD COLUMN`，**不重建表**。

**只快照 `DraftAttendees`，不快照常用名詞**：與會者的語意本來就是「本次」必須定格；常用名詞是專案級長期資料，重跑時用最新版才符合直覺（名詞表更新後重跑就該生效）。有一筆測試守這件事。

`ProjectAdapterModel.Clone()` 原本是裸 `MemberwiseClone`（連 `Files` 都是淺的），加了 `List<string>` 之後必須深複製，否則在對話框裡加一個名詞、即使按取消也已經改到清單資料列上。

## 提示詞注入

新增 `Business/Helpers/NameGuidancePromptHelper.cs`（純函式）。

⚠️ **兩份清單都空時必須回傳 `string.Empty`，連換行都不能有**——`MeetingDraftJobRunnerTests` 對 UserPrompt 是全等比對，多一個字元就紅。這條同時是「沒設名單時行為與先前逐字元相同」的回歸保證。

### 兩處注入，map 階段不能漏

逐字稿超過 12000 字元時走 map-reduce，**每段各呼叫一次模型，用的是硬寫的 `chunkPrompt`（不是使用者範本）**。只注入 reduce 的話，長逐字稿的人名在摘要階段就被壓縮掉了——而長會議正是這個功能最有價值的場景。有一筆測試斷言**每一個 chunk 呼叫**都含名單。

### 與 SystemPrompt 的語意衝突

共用的 `SystemPrompt` 寫著「只根據提供的逐字稿內容作答，**不要臆測或補充逐字稿沒有提到的資訊**」，與「把聽錯的人名替換掉」直接衝突。

**沒有改那個常數**（改了會動到 map/reduce 每一次呼叫），而是把例外寫在注入區塊裡、跟授權它的資料放在一起：

```
【本次會議的專有名詞與人名對照】
逐字稿由語音辨識產生，專有名詞與人名常出現同音或近音的誤字。
下列名單屬於「已提供的資訊」，依此更正用字不屬於臆測。

常用名詞：…
與會人員：…

處理規則：
1. 逐字稿中若出現與上列名稱同音或音近、明顯是辨識錯誤的寫法，改為上列的正確寫法。
2. 發言者標示只能使用「與會人員」名單中的名字。
3. 判斷不出對應哪一個名稱時，保留逐字稿原本的寫法，不要猜。
4. 不得新增名單中沒有、逐字稿也沒提到的人名或名詞；名單中未實際發言的人，不要憑空替他生出發言或待辦。
```

「已提供的資訊」那句化解衝突，第 3、4 條把「不要臆測」的守備範圍收回來。只有一份清單時整段只印該份與對應規則，規則編號連續不跳號。

名單放**最前面**：範本形狀不可控，多數把 `{{transcript}}` 擺結尾，附加在後面會緊貼逐字稿、容易被讀成逐字稿的一部分。reduce 階段（且僅 reduce）在最後補一行極短提醒，對沖長提示詞的中段注意力衰減。

## 服務層與 UI

`RequestDraftAsync` 多一個 `IEnumerable<string>? attendees = null`，**插在 `promptTemplateId` 與 `cancellationToken` 之間**——既有 8 支測試全部只傳 3 個位置參數，這樣寫 0 改動照舊編譯。

**不檢查勾選的人是否在名冊內**：UI 只提供名冊選項，加檢查只會引入「使用者開著頁面時別人改了名冊、送出被整筆退回」這種假失敗。只做清洗與 50 人上限（界定提示詞大小，不是權限）。

UI：
- 專案表單兩個名單欄位都跨整列（輸入框加標籤列橫向長，塞進兩欄格線會很擠）
- AI 面板在提示詞**左邊**加一個多選，用 `SelectMode.Multiple` 不是 Tags——這裡只准從名冊挑
- 名冊是空的時候**停用但不隱藏**，Placeholder 寫「此專案尚未設定與會人員」，底下一行「可在『修改專案』中設定名冊」。欄位突然消失比 disabled 更難理解，切換專案時版面還會跳動
- 逐字稿欄位的 `flex` 基準從 320px 收到 260px，否則多一欄之後整列一定換行
- 換專案時清掉勾選；重載後對名冊做一次交集剪枝（名冊被改過時）
- `CanSubmitDraft` 不加與會者條件——這是選填功能

**兩個回歸測試都驗過有牙齒**：把 `UpdateAsync` 的兩行賦值拿掉 → `ProjectServiceTests` 紅 2 筆；把 repository 的 `??=` 拿掉 → API 那筆紅。

> 順帶修掉一個既有測試的潛在缺陷：`ProjectCrud_WithBearerToken_ShouldUseApiResultAndDto` 在 create payload 裡寫死 `Id = 1`，而 controller 會把 DTO 的 Id 直接 map 進實體再 Add。只要資料庫裡已經有第 1 筆就撞主鍵——本次新增第二支建立專案的測試才讓它浮出來。改成 `Id = 0` 讓 EF 自動配號。

### ⚠️ 尚未驗證：LLM 是不是真的會照做

「同一份逐字稿，設名冊前後各跑一次、比對發言者標示」**這一步會產生 API 費用，還沒做**。特別需要驗的是**超過 12000 字元、會走 map-reduce 的長逐字稿**——那條路徑是這次最主要的價值，也最可能只改一半沒被發現（雖然已有單元測試守住「每個 chunk 都含名單」）。

另外名單區塊在 map-reduce 下會重複 N+1 次，實際用量要看過一次才知道要不要把 map 階段的區塊精簡成只列名單、不列四條規則。
