# 歷史會議紀錄可從專案移除（0.4.71 → 0.4.72）

使用者回報：「不小心生成錯地方，不能刪除又不能重複新增」。

## 問題確認

查過之後，這個死角比描述的還嚴格——**全系統沒有任何地方可以解除逐字稿與專案的歸屬**：

- `RequestDraftAsync` 一旦寫進 `Meeting.ProjectId` 就沒有回頭路，而且它會擋掉「已歸屬其他專案」的逐字稿（`一份逐字稿只能屬於一個專案`）
- 唯一的出口是「會議紀錄」頁的 `DeleteAsync`，但那是**連影音檔、逐字稿、AI 對話一起刪**

所以選錯專案的代價是：整筆砍掉 → 重新上傳 → **重新轉錄（再付一次 API 費用）**。

## 做法：移除歸屬，不是刪除

新增 `MeetingService.DetachFromProjectAsync(meetingId, projectId, ct)`，清掉歸屬與 AI 草稿，**實體檔案一律保留**。那份逐字稿會回到「可選逐字稿」清單，直接指定到正確的專案重跑即可。

| 會清掉 | 會保留 |
| --- | --- |
| `ProjectId` | 影音檔 |
| `DraftContent` / `DraftStatus` / `DraftError` | 逐字稿檔 |
| `DraftPromptTemplateId` / `DraftPromptTemplateName` | 這場會議的 AI 問答對話（綁的是會議不是專案） |
| `DraftAttendees` / `DraftStartedAt` / `DraftCompletedAt` | 已抽出的待辦（待辦有自己的 `ProjectId`，是獨立的工作項目） |

### 三道防線

- **團隊權限**：比照同檔其他操作走 `TagStringHelper.IsTeamAccessible`
- **歸屬比對**：呼叫端要傳 `projectId`，與實際歸屬不符就拒絕——擋掉「畫面過期、其實已經被移到別的專案」
- ⚠️ **生成中不准移除**：`DraftStatus` 是 `Pending` 或 `Processing` 時拒絕。job runner 只吃 `meetingId`，它會在結束時把草稿寫回這筆紀錄，變成「已經移除了卻又冒出一份草稿」

## UI

「歷史會議紀錄」的操作欄多第 7 顆圖示（`link_off`，紅色），受 `角色_專案項目` ＋ `Delete` 權限管控（與「刪除專案」同一個鍵）。

會刪掉 AI 草稿且無法復原，所以跳二次確認。確認文案刻意講清楚**保留了什麼**——這是它與「會議紀錄」頁那個整筆刪除最大的差別：

> 將把「0902」從「客戶訪談與需求盤點」移除，已產生的會議紀錄內容會一併刪除且無法復原。影音檔與逐字稿會保留，之後可以把這份逐字稿指定到其他專案重新產生。確定要移除嗎？

**整筆刪除仍然只在「會議紀錄」頁**，這裡不提供——兩個動作的後果差太多（要不要重新付轉錄費用），放在一起只會誤點。

## 驗證

測試 **676 → 682 全綠**（+6）：

- 移除後歸屬與草稿欄位全部清空，但 `TranscriptionStatus` 與 `TranscriptRelativePath` **原封不動**
- 移除後可以把同一份逐字稿指定到另一個專案（**先驗證未移除前會被擋**，再驗移除後成功）——這就是這個功能存在的理由
- 歸屬到別的專案時拒絕
- `Pending` 與 `Processing` 兩種狀態都拒絕，且歸屬不變
- 找不到會議時回失敗

實跑（另編一份開在 5289 埠）：按鈕出現在操作欄第 7 位、確認框文案與紅色按鈕正確且疊在最上層、**按取消後三筆紀錄原封不動**。

> ⚠️ **沒有對真實資料實際執行過移除**——那會刪掉使用者已經生成的會議紀錄內容。實際效果由上述 6 筆單元測試涵蓋（跑在真實的 SQLite schema 上）。
