# AI 問答支援多段對話：歷史清單與「開新對話」（0.4.78 → 0.4.79）

使用者回報：「希望 AI 問答有歷史紀錄清單，不要像現在這樣打開就是對話紀錄，**沒地方開新的問答**。」

## 現況：一個對象只有一段對話，想換主題只能全部刪掉

路徑由「範圍＋對象 Id」直接算出來（`AiChat/project/3.jsonl`、`AiChat/meeting/12.jsonl`），
打開視窗就直接接續那一段。唯一的出口是「清空這段對話」——想換個主題問，
得先把先前問過的東西整段刪掉。

## 三個決定

| 決定 | 理由 |
|---|---|
| **大家共用**（維持現狀） | 同一個專案／會議底下所有人看同一份清單，可以接續別人開的對話；清單上標示是誰開的 |
| **自動取第一句提問當標題，之後可改名** | 開新對話時不問名字，不增加「只想快問一句」的摩擦 |
| **既有對話自動轉成第一段** | 使用者最在意的就是先前問過的東西不要不見 |

## 一、儲存：從「一個檔」變成「一個資料夾」

```
之前   AiChat/project/3.jsonl
之後   AiChat/project/3/<對話 Id>.jsonl
```

0.4.60 拍板的核心性質是**路徑可以直接算出來、資料庫連相對路徑都不必存**。
這一版維持同一個性質——**清單也直接從檔案系統列出來，沒有為此新增任何資料表**。

「一段對話一個檔」這個基本單位沒有變，只是一個對象底下可以有多個。
對話 Id 前段是 `yyyyMMddHHmmssfff`，**檔名本身就帶時間**，列清單不必開檔就能排序。

### 標題放哪裡：第一行，不另開 meta 檔

另開一個 `meta.json` 會讓「一段對話」變成兩個檔案要同步，與 0.4.60
「留一張表只是把一段對話拆成兩個地方維護」的理由自相矛盾。

所以標題、建立者、建立時間放在 jsonl 的**第一行**，是一則 `role: "meta"` 的紀錄。
既有的解析對無法辨識的行本來就會跳過，所以**舊檔在新程式下仍讀得出來**——
這也是自動轉檔能安全進行的基礎。

標題用「讀的時候算」而不是「第一次發問時寫回檔案」：後者會讓 append 變成
「讀出來、改一行、整檔重寫」，而整檔重寫是這個類別最危險的路徑。

### ⚠️ meta 行不是訊息——這個實際發生過

第一次實作時只在 `ReadHistoryAsync` 想過要排除 meta，卻沒有真的寫下去，
結果**使用者一打開還沒問任何問題的對話，就看到一則沒有內容、發話者是「AI 助理」的空氣訊息**
（role 不是 `user` 就會被當成回答）。

排除條件必須在**兩個地方**完全一致：`ReadHistoryAsync` 與「第 n 則 → 第幾行」的索引映射。
只排除一邊的話，兩邊的「第 n 則」會錯開一位，**編輯訊息時會改到隔壁那一則**。

### 舊資料自動轉檔

第一次列出某個對象的對話清單時，若 `3.jsonl` 存在而 `3/` 不存在，就把它搬進
`3/<新 Id>.jsonl`。⚠️ **先寫新檔、成功之後才刪舊檔**——中途失敗寧可留兩份，
也不要兩邊都沒有。資料夾已存在就什麼都不做（冪等），所以每次列清單都呼叫也不會重複搬。

轉檔進來的舊對話沒有 meta 行，標題就自動取第一句提問；改名時才補一行在最前面。

## 二、會留下孤兒檔的地方

| 位置 | 之前 | 現在 |
|---|---|---|
| `AiChatStore.TryDelete` | 刪**單一檔案** | 刪**整個對象資料夾**，並順手清掉還沒轉檔的舊單檔 |
| `AiChatStore.CountQuestions` | 遞迴列舉 `*.jsonl` | 不變，但 meta 行不可被算成提問 |
| `MeetingService`／`ProjectService` 的 `DeleteAsync` | 呼叫 `TryDelete` | **簽章不變**，行為跟著改 |

⚠️ `CountQuestions` 必須維持 `SearchOption.AllDirectories`：對話檔多了一層資料夾，
只掃根目錄的話儀表板的「AI 問答次數」會直接變成 0。這一條有專門的測試守著。

⚠️ **並行控制不用重做**：寫入鎖以**完整路徑**為鍵，路徑變細之後鎖的粒度自動跟著變細。
`TryDelete` 改成刪資料夾後，那些鎖仍然刻意不移除（移除會讓互斥直接失效，原註解說明了理由）。

## 三、畫面

`AiChatModal` 是三個入口共用的同一個元件（會議頁、專案頁工具列、專案頁歷史清單），
所以只改元件本身，三處同時生效。

- 左側一欄**對話清單**：標題、最後更新時間、開啟者；目前這段高亮
- 上方一顆「**開新對話**」
- 每段可**改名**（Enter 送出、Esc 取消，與全站一致）與**刪除**（二次確認——那是刪資料）
- 「清空這段對話」語意變成「刪掉目前這一段」，與「開新對話」搭配才完整
- 視窗 `Width` 820 → **1080**：左邊挖一欄清單後，對話區仍有約 776px

### 開啟時載哪一段

載入**最近更新的那一段**；完全沒有對話時直接呈現一段空白的新對話，
**不要先逼使用者按「開新對話」才能問問題**。

### ⚠️「開新對話」在目前這段還沒問過問題時是停用的

否則連按幾次就在共用的清單上堆出一排「新對話」，而且誰也分不出差別。
停用時 Tooltip 會說明原因（「目前已經是一段空白的新對話」），不然看起來像壞掉。

### ⚠️ 每個會改到內容的動作都要重新列清單

提問、編輯、重新產生原本都只重載「訊息」，沒有重載「清單」。漏掉的話，
**第一次發問後左側仍然寫著「新對話」**，而且因為則數還停在 0，上面那顆停用判斷會讓
「開新對話」一直按不下去。三處都補上 `RefreshConversationListAsync()`。

## 四、匯出檔名要帶對話標題

一個對象底下有多段對話之後，`AI問答_{對象}_{日期}.pdf` 同一天匯出兩段會撞成同名，
使用者只會看到瀏覽器自己補的 `(1)`、`(2)`。檔名與 PDF 表頭都補上對話標題。
