# 抽出待辦標示重複項目，並補上會議紀錄頁漏掉的費用確認（0.4.75 → 0.4.76）

使用者問：「同一個會議紀錄，抽出待辦按了兩次，是不是會重複新增到待辦事項介面？」

## 會。而且四層都沒有擋

查過整條路徑，從 UI 到資料庫沒有任何一層會阻止：

| 層 | 現況 |
| --- | --- |
| Modal 開啟 | `loadedMeetingId` 在 `CloseAsync` 清空，**刻意允許關掉再開重抽** |
| Modal 提示 | 只有一行文字「這場會議先前已加入 N 條待辦」，候選仍 `Selected = true` **全部預設打勾** |
| Parser | `TodoExtractionParser.Parse` 沒有 Distinct |
| `BeforeAddCheckAsync` | **只查專案存不存在** |
| `AddAsync` | 直接 `AddAsync` + `SaveChangesAsync`，零查詢 |
| 資料庫 | `Todo` 沒有任何唯一索引（唯一索引全在 RBAC 那幾張表） |

所以第二次按下去、直接按儲存，就會得到 `Title`／`MeetingId`／`ProjectId` 全部相同、
只有 `Id` 與時間戳不同的整批重複資料。而待辦清單的預設排序是 `DueDate` 升冪 + `Id` 降冪，
**重複的兩筆會緊鄰顯示**。

## 做法：標示並預設不勾，但不阻止

候選清單裡與「本會議先前已加入的待辦」標題相同的項目，會標上灰色的「已加入過」標籤，
並且**預設不勾選**。

⚠️ **去重只做在畫面上，服務層一行都不擋。** `TodoExtractionModal` 的儲存迴圈會先呼叫
`TodoService.BeforeAddCheckAsync`，那是很自然的「順手加個重複檢查」的位置——但那會讓
使用者刻意勾回重複項時被退回，變成「勾了卻存不進去」，看起來更像 bug。
開完後續會議再追蹤同一件事是合理的用法，**預設不勾是給預設值，不是禁止**。

同理，「全選」仍然會把重複項一起勾起來。按全選就是明確表示要全部加入。

### 比對範圍：同一場會議、標題相同

只拿**這場會議**已經抽出過的待辦比對，不跨會議。跨會議比對會把「每週回報進度」這種
本來就該重複的事項誤判掉。手動新增的待辦（`MeetingId` 為 null）也不參與比對。

正規化是 `Trim()` ＋ `OrdinalIgnoreCase`，與寫入端一致（候選存進去時是 `candidate.Title.Trim()`），
也與 `PromptTemplateService` 建立內建範本時比對既有名稱的做法相同。

### 服務層：把「數數量」換成「拿標題」

`CountExistingTodosAsync`（回 `int`）改成 `GetExistingTitlesAsync`（回 `IReadOnlySet<string>`）。
畫面同時需要「先前共幾則」與「哪幾則重複」，**一次查詢兩件事都有**，筆數由集合長度得出。
舊方法只有一個呼叫端，直接取代不留孤兒。

提示文字也跟著改寫——原本只講總數，第二次抽出時沒有幫助：

> 這場會議先前已加入 5 條待辦，其中 **3 條與這次抽出的重複**，已標示「已加入過」並預設不勾選。

## ⚠️ 順帶修掉 0.4.73 的缺陷：會議紀錄頁沒有費用確認

抽出待辦是**付費動作**（`TodoExtractionModal` 一開啟就呼叫 `ExtractAsync`，視窗顯示出來時
API 已經打出去了）。0.4.65 立下的規矩寫在
[開發慣例與限制速查](../architecture/開發慣例與限制速查.md)：任何會走到付費路徑的 UI 入口
都要有 `ConfirmAsync` 二次確認，標題要寫出「（會產生費用）」。

- **專案項目頁有**（`ProjectViewView.razor.cs`）
- **會議紀錄頁沒有**——這顆按鈕是
  [0.4.73](2026-09-15-不必先建專案也能產生會議紀錄.md) 加的，當時沒有比照既有慣例補確認

那一頁因此**同時缺費用確認與重複防護**，是最容易誤觸的路徑：誤按兩次＝扣兩次錢而且完全不問。
本次補上，**文案與專案頁逐字相同**——同一個動作在兩頁講不同的話會讓人以為行為不同。
不套 `Danger`：抽出來的只是候選，勾選並儲存後才真的建立待辦。

那支方法原本標了 `async` 卻沒有任何 `await`，補上確認後一併解決。

## 明確不做

- **不加資料庫唯一索引**：同一個標題在不同專案／不同會議本來就合法，硬約束會在正常使用時拋例外。
- **不處理「同一次抽出裡 AI 自己回傳兩筆同名」**：那是模型輸出品質的問題，
  而且確認視窗本來就看得到、可以自己取消勾選。真的發生再處理。

### 待實跑驗證

⚠️ 前四項都需要**真的抽一次待辦**，會產生 API 費用：

1. 同一份會議紀錄抽第二次 → 重複項顯示「已加入過」且未勾選，非重複項仍勾選
2. 按「全選」→ 重複項也會被勾起來（刻意保留的行為）
3. 刻意勾回一個重複項並儲存 → **真的存得進去**（證明沒有誤擋在服務層）
4. 第一次抽出（沒有任何既有待辦）→ 畫面與現況完全相同

第 5 項不花錢：**會議紀錄頁**按「抽出待辦」→ 出現費用確認框，按取消不會呼叫 AI。
