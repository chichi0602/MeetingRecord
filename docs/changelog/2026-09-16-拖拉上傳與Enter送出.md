# 全站拖拉上傳，Enter 送出補上中文輸入法防護（0.4.76 → 0.4.77）

使用者要求：「所有能上傳檔案的地方都可以以拖拉的方式上傳，且每個送出鍵都可以按 Enter 送出。」

## 一、拖拉上傳

全系統只有 **2 個上傳入口**（專案附件、會議影音檔），先前都是裸 `<InputFile>`、各寫各的，
連提示文字的排版都不一樣。這次抽出共用的 `Components/Commons/FileDropZone`，兩處都改用它。

### ⚠️ AntDesign 的 `<Upload Drag>` 不能用

實查 1.6.0 的 `ant-design-blazor.js`：它的 `uploadFile` 是 XHR + FormData **POST 到 `Action` URL**，
.NET 端只拿得到 responseText，拿不到 `IBrowserFile`／`Stream`。而本專案所有 API controller 都是
JWT-only（XHR 帶 Cookie 必定 401），文件也反覆宣示「不新增 HTTP 檔案輸入／輸出面」。
`Defer` + `StartUpload()` 只是延後送出，仍然要 `Action`。

### 作法：零 JS，靠瀏覽器原生行為

把檔案放到 `<input type="file">` 上時，**瀏覽器會自己設定 `input.files` 並觸發 `change`**，
Blazor 的 `OnChange` 照常拿到 `IBrowserFile`。所以只要讓那個 input 以 `opacity:0` 蓋滿整個拖放區即可，
**不需要任何 JS，服務層與兩個上傳 DTO 一行都沒動**。

`@ondragenter` / `@ondragleave` 只用來切換視覺狀態，**一律不 preventDefault**——
那會擋掉原生的 drop，檔案就進不來了。

### 四個實跑才發現的細節

1. ⚠️ **`::deep` 不可省**：`class` 傳給 `<InputFile>` 這個**元件**時，Blazor CSS 隔離的 scope 屬性
   不會跟到它渲染出來的 `<input>`，直接寫 `.file-drop-zone-input` 會被編成 `[b-xxxxx]` 而永遠選不到。
   第一次實跑量到 input 的 `opacity` 是 1、完全沒蓋住拖放區。
2. ⚠️ **dragleave 要用計數器配對**：滑鼠移到子元素上時，瀏覽器會先對子元素發 `dragenter`、
   再對外層發 `dragleave`，只用一個 bool 會讓外框在拖曳過程中不停閃爍。
3. ⚠️ **重選同一個檔案不會觸發 `change`**：input 在 change 之後不會清空 value。
   「拖錯 → 移除 → 再拖同一個」在教會使用者拖拉之後是很自然的操作，所以每次選完就換一個 `@key`
   強制重建 input。
4. ⚠️ **單檔模式拖入多個檔案，Chrome 會整個靜默拒絕**（不觸發 change、不報錯），
   使用者只會覺得「拖進去沒反應」。所以影音檔那個區塊的標題寫明「一次一個」。

### `accept` 對拖入不可信

瀏覽器只在「檔案挑選對話框」套用 `accept`，各家對 drop 是否過濾並不一致。
所以 **C# 那層（`MeetingMediaPolicy.IsAllowedFileName`）是唯一可信的守門員**——它本來就在，
實跑確認拖入 `.exe` 會被擋下並顯示允許的格式清單。

### 順帶擋掉「拖到頁面空白處」

有了明顯的拖放區之後，沒瞄準而放到 Modal 空白處會變成常見誤操作，而瀏覽器的預設行為是
**直接導航去開那個檔案**——Blazor 的 circuit 跟著死，填到一半的表單整份不見。

`MainLayout` 最外層加 `@ondragover:preventDefault` / `@ondrop:preventDefault`（**只設 preventDefault、
不接 handler**，接了的話 `dragover` 每幾十毫秒就往返伺服器一次）。
⚠️ 連帶地 `FileDropZone` 必須 `stopPropagation`，否則 drop 會冒泡上去被外層取消掉——
加完之後有再實跑一次確認拖放仍然正常。

## 二、Enter 送出

### 現況本來就自相矛盾

- `開發慣例與限制速查.md` §6.8（0.4.71）寫著「⚠️ **Enter 不要綁任何動作**」，兩份 PRD 也寫「Enter 不送出表單」。
- 但**實際上有 6 個編輯對話框的 Enter 就是存檔並關閉**，而且 7 個 keydown handler
  **沒有一個做輸入法防護**——只比對 `args.Key == "Enter"`。
- `docs/guides/建立一個新 CRUD 操作網頁說明.md` 還寫著「Enter 觸發儲存」，沒跟著 0.4.71 更新。

也就是說使用者今天在標題欄用注音打字、按 Enter 選字，對話框就會直接存檔關閉。

### 🔑 輸入法防護不需要寫 JS

`KeyboardEventArgs.IsComposing` 在 .NET 9 之後存在，但**全專案零使用**。
`KeyboardEventArgs` 沒有 `KeyCode`，所以「檢查 229」做不到，`IsComposing` 是唯一途徑。

新增 `Components/Commons/FormKeyboardHelper`，`IsSubmit` 同時要求：`Key == "Enter"`、
**非組字中**、且沒有任何修飾鍵。八個編輯對話框、AI 問答、變更密碼、兩個操作型 Modal
與抽出待辦確認全部改走它，不再各寫各的。

**Shift+Enter 在多行欄位換行**不需要寫程式碼——`IsSubmit` 回 false，瀏覽器的原生行為就會換行。

### 補上 Enter 的地方

- 提示詞範本、會議紀錄兩個編輯 Modal（先前因多行而豁免，Shift+Enter 能換行後不再需要豁免）
- **7 個搜尋框**（先前 Enter 完全無效，必須點旁邊的按鈕）
- 變更密碼、AI 轉會議紀錄、歸屬到專案、抽出待辦確認

非 `EditForm` 的 Modal 沒有 `<form>` 可掛 keydown，而 AntDesign `Modal` 沒有開放掛載點
（`Keyboard` 參數只管 Esc，21 處都是這個，容易被誤讀），所以是把內容包一層原生 `<div @onkeydown>`。

### 刻意不綁的地方

| 對象 | 理由 |
| --- | --- |
| **19 個 `ConfirmAsync`** | 那道手續正是 0.4.65 為付費與破壞性動作加的。綁 Enter 等於送出表單的 Enter 還沒鬆手、確認框就被按掉了 |
| **編修逐字稿（Rows 18）、編修會議紀錄（Rows 20）** | 那是在改一份多段落的長文件，不是輸入一句話送出 |
| 登入頁 | 靜態 SSR 原生表單，Enter 早就能送出，而且原生表單天生 IME 安全 |

### `Task.Delay(200)` 留著

那不是可以順手清掉的權宜寫法：AntDesign `Input` 預設 change／blur 才回寫繫結值，
Enter 送出時焦點還在欄位裡，不等就會拿到舊值。註解已補上這個理由。

### 🔴 一項本機驗不了

§6.8 明寫「這個症狀在本機無頭瀏覽器上重現不出來（延遲太低）」。上面那筆「組字中按 Enter」
證明了判斷邏輯正確，但 **Blazor Server 逐鍵回傳的時間差只能由使用者實際用注音打字試**。
建議的驗收步驟：

1. 「分類名稱」用注音打中文 → 按 Enter 選字 → **對話框不可以關閉**
2. 再按一次 Enter（此時已無組字）→ 才存檔關閉
3. 搜尋框打中文按 Enter 選字 → **不可以觸發搜尋**；再按 Enter → 才搜尋
