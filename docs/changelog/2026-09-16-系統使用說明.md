# 新增系統使用說明：一份原始檔，兩個出口（0.4.77 → 0.4.78）

使用者要求「添加系統使用說明，內容自己決定，放哪也請給建議」，並指定
**系統內頁面與 `docs/` 文件兩者都要**，深度以完整動線為主。

## 現況：對終端使用者完全沒有任何說明

盤點確認全系統零份。`MainLayout` 只有一個「關於」對話框（七筆純技術資訊：版本、
執行環境、.NET 版本、運作時間），沒有任何操作說明。

`docs/` 九個分類的讀者全是開發者／維運者／接手者——`系統功能總覽.md` 開宗明義寫著
「讀者是接手者（含 AI），**不是終端使用者**」。

順帶一提，這件事早被記在對標清單 `08-MeetingInk-對標項目決策清單.md` 的 W25
（「使用手冊／FAQ／API 文件」，狀態「待決」，觸發時機「對外開放前」），這一版把它落地。

## ⚠️「兩者都要」的真正風險是分岔，不是工作量

兩份各寫各的，下次改功能一定只記得改一邊。所以**不寫兩份**：

> **只有一份 Markdown 原始檔放在 `docs/guides/系統使用說明.md`，
> 系統那頁在建置時把它嵌進組件再渲染。** 一份內容、兩個出口，結構上不可能不同步。

### 為什麼是 `EmbeddedResource` 而不是複製檔案

`Menu.json` 是從 `ContentRootPath/Datas/` 讀的，但 `docs/` **不存在於發佈輸出**，那個模式用不了。

⚠️ 也**不能**用 `Content` + `CopyToOutputDirectory`：開發時 `ContentRootPath` 是**專案目錄**
而不是 bin 輸出目錄，那樣會變成「發佈後看得到、開發時讀不到」。
`EmbeddedResource` 兩種情境行為一致，所以選它。

⚠️ csproj 的 `LogicalName` 與 `HelpView.ResourceName` **必須一致**。不一致時**建置照樣成功**，
畫面只會永遠停在「載入中…」——這種靜默失效正是測試存在的理由（見下）。

### 兩個渲染細節

- ⚠️ **BOM 一定要去掉**：`docs/*.md` 一律含 BOM（CI 強制），不處理的話字串第一個字元是
  `﻿`，Markdig 會把第一行的 `# 標題` 當成普通段落，整頁標題層級就跑掉。
  本 repo 有前例——`AiChatStore` 讀 jsonl 踩過同一個坑。
- ⚠️ **全域 `.markdown-content` 是為「對話框內的預覽」設計的**：`max-height: 60vh`、
  `overflow: auto`、`font-size: 0.85rem`。整頁手冊直接套上去會被壓進一個 60vh 的內嵌捲動框、
  字還特別小。頁面本來就能捲，不需要第二層捲軸，所以在頁面的 scoped CSS 裡把那三項解除。

### 畫面上不顯示文件表頭

`docs/` 每份文件都有一段表頭（文件版本／文件狀態／最後核對日期），這一份還多一段
「這個檔案同時是說明頁的來源」的維護提醒。**那些是寫給維護者的，對使用者只是雜訊**——
所以保留在檔案裡（文件庫的慣例不破），渲染時切掉第一條水平線之前的內容。
找不到分隔線時原樣回傳：寧可多顯示一段表頭，也不要因為格式改了就整頁空白。

## 內容

以**一條完整路徑**貫穿（錄音 → 轉錄 → 會議紀錄 → 匯出 → 抽待辦），不做欄位字典——
那種東西功能一改就過期。九個章節，其中三塊是刻意寫進去的：

- **哪些動作會花錢**：五條付費路徑逐條列出，並說明「確認框不能用 Enter 只能滑鼠點」是刻意的；
  也寫明**抽出待辦的視窗一打開就已經呼叫 AI**，關掉再開會再算一次錢
- **出錯了怎麼辦**：轉錄失敗不必重新上傳、生成錯專案用「從專案移除」不必重付轉錄費
- **鍵盤慣例**：Enter 送出、Shift+Enter 換行，以及三個刻意的例外

費用文案遵守 `開發慣例與限制速查` 的既有原則：**講成本動因，不講「幾次 API 呼叫」**——
講錯數字比不講更糟。

## 註冊（七處）

依速查表第 5 節的宣告式流程：權限鍵常數、`Menu.json`（**id 用 12**，
`section: "核心功能"`）、`MenuPermissionMap`、`RolePermissionService` 權限矩陣、
`MenuIconTests.AllowedIcons`（⚠️ 加 `help_outline`，**這是會擋住的測試**）、
`_Imports.razor`、頁面本體。

⚠️ **權限**：使用說明照理人人該看得到，但本專案沒有「免權限側邊欄項目」的機制——
`SidebarMenuService` 在 id 不在對應表時會 fallback 用顯示名稱當權限鍵，非管理員一律看不到。
所以照既有慣例註冊權限鍵（單元素群組，比照儀表板），**新建角色時要記得把它勾起來**。
自己發明一條免權限路徑會破壞「UI 與 API 共用單一 RBAC 權威」這個不變量。
