# 修復：拖拉上傳會把剛選好的檔案弄丟（0.4.80 → 0.4.81）

使用者回報「現在上傳影片檔會失敗」。這是 **0.4.77（全站拖拉上傳）的回歸**。

## 症狀

```
14:38:31  選檔  20260210病患篩選進度討論.mp4  FileSize=251,772,273
14:38:43  建立會議成功 MeetingId=6
14:38:43  Failed to upload meeting media. MeetingId=6
          JSException: Cannot read properties of null (reading '_blazorFilesById')
```

日誌證實這是回歸：成功上傳共 5 次，最後一次是 **2026-09-09**；
`_blazorFilesById` 錯誤只出現在 09-17，而 `FileDropZone` 是 09-16 引進的。

## 根本原因（實測，非推論）

`FileDropZone.OnFileChangedAsync` 在**每次選完檔案後立刻**換 `@key`：

```csharp
await OnChange.InvokeAsync(args);   // 呼叫端把 args.File 存起來
resetToken = Guid.NewGuid();        // ← Blazor 立刻銷毀並重建 <input type="file">
```

呼叫端拿到的 `IBrowserFile` 是綁在**那個已被銷毀的元素**上的。稍後
`OpenReadStream` 去 JS 端查它就是 null。

用 CDP 在 input 上做記號，直接觀察到元素被換掉：

```
選檔前： { marked: 'BEFORE', inDom: true }
選檔後： { currentHasMark: '(無記號)', oldStillInDom: false, sameNode: false }
```

⚠️ **兩個上傳入口都中了**：會議影音檔與專案附件都是「先存進待上傳清單、稍後才讀」。

## 修法

換 key 的時機從「剛選完檔案」移到「**呼叫端用完那個檔案之後**」。
`FileDropZone` 新增 `public void Reset()`，呼叫端在下列時機呼叫：

- 會議影音檔：移除待上傳檔案、上傳成功之後、`ResetUploadState`
- 專案附件：移除某個待上傳項目、儲存成功之後、取消對話框

原本那個 `@key` 是為了解決「拖錯 → 移除 → 再拖同一個檔案不會觸發 change」
（input 在 change 之後不會清空 value；點擊挑選的路徑 Blazor 自己會在 click 時清，
但**拖放不會觸發 click**）。移到 `Reset()` 之後這個行為仍然保留。

## 順帶修掉：上傳失敗後重試會卡死

```
14:39:00  Creating meeting → UNIQUE constraint failed: Meeting.Id
14:39:18  Creating meeting → 同樣的錯誤
```

主資料存檔成功、只有上傳失敗時，程式刻意讓使用者留在 Modal 重試。
但 `isNewRecordMode` 仍是 `true`，而 `CurrentRecord.Id` 已經被填上——
再按一次「確定」就是拿同一個 Id 再 INSERT 一次。整個視窗卡死，只能取消重來。

修法：`AddAsync` 成功之後立刻 `isNewRecordMode = false`，重試走 Update。
