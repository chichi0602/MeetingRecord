# AI 用量補上 gpt-5.6-sol 單價，金額改以當時匯率換算台幣（0.4.87 → 0.4.88）

使用者要求：

> appsetting多加一個sol計費方式讓他可以顯示token
> token 依模型、明細、作業(像是ai轉錄洛是會議記錄生成等)、使用者等
> 現在系統是美金 請幫我轉成台幣 用當時匯率換算

---

## 一、先講調查結果：四個維度早就做好了

「依模型／作業／使用者／明細」在 0.4.80 的用量帳本就有了——`/ai-usage` 上有卡片、每日折線、
依功能別圓餅、依模型長條、依使用者長條與分頁明細表，token（輸入／輸出分開）與音訊時長也都在記錄。

**真正壞掉的只有一件事：金額全是「—」。**

| 模型 | 作業 | 次數 | 輸入 token | 輸出 token | 音訊秒數 | 無金額 |
|---|---|---|---|---|---|---|
| `gpt-4o-transcribe` | 語音轉錄 | 4 | — | — | 3096.88 | 0 |
| `gpt-5.6-sol` | 會議紀錄生成／AI 問答／待辦擷取 | 14 | 224,387 | 20,094 | — | **14（全部）** |

`appsettings.json` 的 `LlmSettings:Pricing` 只有 `gpt-4o-mini` 與 `gpt-4o-transcribe`，
而**實際在用的 deployment 是 `gpt-5.6-sol`**（user-secrets 覆寫了 `Providers:AzureOpenAI:Model`，
但沒有覆寫 `Pricing`）。單價查不到 → `AiUsagePricing` 依設計回 `null` 而不是 0 → 畫面顯示「—」。

所以「sol 計費方式」就是字面意思：**幫 `gpt-5.6-sol` 補一組單價**。
單價取自 OpenAI 定價頁：輸入 **$4.00**／輸出 **$20.00** 每百萬 token。

**同時把同家族其他 deployment 的單價一併備好**（`gpt-5.6-terra` $2／$12、`gpt-5.6-luna` $0.2／$1.2、
`gpt-4o-mini-transcribe` $0.003/分）。這看起來像多做的，但成本是零，
而漏掉的代價正是這一版要修的症狀：**換一次 deployment 忘了補單價，那段期間的金額就整批是空的**。

> ⚠️ `gpt-5.6-sol` 的 $4／$20 是 promo 價（至少到 2026/11/21）。JSON 不能寫註解，所以記在
> `docs/operations/日誌與設定檔說明.md`。

## 二、台幣換算

### 匯率來源

`https://open.er-api.com/v6/latest/USD`，免金鑰、每日更新一次。
另外兩個候選實測不可用：**台銀牌告匯率 CSV 被 Cloudflare 擋**（回的是挑戰頁不是 CSV）、
**Frankfurter／ECB 沒有 TWD**。

### ⭐ 最重要的一條：抓匯率永遠不在使用者等待的路徑上

`AiUsageRecorder.RecordAsync` 是在**使用者按下「產生會議紀錄」之後、串流結束之前**被呼叫的。

「過期才抓」的 lazy cache（`await GetRateAsync()`）是最自然也最錯的寫法：它平常瞬間回傳、
通過測試也通過 review，然後某天匯率服務不回應（TCP 沒有 RST、只是不回），
那一次記帳就卡在 HTTP 逾時上——而卡住的位置正好是使用者等在畫面前面的地方。

**防線：`ExchangeRateCache` 不提供任何 async 方法，只有一個同步 property。**
抓取一律由 `ExchangeRateBackgroundService` 在背景做。

### 失敗退路

1. 本行程上一次成功的值
2. **資料庫裡最後一筆有匯率的帳**（冷啟動種子）
3. `FallbackRate`（設為 **32.0**）
4. `null` → 該筆不換算，畫面顯示「—」且不計入總額

第 2 點不需要另開一張表或寫檔：`AiUsageLog.ExchangeRate` 本身就是一份天然的匯率歷史，
最後一列就是最後已知匯率。實跑驗過，重啟時日誌會先出現
`Seeded exchange rate from the usage ledger`，接著才是當次抓取的結果。

⚠️ 撈法只能 `Where(ExchangeRate != null).OrderByDescending(OccurredAt)`——
**絕不可** `OrderByDescending(ExchangeRate)`，SQLite 的 decimal 是 TEXT，那是字典序。

保底值刻意用**整數 32.0** 而不是當下的 31.863639：它只在「連一次都沒抓成功、資料庫也沒有任何歷史匯率」
時才會用到，是個一定會過時的近似值，用整數讓「這是估的」一眼看得出來。

> 原本設計是預設留空（專案一貫「算不出來回 null，絕不回一個看起來合理的錯數字」）。
> 使用者要求「若無法換算匯率 就用固定大致上的匯率就好」，所以改成給值。取捨很明確：
> **離線期間的紀錄會帶一個 1～3% 誤差的匯率，換取畫面上不會出現一片「—」。**

## 三、資料庫：只存匯率，不存換算後金額

`AiUsageLog` 加兩欄：`ExchangeRate`（decimal?）與 `ConvertedCurrency`（string?）。
Migration `AddAiUsageExchangeRate`，兩個 nullable TEXT 欄位。

**刻意不存 `EstimatedCostTwd`**：兩份真相必然漂移（四捨五入位數、日後修正單價時只改一邊），
而且完全換不到效能——SQLite 的 decimal 是 TEXT，`EstimatedCost` 本來就不能在 SQL 端 `SUM`。
台幣 = 同一列的 `EstimatedCost × ExchangeRate`，兩個值都在這一列上，不需要外部查表。

匯率與單價一樣是**寫入當下的快照**。匯率天天在動，讀取時才換算的話今天匯率一變，
去年的帳就整批跟著變——而這頁最主要的用途正是「本月 vs 上月」。

⚠️ `AiUsageRecorder` 多一道守門：只有 `rate.BaseCurrency` 與 `LlmSettings.Currency` 相同時才寫入。
有人把 `Currency` 改成 EUR 卻沒改匯率來源時，得到的是空白（畫面顯示「—」），
而不是錯了 8% 卻看起來很正常的金額。

## 四、⭐ 讀取端最陰險的坑：月比月不可以用台幣算

台幣的月比月 = **用量變化 × 匯率變化**。匯率動 10% 會在「本月估算金額」卡片上
顯示成「花費增加 10%」，而畫面上沒有任何線索指出那是匯率造成的。

**比較的必須是實際花掉的錢（定價幣別），顯示才用台幣。** 已用測試釘住：
本月與上月同期的美金金額相同、匯率差 10% 時，變化率必須是 0%。

其餘讀取端改動都收斂在一個 `CostView` 裡（要不要換算、怎麼加總、怎麼格式化），
免得五個顯示點（卡片、折線、三張分佈圖、明細表）各自判斷而漏掉其中一個。

⚠️ `ToChartCents` **沒改**：換成台幣之後金額依然很小（一次問答約 NT$0.0014），
用整數台幣當幾何量會全部捨成 0。**但折線圖標題一定要寫出單位**——
`LineChart` 沒有 `ChartSlice` 那種 `Display` 覆寫，資料點提示是把 int 原樣印出來，
同一個「12」從 USD 0.12 變成 NT$0.12 數量級差三十幾倍，畫面上卻沒有任何提示。

⚠️ `ExchangeRateSettings.Enabled = false` 時**整頁原樣退回美金**。
「有匯率顯示台幣、沒有顯示美金」會讓總額變成兩種幣別相加——那不是降級，是錯的數字。

## 五、設定

獨立的頂層 `ExchangeRateSettings` 區段，**不塞進 `LlmSettings`**：
後者是「供應商連線與 deployment 定價」，已經 250 行且被三支 provider 讀，
塞一個 HTTP 端點進去會讓「換 LLM 廠商」與「換匯率來源」互相牽動。

```json
"ExchangeRateSettings": {
  "Enabled": true,
  "SourceUrl": "https://open.er-api.com/v6/latest/USD",
  "TargetCurrency": "TWD",
  "RefreshIntervalHours": 24,
  "FallbackRate": 32.0
}
```

⚠️ **`RefreshIntervalHours` 用 `int` 不用 `TimeSpan`**：設定檔寫 `"24:00:00"` 綁定會失敗
（TimeSpan 的小時欄只收 0–23，一天要寫成 `"1.00:00:00"`），而且錯誤訊息完全看不出是這個原因。

啟動驗證擋：`SourceUrl` 非絕對 http(s) URL、`TargetCurrency` 不是三碼英文字母
（`"TWD "` 這種尾隨空白不擋的話會完全正常啟動然後永遠查不到匯率）、
`FallbackRate <= 0`（0 匯率讓所有金額變 NT$0，在圖表上只是看起來「這個月比較省」）、
`RefreshIntervalHours` 不在 1..168。

> `Enabled == false` 時早退跳過其餘檢查。⚠️ 這與 `LlmSettings.Validate` 的結論**正好相反**
> （那邊特地把單價檢查放最前面以避開 `yield break`），不要照抄那邊的註解。
> 差別在於這裡的 `Enabled` 是整段功能的總開關。

## 六、既有 18 筆：用一次性腳本回填，不放進 migration

`scripts/Backfill-AiUsageCost.mjs`。做兩件事：

1. 補 14 筆 `gpt-5.6-sol` 的金額與單價快照——**這部分是誠實的**：單價一直是那個數字，只是當時沒設定
2. 補全部 18 筆的匯率

⚠️ **回填用的是執行當天的匯率，不是那些呼叫發生當天的匯率。** 這與本功能「當時匯率」的賣點
相牴觸，也與 `AiUsageLog` 類別註解「這張表沒有回填」的不變量相牴觸——
**是使用者明確要求下的一次性例外，不是新的慣例。自動路徑（Recorder、migration）一律不回填。**
腳本在動手前會把這件事再講一次，並先備份資料庫。

**不放進 migration** 的理由：那會把今天的匯率永久寫死在版控裡，而且每個新環境都跑一次。

⚠️ **備份必須連 `-wal`／`-shm` 一起複製。** 這個資料庫是 WAL 模式，App 開著的時候最近的交易
還躺在 `-wal` 裡沒有併回主檔——只複製 `.db` 會得到一份「看起來正常但少了最近幾筆」的備份，
而那正是真的需要還原時最糟的情況。腳本先嘗試 `PRAGMA wal_checkpoint(TRUNCATE)`，
別的行程握著讀鎖而失敗時就連 sidecar 一起複製。已實測確認備份內容就是回填前的狀態。

> **為什麼是 `.mjs` 而不是 `.ps1`**：`scripts/` 其他檔案都是 PowerShell，但這支不行——
> 本機只有 Windows PowerShell 5.1，它跑在 .NET Framework 上，載不了專案用的 .NET 10 版
> `Microsoft.Data.Sqlite`（實測「無法載入一個或多個要求的類型」），而機器上沒有 pwsh 7。
> Node 24 內建 `node:sqlite`，不需要安裝任何東西。

## 八、測試（939 → 1001）

新檔 `ExchangeRateResponseParserTests`（21）、`AiUsageExchangeTests` ＋ `ExchangeRateSettingsTests`（23）、
`AiUsageRecorderTests`（3，這支之前完全沒有），並擴充 `AiUsageMetricsTests` 與 `AiUsageAnalysisServiceTests`。

最有價值的四條：

- ⭐ `Summary_MonthOverMonth_ShouldUseSourceCurrencyNotConverted` —— 擋住第四節那個坑
- ⭐ `RecordAsync_WithoutExchangeRate_ShouldStillWriteTheRow` —— 全功能第一不變量：
  抓不到匯率不可以讓記帳失敗，否則等於用「看不到花多少錢」換「看不到用了多少」
- ⭐ `Parse_NonPositiveRate_ShouldReturnNull` —— 回 0 的話整頁金額變 NT$0 而看起來完全正常
- `Observe`／`Parse` 的 `base_code` 交叉驗證 —— 換了來源幣別卻沒改設定時，金額會安靜地錯好幾 %

解析器的成功樣本是**實際打回來的原文**，不是想像的格式（同 `AzureOpenAiUsageParsingTests`）。

兩處突變驗過，各自讓測試變紅：月比月改用換算後金額、把缺席的匯率當成 1。
