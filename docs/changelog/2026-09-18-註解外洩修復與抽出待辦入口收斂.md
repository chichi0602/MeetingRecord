> 且抽出代辦不可在會議記錄這邊顯示 抽出代辦只能在有所屬專案的歷史會議記錄使用

## 一、一段開發者註解被渲染到會議紀錄頁底部

畫面最下方出現這段文字：

```
`夾在兩個屬性中間時， Razor 會把整段註解當成**屬性名稱**傳給元件，執行期才炸
（InvalidOperationException: does not have a property matching the name '
```

### 根本原因（而且很諷刺）

這是 0.4.82 加在 `MarkdownEditorModal.razor` 檔頭的註解。它的內容正是在警告
「不要把 Razor 註解寫進元件的屬性列表裡」——為了說明，內文把註解的開始／結束符號**原樣打了出來**。

**Razor 的註解不能巢狀。** 它從開始符號往後找到**第一個**結束符號就收工。
於是內文裡那個被引用的結束符號提前關掉了註解，後面的說明文字變成一般 markup，
`MarkdownEditorModal` 被 `MeetingViewView` 渲染，那段文字就跟著出現在頁面底部。

包在反引號裡沒有用——**Razor 不看 Markdown，它只認符號序列**。

### 修法

註解改成純文字敘述，不再把符號本身打出來。

### ⚠️ 平衡計數抓不到這個缺陷

「開幾個、關幾個」這種檢查對它無效：出事的那段正好是**開 2 關 2**。

新增 `MeetingRecord.Tests/RazorMarkupTests.cs`，改照 Razor 自己的規則掃描——
從每個開始符號找到第一個結束符號，檢查那段內文裡有沒有再出現開始符號。
以突變測試確認：把缺陷放回去會紅（並指出檔名與行號），還原後轉綠。

這個坑值得做成測試而不是只寫進文件，因為它**編譯得過**、
單元測試與型別系統都攔不住，而失敗的表現是「把內部註解顯示給使用者看」。

## 二、「抽出待辦」從會議紀錄頁移除

待辦在資料表層級就必須有專案（`Todo.ProjectId` 必填）。
而會議紀錄頁有一半的會議是未歸屬的，那顆鈕按下去只能跳一則訊息叫使用者先去歸屬——
**那不是功能，是一顆騙人的按鈕**。

0.4.73 加這顆鈕時的理由是「未歸屬時刻意不停用，改由 handler 跳訊息」，
但比較好的答案是這一頁根本不該有這個入口：歸屬過的會議本來就會出現在專案項目頁的清單裡。

移除 `MeetingViewView` 的按鈕、`TodoExtractionModal` 掛載、`OnExtractTodosAsync`
與四個相關欄位。**`TodoExtractionModal` 元件本身與專案項目頁的入口完全不動。**
