# AI 用量分析：功能下拉連動卡片與圖表，曲線改成「本月累計 vs 上月同期」（0.4.90 → 0.4.91）

使用者回報：

> ai用量分析頁面 右上方選擇功能的地方 如果下拉選擇不同功能 上方card 一併更新成指定功能
> 不要固定顯示全部功能的數值 不然下拉就沒有意義了
> 另外 那邊的曲線圖 好像沒什麼意義 是不是要改顯示的兩個折線 還是乾脆直接移除呢

---

## 一、功能下拉原本只接到明細表

`AiUsageView.ReloadAsync` 呼叫的是 `GetSummaryAsync(trendDays)`——**根本沒有功能參數**。
所以卡片、曲線、圓餅、兩張長條圖永遠是全部功能，只有最下面的明細表會跟著變。

改成 `GetSummaryAsync(AiUsageFeature? feature)`，篩選在 SQL 端做
（`Feature` 是 int 列舉欄位，與 TEXT 型態的 decimal 不同，在資料庫端比對是安全的）。
卡片、模型與使用者分佈、三個提示筆數全部吃篩過的資料，自然跟著功能走。

**選了特定功能時功能別圓餅不顯示**：只剩一片 100%，沒有任何資訊。
`.ai-usage-grid` 是 `auto-fit`，剩下模型長條一張時會自動撐滿整列，不必改 CSS。

⚠️ **統計起始日刻意不套篩選。** 它講的是「帳本從哪天開始記」，不是「這個功能第一次被用是哪天」——
套了的話選「待辦擷取」會顯示比較晚的日期，使用者會以為在那之前的紀錄遺失了。

### 不適用的卡片顯示「—」

選「語音轉錄」時 token 卡片原本會是 0 / 0，選「AI 問答」時轉錄時長卡片是 0 分鐘。
數字沒錯，但 0 會讓人以為「這個月沒用」，其實是「這個功能根本不用這個單位計費」。
沿用專案「算不出來不顯示 0」的慣例，改顯示「—」並在副標說明原因。

## 二、曲線改成「本月累計 vs 上月同期累計」

舊曲線是「文字生成 vs 語音轉錄」的每日金額：資料少時整條幾乎都是 0，
而且那個二分法跟功能下拉、功能別圓餅講的是同一件事。

新曲線兩條都是錢、單位相同，X 軸是本月 1 日到今天，每一點是到當天為止的累計——
**最後一點就是第一張卡片上的金額**，曲線是那張卡的趨勢版，看得出這個月是不是花得比上個月快。
會跟著功能下拉走。

新純函式 `AiUsageMetrics.BuildMonthToDateCumulative`，三個容易寫錯的地方：

- ⭐ **累加原始金額，最後才換成「分」。** 每筆先換成分再加會把小額呼叫全部吃掉：
  一次 AI 問答約 NT$0.0014，換成分是 0.14、四捨五入成 0——一千次加起來仍然是 0。
- **上個月比較短時延續月底值。** 3/31 對上 2 月，第 29～31 天維持 2/28 的累計，而不是掉回 0。
  與 `BuildMonthToDateRanges` 把上月迄日夾到最後一天的規則一致。
- **只畫到今天。** 今天之後沒有資料，延續會看起來像停止花錢、補零會看起來像掉到 0，兩種都錯。

> 卡片上的「與上月同期相比」百分比仍用**美金**算（0.4.88 釘死的規則），曲線用台幣顯示，
> 所以兩條線最後一點的比例與卡片百分比可能差匯率那 1～2%，這是刻意的。

`LineChart` 本身**沒動**——它與儀表板共用（固定兩條線、整數值），只改這一頁餵給它的資料與標籤。
舊的 `BuildDailyCost` 與 `AiUsageMetrics.BuildDailySeries`（含其 2 筆測試）因此變成孤兒，一併移除。

## 三、期間下拉搬到明細表旁邊

曲線改成本月範圍之後，「最近 7／30／90 天」**只剩明細表在用**。
留在右上角的話，就會變成使用者這次抱怨的同一件事——又一個選了上面沒反應的下拉。
搬到明細表標題列右側，換期間時也只重載明細表，不再重算整頁摘要。

## 四、測試（1001 → 1014）

- `AiUsageAnalysisServiceTests` 新增 8 筆：卡片、分佈、提示筆數只算選中的功能；
  ⭐ 統計起始日不受篩選影響；不適用的卡片是「—」而全部功能時兩張都有數字；
  曲線最後一點等於卡片金額
- `AiUsageMetricsTests` 新增 7 筆：點數等於今天幾號、最後一點等於月總額、單調不減、
  ⭐ 3/31 對 2 月延續月底值、⭐ 小額先累加再換分、範圍外的列被忽略、空資料全是 0

三處突變驗過，各自讓測試變紅：拿掉 SQL 端的功能篩選、統計起始日也套篩選、每筆先換成分再累加。
