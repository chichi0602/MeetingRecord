# 移除會議與提示詞範本上的舊團隊標籤（0.4.102 → 0.4.103）

使用者整理的重構大綱：

> 角色管功能、團隊管資料範圍、分類管資料標籤，並移除角色繼承團隊的設計。

0.4.102 已經逐項符合這份大綱，只剩 0.4.35 以前的舊設計還留著：會議與提示詞範本上各有一個「團隊標籤」文字欄位，查詢條件裡也還有依團隊標籤篩選的選項。這些早就沒有畫面入口，也不參與權限，卻讓「團隊」有兩種意思：

- 真正的團隊：`Team`、`UserTeam`、`ProjectTeam`。
- 舊的文字標籤。

使用者決定現在清掉。

---

## 刪除的內容

- **資料庫欄位**：`Meeting.Teams`、`PromptTemplate.Teams`，由 migration `RemoveLegacyTeamTags` 刪除。欄位裡的舊標籤資料會一併消失，使用者已同意。
- **轉接模型**：`MeetingAdapterModel` 與 `PromptTemplateAdapterModel` 的 `Teams`、`TeamsText`，以及 `Clone()` 裡複製它們的那行。
- **對應設定**：會議與範本的 `Teams` 對應。
- **查詢條件**：`DataRequest.TeamFilters`，以及 `MeetingService`、`PromptTemplateService` 裡依團隊標籤篩選的那段。
- **API 傳輸物件**：`MeetingCreateUpdateDto.Teams`、`PromptTemplateCreateUpdateDto.Teams`（`teams` 欄位）。舊的呼叫端多送這個欄位會被忽略，不會報錯。
- **舊的團隊可見性工具**：`TagStringHelper.BuildTeamAccessPredicate`、`TagStringHelper.IsTeamAccessible`。它們實作的是舊的「沒有團隊標籤＝公開」規則，已經沒有任何程式呼叫；留著容易被誤用，也和「沒有公開專案」互相矛盾。
  - `ToStored`、`ToList`、`BuildContainsAnyPredicate` 保留，分類篩選還在用。

真正的團隊機制完全沒動：`Team`、`UserTeam`、`ProjectTeam`、`CategoryTeam`、`EffectiveTeamResolver`、`RecordAccessScope.Teams`。
