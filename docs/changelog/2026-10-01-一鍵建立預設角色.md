# 角色管理一鍵建立四個預設角色（0.4.107 → 0.4.108）

使用者回報：

> 因為之後上線系統會是空白的，角色管理幫我多新增一個按鈕，可以一鍵產出現在系統的這四個角色。

正式上線時資料庫是空的，角色得一個一個建、一格一格勾權限。這次比照提示詞清單的「建立內建範本」，在角色管理頁加一顆「建立預設角色」按鈕。

---

## 四個預設角色

內容照 2026/10/01 實際使用中的四個角色：

| 角色 | 權限 |
|------|------|
| 管理者 | 全部頁面、全部動作 |
| 一般使用者 | 使用說明、登出；專案項目、待辦事項、會議紀錄可以檢視、新增、修改、匯出（不能刪除） |
| 檢視者 | 使用說明、登出；專案項目、待辦事項、會議紀錄只能檢視 |
| 主管 | 使用說明、登出；專案項目、待辦事項、會議紀錄全部動作；分類清單、團隊清單全部動作 |

- 各區的群組鍵（專案管理功能、會議管理功能、資料定義管理功能）會一併給；沒給的話，那一區的選單不會出現。
- 「管理者」角色只是權限全勾的一般角色。真正「不受任何限制」的，是使用者管理裡的「管理者」勾選。

## 修改

- 新增 `MeetingRecord.Business/Helpers/RolePresets.cs`：四個角色的名稱與權限。權限鍵一律用 `MagicObjectHelper` 常數與 `PermissionKey.For` 組出來，不手打字串。
- 新增 `RoleViewService.AddPresetsAsync`：
  - 已有同名角色就略過、不覆蓋（那個角色可能已經調過權限），所以可以重複按。
  - 每個新角色會寫入：
    - `TabViewJson`，角色編輯畫面靠它回填勾選。
    - 權限關聯（`SyncRolePermissionsAsync`）。
    - 一筆 `Role.Create` 稽核紀錄。
  - 回傳「已新增 N 個預設角色，略過 M 個（已有同名角色）」。
- 角色管理頁：
  - 工具列「新增」旁多一顆「建立預設角色」。
  - 按下先跳確認視窗，執行中顯示讀取狀態，完成後通知並重新載入清單。
  - 和「新增」按鈕一樣，有角色管理頁權限的人就看得到。
- **「一般使用者」只有一份定義**：
  - 空系統第一次啟動時，`DefaultRoleSeeder` 就會先建好「一般使用者」。所以按下按鈕時，「一般使用者」會被略過。
  - 為了讓兩邊權限相同，`RolePermissionService.GetGeneralUserPermissionNames()` 改成取自 `RolePresets`。
  - 新建的一般使用者因此從「業務頁全部動作」變成「不能刪除」，和目前實際使用的設定一致。
  - 既有角色不會被改：`DefaultRoleSeeder` 只在角色建立或改名的當下設定權限。

## 測試

`dotnet test` 全數通過（1117 筆）。新增 `RolePresetsTests` 3 筆：

- 空資料庫按一次，建出四個角色，抽查權限是否正確，以及 `TabViewJson` 是否正確。
- 已有同名角色時會略過、不覆蓋原本的權限；重複按不會重複建立。
- 一般使用者的初始權限與預設定義相同。

`DefaultRoleSeederTests` 依新的初始權限調整斷言。

## 請實測

1. 在現有系統按一次，應顯示「已新增 0 個預設角色，略過 4 個」，現有角色不變。
2. 刪掉或改名某個角色後再按，只會補回缺的那一個。
3. 打開建出來的角色編輯畫面，勾選內容要和上表一致。
