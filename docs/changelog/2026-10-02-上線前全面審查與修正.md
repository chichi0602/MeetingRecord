# 上線前全面審查：會議、待辦、AI 問答、帳號與權限（0.4.114 → 0.4.115）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.4.115
- 首次實作版本：0.4.115
- 最後核對日期：2026/10/02

使用者問「現在可以上線給別人用了嗎」，並說明：

- 試用範圍幾乎等於正式上線；
- 會上傳真實的會議錄音、合約；
- 要對會議、待辦、AI 問答、使用者與角色都做 AI 全面審查。

標準因此從「功能正確」提高到「資料可見範圍、權限、資料遺失」也要以正式上線來看。專案項目已在 0.4.114 審查完，這次用同一套做法審其餘功能。

---

## 一、做法

三個 AI 代理人分別以唯讀方式審查，並各自寫小程式實際重現問題：

| 範圍 | 怎麼驗證 |
|---|---|
| 會議紀錄（含轉錄與生成的背景工作） | 用記憶體資料庫跑真實的服務層 |
| 待辦事項與 AI 問答 | 實驗證明 Windows 上「有人在讀檔時追加寫入會失敗」 |
| 帳號與權限（登入、使用者、角色、每個 API 的權限標記） | 實際啟動網站，黑箱測登入、鎖定與匿名呼叫 |

每一個發現都由我讀程式碼查證。確認是錯誤的才修，並補自動測試；需要判斷的列在第四節。

## 二、已修正

### 資料外洩與權限

| 嚴重度 | 問題 | 修正 |
|---|---|---|
| 高 | **刪掉的會議，AI 問答內容可以被別人讀回來**：API 刪會議沒清對話檔，API 新增又照抄用戶端給的編號，對話檔只用編號定位。另一個人送出同一個編號，就能讀到原本那場會議的問答內容。 | API 刪除改走和畫面同一套流程，一併清掉影音、逐字稿與對話；新增一律由資料庫配號。 |
| 高 | **換發權杖不查資料庫**：被停用、鎖定或刪除的人，在 7 天內都能一直換到新的存取權杖；管理者身分也照舊權杖重簽。 | 換發前重查帳號，停用、鎖定、刪除或待改密碼都不換發，身分以資料庫為準。 |
| 中 | **停用的帳號仍能呼叫 API**：API 權限檢查不看帳號狀態，手上的權杖到期前都有效。 | 停用的帳號一律沒有權限，管理者也一樣。 |
| 中 | **API 錯誤回應帶出完整例外堆疊**：正式環境也會回傳資料庫結構、檔案路徑；對看不到的編號送新增，還能從錯誤訊息知道那筆存在。原本的「正式環境隱藏細節」規則只寫在全域過濾器，但每個控制器都自己接住例外，那條規則根本跑不到。 | 控制器的錯誤回應套同一條規則：沒設定時只有開發環境回傳細節。 |
| 中 | **強制改密碼只在網頁生效**：管理者發的初始密碼可以直接拿來用 API，永遠不必改。 | API 登入也擋，提示先到網頁改密碼。 |
| 中 | **待辦會帶出看不到的會議標題**：待辦換專案時來源會議照留；會議改歸屬到別的團隊的專案後，留在原專案的待辦也照樣顯示會議標題。 | 待辦換專案時清掉來源會議；讀取時看不到的來源會議不顯示標題（畫面與 API 都是）。 |
| 中 | 進度面板的「取消」不檢查權限：只有檢視權限的同團隊成員，可以中止別人正在跑的轉錄（已送出的段落照樣計費）。 | 取消要有會議紀錄的修改權限，沒有就不顯示取消鈕。 |
| 低 | 待辦「完成」勾選框沒權限時只是停用，處理器仍掛著。 | 處理器裡再檢查一次權限。 |

### 資料遺失與錯亂

| 嚴重度 | 問題 | 修正 |
|---|---|---|
| 中 | **AI 問答付費的答案會寫不進去**：讀對話檔時不讓別人寫，A 的答案要寫回時，B 剛好在開對話清單，A 就顯示「回答失敗」，錢照付。 | 讀取改成共用模式；寫入遇到短暫鎖定時稍等重試。 |
| 中 | **被刪的對話會復活**：A 刪了對話，B 的視窗還停在那段，B 一提問整段又出現；提問中專案被刪，目錄還會被重建成沒人清的孤兒。 | 提問前與寫入時都確認對話還在，不在就提示「請開新對話再提問」，不會替已刪除的對話付費。 |
| 中 | **被拒絕的修改日後仍被寫進資料庫**（和 0.4.114 專案那次同一類）：會議與待辦的寫入失敗後，改過的資料還留在同一條連線的追蹤裡，下一次任何存檔都會把它寫進去。會議上傳失敗時，還會留下「待處理」卻從沒排進佇列的狀態。 | 每個失敗路徑都清掉追蹤。 |
| 中 | **轉錄進行中可以替換影音檔**：舊檔那趟轉錄不會停，跑完把舊錄音的逐字稿和「已完成」寫到已經換成新檔的會議上。 | 轉錄或會議紀錄生成進行中，一律不能換檔。 |
| 中 | **轉錄進行中可以刪除會議**：工作繼續跑、繼續計費，最後寫出的逐字稿檔沒有資料列可掛，永遠留在磁碟上。 | 進行中不能刪；轉錄存不進資料庫時，刪掉剛寫出的逐字稿。上傳存不進資料庫時，也刪掉剛落地的影音檔。 |
| 中 | **先選一個有效檔、再選一個不合法的檔，上傳必定失敗**：畫面仍顯示待上傳第一個檔，實際上已經讀不到它。 | 選到不合法的檔時，一併清掉先前挑的檔。 |
| 中 | 會議、待辦的表單沒有防連點：連按確定或連按 Enter 會建出兩筆。 | 加上「存檔中」保護，確定鈕顯示讀取中。 |
| 中 | 會議刪除不看結果，失敗（包括被上面的規則擋下）也顯示「刪除成功」。 | 依結果顯示成功或失敗原因。 |
| 中 | **管理者編輯使用者會把被鎖的帳號解鎖**，也會清空兩步驟驗證設定（畫面上沒有這些欄位，整筆蓋回時被清掉）。 | 編輯時一律帶回原值；**重設密碼才解鎖**，忘記密碼被鎖的人拿到新密碼可以立刻登入。 |
| 低 | AI 抽待辦部分失敗時，成功的那幾條仍勾著，再按一次「加入」會重複建立。 | 成功的從清單拿掉。 |
| 低 | 提問中關掉 AI 問答視窗再開另一個對象，前一題的答案會出現在新視窗；前一題失敗時，還可能讓整條連線斷掉。 | 處理中不能關視窗；收回提問前先檢查清單不是空的。 |
| 低 | 待辦負責人尾巴帶全形空白或 Tab 時，面板算 5 筆、點下去只出現 4 筆。 | 清單和面板改用同一個比對規則。 |
| 低 | 有人替你加了協作團隊後，待辦編輯視窗的「所屬專案」會是空白。 | 開表單前重新載入可選專案；下拉改用逐一列出選項的寫法。 |
| 低 | 待辦 API 收任意的狀態與優先度字串，新增時照抄用戶端給的編號。 | 狀態、優先度必須在選項內；一律由資料庫配號。 |

### 測試本身的問題

整站整合測試沒有把 AI 對話、影音與逐字稿目錄指到暫存區，沿用設定檔裡的 `C:\temp\MeetingRecord\…`。0.4.114 起 API 刪專案會清對話，測試等於會用測試資料庫的編號，去刪本機開發環境同編號的 AI 對話。已改成全部指到測試暫存目錄。

## 三、檢查後確認沒問題的部分

- **每個 API 都要登入**，也都有動作權限；匿名一律 401。登入失敗訊息不洩漏帳號存不存在，鎖定實測有效。
- **資料可見範圍**：API 每次都從資料庫查使用者與團隊，不信任權杖裡的管理者標記。
- **檔案與路徑**：影音與逐字稿沒有任何下載端點。實體檔名一律是亂數，沒有路徑跳脫風險。
- **角色刪除**：會重新指派受影響使用者的主要角色，最後一個角色不能刪。
- **Google 登入**：自動建立的帳號預設停用；回呼網址防止被導到外站。
- **正式環境**：Swagger 關閉、跨網域預設全擋；日誌沒有寫入密碼或權杖。

## 四、未修，請判斷

| 項目 | 說明 |
|---|---|
| 儀表板「各專案會議份數」 | 看不到某專案的人，也會看到那個專案的名稱與會議數。之前決定儀表板是全公司彙總的例外，但現在是真實資料，專案名稱本身可能就是機密。 |
| `/UploadFiles` 不用登入就能存取 | 目前沒有任何程式寫檔到這個目錄，但萬一下載目錄被設成影音或逐字稿目錄的上層，檔案就直接外流。建議拿掉。 |
| 停用的團隊仍有效 | 0.4.114 已列，仍待定義「停用」的意義。 |
| 登入 Cookie 沒有明確設定只走 HTTPS | 正式環境如果走 HTTPS，會自動加上安全旗標。若內網走 HTTP，強制設定反而登不進去，要先確認部署方式。 |
| AI 用量頁 | 勾了這個權限的非管理者看得到全公司的用量。請確認這是刻意的。 |
| 會議紀錄編修沒有並行保護 | 兩人同時編修，後存的人會蓋掉前一人。 |
| 匯出 PDF 會去抓會議紀錄裡的網路圖片 | 若有人在會議紀錄放內網網址的圖片，伺服器匯出時就會連過去。 |
| 進度面板「關閉通知」是全域的 | 一個人按關閉，所有人的通知都不見。工作剛好結束時按到取消，會留下標記，下次重新轉錄會被無聲取消。兩者機率都低。 |
| 換新影音檔後，舊的會議紀錄仍顯示「已完成」 | 沒有自動清掉，因為那可能是人工改過的內容。要不要提示或清掉，請你決定。 |
| 範例的天氣 API 沒有權限 | 開專案時留下的範例，不含任何資料，可以刪。 |
| 使用者管理、角色管理選單 | 若某角色被勾到這兩個權限，非管理者會看到選單，點進去被擋。只是畫面不一致，不是越權。 |

## 五、測試

`dotnet test` 全數通過，共 1162 筆，新增 24 筆：

- **會議**：轉錄或生成進行中不能刪除、不能換檔。
- **待辦**
  - 換專案時清掉來源會議。
  - 看不到的來源會議不顯示標題，管理者看得到。
  - 負責人帶全形空白或 Tab 時，面板和清單筆數一致。
- **AI 問答**
  - 對已刪除的對話寫入會被擋，而且不會重建目錄。
  - 別人開著檔案時，仍寫得進去。
- **帳號**
  - 停用的帳號沒有權限，管理者也一樣。
  - 換發權杖會擋停用、鎖定、待改密碼與已刪除的帳號。
  - 編輯使用者不會解鎖，重設密碼才會。
- **API**
  - 停用後換發權杖回 401；待改密碼的帳號 API 登入回 401。
  - 待辦的狀態與優先度白名單；待辦與會議新增不照抄編號。
  - API 刪除會議會被進行中的轉錄擋下，成功時清掉 AI 對話。
  - 錯誤細節只在開發環境，或明確開啟時才回傳。

畫面上的修正（防連點、選檔、關視窗、進度面板取消鈕）無法用自動測試涵蓋，已加進「上架前人工測試清單」。
