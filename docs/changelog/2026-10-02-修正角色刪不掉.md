# 修正角色刪不掉（0.4.109 → 0.4.110）

使用者回報：

> 角色管理那邊刪除角色的部分一直刪不掉，請修正。不管是刪除速度，還是什麼 bug 導致無法刪除。

## 原因

執行紀錄顯示每次刪除都失敗：`SQLite Error 19: 'FOREIGN KEY constraint failed'`。

1. 使用者的「主要角色」欄位（`MyUser.RoleViewId`）設有 Restrict 外鍵：只要有人以這個角色當主要角色，資料庫就不讓刪。例如 support 的主要角色就是「管理者」。
2. 畫面沒有看刪除結果。刪除失敗時照樣跳出「刪除成功」，清單重新載入後角色還在，看起來就像一直刪不掉。

和刪除速度無關。

## 修正

**刪除時自動替受影響的人換主要角色。** 在同一個交易裡依序處理：

1. 以這個角色當主要角色的人，優先改用他身上還有的其他角色。
2. 沒有其他角色的人改用「一般使用者」，並補上角色關聯。
3. 連「一般使用者」都沒有（例如要刪的就是它）時，改用剩下的第一個角色。
4. 刪除角色。額外角色的關聯與權限關聯由資料庫連帶刪除。

不直接把主要角色清空，是因為沒有角色的帳號登入時會被登出。如果刪的是管理者帳號正在用的角色，連管理者都會進不了系統。

**唯一擋下的情況**：要刪的是系統中最後一個角色。這時會顯示「系統至少要保留一個角色，否則所有帳號都會無法登入」。

**畫面**

- 確認視窗會先說明有幾位使用者掛著這個角色，以及刪除後他們會改用什麼角色。
- 刪除後依實際結果顯示「刪除成功」或錯誤原因。

稽核紀錄 `Role.Delete` 多記一項：換掉主要角色的人數。

## 測試

`dotnet test` 全數通過（1127 筆）。

- 新增 `RoleViewDeleteTests` 5 筆：
  - 刪除主要角色時，改用使用者的其他角色。
  - 只有這個角色的使用者，改用一般使用者。
  - 刪除一般使用者本身時，改用剩下的角色。
  - 不能刪除最後一個角色。
  - 人數統計正確。
- `AuditEventsTests.RoleDelete_ShouldWriteRoleDeleteAudit` 原本刪的是資料庫裡唯一的角色，會被新的保護擋下，所以補放一個角色。這項測試要驗證的稽核內容不變。

## 請實測

1. 刪除一個有人在用的角色，例如「主管」：確認視窗會說明人數，刪除後角色消失，那些人在使用者管理裡改成其他角色。
2. 刪除沒有人用的角色：直接成功。
3. 刪到只剩一個角色時再刪：會被擋下並顯示原因。
