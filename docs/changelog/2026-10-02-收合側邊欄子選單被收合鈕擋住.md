# 收合側邊欄時「系統管理」子選單點不到（0.4.110 → 0.4.111）

使用者回報：

> 左側選單收合時，「系統管理」無法點一下展出右側選單後直接點擊，一定要把左側選單整個展開，才能點開下拉，再點使用者管理等功能。不過「資料定義」又可以在左側清單收起來時，點小圖示顯示出清單後直接點擊。

## 原因

- 收合鈕（側邊欄右緣那顆黑色「>」圓鈕）在桌機版固定在**視窗高度的正中間**，圖層又高於側邊欄。
- 視窗正中間剛好落在「系統管理」那一列。
- 收合態的子選單是靠滑鼠停在選單項目上才顯示的。滑鼠從「系統管理」圖示往右移向子選單時，會先碰到收合鈕。
  - 收合鈕不屬於選單項目，一碰到它，選單項目就不再算是「滑鼠停留中」，子選單立刻關掉，所以永遠點不到。
  - 收合鈕的圖層也比子選單高，蓋住了子選單的左緣。
- 「資料定義」在收合鈕下方，滑鼠路徑不會經過它，所以正常。
- 換個視窗高度，被擋住的也可能變成別的選單項目。

## 修正

在全站樣式 `app.css` 加入一條規則：滑鼠停在收合態的任一選單項目上（或用鍵盤聚焦）時，收合鈕暫時淡出、不接收滑鼠事件，滑鼠事件會落回底下的選單項目。滑鼠離開選單後，收合鈕恢復。

- 收合鈕原本的位置與設計不變。
- 這條規則用到 `:has()`，Edge 與 Chrome 都支援。
- 這條規則放在全站樣式，而不是 `MainLayout` 自己的元件樣式。元件隔離會在選擇器加上 `MainLayout` 的專屬標記，`:has()` 就比對不到側邊選單元件裡的元素。

順帶更正 `開發慣例與限制速查.md` §6.4：圖層數值寫反了。實際是側邊欄 101、收合鈕 102。

## 測試

- 網站建置 0 錯誤，`dotnet test` 全數通過（1127 筆）。這次是純樣式修正，沒有新增測試。
- 請實測：
  1. 收合側邊欄後，滑鼠移到「系統管理」圖示，再往右移到子選單，可以直接點使用者管理、角色管理、AI 用量分析、系統健康度。
  2. 改變視窗高度，讓圓鈕落在其他選單項目上，再試一次。
  3. 滑鼠離開選單後，圓鈕恢復顯示，可以正常收合與展開。
