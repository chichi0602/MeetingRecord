## 目的

MeetingRecord 在 0.4.24 前後從 NET10-Blazor-Starter 樣板分出，之後 Starter 的文件慣例持續演進（封存規則、表頭更新規則、維護規範同步表、介面與對話窗設計規範、畫面與欄位字典），本專案的 `docs/` 沒有跟上：

- 多數表頭停在 0.4.23～0.4.103；45 篇 changelog 沒有表頭。
- 索引、根目錄 `readme.md` 與部分內文仍自稱「NET10-Blazor-Starter／腳手架」。
- 內文有過時描述：`AiChatMessage` 資料表（0.4.60 已移除）、使用者選單的「設定 API 密碼」（0.4.113 已移除）、SqlServer、`檔案:行號` 參照。
- 儀表板、AI 用量分析、使用說明、AI 問答沒有 PRD。

本次以 Starter 的 `docs/` 為參考整理本專案文件，**只借用慣例與版型，不搬入 Starter 獨有的功能文件**（備份、排程、寄信、例外紀錄等，本系統都沒有）。程式碼沒有變更，只有版本號 +1。

## 二、設計決定

- **封存而不刪除**：樣板時期的規劃與規格仍是「為什麼長這樣」的脈絡，刪掉會讓舊 changelog 的連結斷掉；封存並註記現況差異即可避免誤用。
- **表頭一次升到 0.4.118**：這次是全面整理，所有活文件表頭統一改為 0.4.118／2026/10/08、文件版本 +1。之後回到維護規範第 6.2 節「逐句核對過才更新」的規則。changelog 各篇、superpowers 規格與 `planning/07` 研究報告屬當時紀錄，表頭不動。
- **UI 規範依本系統程式碼重寫**：Starter 的 `theme.css`、`OverlayStyles`、`ConfirmDialog` 本系統都沒有，只借用「常駐介面 vs 浮層」兩份分工的版型。

## 四、整理時發現、未在本次處理的程式問題

以下問題程式本身未修改，待另開工作評估；前五項已在[畫面與欄位字典](../guides/畫面與欄位字典.md)或[介面視覺設計規範](../architecture/介面視覺設計規範.md)以 ⚠️ 註記：

- 多個清單服務在 `Take = 0` 時沒有截斷結果（`MeetingService`、`MyUserService`、`RoleViewService`、`CategoryService`、`TeamService`），只有 `TodoService`、`PromptTemplateService` 已修正。
- `/myusers`、`/roleviews` 以 `IsAdmin` 守門，但選單與角色矩陣用權限鍵；「管理者」預設角色不是 `IsAdmin`，會看到選單卻進不去。
- 兩條改密碼路徑規則不一致（對話框要求至少 6 碼、`/ChangePassword` 沒有）；新密碼設成 `123456` 會一直被導回改密碼頁。
- 會議與提示詞表單只列出啟用中的分類，編輯時可能把已停用的分類悄悄拿掉。
- 部分元件仍有色票以外的硬編色碼；使用者選單項目預設是錯誤紅色。
- `AiChatModal` 下載 PDF 時沒有在處理器內重新檢查 `CanExport`。
- 樣板遺留頁面 `/counter`、`/weather` 與 `WeatherForecastController` 仍可存取。
