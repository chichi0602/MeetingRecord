# 會議上傳看得到進度、連線中斷不再蓋掉錯誤（0.4.115 → 0.4.116）

使用者在 IIS Production 環境回報：

> 上傳會議記錄應該要有上傳進度，不然剛剛上傳，然後只有右下角顯示新增成功，但畫面上完全空白，也沒有列表看到我上傳的東西，旁邊寫轉錄中並記錄進度趴數等。

---

## 一、現象

| | 內容 |
|---|---|
| 操作 | 新增會議，填好資料，選好 127 MB 的 mp4（`20260904病患篩選統計圖表討論.mp4`），按確定，再確認費用 |
| 預期 | 上傳時看得到進度百分比；上傳完成後清單上出現這筆會議，旁邊顯示「轉錄中」和百分比 |
| 實際 | 右下角只跳出「新增成功」；畫面空白，清單上沒有這筆會議，也沒有任何進度 |

執行紀錄（節錄）：

```
10:58:56.21 Meeting created successfully. MeetingId=2
10:58:56.21 Uploading meeting media. MeetingId=2, FileSize=127891429
10:59:07.18 CircuitHost: Unhandled exception in circuit … System.TimeoutException: Did not receive any data in the allotted time.
10:59:07.20 MeetingViewView: Failed to upload meeting media. MeetingId=1
            System.ObjectDisposedException: Cannot access a disposed context instance … BackendDBContext
            at MeetingService.SaveMediaAsync … line 530
```

## 二、原因

1. **對話框被關掉，進度列跟著不見。**
   - 會議對話框的確定鈕按下後，AntDesign 會自己把對話框關掉。
   - 程式只有在驗證失敗、取消、上傳失敗時會把它開回來，正常上傳的路上沒有。
   - 上傳進度列放在對話框裡，所以使用者看不到。
   - 清單要等上傳完成才會重新整理，所以上傳期間清單上沒有這筆新會議。
2. **上傳到第 11 秒，Blazor 連線被終止，整頁空白。**
   - `TimeoutException` 是 Blazor 透過 SignalR 讀取瀏覽器檔案的串流判定逾時。
   - 逾時會直接終止整條連線，資料庫連線（DbContext）也一併被釋放。
   - 預設逾時是 1 分鐘，這次第 11 秒就斷了，時間對不上，**根本原因還沒確認**，見第四節。
3. **錯誤處理本身又丟出例外，蓋掉了原本的錯誤。**
   - `MeetingService.SaveMediaAsync` 的 catch 第一行要清 DbContext 的追蹤狀態，但 DbContext 已經被釋放，又丟出 `ObjectDisposedException`。
   - 結果服務層沒有記下真正的錯誤，「刪除剛落地的新檔」的清理也被跳過。
   - 這次半截的新檔，`MeetingFileStore` 自己已經刪掉了，沒有留下孤兒檔。
4. **錯誤紀錄記錯會議編號。**
   - 上傳的是 2 號會議，失敗紀錄卻寫 `MeetingId=1`。
   - 畫面的失敗紀錄讀的是「目前正在編輯的那筆」。因為對話框已經關掉，上傳期間使用者可以去點別筆會議的編輯，目前那筆就被換掉了。
   - 這是推測，紀錄裡沒有直接證據，但這是程式裡唯一會讓編號變掉的路徑。

## 三、修正

- **上傳期間對話框不關**（`MeetingViewView.razor.cs`）：
  - 主資料存好、開始上傳之前，先把對話框留住，並先重新整理清單，讓新會議先出現在背後。
  - 上傳期間，對話框裡的進度列跑 0～100%。確定鈕轉為 loading，取消鈕無效。
  - 上傳完成後，對話框才關閉。清單上的轉錄狀態與百分比沿用既有的即時進度。
  - 對話框有遮罩，上傳期間點不到別筆會議，所以第二節第 4 點的情況也不會再發生。
- **錯誤紀錄記對會議**：上傳開始時先記下會議編號，送出上傳與記錄失敗都用這個編號，不再讀「目前正在編輯的那筆」。
- **連線中斷時保住原本的錯誤**（`MeetingService.SaveMediaAsync`）：清追蹤狀態時，如果 DbContext 已經釋放就略過。錯誤紀錄與孤兒檔清理照常執行。
  - 其他方法的 catch 也有同樣寫法，但這次沒有改，因為只有上傳會跑久到在中途碰上連線中斷。

## 四、尚未解決：IIS 上的連線逾時

這次只讓使用者「看得到發生什麼事」，**沒有**解決大檔上傳會斷線的問題。下一步：

1. 確認那台 IIS 有沒有安裝並啟用「WebSocket Protocol」。沒有的話，Blazor 會退回長輪詢，大檔很容易中斷。已補進 [正式部署與安全檢查清單](../operations/正式部署與安全檢查清單.md)。
2. 部署 0.4.116 後，用同一個檔案再測一次：
   - 在瀏覽器開發者工具確認 `_blazor` 走的是 WebSocket。
   - 如果還是中斷，錯誤紀錄裡應該只剩真正的 `TimeoutException`。
3. 如果啟用 WebSocket 後還是中斷，就把影音上傳改成瀏覽器直接 POST 到後端 API，不經過 Blazor 連線。這個改動比較大，到時候另外提方案。
