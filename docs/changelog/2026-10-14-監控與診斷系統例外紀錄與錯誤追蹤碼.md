- 首次實作版本：0.4.122

「監控與診斷」移植的第三階段（前兩階段：[選單與日誌等級、資料庫用量](2026-10-14-監控與診斷選單與日誌等級資料庫用量.md)、[日誌檢視與 AI 日誌分析](2026-10-14-監控與診斷日誌檢視與AI日誌分析.md)）。下一階段：④ 系統健康監控改版。

## 一、錯誤追蹤碼

- 每個 HTTP 請求、每次 Blazor 互動各一組 8 碼（例如 `K7Q2M9XA`），寫在日誌第 2 欄。
- HTTP 請求的碼取代 `HttpContext.TraceIdentifier`，所以 API 回應的 `TraceId` 也是同一組。
- 畫面出錯時，錯誤畫面會顯示追蹤碼。使用者回報這組碼，管理者就能在「日誌檢視」的 TraceId 篩選，或「系統例外紀錄」的關鍵字查到那一次的紀錄。
- `nlog.config` 第 2 欄改成 `${scopeproperty:item=TraceCode:whenEmpty=${aspnet-TraceIdentifier}}`。欄位數不變，日誌檢視照常解析。

## 二、例外自動收集

- **新增 `ExceptionLogProvider`（ILoggerProvider，與 NLog 並存）**：所有帶例外的 `LogError`／`LogCritical` 都會被收下。服務層既有的 `catch { logger.LogError(ex, …) }` 一行都不用改。
- **背景寫入**：例外先進佇列，再由背景寫入器寫進新資料表 `ExceptionLog`（migration `AddExceptionLog`）。
  - 相同的例外合併成一列並累加次數。
  - 完整堆疊存成檔案，放在新設定 `ExceptionPath` 底下。
- **來源**：

  | 來源 | 由誰標記 |
  |---|---|
  | 畫面 | Blazor 互動、HTTP 頁面請求 |
  | WebAPI | `/api` 開頭的請求 |
  | 背景作業 | 轉錄、會議紀錄生成、匯率、清理服務 |
  | 系統啟動 | 啟動流程 |
  | 系統 | 未觀察的 Task 例外 |
  | 瀏覽器 | JavaScript 錯誤回報 |

- **錯誤邊界**：`Routes.razor` 加兩層 `LoggingErrorBoundary`（頁面、浮層）。以前 Blazor 元件裡未處理的例外，日誌上完全看不到。
- **瀏覽器錯誤回報**：登入後才註冊，每個 circuit 每分鐘最多 10 筆，忽略瀏覽器外掛的錯誤。
- **啟動失敗補登**：
  - 啟動失敗時先寫一個補登檔，下次成功啟動、Migration 之後再補進資料表。
  - 補登也涵蓋 `app.Build()` 之前的失敗。
  - 排除 `HostAbortedException`，所以 `dotnet ef` 不會留下假紀錄。
- **自動清理**：每天刪除「最後發生」超過 90 天的紀錄與堆疊檔（`LogRetentionSettings:ExceptionLogDays`，0＝不清）。

## 三、系統例外紀錄頁（`/system-exceptions`，只限管理者）

- 選單：系統管理 → 監控與診斷 → 系統例外紀錄（id 39，`bug_report`），加進 `AdminOnlyMenuIds`。
- 篩選：最後發生、來源、使用者、關鍵字（可直接貼追蹤碼）。
- 表格：最後發生、次數、類型、訊息、頁面、使用者。點列複製；「查看」看完整堆疊。
- 工具列：複製、匯出 CSV、清除 N 天未再發生、全部清除。
- **AI 例外分析**：
  - 送出前先跳「（會產生費用）」確認，**不送帳號**。
  - 回覆逐段顯示，完成後整理成管理者摘要、根本原因、修正建議、排查步驟、需要確認的問題。
  - 可複製或匯出 PDF；關閉視窗即取消。
  - 記入 AI 用量，新功能別 `AiUsageFeature.ExceptionAnalysis = 6`「AI 例外分析」。
- 刪除、清除、匯出、AI 分析都寫稽核，不記例外內容。

## 四、和 Starter 的差異

- 拿掉 Email 告警與 AI 追問。
- `ExceptionLogService` 改用 scoped `BackendDBContext`（本專案沒有 `IDbContextFactory`）。
- 匯出只做 CSV，新增 `CsvExport`，含防公式注入。
- 保留期限改用簡單的背景服務，不引入排程框架。
- 錯誤畫面與頁面全部改用燕麥奶茶配色與本專案元件。
