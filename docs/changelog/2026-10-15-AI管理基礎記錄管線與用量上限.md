與使用者確認的決定：

- **記錄範圍**：AI 對話紀錄記錄會議紀錄生成（含分段摘要）、AI 問答、抽出待辦、AI 日誌／例外分析的完整送出內容與回應。語音轉錄只記檔名、時長與轉出的文字，不存音訊。
- **保留與連帶刪除**：

- **會議時長**：會議自己記時長，儀表板「會議時數」改讀這一欄。

## 一、所有付費 AI 呼叫的唯一出入口：`AiCallGateway`

以前五個呼叫端各自重複「呼叫供應商 → 記帳」的程式：會議紀錄生成、語音轉錄、AI 問答、抽出待辦、日誌／例外分析。現在全部改走 `AiCallGateway`，一次呼叫在這裡完成四件事：

1. **用量上限檢查**：已達上限時，寫稽核 `Ai.QuotaBlocked`，拋出 `AiQuotaExceededException`。這次呼叫不會送出，也不會記帳。
2. **產生 CallId**。
3. **呼叫供應商**：同時收下逐段回應，取消或失敗時已收到的部分照樣保留。
4. **記錄**：寫用量帳本與 AI 對話紀錄，兩邊用同一個 CallId。成功、失敗、取消都記，兩邊一對一。

其他行為：

- **HTTP 狀態**：供應商回非 2xx 時改拋 `AiProviderHttpException`。它繼承 `InvalidOperationException`、訊息不變，多帶 HTTP 狀態碼。
- **不存的東西**：圖片只記類型與大小，不存 base64；不存 API 金鑰、標頭與網址 query。
- **守門測試**：`AiCallGatewayUsageTests` 掃描原始碼，Business／Web 只有 gateway 與供應商實作可以直接呼叫供應商。

## 二、AI 對話紀錄（先只有記錄，頁面在 1.0.30）

- **儲存**：
  - 新表 `AiCallLog`：一次呼叫一列，只存中繼資料，沒有外鍵。
  - 送出內容與回應全文存成 JSON 檔，位置是新設定 `ExternalFileSystem.AiCallLogPath` 底下的 `yyyyMM/{CallId}.json`。
- **關聯**：
  - 用量帳本 `AiUsageLog` 新增 `CallId` 欄位，可從用量找回當次的完整對話。
  - 同一趟工作的多次呼叫共用 `ThreadKey`，例如同一次會議紀錄生成的分段摘要與最終整理、同一段 AI 問答、同一個音檔的各段轉錄。
  - 每一筆另有「關聯說明」，例如「會議 #12〈週會〉分段摘要 2/5」「例外紀錄 #3（NullReferenceException）」。
- **保留期限**：新背景服務 `AiLogRetentionBackgroundService` 每天執行一次。
  - AI 對話紀錄超過 `AiCallLogSettings:RetentionDays`（預設 90）天就清除；停用記錄時照樣清。
  - 用量帳本只在 `LogRetentionSettings:AiUsageLogDays` 大於 0 時才清。
  - 有刪除時寫稽核 `AiCallLog.AutoPurge`／`AiUsage.AutoPurge`。
- **連帶刪除**：刪除會議與刪除專案時，依上面的規則一起刪除對話紀錄。
- **檔案儲存用量**：「資料庫用量」頁與健康監控的檔案系統、主機資源都納入這個新目錄。

## 三、AI 用量上限

新增設定 `AiQuotaSettings`：

| 鍵 | 用途 |
|---|---|
| `GlobalMonthlyTwd` | 全系統每月上限（新台幣） |
| `PerUserMonthlyTwd` | 每人每月上限（新台幣） |

兩者 0＝不限制，以 `IOptionsMonitor` 讀取，改設定檔即生效、不必重啟。

用量怎麼算：本月用量帳本的估算金額，依每一列自己的匯率換算成新台幣後加總。

- 有金額但沒有匯率的列，改用目前匯率。
- 未設定單價的列算 0 元。
- 讀不到帳本時放行並記錯誤。

什麼時候檢查：

| 情況 | 行為 |
|---|---|
| 即時功能（AI 問答、抽出待辦、日誌／例外分析） | 每次呼叫前檢查，被擋時跳出訊息 |
| 背景工作（轉錄、會議紀錄生成） | 工作開始時檢查一次（轉檔之前）；被擋就標為失敗，失敗原因寫「已達 AI 用量上限…」，之後可以重新執行；一旦開始就做完 |
| 重新轉錄、產生會議紀錄的入列前 | 先預檢；被擋就直接回訊息，不改任何狀態 |
| 上傳後自動入列的轉錄 | 由工作開始時那一次檢查擋下 |

- 被擋時記 Warning，不會進系統例外紀錄。
- 多個呼叫同時進行時都會通過檢查，所以實際用量可能略超過上限。

系統健康監控新增「AI 用量上限」，共 18 項，權重重新分配，合計仍是 100。

| 狀態 | 燈號 |
|---|---|
| 全系統達上限 | 紅燈 |
| 全系統達八成，或有使用者達到每人上限 | 黃燈 |

## 四、會議自己記時長

- 新欄位 `Meeting.MediaDurationSeconds`：轉錄完成時寫入，重新上傳影音時清空，編輯會議時保留原值。
- 儀表板「會議時數」改讀這一欄，所以清除用量帳本不會讓時數變少。
- migration `AddAiCallLogAndMeetingDuration` 從現有帳本回填既有會議的時長，算法與改版前的儀表板相同：只算轉錄完成的會議、最後一輪、成功的段落，數字與改版前一致。

## 五、測試

- **新增**：
  - `AiCallGatewayTests`（12 則）：帳本與對話紀錄的 CallId 一致；失敗或取消時保留部分回應與 HTTP 狀態；被上限擋下時不呼叫、不記帳、寫稽核；背景工作通過後不再檢查；停用記錄；記錄器失敗不影響呼叫；圖片與音訊不落地。
  - `AiCallGatewayUsageTests`：原始碼守門。
  - `AiCallLogServiceTests`：寫入、停用、截斷、寫檔失敗、資料庫失敗不留孤兒檔、連帶刪除（會議／專案層級）、保留期限與孤兒目錄清除。
  - `AiLogSettingsTests`：三組設定的驗證，帳本保留天數只能是 0 或至少 62。
  - `AiQuotaServiceTests`（10 則）：每列匯率、每人、未定價、缺匯率、跨月、讀取失敗放行、八成警示、排行、訊息。
  - `MeetingDurationBackfillSqlTests`：只算最後一輪成功的段落；未完成的會議不填。
  - `AiLogRetentionBackgroundServiceTests`：預設只清對話紀錄；設了天數才清帳本；沒刪除就不寫稽核。
  - `TranscriptionJobRunnerTests`（原本沒有）：寫入時長、每段一筆對話紀錄、被上限擋時不轉檔、通過後不逐段檢查。
- **補充**：
  - 會議紀錄生成：同一個 ThreadKey；被上限擋下。
  - 診斷分析：被上限擋下、關聯說明。
  - 會議服務：刪除時連帶刪除對話紀錄但保留帳本、編輯時保留時長、重新轉錄的預檢。
  - 帳本：存入 CallId、寫入失敗時移出追蹤。
  - 健康監控：AI 用量上限三種燈號。
- **調整**：
  - 儀表板會議時數的兩則測試改為讀 `MediaDurationSeconds`。
  - 原本「只算最後一輪」的兩則規則測試搬到回填 SQL 測試。
  - 整合測試的健康監控項目數改為 18。
- **結果**：全部 1,453 則通過。
- **實測**：用實際的供應商與本機設定打一次 Azure。帳本與對話紀錄的 CallId 一致，費用照常計算，內容檔裡沒有 API 金鑰。這個暫時測試檔已刪除，不進版控。
- **冒煙**：本機啟動後套用 migration，保留期限服務有執行，日誌沒有錯誤。

## 六、上線注意

- 新目錄 `AiCallLogPath`（預設 `C:\temp\MeetingRecord\AiCallLog`）存放會議逐字稿、會議紀錄與 AI 問答的全文。只開放給應用程式身分，不可放在網站目錄或下載目錄內，並納入備份政策。
- 用量上限預設不限制。要啟用時，在 `AiQuotaSettings` 設金額。
- 上線後第一次啟動會自動套用 migration（新表、兩個新欄位、回填會議時長）。
