# AI 設定防呆與「測試 AI 連線」（1.0.34 → 1.0.35）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：1.0.35
- 首次實作版本：1.0.35
- 最後核對日期：2026/10/15

## 起因

1.0.34 部署到 IIS 後，產生會議紀錄失敗，Azure 回 `404 DeploymentNotFound`，但 Azure 上明明有 `gpt-5.6-sol` 這個部署。

- 伺服器的 `appsettings.Production.json` 把部署名稱寫成 `"Deployment": "gpt-5.6-sol"`，當時系統只認 `Model`。
- .NET 設定繫結會**靜默忽略**不認得的鍵，於是 `Model` 退回 `appsettings.json` 的預設值 `gpt-4o-mini`，Azure 上沒有這個部署而回 404。
- 本機正常是因為 user-secrets 用的是 `Model`；IIS 的轉錄正常，是因為 `TranscriptionModel` 剛好退回的預設值 `gpt-4o-transcribe` 存在。
- 錯誤訊息只有 Azure 原文，看不出系統送出的是哪個部署名稱。

## 一、設定

- **`Deployment` 當成 `Model` 的別名**（Azure 入口網站稱為「部署」）；`TranscriptionDeployment` 是 `TranscriptionModel` 的別名。兩個都填而且不同時以正式鍵為準。IIS 上的既有寫法不必改。
- **`appsettings.json` 的 `LlmSettings` 改成全部空白**，不再有預設部署名稱悄悄頂替。開發用佔位值移到 `appsettings.Development.json`，本機照舊以 user-secrets 覆寫。
- **缺部署名稱不擋啟動**：`Model`、`TranscriptionModel`、`Endpoint` 空白時照常啟動，該 AI 功能停用、健康監控亮紅燈，用到時的錯誤訊息寫明缺哪個鍵。`StartupSafetyValidator` 也不再因 `TranscriptionModel` 空白中止 Production 啟動。指定的供應商不存在、單價為負數仍會擋啟動。
- **不認得的鍵**：新增 `LlmConfigurationInspector`，啟動時對每個不認得的鍵與別名衝突寫 Warning（`LlmSettings configuration warning`）。

## 二、錯誤訊息

新增 `AzureDeploymentErrors`，文字生成與轉錄共用：

- 404 DeploymentNotFound：「找不到 Azure 部署「gpt-4o-mini」（xxx.services.ai.azure.com）。請確認 LlmSettings:Providers:AzureOpenAI:Model（或別名 Deployment）填的是 Azure 上的部署名稱。原始回應：…」
- 部署名稱空白：「尚未設定文字生成的 Azure 部署名稱，請在 LlmSettings:Providers:AzureOpenAI:Model（或別名 Deployment）填入。」不會送出請求。
- 只含主機名稱，不含金鑰、標頭或查詢字串（這段會存進用量帳本與 AI 對話紀錄）。

## 三、系統健康監控

- 「AI 供應商設定」的佐證列改成顯示**實際生效**的端點主機、生成部署與轉錄部署。
- 有不認得的鍵（例如 `ModelName`）或別名衝突：黃燈，並提示「是不是要寫 Model？」。
- 生成部署名稱空白，或明確指定轉錄供應商卻沒填轉錄部署名稱：紅燈，寫明缺哪個鍵。
- 新增「**測試 AI 連線**」按鈕（管理者手動）：
  - 先跳「確認測試 AI 連線（會產生費用）」。
  - 文字生成送一則極短提問、語音轉錄送記憶體產生的 1 秒靜音，經 `AiCallGateway`（新服務 `AiConnectionTestService`），記入用量帳本與 AI 對話紀錄，受每月用量上限管制，各探測最多等 60 秒。
  - 結果顯示在 AI 供應商設定卡片底下（成功／失敗、部署、主機、耗時、原因），不併入分數；稽核寫 `Ai.ConnectionTest`。
- 新增功能別 `ConnectionTest = 7`（token）、`TranscriptionConnectionTest = 8`（音訊）。

## 四、升級注意

- 1.0.35 起沒有預設部署名稱。正式環境請確認 `Model`（或 `Deployment`）與 `TranscriptionModel`（或 `TranscriptionDeployment`）都有填 Azure 上的**部署名稱**；1.0.34 以前沒填 `TranscriptionModel` 會悄悄沿用 `gpt-4o-transcribe`，現在會停用轉錄。
- 上線後到系統健康監控按「測試 AI 連線」確認兩項都成功。

## 五、測試

- **新增**：`LlmConfigurationInspectorTests`（5 則）、`AzureDeploymentErrorsTests`（4 則）、`AiConnectionTestServiceTests`（6 則）。
- **擴充**：`LlmSettingsTests`（別名 3 則、空白不擋啟動、供應商不存在仍擋）、`SystemHealthChecksTests`（佐證列、缺部署名稱、缺轉錄部署、不認得的鍵 4 則）、`StartupSafetyValidatorTests`（轉錄部署空白不擋、`TranscriptionDeployment` 別名）。
- **結果**：全部 1,581 則通過；`ApiIntegrationTests` 在 AI 設定全空白的 Testing 環境照常啟動。
