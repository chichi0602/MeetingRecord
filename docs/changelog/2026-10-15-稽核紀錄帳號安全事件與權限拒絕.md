## 二、行為調整

- **登入成功改由呼叫端寫**：`MyUserServiceLogin.LoginAsync` 只寫失敗類，新增 `via` 參數（預設 `Web`）寫進摘要。
  - 網頁登入在 `SignInAsync` 之後寫 `Login.Success via=Web`。
  - API 登入在發出權杖之後寫 `Login.Success via=Api`。
  - 修掉的問題：以前 API 因「必須先改密碼」拒絕登入時，稽核卻已經記了一筆登入成功；現在只記 `Login.Failed reason=MustChangePassword`。
- **強制登出帶原因**：`AuthenticationStateHelper.Check` 把人踢出時改導向 `/Auths/Logout?reason=…`（`Share/Helpers/AuditVia.cs` 的 `LogoutReasons`）。登出頁在登出前取身分，依原因寫 `Logout.Forced` 或 `Logout.Manual`；未登入的人開登出頁不寫。
- **頁面拒絕紀錄刻意不放進 `CheckAccessPage`／`CheckIsAdmin`**：側邊欄過濾每個選單項目都會呼叫它們。
- 稽核紀錄頁的說明列改為「涵蓋登入登出、密碼與帳號異動、角色異動、權限拒絕、各管理頁的匯出與清除等事件」。

## 三、刻意不記

- 登入頁驗證碼錯誤、欄位空白（還沒驗證帳密）。
- 改密碼時欄位空白、兩次輸入不一致這類輸入錯誤。
- 資料範圍擋下（看不到的專案／會議當成不存在、回 404），留到第三批評估。
- 管理頁執行動作前的靜默管理者檢查、Google 未設定、JWT 政策型 403（`OnForbidden`）。
