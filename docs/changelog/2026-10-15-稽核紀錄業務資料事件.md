## 一、共用基礎：寫入服務自己找操作者

- 新增 `IAuditActorProvider`（Business）與 `AuditActorProvider`（Web/Auth）：Blazor 用 `CurrentUserService`，API 請求從 HttpContext 的 claims 取。以前 API 路徑的 `CurrentUserService` 是空的，業務服務分不出是誰。
- `IAuditLogService` 新增 `WriteForCurrentUserAsync(action, success, targetType, targetId, detail)`。業務服務只多注入一個 `IAuditLogService`，網頁與 API 兩條路的操作者都對。
- `AuditVia.AiExtract`：AI 抽出待辦批次加入。

## 三、行為調整

- 網頁摘要標 `via=Web`、API 標 `via=Api`；專案與會議的 API 刪除經 Service，`DeleteAsync` 新增 `via` 參數由控制器傳入。
- `ProjectService` 的附件存檔與刪除改回傳實際處理的檔案清單，才能逐檔記錄。
- `TodoService.SetCompletedAsync`／`DeleteAsync` 與三個 Repository 的更新、刪除把「找不到」和「看不到」拆開判斷：找不到不記，看不到記權限拒絕；對使用者仍一律當成不存在。
- `AiChatService.CreateConversationAsync` 新增 `audit` 參數，開視窗自動建立時傳 `false`；`EnsureAccessAsync` 只在寫入類操作被擋時記錄。
- 稽核紀錄頁的動作膠囊新增業務類（專案、會議、待辦）與資料定義類（團隊、分類、提示詞）的配色。

## 四、刻意不記

- 讀取被資料範圍擋下、開視窗自動建立的對話、AI 問答提問本身（另見 Token 用量與 AI 對話紀錄）、AI 問答的圖片預覽。
- 409 衝突、404、驗證失敗。

- **調整**：所有建構業務服務的測試夾具改傳 `TestAuditLogs.CreateService(context, actor)`；新增 `TestAuditActor`。
