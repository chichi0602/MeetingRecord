# 使用說明：分類瀏覽＋快速搜尋（1.0.41 → 1.0.42）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：1.0.42
- 首次實作版本：1.0.42
- 最後核對日期：2026/10/16

使用者回報：

> 使用說明多一個搜尋快捷，才可以找自己遇到的問題。使用說明做分類，因為全部在同一頁很亂，分類比較好找問題。

使用者選定：合併成 6 大類；搜尋時直接顯示符合的段落內容、關鍵字高亮。

---

## 一、原因

- 說明頁把整份《系統使用說明》（13 章、約 50 小節）一次渲染在同一頁，只能從頭往下捲。
- 沒有任何搜尋；瀏覽器的 Ctrl+F 找得到字，但看不出那段屬於哪個功能。
- 說明裡兩個跨章節連結（例如「出現『已達 AI 用量上限』時」）**從來都連不到**：Markdown 管線預設只用英數字產生標題 id，中文標題的 id 被削成 `ai` 之類，與照 GitHub 寫法寫的連結對不上。

## 二、修改

### 分類

- 內容來源不變：仍是 `docs/guides/系統使用說明.md` 這一份（文件庫與系統內說明不會分歧）。
- 每個 `##` 章節前一行加 `<!-- 說明分類：XXX -->`，固定 6 類、依序：**新手入門｜會議與逐字稿｜專案與待辦｜AI 與費用｜管理員｜常見問題**。
  在 GitHub 上看不到這行；系統渲染前會剝掉（渲染管線關掉了 HTML，不剝會印成文字）。
- 說明頁左邊是分類清單（捲動時固定在畫面上），右邊只顯示目前那一類。窄螢幕時分類變成上方一排膠囊。

### 搜尋

- 上方搜尋框，打字就篩選（停 0.2 秒才搜），右邊直接列出符合的段落卡片，標明「分類 › 章 › 小節」，關鍵字以底色標出。
- 搜尋單位：每章開頭段、每個小節，常見問題**一題一張卡**（卡片標題就是題目）。
- 多個關鍵字用空白隔開＝全部都要出現；不分大小寫；標題命中的排前面。
- 快速鍵：說明頁任何地方按 **/** 直接開始搜尋，在搜尋框按 **Esc** 清掉、回到分類。
- 找不到時提示試其他關鍵字或看「常見問題」。
- 高亮只在文字節點上加標記，不改動連結與標題的屬性。

### 跨分類連結

- 點說明裡的 `#錨點` 連結：先切到目標所在的分類、清掉搜尋，再捲到那一節。
- 修正標題 id：Markdown 管線改用 GitHub 樣式的自動 id（保留中文）。只影響標題的 `id` 屬性，AI 問答、會議紀錄等其他用到同一條管線的地方畫面不變。

### 結構

- `HelpManual`（純函式）：切分類、切搜尋單位、搜尋、找錨點所在分類，可單元測試。
- `help-view.js`＋`HelpViewInterop`：快速鍵、高亮、錨點點擊；失敗只記 log，不影響頁面。

## 三、測試

新增 `HelpManualSearchTests`：

- 用真的說明檔：6 類依序且都不是空的、每章都有合法分類標記、畫面上看不到標記、說明裡每個 `#錨點` 都找得到所屬分類、搜「轉錄失敗」找得到常見問題那一題。
- 用範例：程式碼區塊裡的 `##` 不算章節、章節間的分隔線不殘留、常見問題一題一張卡、多關鍵字與大小寫、標題優先、空白查詢、麵包屑、不認得的分類標記會被回報。

`HelpManualTests` 的「去掉檔頭」測試改為：正文從分類標記開始、下一行是 `##`。

測試全部通過（1619 個）。
