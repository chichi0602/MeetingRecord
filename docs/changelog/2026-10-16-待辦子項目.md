# 待辦子項目，抽出時自動掛為子項目（1.0.44 → 1.0.45）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：1.0.45
- 首次實作版本：1.0.45
- 最後核對日期：2026/10/16

使用者問：

> 同個功能的子功能，要怎麼新增在待辦裡面？
> 好比我一個會議紀錄用兩個提示詞新增了兩筆不同的會議紀錄，我兩個都按抽出待辦，會有什麼問題，該怎麼解決？

使用者決定：子項目是**完整的子待辦**（自己的負責人、期限、狀態、異動紀錄與通知），**只分一層**；抽出時 AI 判斷某條是既有待辦的一部分，預設「加為子項目」。

---

## 一、原因

- **沒有上下層**：待辦只能各自獨立一筆，同一件事的子步驟看不出關係。
- **兩個提示詞的情境**：一場會議只有一份會議紀錄，換提示詞重新產生會**覆蓋**舊的，所以實際是「A 產生 → 抽出 → 換 B 重新產生 → 再抽出」。1.0.44 已經處理「同一件事」（對應既有、更新期限負責人）；剩下的是**粒度**不同——A 寫「完成報表」，B 拆成「整理資料／畫統計圖／寫結論」，一筆既有待辦只能配一條，其餘兩條變成不相干的新待辦，清單散成四筆。

## 二、修改

### 子項目

- `Todo.ParentTodoId`（自我參照，Cascade）：刪主待辦連子項目一起刪（含它們的異動紀錄），刪除確認會寫出子項目數。
- 規則（畫面與 API 共用 `TodoHierarchyRules`）：只分一層（子項目底下不能再有子項目、已有子項目的不能變成別人的子項目）、不能掛自己、子項目與主待辦同專案。主待辦搬專案時子項目跟著搬。主待辦與子項目的狀態各自獨立。
- 主待辦的異動紀錄多一種「子項目」事件：新增、移除、換主待辦時記下，**只記錄不通知**；子項目本身改期限、負責人、狀態照常通知。

### 待辦頁

- 清單只分頁主層，子項目收在主待辦底下（可展開，預設收合），標題旁顯示「子項目 1/3」（全完成變綠色）。
- 搜尋與篩選：主待辦或它的任一子項目符合就列出；展開的子項目照篩選結果，完成數看全部子項目。
- 主層待辦的操作欄多「新增子項目」，開新增視窗並預填專案與主待辦；編輯視窗多「屬於（主待辦）」可選。
- 右側負責人面板維持平的，子項目下方標「屬於：〈主待辦〉」。
- 自動決定每頁筆數的量測只算主層列，展開子項目不會讓每頁筆數來回跳。

### 抽出待辦

- 給 AI 的既有待辦清單標出「主項目／子項目」，並請它在某條是既有待辦的**一部分**時填 `parentTodoId`（只能掛在主項目底下；與「同一件事」擇一，同時給時以同一件事為準）。
- 確認視窗顯示「屬於：〈主待辦〉」，動作預設「加為子項目」，可改「另外新增」。按鈕寫出含幾條子項目。
- 不做：同一次抽出裡「新的主待辦＋它的子項目」一起建立；需要時先建主待辦，再抽一次或手動新增子項目。

### Web API

- 待辦的建立／修改可帶 `parentTodoId`，套同一份規則，違規回 400 並說明原因。修改是整筆取代：沒帶 `parentTodoId` 等於取消子項目關係。

### 資料庫

- Migration `AddTodoParent`：只新增欄位、索引與外鍵，不動既有資料（既有待辦都是主層）。

## 三、測試

- `TodoChangeAndNotificationTests` 新增 11 個：新增子項目記在主待辦且不通知、不能多層、不能跨專案、已有子項目的不能變成子項目、不能掛自己、搬主待辦子項目跟著搬、刪主待辦連帶刪除、刪子項目在主待辦記移除、清單只分頁主層並帶完成數、搜尋命中子項目時列出主待辦、子項目改期限照常通知、API 跨專案擋下。
- `TodoExtractionParserTests` 新增 3 個：提示詞標出主項目／子項目並要求 parentTodoId；只收主項目 Id、可多條掛同一筆；同時給兩種時以同一件事為準。

測試全部通過（1666 個）。
