# 已完成專案＝封存：唯讀與檢視切換（1.0.45 → 1.0.46）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：1.0.46
- 首次實作版本：1.0.46
- 最後核對日期：2026/10/19

使用者問：

> 已完成專案要怎麼呈現在專案那邊（封存？），然後有個地方可以看要顯示哪類型的專案嗎？

使用者決定：
- 「已完成」就是封存，不另外加狀態；改回其他狀態就是重新開啟。
- 封存的專案**唯讀**，要改要先「重新開啟」；管理者不受限。
- 專案頁與待辦頁加檢視切換「使用中｜已完成｜全部」，**每次都回到「使用中」**，不記憶。

---

## 一、原因

- 專案狀態原本就有「已完成」，但只是一個標籤：已完成的專案一直混在專案頁、會議頁、待辦頁的下拉選單裡，越做越多就越難找。
- 專案頁原本的「團隊／分類／狀態」篩選預設全部顯示，而且不顯眼，沒有一眼就能切換「只看進行中的」的地方。
- 已完成的專案還能繼續加待辦、產生會議紀錄，結案後的資料容易被不小心改掉。

## 二、修改

### 規則（畫面與 API 共用 `ProjectArchiveRules`）

- 專案狀態是「已完成」就是封存；「使用中」是其他四種（未開始／進行中／暫緩／等待）。
- 封存專案的內容不能修改，一般使用者會看到「這個專案已完成（封存），請先重新開啟再修改。」；管理者放行。擋下的路徑：
  - 待辦：新增、修改（含搬進封存專案、從封存專案搬出）、勾完成、刪除、抽出時更新既有待辦；Web API 的新增、修改、刪除回 400。
  - 會議：修改、刪除、上傳媒體、重新轉錄、歸屬到封存專案、從封存專案移除、產生會議紀錄指定封存專案、編修已歸屬會議的會議紀錄。
  - 專案附件：上傳、刪除（狀態維持已完成時）。
- 不擋：檢視、下載 PDF、AI 問答、異動紀錄，以及專案本身的「編輯」（改狀態就是重新開啟）。
- 會議頁的專案選單（歸屬到專案、AI 轉會議紀錄）不列封存專案；已歸屬的會議照常顯示原本的專案名稱。

### 專案頁

- 篩選列最前面加「使用中｜已完成｜全部」，預設使用中；原本的「狀態」篩選只列目前檢視範圍內的狀態。
- 「全部」檢視時，已完成的專案在下拉裡標「（已完成）」。
- 選到封存專案：上方提示「這個專案已完成，目前是唯讀」，有編輯權限的人看得到「重新開啟」按鈕（確認後改成「進行中」）。
- 封存時隱藏 AI 轉會議紀錄、抽出待辦、從專案移除，會議紀錄視窗不能切到編修；管理者照樣看得到提示條，但不受限。
- 在專案表單把狀態改成「已完成」存檔前會先確認一次，存檔後自動切到「全部」，專案不會突然從畫面消失。

### 待辦頁

- 工具列加同一組「使用中｜已完成｜全部」，預設使用中：清單與右側負責人面板都只算使用中專案的待辦。
- 專案篩選跟著檢視列出對應專案；切換檢視時，原本選的專案不在範圍內就清掉。新增／編輯表單的專案選單不列封存專案。
- 封存專案的待辦：勾完成、修改、刪除、新增子項目停用（管理者除外），異動紀錄照常可看。
- 通知鈴鐺或連結點到封存專案的待辦時，自動切到「全部」。

## 三、測試

- `TodoChangeAndNotificationTests` 新增：封存專案一般成員不能改待辦、管理者可以；不能把待辦搬進封存專案；重新開啟後可以再改；API 擋下並回驗證錯誤；待辦清單依檢視篩選（Theory）；`ApplyScope` 分出使用中與已完成。
- `MeetingServiceTests` 新增：封存專案一般成員不能歸屬會議、不能編修會議紀錄，管理者可以。

測試全部通過（1675 個）。
