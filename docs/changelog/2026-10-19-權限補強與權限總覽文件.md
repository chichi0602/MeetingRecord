# 權限補強：上傳者專屬動作、主責團隊管團隊設定、儀表板不露名稱（1.0.46 → 1.0.47）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：1.0.47
- 首次實作版本：1.0.47
- 最後核對日期：2026/10/19

使用者問：

> 同專案的可以去動同專案但非自己上傳的紀錄嗎？不同專案的人上傳應該只能看到自己上傳的內容，不能跨組織看到別人的項目。刪除紀錄後是連同專案那邊一起移除嗎？那待辦呢？我希望這個系統還是要有基本的安全性。

使用者決定：
- 同專案的人可以一起看、一起改會議（標題、分類、會議紀錄、重新產生、AI 問答），但**刪除、從專案移除、換影音檔、重新轉錄只限上傳者與管理者**；上傳者是一般使用者也能刪自己上傳的。
- **專案的團隊設定與刪除只限主責團隊的成員**（與管理者）；協作團隊的人照常改其他內容。
- 儀表板維持全公司數字，但**看不到的專案名稱不露出**，併成「其他專案」。
- 刪除行為維持現狀（刪會議保留抽出的待辦、刪專案保留會議），**寫清楚、讓使用者在確認框就看得到**；另寫一份權限總覽文件。

---

## 一、原因

- 可見範圍本來就是對的：看不到的專案、別人未歸屬的會議都當成不存在，不會跨團隊看到。問題在「看得到」之後：
  - 同專案任何人只要角色有刪除權限（例如「主管」），就能刪掉同事上傳的會議，連影音檔、逐字稿一起永久刪除；也能把同事的會議「從專案移除」，移除後只剩上傳者看得到，等於從其他人手上拿走。
  - 協作團隊的人可以把自己的團隊設成主責、把原本的主責團隊踢出去，等於搶走整個專案；也能直接刪掉別的部門主責的專案。
  - 儀表板「各專案會議數」會列出所有專案名稱，看不到某專案的人也看得到它的名稱。
- 刪除會帶走什麼沒有地方寫清楚：刪會議的確認框只說影音檔與逐字稿，沒說待辦會不會跟著不見。

## 二、修改

### 會議：上傳者專屬動作（`ProjectAccess.IsMeetingOwner`）

- 刪除、從專案移除、換影音檔、重新轉錄只限上傳者（`Meeting.CreatedByUserId`）與管理者，在 `MeetingService` 的 `DeleteAsync`／`DetachFromProjectAsync`／`SaveMediaAsync`／`RequeueTranscriptionAsync` 擋下，訊息例如「只有上傳者或管理者可以刪除這筆會議紀錄。」。沒有上傳者紀錄的舊會議只有管理者。
- 上傳者只要角色有 `會議紀錄:edit` 就能刪自己的；「主管」有刪除權限也不能刪別人上傳的。
- 會議頁：別人上傳的會議不顯示「刪除」「重新轉錄」；修改視窗的影音檔拖放區停用，提示「只有上傳者或管理者可以更換影音檔；其他欄位可以照常修改。」。
- 專案頁：「從專案移除」只對上傳者顯示（要 `專案項目:edit` 或 `delete`、專案不是唯讀）。
- 刪除確認框改成：「確定要刪除這筆會議紀錄嗎？影音檔、逐字稿、會議紀錄與 AI 問答會一併刪除。從這場會議抽出的 N 筆待辦會保留在專案裡（不再連到這場會議）。此操作無法復原。」（N 由新的 `MeetingService.CountLinkedTodosAsync` 算，0 筆時不顯示中間那句）。
- Web API：`DELETE api/Meeting/{id}` 改要求 `會議紀錄:edit`（原本 `delete`），不是上傳者回 400。

### 專案：主責團隊管團隊設定與刪除（`ProjectAccess.CanManageProject`）

- `ProjectAccess` 多一個選填的 `PrimaryProjectIds`（自己的團隊是主責的專案），由 `ProjectAccessService` 載入。
- 修改既有專案時，不是主責團隊成員的人改了主責或協作團隊就擋下：「只有主責團隊的成員可以變更團隊設定。」（`ResolveProjectTeams` 新增 `projectId`、原協作團隊兩個參數，畫面 `ProjectService` 與 API `ProjectRepository` 共用）。團隊沒變就照常存檔，其他欄位不受影響。
- 刪除專案（`ProjectService.DeleteAsync`）：不是主責團隊成員擋下「只有主責團隊的成員可以刪除專案。」；已完成（封存）的也擋，要先重新開啟。
- 專案頁：非主責成員的團隊欄位停用並加提示；「刪除專案」按鈕只有主責團隊成員且專案不是唯讀時可按。
- Web API：`PUT api/Project/{id}` 改團隊被擋回 400；`DELETE api/Project/{id}` 上述兩種情況回 400（以前任何失敗都回 500）。
- 新增專案規則不變。

### 儀表板

- 「各專案會議數」把目前使用者看不到的專案名稱併成「其他專案」（`DashboardService.HiddenProjectLabel`），數字照算；管理者看得到全部名稱。`DashboardService` 因此注入 `ProjectAccessService`，只用來決定名稱，不過濾數字。
- 提示詞範本名稱照常顯示（範本本來就對所有人開放）。

### 文件

- 新增 [權限與資料可見範圍總覽](../security/權限與資料可見範圍總覽.md)：三個維度、誰看得到、權限矩陣、預設角色、刪除會帶走什麼、已完成專案、刻意的例外、安全機制與已知限制。
- 系統使用說明新增「誰看得到、誰能改、刪除會帶走什麼」一節與五則常見問題。
