# 專案頁記住上次選的專案（1.0.50 → 1.0.51）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：1.0.51
- 首次實作版本：1.0.51
- 最後核對日期：2026/10/20

使用者要求：

> 專案項目 預設打開上一次操作的選項為預設選擇項目。

決定：

- **只記專案**。團隊、分類、狀態篩選與「使用中｜已完成｜全部」照舊每次重設——1.0.46「每次回到使用中」的規則不變。
- 上次的專案已完成、已刪除或已經看不到時，照原本的規則改選「使用中」的第一筆。
- **記在帳號上（資料庫）**，換電腦、換瀏覽器也一樣。

---

## 一、原因

- 專案頁每次打開都選下拉的第一筆專案，平常只跟一兩個專案的人每次都要重新挑。

## 二、修改

- `MyUser` 新增可空欄位 `LastProjectId`，**刻意不設外鍵**：專案刪掉後留著舊 Id，專案頁看不到就改選第一筆。migration `AddUserLastProject`（`20261020022829`）只加這一欄，不動任何資料。
- `ProjectService`：
  - `GetLastSelectedProjectIdAsync()`：讀目前使用者記下的專案；取不到使用者（UserId 0）回 null。
  - `SaveLastSelectedProjectAsync(projectId)`：用 `ExecuteUpdate` 只寫這一欄，不動 `UpdateAt`、不記稽核（只是畫面偏好）；看不到的專案與 UserId 0 不寫；寫入失敗只記 log，不影響畫面。
- `ProjectViewView`：
  - 開頁時先把選取設成上次的專案，再第一次載入清單；看不到、已完成或已刪除時由原本的規則改選使用中的第一筆。
  - 在下拉選專案、新增專案後（畫面切到新專案）才記下；自動改選第一筆**不記**，免得一次篩選就把原本記住的專案蓋掉。

## 三、測試

- `ProjectAccessTests` 新增 2 則：`LastSelectedProject_IsRememberedPerUser_AndInvisibleProjectsAreIgnored`（各帳號分開記、看不到的專案不記）、`LastSelectedProject_UnresolvedUser_ReadsNullAndWritesNothing`（取不到使用者時讀 null、不寫入）。全部測試通過（1684 個）。
- 畫面行為靠上架前人工測試清單 7-16～7-20 驗證。
