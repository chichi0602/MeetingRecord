# 清單全選／多選刪除（1.0.52 → 1.0.53）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：1.0.53
- 首次實作版本：1.0.53
- 最後核對日期：2026/10/20

使用者要求：

> 每個會有清單列的都多一個可以全選/多選的功能，才方便刪除

決定：

- 列上有「刪除」的 10 個清單都加多選刪除：會議紀錄、待辦事項、團隊、分類、提示詞、使用者、角色、AI 對話紀錄、Token 用量（明細）、系統例外紀錄。
- 專案頁的「歷史會議紀錄」列上動作是「從專案移除」，所以改成多選「從專案移除」。
- 唯讀清單（日誌檢視、系統健康監控、資料庫用量、Token 彙總表）不加。
- **全選＝這一頁**：表頭勾選只選目前這一頁；換頁、排序、搜尋、改篩選就清掉勾選；批次跑完清單重新整理、勾選清空。
- 刪除權限一律不變：單筆不能刪的列就勾不起來。

---

## 一、原因

- 清單只能一筆一筆按「刪除」、一筆一筆確認，要清掉一批測試資料或過期紀錄很費工。

## 二、修改

- **共用元件**（`Components/Commons/`）：
  - `BatchSelectionBar`：勾了 1 筆以上才出現在表格上方，「已勾選 N 筆　[刪除所選]　[取消勾選]」，按鈕文字與圖示可換（專案頁用「從專案移除所選」）。
  - `BatchRunner.RunAsync`：**逐筆依序**呼叫既有的單筆刪除（單筆方法各自負責權限、檔案、對話、AI 紀錄、稽核、子項目），不另寫 `RemoveRange`。**不平行**——Blazor 一條連線共用同一個 DbContext。某筆失敗或丟例外只記成失敗，不中斷其他。
  - `BatchResult.Summary`：「已刪除 3 筆。」或「已刪除 3 筆，2 筆沒有刪除：A（原因）、B（原因）。」，最多列 5 筆，其餘「等 N 筆」；`BatchResultNotifier.Notify` 全部成功用成功樣式、有失敗用警告樣式。
- **共通行為**：不能刪的列勾選框停用，表頭全選只選到能刪的列；所有表格都設了 `RowKey`；確認框寫明筆數與連帶影響。
- **各頁**（規則都與單筆刪除相同）：
  - 會議紀錄：上傳者或專案負責人＋`會議紀錄:edit`、不在上傳中才勾得起來；確認框合計「從這些會議抽出的 N 筆待辦會保留在專案裡」；轉錄或生成中的由服務層擋下，列在通知裡附原因。背景進度重載時勾選依 Id 保留，換頁、排序、搜尋、分類過濾才清掉。
  - 待辦事項：專案負責人＋`待辦事項:edit`＋專案不是唯讀才勾得起來。選取欄與「完成」勾選框分開；主待辦與子項目各自勾（`CheckStrictly`），主待辦已勾時略過它被勾的子項目（`TodoBatchSelection.ExcludeChildrenOfSelectedParents`），確認框寫明一起刪掉幾個子項目。表格 `ScrollX` 934 → 966px，標題欄的 `nth-child` 樣式在有選取欄時改用 `.todo-view-has-selection`。
  - 團隊：`團隊清單:delete`；每筆照跑刪除前檢查，還是專案主責團隊的（非管理者）列為沒刪除。
  - 分類、提示詞：角色的 `delete`；**單筆刪除改成看結果**（以前一律顯示「刪除成功」）。
  - 使用者（管理者）：沿用批次調整團隊的那組勾選，批次列加「刪除所選」；自己的帳號略過，列為「不能刪除自己的帳號」；單筆刪除改成看結果；清單重載時清掉勾選。
  - 角色（管理者）：確認框合計掛著這些角色的使用者人數（同一人掛好幾個勾選的角色會重複計算）。
  - AI 對話紀錄、Token 用量明細、系統例外紀錄（管理者）：每筆照單筆一樣各寫一次稽核；`ScrollX` 各加 32。系統例外紀錄點列就複製，AntDesign 的 `Selection` 擋不住點擊冒泡，所以改用自己做的勾選欄（外層 `stopPropagation`，表頭勾選＝選這一頁），點勾選框不會複製。
  - 專案頁歷史會議紀錄：能單筆移除（`CanDetach`：上傳者、專案不是唯讀）的列才勾得起來，「從專案移除所選」；清單不分頁，全選＝整個清單。
- **API**：不加批次端點，仍是單筆 `DELETE`。

## 三、測試

- 新增 `BatchDeleteTests`（4 則）：逐筆依序執行且失敗或例外後照樣跑完、`Summary` 文字與超過 5 筆的截斷、待辦主待辦已勾時略過子項目、`Flatten` 含展開的子項目。
- 全部測試通過（1694 個）。
- 畫面行為靠上架前人工測試清單 15-5～15-16 驗證。
