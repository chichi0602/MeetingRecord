# 待辦改期限原因與甲方帳號（1.0.54 → 1.0.55）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：1.0.55
- 首次實作版本：1.0.55
- 最後核對日期：2026/10/22

使用者要求：

> 代辦事項 改期限多一個備註功能
> 這功能主要是想給專案的甲方 提供他查看專案的帳號 並且在代辦那邊可以進行編輯 若有需要改時程 會附上一些備註 這樣專案所有負責人都可以透過小鈴鐺來接收訊息

決定（與使用者確認）：

- 改期限**一定要寫原因**；AI 抽出時自動更新期限不強制。
- 小鈴鐺收件人**維持現狀**（專案主責＋協作團隊成員，不含改的人），訊息後面附上原因。
- 新增「**甲方**」預設角色。
- 甲方在待辦有全部權限，但**只能刪自己建立的待辦**；甲方**每做一個修改動作都通知專案負責人**。

---

## 一、改期限原因（所有人）

- 修改視窗裡期限的**日期**跟開啟時不同，就出現必填的「改期限原因」（最多 500 字）。只差時間、同一天不算改期限。
- 檢查規則 `TodoChangeRecorder.ValidateDueDateNote`，畫面（`TodoService.UpdateAsync`）與 API（`TodoRepository.UpdateAsync`，`TodoCreateUpdateDto.dueDateChangeNote`）共用；沒填回「改期限請填寫原因。」（API 400）。
- `ApplyExtractedUpdateAsync`（AI 抽出更新既有待辦）與勾完成不需要。
- 原因存進期限那一列的 `TodoChange.Note`：
  - 通知訊息結尾加「（備註：…）」；
  - 異動紀錄視窗在該列下方顯示「原因：…」；
  - 「期限已變更」膠囊的提示結尾加「，原因：…」。

## 二、甲方帳號

- **身分**：`MyUser.IsExternal`，使用者管理編輯視窗的「甲方」勾選。`ProjectAccess` 多 `IsExternal`，由 `ProjectAccessService.LoadAsync` 一起讀出（管理者一律 false）。用帳號旗標而不看角色名稱：角色名稱可以被改掉。
- **預設角色「甲方」**（`RolePresets`）：使用說明、專案管理群組、`專案項目:view`、`待辦事項` 全部動作、登出。舊系統在角色管理再按一次「建立預設角色」就會補上。
- **看得到哪些專案照樣靠團隊**：甲方放進一個團隊，把該團隊設為專案的協作團隊。
- **通知專案負責人**：甲方的任何修改都通知 `Project.OwnerUserId`（帳號啟用中，`ProjectAccessService.GetProjectOwnerIdsAsync`）：
  - 修改：任何欄位（標題、期限、負責人、狀態、優先度）或描述有變，訊息列出全部變動，例「戊 把『完成報表』的優先度改為 高，並修改了描述」。負責人同時是團隊成員時只收這一則。
  - 新增：「戊 新增了待辦『…』」（`TodoChangeRecorder.StageCreatedAsync`，待辦存檔拿到 Id 後再存一次通知）。
  - 刪除：「戊 刪除了待辦『…』」（`StageDeletedAsync`）。
  - 勾完成走一般的狀態變更，也會通知。
  - 一般使用者的規則不變：只有期限、負責人、狀態變更才通知團隊。
- **刪除**：`Todo.CreatedByUserId`（1.0.55 起新增時填入，畫面、API、AI 抽出都填；舊資料為 null；修改時保留原值）。`ProjectAccess.CanDeleteTodo`：專案負責人與管理者可刪任何待辦，甲方另外可刪自己建立的；不行時甲方看到「甲方帳號只能刪除自己建立的待辦。」。待辦頁的刪除鈕、多選勾選框跟著同一條規則。
- **負責人候選**：`ProjectOwnerRules.GetCandidatesAsync` 排除甲方帳號。
- ⚠️ 甲方有 `專案項目:view`，所以看得到該專案的歷史會議紀錄、可以 AI 問答。不想讓甲方看到內部會議的專案，就不要把甲方的團隊加進去。

## 三、資料庫

- migration `AddTodoChangeNoteAndExternalUser`（`20261022065353`），只加三個欄位，不動既有資料：
  - `TodoChange.Note`（TEXT，≤500，可空）
  - `Todo.CreatedByUserId`（INTEGER，可空，不設外鍵）
  - `MyUser.IsExternal`（INTEGER，預設 0）

## 四、測試

- `TodoChangeAndNotificationTests` 新增 12 則：
  - 改期限沒填原因：畫面與 API 都擋。
  - 有填原因：記進 `Note`、通知結尾有備註、清單提示有原因。
  - 只改其他欄位、同一天改時間：不要求原因。
  - AI 抽出：不要求原因。
  - 甲方改優先度與描述：只通知負責人；一般使用者改優先度仍不通知。
  - 甲方改期限：負責人只收一則，團隊照收。
  - 甲方新增、刪除：畫面與 API 都通知負責人；一般使用者新增會記建立者、不通知。
  - 甲方只能刪自己建立的，負責人仍可刪任何待辦。
  - 修改不會清掉建立者。
  - 負責人候選不含甲方。
- `RolePresetsTests` 驗證「甲方」角色的權限；預設角色數改看 `RolePresets.All.Count`。
- 既有兩則改期限的測試補上原因。
- 全部測試通過（1717 個）。畫面行為靠上架前人工測試清單 10-30～10-34 驗證。
