> API 授權守門測試

決定（與使用者確認）：模板遺留的 `WeatherForecastController` 直接刪除。

---

## 一、原因

- 改成 WASM 後畫面上的權限檢查只決定按鈕顯不顯示，真正的把關全在 API；遷移要新增上百支 API，漏掉一支 `[HasPermission]` 就是越權。先建一道自動防線。
- 盤點時發現分類、提示詞、團隊三組 Controller 完全沒有 HTTP 層測試，會議只測過管理者新增與刪除。
- 模板遺留的 `/WeatherForecast` 沒有任何驗證，任何人都能呼叫。

## 二、修改

- **刪除** `Controllers/WeatherForecastController.cs` 與它專用的 `Models/Others/WeatherForecast.cs`（`Weather.razor` 樣板頁用的是自己的內部類別，不受影響）。
- **新增 `ApiAuthorizationConventionTests`**：反射掃描 Web 組件所有 Controller 的每個 action，必須是下列其一，否則失敗並列出端點：
  - 在匿名白名單：`AuthController.Login`、`AuthController.Refresh`、`ExternalAuthController.*`；
  - `[Authorize]`＋`[HasPermission]`；
  - `[Authorize]` 且在「只需登入」白名單：`AuthController.Me`。
  - 另驗：每個 `[Authorize]` 都指定 `AuthenticationSchemes`、白名單沒有已不存在的端點、掃描確實找得到已知的 Controller（避免什麼都沒掃到而白白通過）、`WeatherForecastController` 不得復活。
- **新增 `ApiIntegrationTests.Authorization.cs`**（`ApiIntegrationTests` 改為 partial，共用同一個測試主機）：分類、提示詞、團隊、會議 20 支端點各驗三件事——沒權杖 401；角色有該頁其他所有動作、唯獨缺這個動作時 403 並留 `PermissionDenied` 稽核（同時證明用的是正確的動作鍵，例如會議刪除要求的是 edit）；角色只有這一個動作時成功。會議另驗別團隊專案的會議、他人上傳的未歸屬會議：即使有全部動作權限，讀、改、刪一律 404，搜尋也不會列出。建測試帳號的程式抽成 `CreateApiUserAsync`。
- **測試主機調整**（只影響測試）：
  - `ApiTestApplicationFactory` 把 "api" 限流換成幾乎不限。正式環境是全站共用一個桶、每分鐘 120 次，測試一個類別就超過，之後全部回 429 空 body，看起來像一堆無關的測試壞掉。
  - `ApiIntegrationTests` 與 `GoLiveReviewApiTests` 放進同一個不平行的 `ApiHostCollection`。factory 設的是行程層級環境變數，兩個主機同時啟動會指到同一個資料庫、同時跑啟動種子資料而偶發 `UNIQUE constraint failed: Permission.Key`（新測試讓它更容易出現，連跑 5 次確認修好）。

- 版本 1.0.57 → 1.0.58。

## 三、測試

- 新增 67 則（授權矩陣 60、會議看不到 2、守門掃描 5）；全套 1,802 則通過。
- 暫時拿掉 `CategoryController.GetById` 的 `[HasPermission]`，掃描測試變紅並指出 `CategoryController.GetById`，還原後恢復綠燈。

## 四、留意

- 正式環境的 API 限流是**全站共用**每分鐘 120 次（不分使用者），對外服務、使用者變多時所有外部用戶端會互搶。這次沒有改，列為後續議題；D（分塊上傳）的上傳端點會免除限流。
