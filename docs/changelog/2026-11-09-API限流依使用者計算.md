# API 限流依使用者計算（1.0.62 → 1.0.63）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：1.0.63
- 首次實作版本：1.0.63
- 最後核對日期：2026/11/09

使用者要求：

> API 限流依使用者計算

---

## 一、原因

- Web API 的限流寫死成**全站共用一個桶、每分鐘 120 次**，不分使用者。對外服務、外部用戶端變多時，一個人批次呼叫就會讓所有人一起收到 429（1.0.58 撰寫 API 授權測試時發現，見 [API 授權守門測試](2026-11-09-API授權守門測試.md) 第四節）。
- `UseRateLimiter()` 排在 `UseAuthentication()` 之前，限流時還不知道是誰，所以就算想分開算也做不到。
- 被擋時回 429 空 body，不符「Web API 一律包 `ApiResult`」。

## 二、修改

- 新增 `Web/Configuration/RateLimitSettings.cs`（`appsettings.json` 的 `RateLimitSettings`，啟動時驗證範圍）：`PermitLimitPerUser`（預設 120）、`PermitLimitPerAnonymousIp`（預設 30）、`WindowSeconds`（預設 60）。
- `AddConfiguredRateLimiting(configuration)`：`"api"` 政策改成依分區的固定時間窗——已登入 → `user:{帳號 Id}`（Cookie 的 Sid／JWT 的 NameIdentifier，與 `RecordAccessScopeProvider` 同樣兩個都看）；未登入（含登入、refresh）→ `ip:{來源 IP}`。分區鍵抽成 `ResolveRateLimitPartitionKey` 方便測試。
- 被擋時回 **429 `ApiResult`**（「請求太頻繁，請稍後再試。」）並帶 `Retry-After`。
- `Program.cs`：`UseRateLimiter()` 移到 `UseAuthentication()`／`UseAuthorization()` 之後。
- 測試主機：拿掉 1.0.58 那段「移除限流設定、換成幾乎不限」的特殊處理，改成用設定放寬；`ApiTestApplicationFactory` 的設定改成子類別可覆寫。
- 上傳分塊端點仍以 `[DisableRateLimiting]` 免除；網頁本身（Blazor 連線）不受影響。
- 文件：[日誌與設定檔說明](../operations/日誌與設定檔說明.md) §4.3.0.0、[正式部署與安全檢查清單](../operations/正式部署與安全檢查清單.md)、[Web API 設計慣例](../architecture/Web%20API%20設計慣例.md)、[開發慣例與限制速查](../architecture/開發慣例與限制速查.md) §4、[架構總覽](../architecture/架構總覽.md)（中介軟體順序）、[測試指南](../guides/測試指南.md)。
- 版本 1.0.62 → 1.0.63。

## 三、測試

- 新增 `RateLimitPartitionTests`（分區鍵 4 則＋預設值 1 則）、`RateLimitIntegrationTests`（限流調成每人／每 IP 3 次的測試主機：甲第 4 次 429 且 body 是 `ApiResult`、帶 `Retry-After`；乙同時照常 200；未登入依 IP 第 4 次 429）。
- 全套 1,858 則連跑兩次通過；端對端全套照跑。

## 四、部署時

- 預設值與原本的總量相近（每帳號 120／分），通常不必調整；外部用戶端用量大時調高 `PermitLimitPerUser`。
- 在反向代理後面要確認轉送標頭生效，否則所有未登入的人共用代理那一個 IP 的額度（30／分）。
