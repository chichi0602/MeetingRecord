# WASM 遷移 M1：WASM 前端專案與空殼頁（1.1.0 → 1.1.1）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：1.1.1
- 首次實作版本：1.1.1
- 最後核對日期：2026/11/09

使用者要求：

> 開始（M1 第二步：新增 WASM 前端專案與空殼頁）

---

## 一、原因

- 1.1.0 已讓 Web API 接受登入 Cookie。這一步建立瀏覽器端的 WASM 前端專案，做出能登入、看到依權限過濾的選單的空殼頁，作為之後逐頁搬移的基礎。
- 遷移採**逐頁切換**：已搬的頁在瀏覽器執行、其餘仍是 Blazor Server，分支隨時可用。

## 二、修改

- **新專案** `src/MeetingRecord/MeetingRecord.Web.Client`（Blazor WebAssembly，net10.0）：只參考 Dtos、Share；套件 AntDesign 1.6.0、`Microsoft.AspNetCore.Components.WebAssembly`／`Components.Authorization` 10.0.14。
  - `ClientRoutes`：WASM 端路由，遇到不在 `WasmRoutes` 的路徑就整頁載入（交給 Server 頁）。
  - `Api/ApiClient`：一律解成 `ApiResult<T>`，回應不是 ApiResult 也回失敗結果；401 整頁導到登入頁。`Api/ClientHeaderHandler` 每個請求帶 `X-MeetingRecord-Client`（1.1.0 的 CSRF 防護）。`Api/ClientJsonContext`：JSON 原始碼產生器（修剪後反射式序列化會出錯）。
  - `Auth/SessionService`、`SessionAuthenticationStateProvider`：依 `GET /api/v1/session` 建立登入身分，頁面可用 `AuthorizeView`。
  - `Layout/WasmLayout`：開頁先問 Session——未登入導到登入頁、刪除／停用／沒有角色導到登出頁並帶原因、須改密碼導到變更密碼頁；通過才畫側邊選單（`GET /api/v1/session/menu`）、使用者名稱與登出；`ErrorBoundary` 顯示錯誤。
  - `Pages/WasmHome`（`/wasm`）：「WASM 預覽」空殼頁。
- **共用** `Share/Helpers/WasmRoutes`：已改在瀏覽器執行的路徑（目前只有 `/wasm`），兩邊的 Router 都看這一份。
- **伺服器端**：
  - `Program.cs` 加 `AddInteractiveWebAssemblyComponents()` 與 `AddInteractiveWebAssemblyRenderMode().AddAdditionalAssemblies(Web.Client)`；Web 參考 Web.Client 與 `Microsoft.AspNetCore.Components.WebAssembly.Server` 10.0.14。
  - `App.razor`：WASM 路徑改畫 `ClientRoutes`（`InteractiveWebAssembly`，不預先算繪），其餘照舊。
  - `Routes.razor`：Server 端 Router 在 `OnNavigateAsync` 遇到 WASM 路徑就整頁載入。
- **套件版本**：WASM 相關套件用 10.0.14。一開始用 10.0.5，`Microsoft.AspNetCore.Components.WebAssembly.Server` 10.0.5 被 NuGet 標出兩個「高」嚴重性弱點（GHSA-g27p-qf6j-c96c、GHSA-qjpx-jqm5-h2c4），10.0.14 已無警告。
- **與計畫不同**：前端錯誤回報 API（`POST /api/v1/client-errors`）延後。現有的 `BrowserErrorReporter` 以「每條 Blazor 連線每分鐘 10 筆」限流、帳號取自連線；改成 HTTP API 要另做依帳號的限流，否則每人每分鐘可灌 120 筆到例外紀錄。WASM 版面先用 `ErrorBoundary` 顯示錯誤。
- 文件：[開發慣例與限制速查](../architecture/開發慣例與限制速查.md) §1、[架構總覽](../architecture/架構總覽.md)、[測試指南](../guides/測試指南.md)、[09 號遷移評估](../planning/09-Blazor-WASM-遷移評估與測試策略.md) 十、之二。

## 三、測試

- **可行性先驗證**：只建空專案與空頁時，先確認 Server 頁 → WASM（Server 頁內 `Blazor.navigateTo`）、WASM → Server 頁（點連結）、直接開網址都正常，才往下做。
- 新增端對端 `WasmShellTests`（計入 L3，共 8 則）：
  - WASM-01（管理者、主責、檢視者、甲方、無團隊）：`/wasm` 的選單連結集合與 Server 頁側邊欄完全相同，並顯示目前登入者；
  - WASM-02：WASM 與 Server 頁雙向切換；
  - WASM-03：未登入導到登入頁；
  - WASM-04：須改密碼導到變更密碼頁。
  - 抓錯檢查：伺服器選單改成人人當管理者 → WASM-01 四個非管理者人物失敗；拿掉改密碼導向 → WASM-04 失敗。驗完已還原。
- 新增 `WebClientArchitectureTests`：WASM 專案只能參考 Dtos／Share／Models、不可有 EF Core 或驗證套件。
- **修剪與大小**（`dotnet publish -c Release`）：修剪警告 0；Brotli 後 `_framework` 全部 `.br` 合計約 4.3 MB（含三個語系檔，瀏覽器只下載其中一個），在 5 MB 門檻內。最大的是 .NET 執行環境約 950 KB、AntDesign 約 790 KB、CoreLib 約 650 KB。
- 全套單元／API 與端對端照跑（含既有 89 則）。
