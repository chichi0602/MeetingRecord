# 上傳失敗顯示真正原因（1.0.66 → 1.0.67）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：1.0.67
- 首次實作版本：1.0.67
- 最後核對日期：2026/11/09

使用者要求：

> 先修小問題，再規劃 M1（1.0.66 L4 端對端測試發現的「登入過期時上傳的訊息不夠明確」）

---

## 一、原因

- 登入過期時上傳影音檔，畫面只顯示「影音檔上傳失敗。會議資料已保留…」，沒說是登入失效，使用者不知道要重新登入（1.0.66 的 L4-07 發現）。
- 瀏覽器端（`chunk-upload.js`）其實知道原因並回報伺服器——「登入已失效，請重新登入後再上傳。」「網路不穩，重試多次仍無法上傳…」、伺服器拒收的訊息，以及伺服器端的閒置逾時——但上傳工作階段丟的是一般 `IOException`，服務層分不出來，一律換成「影音檔上傳失敗」。專案附件也一樣，一律「{檔名} 讀取失敗，請重新選擇。」。

## 二、修改

- 新增 `Share/Helpers/UploadInterruptedException`（繼承 `IOException`，訊息就是給使用者看的原因）。放 Share 是因為 Web 要丟、Business 要認。
- `ChunkedUploadSession.Fail` 改丟這個型別。
- `MeetingService.SaveMediaAsync`：失敗原因是 `UploadInterruptedException` 時，畫面與右下角面板都顯示「影音檔上傳失敗：{原因}」（畫面照舊接「會議資料已保留…」）；其他例外照舊只顯示一般訊息，不秀內部細節。
- 專案頁選附件：同樣情況顯示「{檔名} 上傳失敗：{原因}」。
- 文件：[檔案上傳機制](../features/檔案上傳機制.md) §3.0.1；1.0.66 的 changelog 與基準報告附註註明已修。
- 版本 1.0.66 → 1.0.67。

## 三、測試

- `ChunkedUploadStoreTests`：中止與逾時改為驗證拿到 `UploadInterruptedException`、訊息照舊。
- `MeetingServiceTests`：瀏覽器放棄時回傳與面板都是「影音檔上傳失敗：網路不穩…」；一般串流錯誤仍是「影音檔上傳失敗。」。修正前這三則失敗。
- 端對端 L4-07 改為驗證通知含「登入已失效」：修正前失敗、修正後通過。
- 全套測試與端對端全套照跑。
