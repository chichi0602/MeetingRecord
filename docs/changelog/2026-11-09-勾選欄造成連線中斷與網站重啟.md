# 勾選欄造成連線中斷與網站重啟（1.0.58 → 1.0.59）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：1.0.59
- 首次實作版本：1.0.59
- 最後核對日期：2026/11/09

發現經過：實作分塊上傳（WASM 遷移前置工作 D）時用瀏覽器實測，在會議紀錄頁按「新增」存檔後連線立刻斷掉，接著整個伺服器行程當掉。用 1.0.55 的程式碼照同樣步驟重跑一樣會發生，確定是既有問題；使用者確認正式機也出現過「重新連線」與網站突然重啟。

決定（與使用者確認）：先修這個問題、獨立成一版，分塊上傳延到 1.0.60。

---

## 一、原因

- 1.0.53 加入清單多選時，**會議紀錄頁、專案頁歷史會議、待辦頁**三個清單用「這一頁有沒有可以刪（移除）的列」決定要不要畫勾選欄（`<Selection>`）。進頁面時資料還沒載入、每次存檔後重新載入，整欄就會一下有一下沒有。
- AntDesign 1.6.0（查過 1.6.2 原始碼也一樣）的 `Selection.Dispose` 寫的是 `Table?.Selection.Type`：表頭那顆 Selection 不在時 `Table.Selection` 是 null，清掉列上的 Selection 就丟 `NullReferenceException`。
  - 這個例外發生在 Blazor 算繪時，**連線當場斷掉**（使用者看到「重新連線」）；
  - `Dispose` 中途丟例外、沒走到取消 finalizer 那一步，之後垃圾回收時元件的 finalizer 又呼叫一次 `Dispose` 再丟一次——finalizer 執行緒的例外無法攔截，**整個伺服器行程直接結束**，所有人一起斷線，IIS 重啟應用程式集區。
- 其他七個清單（分類、團隊、提示詞、使用者、角色、AI 對話紀錄、Token 用量）的勾選欄是無條件出現或只看權限，權限在頁面存活期間不會變，所以沒事（實測分類清單連續新增不會發生）。

## 二、修改

- 三個清單的勾選欄改成**只看權限**，不能勾的列照舊用 `Disabled` 擋：
  - 會議紀錄頁：`ShowSelection` 改為有「會議紀錄：編輯」權限（刪除會議要求的就是 edit）。
  - 待辦頁：`ShowSelection` 改為有「待辦事項：編輯」權限。
  - 專案頁歷史會議：新增 `ShowDetachSelection`＝有「專案項目：編輯」或「刪除」權限（與 `CanDetach` 的權限部分相同；上傳者、封存專案在列上停用）。
- 畫面差異：有編輯權限但這一頁沒有任何可刪的列時，勾選欄仍會出現、只是全部停用（以前會整欄隱藏）。
- 新增 `TableSelectionColumnTests`：掃所有 `.razor` 的 `<Selection>`，包住它的 `@if` 只能是只由 `CheckAccessAction` 組成的屬性，以資料決定的條件會被擋下；另驗規則本身擋得下 1.0.53 的三種寫法。
- 文件：[開發慣例與限制速查](../architecture/開發慣例與限制速查.md) §6.11、[測試指南](../guides/測試指南.md)。
- 版本 1.0.58 → 1.0.59。

## 三、測試

- 新的守門測試在修改前列出三個違規頁面（會議、專案、待辦），修改後通過；全套 1,804 則通過。
- 瀏覽器實測（Edge 無頭模式，獨立的測試資料庫）：
  - 修改前：會議紀錄頁每次新增存檔都記到 `AntDesign.Selection.Dispose` 的例外，連線斷掉，之後伺服器行程結束（1.0.55 同樣重現）。
  - 只把會議頁條件改成權限的實驗：連續新增 3 筆，0 次例外、伺服器不中斷——證實是勾選欄出現／消失觸發的。
  - 正式修改後：連續新增 3 筆，0 次例外、0 次連線錯誤，伺服器持續正常。
- 專案頁與待辦頁是同一個寫法、同一個修法，沒有另外做瀏覽器實測（要先建立團隊、專案、會議歸屬等資料），由守門測試把關。

## 四、留意

- AntDesign 的這個缺陷本身還在（上游 1.6.2 未修）。只要勾選欄在有資料列時被拿掉就會再發生，所以規則寫進開發慣例並由測試把關；升級 AntDesign 時可以再確認上游是否修好。
