# 套件弱點修補（1.0.67 → 1.0.68）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：1.0.68
- 首次實作版本：1.0.68
- 最後核對日期：2026/11/09

使用者要求：

> 先在 main 修套件弱點（WASM 遷移 1.1.1 建置時 NuGet 稽核標出的兩個既有弱點）

---

## 一、原因

NuGet 稽核標出兩個既有弱點，正式機也有（與 WASM 遷移無關，遷移前就存在）：

| 弱點 | 嚴重度 | 怎麼進來的 |
|------|--------|------------|
| `System.Drawing.Common` 4.7.0（GHSA-rxg9-xrhp-64gj） | 危急 | Business 的 `OpenCCNET` 1.1.0（簡繁轉換，已是最新版）→ `jieba.NET` 0.42.2 → `System.Configuration.ConfigurationManager` 4.7.0 → `System.Security.Permissions` 4.7.0 → `System.Windows.Extensions` 4.7.0 → `System.Drawing.Common` 4.7.0 |
| `Microsoft.OpenApi` 2.4.1（GHSA-v5pm-xwqc-g5wc） | 高 | Web 的 `Swashbuckle.AspNetCore` 10.1.5 與 `Microsoft.AspNetCore.OpenApi` 10.0.5（Swagger 文件產生） |

## 二、修改

- `MeetingRecord.Business.csproj`：直接參考 `System.Configuration.ConfigurationManager` 10.0.14。新版不再相依 `Security.Permissions`／`Windows.Extensions`，帶進 `System.Drawing.Common` 的整條路徑斷掉（`dotnet nuget why` 確認已無相依）。`jieba.NET` 只要求 ≥ 4.7.0，相容；`OpenCCNET` 日後升版不再帶舊版時可拿掉這行。
- `MeetingRecord.Web.csproj`：`Swashbuckle.AspNetCore` 10.1.5 → 10.3.1、`Microsoft.AspNetCore.OpenApi` 10.0.5 → 10.0.14，`Microsoft.OpenApi` 隨之升到 2.12.2；程式不必改。
- 版本 1.0.67 → 1.0.68。

## 三、測試

- `dotnet build` 已無 NU1903／NU1904 弱點警告。
- 新增 `SwaggerDocumentTests`：升版後 API 文件仍產得出來，Bearer 安全定義還在（測試環境不開 Swagger UI，直接用產生器驗）。
- 全套單元／API 與端對端照跑（含簡繁轉換的既有測試）。

## 四、部署時

- 一般覆蓋部署即可，沒有設定或資料庫變更。
