# 部署檢查清單與 IIS 上傳實測（1.0.63 → 1.0.64）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：1.0.64
- 首次實作版本：1.0.64
- 最後核對日期：2026/11/09

使用者要求：

> 部署檢查清單與 IIS 上傳實測

---

## 一、原因

- 1.0.56～1.0.63 的改善（分塊上傳、勾選欄當機修正、表單 Enter 修正、限流依使用者）要在正式機（IIS）上真的生效，部署時需要一份集中的檢查清單。
- 1.0.60 起大檔上傳改走 `PUT /api/v1/uploads/...`。IIS 若裝了 WebDAV 發佈，會先攔下 PUT 回 405，本機 Kestrel 測不出來，只能在正式機上實際上傳一次才知道。

## 二、修改

- [正式部署與安全檢查清單](../operations/正式部署與安全檢查清單.md) 新增「升級到 1.0.56～1.0.64 時」：
  - 不需要資料庫 migration（`MeetingRecord.AccessDatas` 從 1.0.55 到 1.0.64 沒有任何異動，已用 `git diff` 確認）；
  - IIS 移除 WebDAV（附 `web.config` 片段）；
  - 分塊 8 MB，請求大小上限不必調整；
  - 新設定 `RateLimitSettings`；
  - 部署後的檢查：跑上傳實測、會議頁新增一筆確認沒有斷線、例外紀錄沒有 `AntDesign.Selection`、日期欄按 Enter 不會存檔。
- 新增 `scripts/Test-IisUpload.ps1 -BaseUrl -Account [-SizeMB 200] [-Project] [-Headed] [-IgnoreTlsErrors]`：密碼互動輸入（或預先設 `MEETINGRECORD_SMOKE_PASSWORD`），以環境變數呼叫端對端專案裡新的 `Smoke/DeploymentSmokeTests.cs`（`Category=DeploymentSmoke`，沒設 `MEETINGRECORD_SMOKE_URL` 時自動略過）。
- 實測流程：登入 → 專案頁（可指定專案）→ 編輯專案 → 選一個產生的 N MB 附件（選檔當下就以分塊傳到伺服器暫存）→ 等「待上傳檔案」出現並計時 → **取消並放棄**。不存任何資料、不呼叫付費 AI。
  - 通過：印出分塊數、耗時、平均速度；
  - 分塊回 405：明確提示 WebDAV 攔下 PUT；其他非 200 印出狀態碼與網址；
  - 登入失敗印出畫面上的錯誤訊息；指定的專案不在下拉裡會立刻列出看得到的前幾個專案；
  - 其他失敗寫出卡在哪一步，並在暫存資料夾存一張 `smoke-upload-failure-*.png` 截圖。
- [測試指南](../guides/測試指南.md) §3.2 補用法。
- 版本 1.0.63 → 1.0.64。

## 三、測試

- 對本機 Kestrel（`-BaseUrl http://127.0.0.1:5199`）實跑：200 MB／25 塊通過；`-Project` 指定專案通過；密碼錯誤顯示「登入失敗：帳號或者密碼不正確」；不存在的專案立刻失敗並列出可選專案；失敗時有截圖；跑完資料庫沒有新增 `ProjectFile`。
- 全套測試照跑，部署冒煙測試在沒有設定網址時為略過。
- IIS 正式機的實測由使用者在正式環境執行。

## 四、已知事項

- 實測時發現既有問題：專案附件存檔後，伺服器暫存資料夾（`%TEMP%\MeetingRecord\pending-uploads`）會留下一份暫存檔沒刪掉（存檔流程在檔案串流還開著時就刪暫存檔，Windows 上刪不掉）。本版未修，已於 1.0.65 修正，見 [專案附件暫存檔殘留修正](2026-11-09-專案附件暫存檔殘留修正.md)。
