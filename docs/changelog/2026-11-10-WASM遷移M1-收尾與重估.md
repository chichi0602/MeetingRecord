使用者要求：

## 一、原因

- M1 的完成條件是「空殼 WASM 在 IIS 測試機可登入、看到依權限過濾的選單；重估端點數」。目前沒有 IIS 測試機，本機也沒有安裝 IIS，所以改在本機以發佈輸出驗證能驗的部分，IIS 部署寫成草稿、測試機驗證標為待補。

## 二、修改

- **端對端 WASM-06**：發佈後的 `_framework` 檔案回 `Content-Encoding: br`；推播 `/hubs/app` 走 WebSocket（不是退回 LongPolling）；量首次與有快取的載入時間並寫進測試輸出（斷言放寬到 10／5 秒）。
- **部署草稿**：[正式部署與安全檢查清單](../operations/正式部署與安全檢查清單.md) 新增「WASM 版部署」：IIS 要開 WebSocket、`_framework` 由 ASP.NET Core 送出且已預先壓縮（IIS 動態壓縮不要再壓）、`web.config` 用發佈產生的、反向代理放行 WebSocket、部署後的檢查方式；標明「待補：尚無 IIS 測試機」。
- **重估端點數**：[09 號遷移評估](../planning/09-Blazor-WASM-遷移評估與測試策略.md) §4.3 改為逐方法盤點——UI 呼叫的服務方法 174 個、既有 API 已涵蓋 25 個、21 個可併入既有端點、約 128 個要新開，並依 M2（46）、M3（47）、M4（13）、M5（40）分配；§6 規模重估，M4 由 L 調為 M；M1 標完成（IIS 測試機驗證待補）。
- **報告腳本**：`scripts/New-TestReport.ps1`、`scripts/Run-E2E.ps1` 加 `-Milestone`（預設 M0，原本行為不變）；給 M1 時標題為「M1 里程碑報告」、檔名「…-M1-里程碑測試報告-版本.md」。
- **M1 測試報告** 入庫，見 [testing 索引](../testing/README.md)。
- 文件：[測試指南](../guides/測試指南.md)（WASM-06、`-Milestone`）。
- 版本 1.1.2 → 1.1.3。

## 三、測試與量測

- 全套單元／API 與端對端（含 WASM-01～06）照跑，產出 M1 報告。
- 本機量測：WASM 首次載入約 1.8～2.2 秒（門檻 ≤ 4 秒）、有快取約 1.7～1.9 秒（**超過 1.5 秒門檻**，主要是開頁時依序打 Session、選單、未讀數三支 API；M6 效能調校處理）；Brotli 下載量約 4.15 MB（門檻 ≤ 5 MB）。

## 四、M1 留下的待辦

- IIS 測試機驗證（有機器時照部署草稿與端對端測試驗）。
- 前端錯誤回報改走 API（要依帳號限流，1.1.1 延後）。
- 需改密碼的帳號以 Cookie 直接呼叫 API 尚未擋（M2 開放更多寫入 API 前補上，1.1.0 記錄）。
- 有快取的載入時間超過門檻（M6）。
- 1.1.2 同步 main 時全套偶發一次 MD-02（分類批次刪除）失敗，之後未再出現；再出現時保留網站日誌追查。
