- 文件狀態：已實作
- 現行系統版本：1.1.10
- 首次實作版本：1.1.10
- 最後核對日期：2026/11/10

使用者要求：

> 開始（M2 第七步：使用者管理搬到 WASM）

---

## 一、原因

- 照前幾頁的做法，把使用者管理搬到 WASM。這頁只限管理者，以前沒有任何使用者 API，要新開。
- 使用者資料帶密碼雜湊與 Salt，不能原樣送到瀏覽器。
- 「不能刪除自己」只有畫面的批次刪除會略過，單筆刪除、停用自己、拿掉自己的管理者身分、刪除或停用 support 都沒擋；改成經 API 之後一定要在伺服器擋。
- `MyUserService` 判斷「目前是誰在操作」只看 Blazor 才會填的 `CurrentUserService`，從 API 呼叫時稽核的操作者是空的，「替別人重設密碼」也會把自己當成別人。

## 二、修改

- **新屬性 `[AdminOnly]`**：已登入、啟用中而且是管理者才通過；不是管理者 403 並寫「缺少權限：管理者」稽核。授權守門測試認得它（可代替 `[HasPermission]`）。
- **新 `UserController`（`api/v1/User`，只限管理者）**：搜尋、單筆、新增、修改、刪除、啟用切換、批次加入／移出團隊、角色清單（標出新建帳號的預設角色）、啟用中的團隊。
  - 回應一律用新的 `UserDto`：**不含密碼雜湊、Salt、兩步驟驗證金鑰、Google 編號**；密碼只在新增或重設時單向送入。
  - 修改時先讀出原資料再套上可改的欄位，Google 登入綁定等畫面以外的欄位不會被清掉；額外角色與團隊沒帶就不動、密碼留白就不變。
- **`MyUserService`**：
  - 新規則：不能刪除或停用自己與 support、不能拿掉自己的管理者身分（以前只在畫面）。
  - 「目前操作者」改經 `IAuditActorProvider`（Blazor 頁看 `CurrentUserService`、API 從 claims 取），稽核操作者與「替別人重設密碼要對方改」在 API 呼叫時也正確。
  - 修正：修改時帶回 `LastProjectId`——以前管理者每編輯一次使用者，對方記住的「上次選的專案」就被清掉。
- **使用者管理頁搬到 WASM**：`Web.Client/Pages/Admins/MyUserPage`，由原本的 `MyUserView` 改寫（`git mv` 保留歷史）。畫面、文字、確認框、通知都不變；守門改成 `PermissionView.IsAdmin`；角色下拉改用逐項列出（原本依屬性名稱反射取值，WASM 修剪後不保證留得住）；資料改走新的 `UserApi`。`WasmRoutes` 加 `/myusers`。
  - 順手修正：以前新增、修改使用者即使存檔失敗也顯示成功，現在會顯示失敗原因、表單留著。
- 文件：[開發慣例與限制速查](../architecture/開發慣例與限制速查.md) §1（`[AdminOnly]`、服務層取操作者、整筆蓋回時 API 先讀原資料）、[認證授權與權限機制](../security/認證授權與權限機制.md)、[Web API 端點目錄](../architecture/Web%20API%20端點目錄.md)、[使用者管理 PRD](../prd/使用者管理-prd.md)、畫面與欄位字典、對話窗規範、09 號「十、之三」。
- 版本 1.1.9 → 1.1.10。

## 三、測試

- 新增 `UserApiTests`：
  - 只限管理者：沒登入 401；有「使用者管理」權限鍵的非管理者也 403，並留稽核；
  - 單筆與清單的原始回應都沒有 password、salt、twoFactorSecret、googleId；
  - 新增沒密碼 400、帳號重複 409；
  - 修改只改名字時，Google 綁定、上次選的專案、密碼雜湊、須改密碼標記、團隊都保留；帶空陣列才清空團隊；稽核的操作者是 API 呼叫者；
  - 替別人重設密碼要對方下次改，改自己的不會；
  - 刪除自己、停用自己、拿掉自己的管理者身分、刪除或停用 support 都回 400 與原因，資料沒變；
  - 批次加入／移出團隊回實際人數，團隊不存在 404；角色清單標出預設角色。
- 授權守門測試改成也認 `[AdminOnly]`；`FormEnterGuardTests` 的表單清單改指 WASM 專案。
- 端對端：ADM-01、ADM-04（`/myusers`）一行不改照過；新增 ADM-05：修改使用者加入團隊甲、勾選後批次加入團隊乙（資料庫確認兩個都在）、停用再啟用，點自己那列的狀態要停用時出現「不能停用自己的帳號」。
- 抓錯檢查：拿掉「不能刪除自己」、拿掉 `[AdminOnly]`、拿掉 `LastProjectId` 帶回 → 對應的測試都失敗。驗完已還原。
- 全套單元／API 與端對端照跑。
