# WASM 遷移 M2：共用元件與版面外框搬到 WASM 專案（1.1.4 → 1.1.5）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：1.1.5
- 首次實作版本：1.1.5
- 最後核對日期：2026/11/10

使用者要求：

> 開始（M2 第二步：共用元件與版面外框搬到 Client，WASM 頁外觀與現有頁面一致）

---

## 一、原因

- M2 要把一般 CRUD 頁搬到 WASM。這些頁面用到的共用元件（提示、按鈕、批次操作列、表單輔助、對話窗樣式）原本都在 Blazor Server 專案，WASM 前端用不到；WASM 頁的外框也只是 M1 的簡易版，跟現有頁面長得不一樣。

## 二、修改

- **共用元件搬到 `MeetingRecord.Web.Client/Components/Commons`，命名空間不變**：HoverTip、CrudActionButton、BatchSelectionBar、StatusToggleTag、InputWatcher、FormKeyboardHelper、FormSubmitGate、FormDirtyHelper、BatchRunner 系列、FormModalHelper（連同各自的樣式）。資料夾的 `_Imports.razor` 以 `@namespace` 維持 `MeetingRecord.Web.Components.Commons`；Web 參考 Client，Server 頁照用，舊頁面與測試不必改。上傳、Markdown 編輯器、各 Interop 等 M2 用不到的留到 M3。
- **側邊選單改吃 `MenuItemDto` 並搬到 Client**：NavMenu、SidebarMenuNode、SidebarMenuSectionBuilder。NavMenu 不再自己做登入檢查、載選單（以前與 MainLayout 各載一次），改由外框傳入選單與系統名稱。伺服器端的轉換抽成 `MenuItemMapping`（Session 選單 API 與 MainLayout 共用）。
- **全站外框 `AppShell`**（Client）：原本 MainLayout 的版面、側邊欄收合、頂端列（頁面標題）、使用者選單、變更密碼與關於對話窗、`FormModalHelper`、`#blazor-error-ui`。資料與動作由參數傳入，通知鈴與進度面板用插槽。
  - Server 頁的 `MainLayout` 改成供應伺服器資料給 AppShell，外觀與行為不變；通知鈴、進度面板、瀏覽器錯誤回報照舊。
  - WASM 頁的 `WasmLayout` 改用 AppShell，外觀與 Server 頁相同；變更密碼與關於在 1.1.6 接上 API 前先不顯示，通知先只顯示未讀數。
  - 頁面標題比對網址時去掉查詢字串（以前 `/todos?todoId=…` 會顯示成預設標題「系統首頁」）。
- **`RZ10012` 設為編譯錯誤**（Web 與 Web.Client）：找不到元件時 Razor 只發警告，標籤會被當成普通 HTML 原樣輸出、畫面整塊不見。這次就踩到——Client 少了一行 `@using`，WASM 頁的外框整個沒畫出來，端對端測試才抓到。
- Client 加 `BlazorMaterialIcons` 0.0.1。
- 文件：[開發慣例與限制速查](../architecture/開發慣例與限制速查.md) §1、[架構總覽](../architecture/架構總覽.md)、09 號「十、之三」。
- 版本 1.1.4 → 1.1.5。

## 三、測試

- 原始碼掃描測試新增共用的 `ComponentSourceRoots`，同時掃 `MeetingRecord.Web/Components` 與 `MeetingRecord.Web.Client`（排除 `bin`／`obj`）：ModalSizeClass、HoverTipUsage、RazorMarkup、TableSelectionColumn、FontUsage。
- `LayoutMountTests` 改為檢查：MainLayout 有 AppShell、通知鈴、進度面板；AppShell 有對話窗樣式、錯誤提示列與兩個插槽；WasmLayout 有 AppShell。
- 選單測試改用 `MenuItemDto`，新增 `MenuItemMapping` 的轉換測試（分區、圖示、子項第三層）。
- 端對端 WASM-01 改成兩邊用同一個選擇器比對側邊欄連結，並檢查 WASM 頁的頁面標題與使用者名稱；MNU-01（側邊選單依人物）等 Server 頁情境照過。
- 驗證 `RZ10012` 防護：拿掉那行 `@using`，建置直接失敗。
- 全套單元／API 與端對端照跑。

## 四、留待後續

- `FormDirtyHelper`（反射式 JSON）在 WASM 修剪後是否正常，要等 1.1.6 WASM 的變更密碼對話窗接上 API 才實測。
