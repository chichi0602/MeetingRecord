# WASM 遷移 M2：分類清單搬到 WASM（1.1.6 → 1.1.7）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：1.1.7
- 首次實作版本：1.1.7
- 最後核對日期：2026/11/10

使用者要求：

> 開始（M2 第四步：第一個實際頁面「分類清單」搬到 WASM）

---

## 一、原因

- M2 要把一般 CRUD 頁逐頁搬到 WASM。分類清單最單純，先拿它定下後面幾頁的做法。
- 分類 API 原本走另一份 `CategoryRepository`，規則跟畫面不一致：例如名稱重複，API 只擋完全相同的字，畫面則是去頭尾空白、不分大小寫。WASM 頁要經 API 拿資料，兩邊必須是同一套規則（使用者 2026/11/10 決定：既有 API 改走同一套規則並擴充）。

## 二、修改

- **分類 API 改呼叫 `CategoryService`**（路由、權限、回傳型別不變）：
  - 新增與修改先跑畫面用的同一個檢查，名稱重複回 409；找不到回 404。
  - 新增與修改可帶 `teamIds` 同步「負責團隊（參考）」；**沒帶就不動**、帶空陣列才清空，舊呼叫端不會把團隊清掉。
  - 新增 `PUT /api/v1/Category/{id}/enabled`（切換啟用，要修改權限）與 `GET /api/v1/Category/teams/selectable`（可選團隊，要檢視權限）。
  - 搜尋保留原本的「依啟用狀態篩選」與「依建立時間排序」（服務補上這兩個選項，畫面呼叫方式不變）。
  - 稽核照舊標 `via=Api`（服務的新增、修改、刪除加 `via` 參數，預設仍是 `Web`）。
  - `CategoryRepository` 與對應的物件對應設定沒人用了，已刪除。
- **分類頁搬到 WASM**：`Web.Client/Pages/Categories/CategoryPage`，由原本的 `CategoryViewView` 改寫（`git mv` 保留歷史）。畫面、文字、按鈕、確認框、通知、Enter 送出防連按、未存檔離開確認都不變；資料改走新的 `CategoryApi`。`WasmRoutes` 加 `/categories`，從其他頁點過去是整頁載入。
  - 順手修正：以前新增分類即使存檔失敗也顯示「新增成功」，現在會顯示失敗原因、表單留著。
- **`PermissionView`**（`Web.Client/Auth`）：WASM 頁依 Session API 的權限鍵決定能不能進頁、顯示哪些按鈕，規則與 Server 頁相同。之後幾頁共用。
- WASM 端 `ApiClient` 加 PUT 與 DELETE。
- 文件：[開發慣例與限制速查](../architecture/開發慣例與限制速查.md) §1（API 走服務層、`PermissionView`、搬頁固定動作）、[認證授權與權限機制](../security/認證授權與權限機制.md)、[Web API 端點目錄](../architecture/Web%20API%20端點目錄.md)、[分類清單 PRD](../prd/分類清單-prd.md)、架構總覽、畫面與欄位字典、對話窗與介面視覺規範、新 CRUD 說明、09 號「十、之三」。
- 版本 1.1.6 → 1.1.7。

## 三、外部程式看得到的行為變更（分類 API）

| 項目 | 1.1.6 以前 | 1.1.7 起 |
|------|-----------|---------|
| 名稱重複 | 只擋完全相同的字；訊息「分類名稱 'x' 已存在」 | 去頭尾空白、不分大小寫；訊息「分類名稱已存在，無法新增。」／「…無法修改。」 |
| 回應內容 | 分類欄位 | 多了 `teamIds`、`teamNames` |
| 新增、修改 | 不處理團隊 | 可帶 `teamIds` 同步團隊；沒帶不動 |
| 搜尋的排序 | 只依指定欄位 | 指定欄位相同時再依編號排序（與畫面一致） |
| 新端點 | — | `PUT {id}/enabled`、`GET teams/selectable` |

## 四、測試

- 新增 `CategoryApiTests`：名稱大小寫或前後空白不同算重複（409）；新增帶團隊會同步、修改沒帶團隊保留、帶空陣列清空；修改撞名 409、不存在 404；啟用切換有寫稽核、新增稽核是 `via=Api`；搜尋依啟用狀態篩選、排序欄位名不分大小寫；可選團隊只有啟用中的。
- 新增 `PermissionViewTests`：進頁規則與伺服器的 `CanAccessPage` 逐條對照；動作規則（動作鍵或整頁鍵、管理者）。
- 授權矩陣加啟用切換與可選團隊（401／缺該動作 403 並留稽核／只有該動作成功）。
- `FormEnterGuardTests` 的表單清單改成可指到 WASM 專案；`TableSelectionColumnTests` 的規則也認 `PermissionView.Can`（補回歸案例）。
- 端對端：MD-01、02、05、06 一行不改照過（現在測的是 WASM 版）；新增 WASM-09：從 Server 頁切到分類清單、資料走分類 API、點「名稱」排序會把排序條件送給伺服器（確認修剪後排序欄位名正確）。
- 抓錯檢查：讓修改在沒帶 `teamIds` 時也同步團隊 → `CategoryApiTests` 的團隊保留案例失敗。驗完已還原。
- 全套單元／API 與端對端照跑。
