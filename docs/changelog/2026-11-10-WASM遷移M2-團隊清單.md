- 文件狀態：已實作
- 現行系統版本：1.1.8
- 首次實作版本：1.1.8
- 最後核對日期：2026/11/10

使用者要求：

> 開始（M2 第五步：團隊清單搬到 WASM）

---

## 一、原因

- 照 1.1.7 分類清單定下的做法，把團隊清單搬到 WASM。
- 團隊 API 原本走另一份 `TeamRepository`，規則跟畫面不一致（例如名稱、代號重複，API 只擋完全相同的字）。
- 團隊頁的編輯視窗要列出可加入的帳號（全公司啟用帳號的姓名與帳號）。現在只有能新增或修改團隊的人會打開那個視窗；搬到 WASM 後要開 API，使用者 2026/11/10 決定：**只有新增或修改權限拿得到，只有檢視權限拿不到**。

## 二、修改

- **`[HasPermission]` 支援任一動作即可**：`[HasPermission(頁, new[] { 動作A, 動作B })]`，有其中一個權限就通過；403 訊息與稽核寫「缺少權限：頁:動作A 或 頁:動作B」。原本的寫法行為不變。
- **團隊 API 改呼叫 `TeamService`**（路由、權限、回傳型別不變）：
  - 新增與修改先跑畫面用的同一個檢查，名稱或代號重複回 409；找不到回 404。
  - 新增與修改可帶 `memberIds` 同步成員；**沒帶就不動**、帶空陣列才清空。清單帶成員數，單筆另帶成員編號。
  - 刪除先跑「還是不是專案主責團隊」的檢查（非管理者回 409，管理者照刪），與畫面相同。
  - 新增 `GET /api/v1/Team/{id}/delete-check`（畫面在跳確認框之前先問能不能刪）、`PUT /api/v1/Team/{id}/enabled`（切換啟用）、`GET /api/v1/Team/members/selectable`（可選成員，要新增或修改權限）。
  - 搜尋保留「依啟用狀態篩選」與「依建立時間排序」；稽核照舊標 `via=Api`。
  - `TeamRepository` 與對應的物件對應設定沒人用了，已刪除。
- **團隊頁搬到 WASM**：`Web.Client/Pages/Teams/TeamPage`，由原本的 `TeamViewView` 改寫（`git mv` 保留歷史）。畫面、文字、確認框、通知都不變；單筆刪除照舊先檢查、不能刪就不跳確認框；資料改走新的 `TeamApi`。`WasmRoutes` 加 `/teams`。
  - 順手修正：以前新增團隊即使存檔失敗也顯示「新增成功」，現在會顯示失敗原因、表單留著。
- 文件：[開發慣例與限制速查](../architecture/開發慣例與限制速查.md) §1（任一動作授權、刪除前檢查端點）、[認證授權與權限機制](../security/認證授權與權限機制.md)、[Web API 端點目錄](../architecture/Web%20API%20端點目錄.md)、[團隊清單 PRD](../prd/團隊清單-prd.md)、架構總覽、資料模型、畫面與欄位字典、對話窗規範、09 號「十、之三」。
- 版本 1.1.7 → 1.1.8。

## 三、外部程式看得到的行為變更（團隊 API）

| 項目 | 1.1.7 以前 | 1.1.8 起 |
|------|-----------|---------|
| 名稱、代號重複 | 只擋完全相同的字；訊息「團隊名稱 'x' 已存在」等 | 去頭尾空白、不分大小寫；訊息「團隊名稱已存在，無法新增。」／「團隊代號已存在，無法修改。」等 |
| 回應內容 | 團隊欄位 | 多了 `memberCount`；單筆另有 `memberIds` |
| 新增、修改 | 不處理成員 | 可帶 `memberIds` 同步成員；沒帶不動 |
| 刪除 | 主責團隊回 409、找不到 404 | 相同（改由服務層判斷） |
| 新端點 | — | `GET {id}/delete-check`、`PUT {id}/enabled`、`GET members/selectable`（新增或修改權限） |

## 四、測試

- 新增 `TeamApiTests`：名稱或代號大小寫、前後空白不同算重複（409）；新增帶成員會同步、修改沒帶成員保留、空陣列清空，搜尋的成員數跟著變；非管理者刪主責團隊時 delete-check 與刪除都 409、團隊還在，管理者照刪；啟用切換有稽核、新增稽核是 `via=Api`；搜尋依啟用狀態篩選、依代號排序；可選成員只有啟用中的帳號。
- 授權：矩陣加啟用切換與刪除前檢查；新增 `TeamSelectableMembers_ShouldRequireCreateOrEdit`（沒登入 401；只有檢視與刪除 403、稽核寫「…:create 或 …:edit」；只有新增或只有修改都成功）。這組整合測試同時涵蓋 `[HasPermission]` 任一動作的判斷，沒有另寫屬性的單元測試。
- `FormEnterGuardTests` 的表單清單改指 WASM 專案。
- 端對端：MD-03 一行不改照過；新增 MD-07：管理者修改團隊、加一位成員（資料庫確認成員已寫入）、再刪除（先檢查、再確認）。
- 抓錯檢查：拿掉 API 刪除的主責檢查 → `TeamApiTests` 的主責團隊案例失敗；把成員清單改成只要檢視權限 → 任一動作授權測試失敗。驗完已還原。
- 全套單元／API 與端對端照跑。
