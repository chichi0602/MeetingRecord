# WASM 遷移 M2：變更密碼頁與設定 API 密碼頁搬到 WASM（1.1.12 → 1.1.13）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：1.1.13
- 首次實作版本：1.1.13
- 最後核對日期：2026/11/10

使用者要求：

> M2 剩下的工作一次做完（1.1.12～1.1.14 連續做、每版自動 commit），接著做 M3。

## 一、原因

- 照前幾頁的做法，把 `/ChangePassword`（變更密碼）與 `/Profile`（設定 API 密碼）搬到 WASM。
- 這兩頁原本直接注入 `MyUserService`，WASM 頁要改走 API；而且須改密碼的帳號會被 WASM 版面導到 `/ChangePassword`，這頁搬到 WASM 後不能導向自己。

## 二、修改

- **新增 3 支 API**（`AccountController`，只需登入、只動呼叫者自己，規則與訊息照原頁）：
  - `POST /api/v1/account/change-own-password`：要確認新密碼、沒有字數下限、稽核記 `via=FirstLogin`；須改密碼的帳號也能呼叫，改完清掉標記。
  - `GET /api/v1/account/password-status`：回自己有沒有本地密碼，設定 API 密碼頁用來決定要不要顯示「目前密碼」。
  - `POST /api/v1/account/api-password`：已有本地密碼要驗目前密碼，還沒有的（例如 Google 帳號）免驗。
  - 失敗回 400，訊息放 `ErrorMessage`；support 帳號一律被拒。
- **兩頁搬到 WASM**（`Web.Client/Pages/Account/`）：畫面、文字、表單驗證、成功訊息都不變；帳號與是不是 support 改從 Session 取；成功或取消後整頁載入 `/meetings`（會議頁還是舊版頁面）。
- **避免導向自己**：`WasmLayout` 對須改密碼的帳號導到 `/ChangePassword`，但目前就在這頁時照常畫出；`ApiClient` 在這頁收到「須改密碼」的 403 也不再導向。
- `WasmRoutes` 加 `/ChangePassword`、`/Profile`（比對不分大小寫）。
- 文件：[登入與帳號流程 PRD](../prd/登入與帳號流程-prd.md)、[Web API 端點目錄](../architecture/Web%20API%20端點目錄.md)、[認證授權與權限機制](../security/認證授權與權限機制.md)、[密碼種類與儲存機制](../security/密碼種類與儲存機制.md)、畫面與欄位字典、09 號「十、之三」。
- 版本 1.1.12 → 1.1.13。

## 三、外部可見的行為變更

| 項目 | 以前 | 現在 |
|---|---|---|
| 變更密碼頁、設定 API 密碼頁 | 只有網頁畫面 | 另有對應的 API，規則相同 |
| 對外既有 API | — | 不變 |

## 四、測試

- 新增 `AccountPasswordPagesApiTests`：
  - 變更密碼：目前密碼錯、兩次不一致都回 400 加原頁訊息；須改密碼的帳號可以改，改完標記清掉，稽核是 `via=FirstLogin`；support 被拒。
  - 設定 API 密碼：已有本地密碼要驗目前密碼；清掉本地密碼後免驗；設定後能用新密碼呼叫 `/api/v1/auth/login` 取得權杖。
- 授權守門白名單加 3 支端點並寫明理由。
- 端對端：
  - LGN-04、WASM-04 一行不改照過。
  - 新增 **LGN-08**：新建一個須改密碼的帳號，登入後導到 WASM 版變更密碼頁，改完導到會議頁、不再被導回，資料庫的標記已清掉。
  - 新增 **ACC-01**：新建一般帳號，在設定 API 密碼頁設定新密碼後，用帳號加新密碼呼叫 API 登入成功。
- 抓錯檢查：拿掉 `WasmLayout` 對變更密碼頁的例外 → LGN-08 失敗。驗完已還原。
- 全套單元／API 與端對端照跑。
