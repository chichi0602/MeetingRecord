# WASM 遷移 M2：提示詞清單搬到 WASM（1.1.8 → 1.1.9）

- 文件狀態：已實作
- 現行系統版本：1.1.9
- 首次實作版本：1.1.9
- 最後核對日期：2026/11/10

使用者要求：

> 開始（M2 第六步：提示詞清單搬到 WASM）

## 一、原因

- 照 1.1.7、1.1.8 的做法，把會議紀錄提示詞清單搬到 WASM。
- 提示詞 API 原本走另一份 `PromptTemplateRepository`，規則跟畫面不一致：名稱只擋完全相同的字；分類欄位 `categories` 是資料庫的原始儲存字串，外部程式傳成別的格式就直接存進去，之後分類篩選對不到。
- 「建立內建範本」「新增單一範本」的內容與未知變數檢查都在 Business，WASM 頁拿不到。

## 二、修改

- **提示詞 API 改呼叫 `PromptTemplateService`**（路由、權限、回傳型別不變）：
  - 新增與修改先跑畫面用的同一個檢查，名稱重複回 409；找不到回 404。
  - **分類**：DTO 多了 `categoryNames`（名稱清單）。有帶就以它為準；沒帶才看舊欄位 `categories`（儲存格式），兩個都沒帶＝沒有分類（跟以前修改時一樣會清空）。存檔時一律正規化（去空白、去重複），回應兩個欄位都有。
  - 新增 `PUT {id}/enabled`（切換啟用）、`GET presets`（內建範本名稱）、`POST presets`（一次建立全部，可重複按）、`POST presets/single`（只新增一個；已存在 409、不在清單 404）、`GET categories/enabled`（啟用中的分類名稱）。內建範本的規則從畫面搬進 Controller。
  - 搜尋保留「依啟用狀態篩選」；稽核照舊標 `via=Api`。
  - `PromptTemplateRepository` 與對應的物件對應設定沒人用了，已刪除。服務的新增會回填新的編號（API 要回傳新建的那筆）。
- **`PromptVariableHelper` 搬到 `MeetingRecord.Share`**：伺服器產生會議紀錄與 WASM 頁共用，WASM 頁照舊「只提醒、不阻擋」未知變數。內建範本 `PromptTemplatePresets` 留在 Business，前端經 API 拿名稱。
- **提示詞頁搬到 WASM**：`Web.Client/Pages/PromptTemplates/PromptTemplatePage`，由原本的 `PromptTemplateViewView` 改寫（`git mv` 保留歷史）。畫面、文字、確認框、通知、狀態欄的按鈕與無障礙說明都不變；資料改走新的 `PromptTemplateApi`。`WasmRoutes` 加 `/prompttemplates`。
  - 順手修正：以前新增、修改提示詞即使存檔失敗也顯示成功，現在會顯示失敗原因、表單留著。未知變數的提醒改成存檔成功後才出現。
- 原計畫的「搜尋加分類篩選」這版不做：畫面沒有分類篩選，外部 API 也沒用到。
- 文件：[開發慣例與限制速查](../architecture/開發慣例與限制速查.md) §1（WASM 頁要用的純邏輯放 Share）、[認證授權與權限機制](../security/認證授權與權限機制.md)、[Web API 端點目錄](../architecture/Web%20API%20端點目錄.md)、[會議紀錄提示詞 PRD](../prd/會議紀錄提示詞-prd.md)、會議紀錄產生流程 PRD、架構總覽、畫面與欄位字典、對話窗規範、09 號「十、之三」。
- 版本 1.1.8 → 1.1.9。

## 三、外部程式看得到的行為變更（提示詞 API）

| 項目 | 1.1.8 以前 | 1.1.9 起 |
|------|-----------|---------|
| 名稱重複 | 只擋完全相同的字；訊息「提示詞名稱 'x' 已存在」 | 去頭尾空白、不分大小寫；訊息「提示詞名稱已存在，無法新增。」／「…無法修改。」 |
| 分類 | `categories` 原樣存進資料庫 | 新欄位 `categoryNames` 優先；舊欄位照儲存格式解析；一律正規化後再存 |
| 回應內容 | `categories`（儲存字串） | 多了 `categoryNames` |
| 搜尋的排序 | 只依指定欄位 | 指定欄位相同時再依編號排序（與畫面一致） |
| 新端點 | — | `PUT {id}/enabled`、`GET`／`POST presets`、`POST presets/single`、`GET categories/enabled` |

## 四、測試

- 新增 `PromptTemplateApiTests`：名稱大小寫或前後空白不同算重複（409）；`categoryNames` 會正規化、舊欄位 `categories` 照樣認得、回應兩個欄位都有、存好的分類篩選對得到、修改帶 `categoryNames` 會取代；內建範本名稱清單、建立全部可重複呼叫（第二次全部略過）、單一範本已存在 409／不在清單 404／成功回新建資料；啟用切換有稽核、新增稽核是 `via=Api`；啟用分類清單只有啟用中的；搜尋依啟用狀態篩選與名稱排序。
- 授權矩陣加啟用切換、內建範本三支、啟用分類清單。
- 既有的 `PromptVariableHelperTests`、`PromptTemplatePresetsTests` 照過（只改命名空間）。
- `FormEnterGuardTests` 的表單清單改指 WASM 專案。
- 端對端：MD-04 一行不改照過；新增 MD-08：選一個內建範本「新增此範本」、再按一次出現「已存在，未新增」；修改時選分類、內容加 `{{foo}}`，出現「提示詞變數提醒」且照樣存檔，資料庫確認分類與內容已寫入。
- 抓錯檢查：讓 API 忽略 `categoryNames` → 分類案例失敗；拿掉單一範本的重複檢查 → 409 案例失敗。驗完已還原。
- 全套單元／API 與端對端照跑。
