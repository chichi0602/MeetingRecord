# WASM 遷移 M2：角色管理搬到 WASM（1.1.10 → 1.1.11）

- 文件狀態：已實作
- 現行系統版本：1.1.11
- 首次實作版本：1.1.11
- 最後核對日期：2026/11/10

使用者要求：

> 開始（M2 第八步：角色管理搬到 WASM）

---

## 一、原因

- 照前幾頁的做法，把角色管理搬到 WASM。這頁只限管理者，以前沒有角色 API。
- 權限矩陣是一棵樹（群組 → 頁面 → 動作），存檔時才轉成權限鍵；以前沒有任何地方檢查樹裡的名稱是否在權限目錄裡，改成經 API 之後，任意名稱都可能變成權限鍵。
- 「建立預設角色」的確認框寫「四個角色」，1.0.55 加了甲方之後實際是五個。

## 二、修改

- **新 `RoleController`（`api/v1/Role`，只限管理者 `[AdminOnly]`）**：搜尋（不帶權限樹）、單筆（含權限樹）、權限範本（全部未勾選）、新增、修改、刪除、使用人數、建立預設角色。
  - **權限樹檢查**：群組、頁面都要在權限目錄的同一群組裡，動作要在檢視／新增／編輯／刪除／匯出，否則 400「權限項目「X」不在權限目錄裡。」。只限管理者的頁面本來就刻意不在目錄裡，經 API 也勾不到。
  - 修改時建立時間沿用原值（服務整筆蓋回資料庫）；沒帶權限樹＝權限不變。
  - 權限樹的 DTO（`Dtos/Roles`）與伺服器的模型欄位相同，Controller 負責互轉。
- **`RoleViewService`**：「目前操作者」改經 `IAuditActorProvider`（同 1.1.10 使用者管理），API 呼叫時稽核的操作者正確；新增會回填新的編號。
- **角色管理頁搬到 WASM**：`Web.Client/Pages/Admins/RoleViewPage`，由原本的 `RoleViewView` 改寫（`git mv` 保留歷史）。畫面、權限矩陣的勾選連動、文字都不變；清單不帶權限樹，修改時再取單筆；資料改走新的 `RoleApi`。`WasmRoutes` 加 `/roleviews`。
  - 修正：「建立預設角色」確認框改成「管理者、一般使用者、檢視者、主管、甲方五個角色」（系統使用說明同步修正）。
  - 修正：以前新增、修改角色即使存檔失敗也顯示成功，現在會顯示失敗原因、表單留著。
- 沒掛路由的示範檔 `RoleViewViewSample` 原本借用舊頁的類別當記錄器分類，舊頁搬走後改用它自己的類別（只改這一處，檔案保留）。
- 文件：[認證授權與權限機制](../security/認證授權與權限機制.md)、[Web API 端點目錄](../architecture/Web%20API%20端點目錄.md)、[角色管理 PRD](../prd/角色管理-prd.md)、系統使用說明、新 CRUD 說明（加註藍本已搬到 WASM）、畫面與欄位字典、對話窗規範、09 號「十、之三」。
- 版本 1.1.10 → 1.1.11。

## 三、測試

- 新增 `RoleApiTests`：
  - 只限管理者：沒登入 401；有「角色管理」權限鍵的非管理者也 403，並留稽核；
  - 權限樹（群組＋只勾「分類清單：檢視」＋「提示詞清單（全部）」）存成的權限鍵正確，讀回的樹勾選一致；稽核的操作者是 API 呼叫者；
  - 目錄外的頁面、目錄外的動作都 400，角色沒有建立；名稱重複 409；
  - 權限範本就是完整目錄、全部未勾；
  - 刪除有人用的角色：使用人數 1、刪除後那個人改用其他角色；
  - 建立預設角色第二次全部略過。
- `FormEnterGuardTests` 的表單清單改指 WASM 專案。
- 端對端：ADM-03、ADM-04（`/roleviews`）一行不改照過；ADM-02 多一行驗確認框寫「甲方五個角色」；新增 ADM-06：新增只勾「分類清單：檢視」的角色，資料庫的權限鍵有 `分類清單:view`、沒有 `分類清單:create` 與整頁鍵，再刪除（確認框寫「確定要刪除「x」嗎？」）。
- 抓錯檢查：拿掉權限樹檢查、拿掉 `[AdminOnly]` → 對應的測試都失敗。驗完已還原。
- 全套單元／API 與端對端照跑。
