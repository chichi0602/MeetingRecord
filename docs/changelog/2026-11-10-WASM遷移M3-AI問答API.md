## 一、原因

- 會議頁與專案頁上都有「AI 問答」視窗（`AiChatModal`），視窗直接呼叫 `AiChatService`；WASM 頁要經 API。
- 問答會邊產生邊顯示，API 也要能串流。
- 依相依關係先做 AI 問答：
  - 這版做 API；
  - 下一版把視窗搬到 WASM 專案；
  - 再下一版才搬會議頁。
  - 之後的版本號順延。

## 二、修改

- **新增 `AiChatController`**（`api/v1/ai-chat/{project|meeting}/{targetId}/...`，10 支）：
  - 對話：清單、開新對話、改名、刪除；
  - 訊息：歷史、修改訊息；
  - 提問與重新產生（串流）；
  - 讀附件、匯出 PDF。
  - 規則都在 `AiChatService`：資料範圍、附件格式與大小、額度與用量帳本。
- **串流**：
  - 回應是 `application/x-ndjson`，每行一筆：零到多筆 `delta`（新產生的文字），最後一筆 `done`（完整結果）或 `error`（原因）；
  - 在第一段文字產生之前就失敗的，照一般 API 回 404 或 400，畫面可以照舊顯示原因；
  - 連線斷了，產生也跟著停。
- **權限依範圍決定**（新屬性 `AiChatPermissionAttribute`）：
  - 專案範圍看專案項目，會議範圍看會議紀錄或專案項目，與兩個入口的畫面一致；
  - 改名、修改訊息、重新產生要修改權限，刪除要刪除權限，匯出要匯出權限——以前只在畫面上判斷；
  - 授權核心與 `[HasPermission]` 共用（抽成 `HasPermissionAttribute.AuthorizeAsync`），授權守門掃描也認得它。
- **安全**：
  - 附件只認對話檔裡真的有的（用磁碟檔名找），不收用戶端給的檔案資訊；
  - PDF 內容一律由伺服器從對話檔讀；
  - 下載文件附件與匯出 PDF 寫稽核（摘要多 `via=Api`）。
- 文件：
  - [AI 問答 PRD](../prd/AI問答-prd.md)、[Web API 端點目錄](../architecture/Web%20API%20端點目錄.md)；
  - [認證授權與權限機制](../security/認證授權與權限機制.md)、[開發慣例與限制速查](../architecture/開發慣例與限制速查.md)（依路由決定權限的屬性、串流回應）；
  - 09 號「十、之四」。
- 版本 1.1.20 → 1.1.21。

## 四、測試

- 新增 `AiChatApiTests`（測試主機換上端對端用的假 AI 與假 PDF）：
  - 提問：送出多筆 `delta`、最後 `done`，`delta` 串起來等於完整回答；對話存下一問一答；
  - 第一段文字前就失敗：附件超過 5 個回 400 與原文、看不到的會議回 404，都不是「200 加 error 行」；
  - 權限：只有專案項目檢視的人，專案與專案底下會議的問答都看得到，但不能改名；只有會議紀錄權限的人，會議可以、專案不行；
  - 附件：下載寫稽核、不在對話裡的檔名 404；匯出整段對話與稽核；超出範圍的訊息 404；修改訊息時原內容對不上回 409。
- 抓錯檢查：
  - 會議範圍只認會議紀錄的權限 → 權限案例失敗；
  - 第一段文字前的失敗改走串流 → 失敗路徑案例失敗。
  - 驗完都已還原。
- 全套單元／API 與端對端照跑；AI 問答視窗還是舊版（直接呼叫服務），AI 系列照過。
