## 一、原因

- 會議頁搬到 WASM 之前，頁上的 AI 問答視窗要先能在 WASM 執行。
- 專案頁（還是 Server 頁）也用同一個視窗，所以比照通知鈴，做成兩種頁面共用的元件。

## 二、修改

- **`AiChatModal` 搬到 `Web.Client/Components/Commons`**：
  - 畫面、文字、確認框、串流顯示、附件（迴紋針、貼上、拖放）、編修與重新產生全部照舊；
  - 資料來源改成介面 `IAiChatSource`：
    - Server 頁註冊 `ServerAiChatSource`，直接呼叫 `AiChatService`；
    - WASM 頁註冊 `AiChatApi`，打 `api/v1/ai-chat`、讀串流。
  - 兩邊失敗都丟帶原文的例外，視窗照舊顯示「…失敗：原因」。
- **匯出 PDF 與下載附件改由伺服器做**：
  - 由伺服器產生 PDF、從對話檔讀內容、寫稽核；
  - Server 頁與 API 共用 `Web/AiChat/AiChatOperations`；
  - 以前是視窗自己組 PDF、自己寫稽核。
  - PDF 的對象名稱改由伺服器讀，宿主頁不再傳 `TargetName`。
- **開新對話的 API 加 `automatic` 參數**：開視窗時自動建的第一段對話不寫稽核，與 Server 頁一致。
- **共用型別搬到 Share**：
  - `AiChatScope`、附件規則 `AiChatAttachmentPolicy`，WASM 頁也能先在畫面擋一次；
  - 可擷取文字的格式抽成 `AttachmentFormats`，文字擷取器轉呼叫它，不重複寫。
- **`ApiClient` 補下載檔案與串流請求**：失敗時照樣走 401、須改密碼的導向；會議頁的下載也會用到。
- 文件：
  - [AI 問答 PRD](../prd/AI問答-prd.md)、專案項目 PRD；
  - [對話窗 UI 設計規範](../architecture/對話窗%20UI%20設計規範.md)、[開發慣例與限制速查](../architecture/開發慣例與限制速查.md)；
  - 09 號「十、之四」。
- 版本 1.1.21 → 1.1.22。

## 三、外部可見的行為變更

| 項目 | 以前 | 現在 |
|---|---|---|
| `POST api/v1/ai-chat/.../conversations` | 一律寫稽核 | 帶 `automatic=true` 時不寫（開視窗自動建的第一段） |
| 匯出 PDF 與下載附件的稽核 | 由網頁畫面寫 | 由伺服器寫（Server 頁摘要 `via=Web`、API `via=Api`） |

## 四、測試

- `AiChatApiTests` 新增：
  - 自動建立的對話不寫稽核，使用者按「開新對話」才寫。
- 抓錯檢查：讓 API 忽略 `automatic` → 新案例失敗。驗完已還原。
- 端對端：AI 系列（Server 頁的專案與會議問答，現在走 `ServerAiChatSource`）照過。
- 視窗在 WASM 頁的實際操作要等會議頁搬過去（下一版），屆時用端對端驗串流與附件。
- 全套單元／API 與端對端照跑。
