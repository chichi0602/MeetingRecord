## 一、原因

- Server 頁上傳影音檔時，是頁面元件自己拿著分塊組成的串流呼叫 `MeetingService.SaveMediaAsync`，元件靠 Blazor 連線一直等到存完。
- WASM 頁沒有那條連線，上傳要能「建好就回應、存檔在伺服器背景跑、之後查結果」。

## 二、修改

- **新增 `api/v1/uploads` 三支端點**（`UploadSessionController`）：
  - `POST`：建立工作階段，要會議紀錄「新增」或「修改」權限；先跑上傳檢查，不合直接回 400 與原因，不必等瀏覽器送完第一塊；
  - `GET {uploadId}`：查狀態（上傳中、成功、取消、失敗，以及「會議已一併刪除」「來不及取消」）；
  - `DELETE {uploadId}`：取消，等同 Server 頁的「取消上傳」。
  - 分塊照舊送到既有的 `PUT api/v1/uploads/{id}/chunks/{i}`。
- **上傳檢查抽出來**：`MeetingService.CheckMediaUploadAsync`（格式、大小、會議存在、資料範圍、只限上傳者、封存唯讀、背景工作進行中、另一個視窗正在上傳），`SaveMediaAsync` 也改呼叫同一份，規則不變。
- **背景存檔**（`Web/Uploads/MeetingMediaUploadJobs`）：自開 scope，把上傳者填進 `CurrentUserService`，資料範圍與稽核操作者都是上傳者本人；進度、從進度面板取消、失敗原因全部沿用服務層。
- **建好就取消也會刪新增的會議**：WASM 頁建好工作階段就能取消，可能早在服務層開始收檔之前；那時服務層不會刪「新增時附檔」的會議，背景工作補刪，結果與 Server 頁一致。
- **計畫調整**：
  - WASM 端的上傳服務移到會議頁那版，在實際頁面上做端對端驗證；
  - 專案附件的上傳用途移到專案頁那版。
  - 這版只做伺服器端，現有畫面不受影響。
- 文件：[Web API 端點目錄](../architecture/Web%20API%20端點目錄.md) 四之一、[認證授權與權限機制](../security/認證授權與權限機制.md)、[開發慣例與限制速查](../architecture/開發慣例與限制速查.md)（背景以使用者身分呼叫服務的做法）、09 號「十、之四」。
- 版本 1.1.15 → 1.1.16。

| 項目 | 以前 | 現在 |
|---|---|---|
| 上傳 | 只有網頁內部的「送一塊」 | 另有建立、查狀態、取消三支 API（給 WASM 頁用） |
| 對外既有 API | — | 不變 |

## 四、測試

- 新增 `UploadSessionApiTests`：
  - 只有檢視權限不能建立（403）；
  - 建立前檢查：格式不對、別人的會議、會議不存在都回 400 與服務層原文；
  - 完整上傳：送一塊、查到成功、會議記下檔名與路徑，稽核的操作者是上傳者本人；別人查不到這趟上傳（404）；
  - 取消新增時附檔的會議，取消在上傳開始前、上傳途中兩種都把會議刪掉。
- 抓錯檢查：
  - 背景不填上傳者 → 上傳與取消案例失敗；
  - 拿掉建立前檢查 → 檢查案例失敗；
  - 拿掉補刪 → 「上傳開始前取消」案例失敗。
  - 驗完都已還原。
- 全套單元／API 與端對端照跑；Server 頁的上傳情境（MTG、L4 系列）照過。
