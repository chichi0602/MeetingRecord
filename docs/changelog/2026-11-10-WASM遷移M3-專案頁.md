## 一、原因

- 專案頁是 M3 最後一個核心頁；API 在 1.1.24、1.1.25 備妥。
- 這版搬過去之後，會議、專案、待辦三個核心頁都在 WASM。

## 二、修改

### 2.1 頁面

- `ProjectViewView` 搬到 `Web.Client/Pages/Projects/ProjectPage`，`TodoExtractionModal` 一起搬到同一個資料夾；`/projects` 加進 `WasmRoutes`。
- 照舊的部分：畫面、文字、按鈕、確認框、通知、欄位、CSS 全部照舊，PRJ、AI 系列一行沒改就照過。
- 資料來源：
  - 資料走 `ProjectApi`（專案本身與專案底下的會議）與 `TodoExtractionApi`；
  - 按鈕依 `PermissionView` 與 API 帶回的旗標（`isProjectOwner`、`canManageTeams`、`canChangeOwner`）；
  - 會議紀錄生成進度讀 `api/v1/jobs`＋推播。
- 附件由 `ProjectAttachmentUploader` 傳到伺服器暫存檔，傳完才列進「待上傳」，存檔時帶上傳編號，同 Server 頁的流程。
- 表單模型 `ProjectFormModel`，驗證訊息與原本的 `ProjectAdapterModel` 一字不差（伺服器也會再驗）。
- 有「確定」鈕的視窗改成單向 `Visible`（1.1.19 的教訓）：被擋下時視窗本來就不會關，不再有「關掉再打開」那一下。

### 2.2 共用規則搬到 Share

`Share/Helpers/ProjectRules`：
- 專案狀態選項 `StatusOptions`，`ProjectAdapterModel.StatusOptions` 轉呼叫；
- 附件大小上限 `MaxAttachmentFileSize`，`ProjectService.MaxUploadFileSize` 轉呼叫。

### 2.3 伺服器端補齊

搬頁時發現三處缺口，都補在伺服器端，不讓頁面借用別頁的權限：

- **可選逐字稿多帶會議紀錄狀態**：`ProjectTranscriptOptionDto` 加 `hasDraft`、`draftStatus`、`canGenerateDraft`。
  - 沒有這三個欄位時，未歸屬但已有會議紀錄的逐字稿看不出「重新產生將覆蓋既有會議紀錄」，確認框也不會是紅色的覆蓋警告。
- **專案頁自己的選項端點**（只要專案項目檢視）：
  - `GET api/v1/Project/categories/enabled`（分類）；
  - `GET api/v1/Project/teams/filter`（團隊篩選，全部啟用中的團隊，同 Server 頁）。
  - 不補的話，要借用會議頁或專案新增／修改的權限，甲方之類只有檢視權限的人篩選選項會是空的。

### 2.4 孤兒清理

- `BrowserFileUploader` 刪除：Server 頁不再上傳檔案。
- `Routes.razor`（Server）的「上傳中往 WASM 頁先確認」也移除：反方向「WASM 頁上傳中往 Server 頁」由 `ClientRoutes` 負責（1.1.23）。

### 2.5 L4 情境

L4-05（Blazor Server 斷線重連）與 L4-08（上傳中往舊版頁要確認）原本借專案頁當「還沒遷移的 Server 頁」，改用使用說明頁 `/help`（M4 才搬）：

- L4-05 重連後的「仍可操作」：改成在提問框輸入、「發問」變成可按。這個動作要經 Blazor 連線回寫才會啟用。
- L4-08：改成往 `/help` 才跳確認。
