# WASM 遷移 M3：待辦 API 改走服務層、補齊待辦頁要用的端點（1.1.17 → 1.1.18）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：1.1.18
- 首次實作版本：1.1.18
- 最後核對日期：2026/11/10

使用者要求：

> M2 做完後自動做 M3，M3 也一次做完（每版全綠自動 commit 推送），做到 M3 里程碑報告再停。會議、專案、待辦既有的對外 API 照 M2 做法改走同一套規則。

---

## 一、原因

- 待辦頁要搬到 WASM，所有資料都得經 API。
- 待辦 API 原本走另一套 `TodoRepository`，規則與畫面的 `TodoService` 各寫一份（刪除、子項目、封存、改期限原因都要兩邊同步）。
- 待辦頁比預期大，拆成兩版：這版做 API，下一版（1.1.19）搬頁面。

## 二、修改

- **`TodoController` 改走 `TodoService`**：既有五支（取單筆、搜尋、新增、修改、刪除）路由、權限、回應形狀都不變；寫入時 `via=Api`（異動紀錄與稽核照舊看得出是 API 改的）。`TodoRepository` 沒人用了，刪除。
- **對外搜尋維持平面清單**：服務層補 `SearchFlatAsync`（從 `TodoRepository` 原樣搬來），子項目照舊也是一筆；畫面的清單（只分頁主層、子項目跟著主待辦）另開 `POST api/v1/Todo/tree`。
- **`TodoDto` 只加欄位**：專案狀態、建立者、主待辦標題、子項目與完成數、期限變更說明、呼叫者能不能刪（`canDelete`）。
- **畫面用的新端點**：勾選完成、負責人面板（統計與某人的清單）、異動紀錄、可選主待辦（新增或修改權限任一）、待辦頁可選的專案（不借用專案頁權限）。
- **服務層補兩件事**：
  - `UpdateAsync`、`SetCompletedAsync`、`DeleteAsync` 加 `via` 參數（比照 M2）；`AddAsync` 回填新編號；
  - 新增時檢查「來源會議要看得到、而且屬於同一個專案」（0.4.114，原本只在 API 擋），搬進服務層，所有入口都適用。畫面上來源會議只會由 AI 抽待辦帶入（同專案），不受影響。
- 文件：[Web API 端點目錄](../architecture/Web%20API%20端點目錄.md)、[認證授權與權限機制](../security/認證授權與權限機制.md)、[權限與資料可見範圍總覽](../security/權限與資料可見範圍總覽.md)、[待辦事項 PRD](../prd/待辦事項-prd.md)、[開發慣例與限制速查](../architecture/開發慣例與限制速查.md)、架構總覽、09 號「十、之四」（待辦拆兩版，之後的版本號順延一號）。
- 版本 1.1.17 → 1.1.18。

## 三、外部可見的行為變更

| 項目 | 以前 | 現在 |
|---|---|---|
| 回應欄位 | `TodoDto` 只有基本欄位與專案、來源會議標題 | 多了專案狀態、建立者、主待辦標題、`canDelete` 等（只加不改） |
| 搜尋 | 平面清單 | 不變（多帶主待辦標題） |
| 錯誤訊息 | 新增、修改、刪除被擋回 400，訊息在 `errors.Validation` | 不變；規則訊息與畫面一致 |
| 勾選完成與取消完成的稽核 | 摘要沒有 `via` | 摘要多了 `via=Web`／`via=Api` |
| 新端點 | — | 清單樹、勾選完成、負責人面板、異動紀錄、可選主待辦與專案 |

## 四、測試

- 新增 `TodoApiTests`：
  - 清單樹：子項目跟著主待辦、不單獨出現；負責人看到可刪、同專案成員看到不可刪；對外搜尋照舊是平面清單；
  - 寫入規則經 API 回 400 與服務層原文：改期限沒附原因、不是負責人刪除、封存後勾選完成；附原因後修改成功，異動紀錄記 `via=Api`；
  - 封存後清單的「可刪」變成否，「使用中」檢視看不到；
  - 負責人面板與可選專案只算呼叫者看得到的；
  - 主待辦選項：只有檢視 403、只有新增或只有修改都可以；
  - 看不到的待辦：取單筆、修改、刪除、勾選完成都 404，資料沒變。
- 授權矩陣加 11 支待辦端點（每支驗 401、只缺該動作 403 並留稽核、只有該動作成功）。
- `TodoChangeAndNotificationTests` 原本「網頁與 API 兩條路都要擋」的案例，API 那一半改成以 `via=Api` 呼叫同一個服務（API 現在就是這樣呼叫）。
- 既有 API 測試照過，包含「來源會議屬於別的專案要 400」——它在服務層補上檢查前是失敗的。
- 抓錯檢查：
  - 「可刪」不看是不是專案負責人 → 清單樹案例失敗；
  - 勾選完成拿掉「看不到回 404」 → 看不到的待辦案例失敗。
  - 驗完都已還原。
- 全套單元／API 與端對端照跑；待辦頁還是舊版頁面，TDO 系列照過。
