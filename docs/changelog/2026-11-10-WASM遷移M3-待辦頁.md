# WASM 遷移 M3：待辦頁搬到 WASM，修正表單被擋下時關窗、網頁 API 另訂限流額度（1.1.18 → 1.1.19）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：1.1.19
- 首次實作版本：1.1.19
- 最後核對日期：2026/11/10

使用者要求：

> M2 做完後自動做 M3，M3 也一次做完（每版全綠自動 commit 推送），做到 M3 里程碑報告再停。

> （限流）網頁另訂較高額度。

---

## 一、原因

- 待辦頁要搬到 WASM（API 在 1.1.18 已備好）。
- 搬的過程中端對端測試抓到三個問題：
  1. **WASM 表單被伺服器擋下時，視窗被關掉、填的內容不見**（例如改期限沒附原因、分類名稱重複）。M2 搬過去的頁面也一樣，只是之前沒有情境測過。
  2. **網頁本身的 API 呼叫撞到限流**：WASM 頁的每個操作都是好幾支 API，與外部程式共用「每帳號每分鐘 120 次」，正常操作就會被擋成 429。
  3. **貼上關鍵字後直接按搜尋會按空**：輸入框在按下的瞬間才把值寫回、「清空搜尋」才出現，把搜尋鈕推走，滑鼠放開時已經不在按鈕上。

## 二、修改

- **待辦頁搬到 WASM**（`Web.Client/Pages/Todos/TodoPage`，原 `TodoViewView`）：
  - 畫面、文字、確認框、通知、自動列數、負責人面板、子項目、多選刪除、`?todoId=` 深連結全部照舊；
  - 資料改走 `TodoApi`，按鈕依 `PermissionView`，能不能刪由 API 依呼叫者算好；
  - 異動紀錄的欄位名稱、來源、新舊值文字改由伺服器組好（`TodoChangeDto` 多了顯示欄位）。
  - 負責人面板的篩選、多選刪除、自動列數三個輔助類別一起搬到 Client，改用 DTO。
- **選項與顯示規則抽到 Share**：`TodoRules`（狀態與優先度選項、逾期、截止日文字）、`ProjectScopeRules`（封存與「使用中｜已完成｜全部」）。伺服器的 `TodoAdapterModel`、`ProjectArchiveRules` 與 WASM 頁的 `TodoDto` 都轉呼叫它們，規則只有一份。
- **WASM 表單被擋下時不再關窗**（M2 的分類、團隊、提示詞、使用者、角色頁，以及共用外框的變更密碼視窗一起修）：
  - AntDesign 1.6 按「確定」時會先送出「關閉」再呼叫存檔；改成單向繫結，開關由頁面決定（存檔成功、取消才關）；
  - 存檔成功時先關窗，再通知與重新載入。
- **網頁本身的 API 另訂限流額度**：新設定 `PermitLimitPerWebUser`（預設每個帳號每分鐘 600 次），靠登入 Cookie 的請求用它；帶 JWT 的外部程式維持 `PermitLimitPerUser`（120 次），兩份分開計算。
- **待辦頁「清空搜尋」移到搜尋鈕前面**，與其他清單頁一致，不會再把搜尋鈕推走。
- **待辦清單的預設排序真的生效**：表格在沒有排序時也會回報某一欄、方向為「無」，以前照樣送出排序欄位，服務層因此跳過預設排序又沒有方向可排；現在沒有方向就不送。這是 Server 版就有的問題。

  - [開發慣例與限制速查](../architecture/開發慣例與限制速查.md)（WASM 視窗與工具列、`TodoRules`）；

  - 09 號「十、之四」。

## 三、外部可見的行為變更

| 項目 | 以前 | 現在 |
|---|---|---|
| 網頁本身的 API 限流 | 與外部程式共用每帳號每分鐘 120 次 | 另計，每帳號每分鐘 600 次（`PermitLimitPerWebUser`）；外部程式（JWT）不變 |
| WASM 表單儲存被擋下 | 視窗關掉、內容不見 | 視窗留著、內容還在，顯示原因 |
| 待辦清單預設排序 | 實際上沒有排序 | 有截止日的在前、越早到期越前面 |
| `GET api/v1/Todo/{id}/changes` | — | 多了欄位名稱、來源、新舊值的顯示文字 |

## 四、測試

- 新增 `ModalVisibleBindingTests`：WASM 專案裡有「確定」鈕的視窗不得用 `@bind-Visible`（附規則本身的回歸案例）。
- 限流：
  - 分區規則改成網頁 `web:`、外部程式 `user:`；
  - 新增整合測試：網頁 Cookie 呼叫可以用到網頁額度（比外部程式多），用完才 429。
- 端對端：
  - TDO-01～10、NTF-01、WASM 系列一行不改照過；
  - 新增 **MD-09**：分類名稱重複被擋下時，視窗留著、填的名稱還在。
- 抓錯檢查：
  - 分類頁改回雙向繫結 → MD-09 與掃描測試失敗；
  - 網頁請求改回 `user:` 分區 → 兩則限流測試失敗。
  - 驗完都已還原。
- 追查過程（記錄給之後的人）：
  - 以為是查詢回應後發先至，加過序號但沒有解決，已撤掉；
  - 最後靠瀏覽器端的 DOM 點擊紀錄確認點擊落在外層 `DIV`，才找到版面位移的真因。
- 全套單元／API 與端對端照跑。
