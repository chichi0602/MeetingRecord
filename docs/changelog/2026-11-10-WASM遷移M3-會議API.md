# WASM 遷移 M3：會議 API 改走服務層、補齊會議頁要用的端點（1.1.19 → 1.1.20）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：1.1.20
- 首次實作版本：1.1.20
- 最後核對日期：2026/11/10

使用者要求：

> M2 做完後自動做 M3，M3 也一次做完（每版全綠自動 commit 推送），做到 M3 里程碑報告再停。會議、專案、待辦既有的對外 API 照 M2 做法改走同一套規則。

---

## 一、原因

- 會議頁要搬到 WASM，所有資料與動作都得經 API。
- 會議 API 原本走另一套 `MeetingRepository`（只有刪除走服務層），規則與畫面各寫一份。
- 會議頁很大（約 2100 行），比照待辦拆兩版：這版做 API，下一版搬頁面（含 WASM 端上傳）。

## 二、修改

- **`MeetingController` 改走 `MeetingService`**：
  - 既有五支（取單筆、搜尋、新增、修改、刪除）路由、權限、回應形狀不變；
  - 寫入時 `via=Api`；`MeetingRepository` 沒人用了，刪除。
- **對外搜尋維持原樣**：服務層補 `SearchFlatAsync`（從 `MeetingRepository` 原樣搬來）；畫面清單另開 `POST list`。
- **`MeetingDto` 只加欄位**：
  - 歸屬專案、上傳者、有沒有影音檔與逐字稿、能不能重新轉錄；
  - 會議紀錄的狀態、錯誤、提示詞、完成時間；
  - 呼叫者是不是上傳者、能不能刪；
  - 會議紀錄全文只有取單筆時帶。
- **分類多一個清單欄位 `categoryNames`**（比照提示詞）。
- **畫面用的新端點（13 支）**：
  - 清單；
  - 刪除前的連結待辦數；
  - 重新轉錄；
  - 產生、修改會議紀錄；
  - 歸屬專案；
  - 逐字稿全文、下載 .txt、複製後寫稽核；
  - 匯出 PDF（可帶還沒存的內容）；
  - 會議頁可選的專案（附與會人員名冊）、提示詞、分類。
- **稽核改由伺服器寫**：下載與匯出原本是畫面自己寫稽核，現在由 API 寫，摘要多 `via=Api`。
- **服務層**：新增、修改加 `via` 參數。

- 版本 1.1.19 → 1.1.20。

## 三、外部可見的行為變更

| 項目 | 以前 | 現在 |
|---|---|---|
| 回應欄位 | `MeetingDto` 只有中繼資料與轉錄狀態 | 多了歸屬、會議紀錄狀態、旗標等（只加不改） |
| 修改已完成（封存）專案的會議 | API 照改 | 400「已完成的專案為唯讀」（與畫面一致，管理者除外） |
| 分類 | 只有儲存格式的 `categories` | 另有 `categoryNames`；回應兩個都填 |
| 新端點 | 只有基本 CRUD | 清單、重新轉錄、會議紀錄、歸屬、逐字稿、下載與匯出、選項 |

## 四、測試

- 新增 `MeetingApiTests`：
  - 清單依分類篩選，上傳者看到「是上傳者、可刪」，同專案成員兩者都否；清單不帶會議紀錄全文，取單筆才帶；
  - 新增一律未歸屬，`categoryNames` 去空白去重複，回應兩種格式都有；
  - 修改封存專案的會議回 400；
  - 逐字稿全文、下載（含 BOM）、複製都寫稽核；
  - 匯出 PDF 用的是還沒存的內容，並寫稽核（PDF 渲染用假的）；
  - 修改會議紀錄、歸屬專案經服務層生效；
  - 只有檢視權限的人，重新轉錄、產生與修改會議紀錄、下載、匯出都 403，但讀得到逐字稿。
- 授權矩陣加 8 支會議端點。
- 寫測試時抓到一個疏漏：清單也帶了會議紀錄全文，改成只有取單筆才帶。
- 抓錯檢查：
  - 「是上傳者」一律為真 → 清單案例失敗；
  - 下載逐字稿不寫稽核 → 逐字稿案例失敗。
  - 驗完都已還原。
- 全套單元／API 與端對端照跑；會議頁還是舊版頁面，MTG 與 L4 系列照過。
