# WASM 遷移 M3：會議頁搬到 WASM，上傳換頁不中斷（1.1.22 → 1.1.23）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：1.1.23
- 首次實作版本：1.1.23
- 最後核對日期：2026/11/10

使用者要求：

> M2 做完後自動做 M3，M3 也一次做完（每版全綠自動 commit 推送），做到 M3 里程碑報告再停。上傳在 WASM 端是整個前端層級的：換到其他 WASM 頁照樣繼續傳；關分頁、重新整理、換到還是舊版的頁面才會中斷，照現在一樣先跳確認。

---

## 一、原因

- 會議頁是 M3 三個核心頁之一，API（1.1.20）、AI 問答視窗（1.1.22）、上傳工作階段（1.1.16）都已備妥。
- 搬過去才能讓上傳變成「整個前端共用」：換頁不中斷。

## 二、修改

### 2.1 會議頁

- `MeetingViewView` 搬到 `Web.Client/Pages/Meetings/MeetingPage`，`/meetings` 加進 `WasmRoutes`。
- 照舊的部分：畫面、文字、按鈕、確認框、通知、欄位全部照舊，MTG 系列一行沒改就照過。
- 資料來源：
  - 資料走 `MeetingApi`（`api/v1/Meeting`）；
  - 按鈕依 `PermissionView`；
  - 能不能刪、是不是上傳者由 API 依呼叫者算好（`MeetingDto.CanDelete`、`IsUploader`）。
- 轉錄、生成進度：
  - 讀 `api/v1/jobs`，有推播就重查；
  - 工作結束才重新載入清單，規則同 Server 頁。
- 逐字稿下載、會議紀錄 PDF 改由伺服器產生並寫稽核，畫面只負責存檔；複製逐字稿的稽核也改由伺服器寫。
- 開「會議紀錄與逐字稿」視窗時才取單筆，清單不帶全文。
- 三個視窗（維護、產生會議紀錄、歸屬到專案）改成單向 `Visible`（1.1.19 的教訓）：伺服器擋下時視窗留著。

### 2.2 上傳由整個前端共用

新的 `Web.Client/Uploads/MeetingUploadManager`：

- **流程**：
  1. 建工作階段（`POST api/v1/uploads`）；
  2. 既有的 `chunk-upload.js` 分塊送；
  3. 每秒查一次狀態直到結束；
  4. 跳結果通知（文字同 Server 頁），再通知頁面重新載入。
- **換 WASM 頁不中斷**：
  - WASM 的 Scoped 就是整個分頁，上傳不綁在頁面上；
  - JS 開始時就拿到檔案本身，表單重設、元件釋放都不影響；
  - 換頁回來，「取消上傳」照樣在那一列。
- **離開的提醒**：
  - 往還沒遷移的舊版頁時，`ClientRoutes` 先跳「上傳還在進行」確認（同 1.1.6 的反方向）；
  - 關分頁、重新整理照舊由 `beforeunload` 提醒。
- **瀏覽器送不下去時**（重試用完、登入失效）：新端點 `POST api/v1/uploads/{id}/fail` 讓伺服器立刻結束那趟上傳、會議保留，同 Server 頁；不回報的話要等 2 分鐘逾時。

### 2.3 所有 WASM 頁的連線韌性（這版端對端測試發現）

- **`ApiClient` 連不上伺服器時回失敗結果、不丟例外**（狀態碼 0，「無法連線到伺服器，請確認網路後再試一次。」）。
  - 以前請求途中一斷網就丟 `HttpRequestException`，整頁被錯誤邊界換成「這個頁面發生未預期的錯誤」。
  - 現在只跳一則讀取失敗的通知。
- **推播通道（`/hubs/app`）一直重試到連上**。
  - `WithAutomaticReconnect` 只處理「連上之後才斷」，而且約 42 秒就放棄：第一次就連不上，或斷太久，整個分頁的即時更新以前就再也不會恢復。
  - 現在背景從 2 秒起加倍、最多 30 秒持續重試；連上後照樣發出「重新連上」，讓進度面板、通知鈴補查。
- **`ApiClient` 401 整頁導到登入頁之前，先通知上傳管理拿掉 `beforeunload`**：否則上傳中登入失效時，瀏覽器會擋下這次導向。
- 錯誤訊息的解讀（`errors.Validation` 與 `errorMessage` 兩種都認）從 `TodoApi` 搬到 `ApiClient.ErrorText`，會議頁也用；`TodoApi.ErrorText` 轉呼叫它。

### 2.4 共用規則

`MeetingMediaPolicy` 從 Business 搬到 `Share/Helpers`，WASM 頁也在畫面先擋一次。轉錄分段秒數 `TranscriptionSegmentSeconds` 也放在這裡：

- FFmpeg 切段（`FfmpegMediaConverter.SegmentSeconds`）用它；
- 畫面的費用說明也用它；
- 兩邊同一個來源。

## 三、外部可見的行為變更

| 項目 | 以前 | 現在 |
|---|---|---|
| 登入後的首頁 `/meetings` | Blazor Server 頁 | WASM 頁 |
| 上傳中換到其他 WASM 頁 | 會議頁是 Server 頁，往 WASM 頁要確認、會中斷 | 不中斷、不必確認；往還沒遷移的舊版頁才確認 |
| 上傳期間在會議頁選另一筆的檔案 | 一頁一次只能一個（要等前一個傳完） | 可以，各自上傳 |
| 上傳途中登入失效 | 停在頁面上顯示「登入已失效…會議資料已保留」 | 整頁導回登入頁；會議保留，伺服器 2 分鐘沒收到分塊才把那趟上傳標成失敗，期間進度面板顯示上傳中 |
| 會議頁的逐字稿複製／下載、PDF 匯出稽核 | 由畫面寫 | 由伺服器寫（`via=Api`） |
| WASM 頁請求途中斷網 | 整頁變成錯誤畫面 | 跳一則讀取失敗的通知，頁面照常可用 |
| WASM 頁推播通道第一次連不上、或斷超過約 42 秒 | 不再重試，即時更新失效到重新整理為止 | 背景持續重試，連上後補查 |
| `POST api/v1/uploads/{id}/fail` | 沒有 | 新增（只認擁有者） |

## 四、測試

### 4.1 新增

- 單元／API：
  - `WasmApiClientTests`：斷網回失敗結果、不丟例外；401 導向前先通知；
  - `UploadSessionApiTests`：回報失敗後立刻結束成「失敗」、帶出原因、會議保留，別人回報不到。
- 端對端：
  - **L4-09**：上傳中換到待辦頁不中斷、不必確認、頁面沒有重新載入；回會議頁看到轉錄完成、檔案雜湊一致。
  - **L4-10**：
    - 開頁時推播協商被擋，頁面照常可用，解除後自己連上；
    - 連上後斷網 10 秒，恢復後自動重連，頁面沒有重新載入、仍可操作。
  - **AI-04**：在 WASM 版會議頁做 AI 問答，串流顯示回答並記入用量帳本。先用標題搜尋那筆種子會議：全套跑時其他情境新增的會議會把它擠出第一頁（第一次全套就是這樣失敗的）。

### 4.2 因會議頁搬到 WASM 而調整的 L4 情境

情境本身不再適用，照新的實際行為改寫：

- **L4-05**：測的是 Blazor Server 連線斷線重連，WASM 頁沒有那條連線，改在還是 Server 頁的專案頁驗；WASM 頁的斷網由 L4-10 驗。
- **L4-07**：
  - 原本先清 Cookie 再存檔，在 WASM 頁存檔本身就是 API 呼叫，會直接導回登入頁；
  - 改成上傳途中才清 Cookie，驗證導得回登入頁、會議保留、沒有存進影音檔。
- **L4-08**：WASM 頁之間切換不再中斷上傳，改成往舊版頁（`/projects`）才跳確認。
- **L4-06**：結果不變（下一次進頁面導回登入頁），但允許「進頁面」被 App 自己的導向打斷——WASM 頁清掉 Cookie 後，背景的 API 呼叫（例如推播觸發的進度查詢）拿到 401 會先整頁導到登入頁，Playwright 那次進頁面就回 `net::ERR_ABORTED`（全套第二次就是這樣偶發失敗的）。

### 4.3 照過的情境

MTG-01～10、L4-01～04 一行沒改照過。

### 4.4 抓錯檢查

| 暫時改壞 | 結果 |
|---|---|
| 推播第一次連不上時不重試 | L4-10 失敗 |
| `ClientRoutes` 不攔往舊版頁的導覽 | L4-08 失敗 |
| `ApiClient` 不接網路錯誤 | `WasmApiClientTests` 失敗 |
| 失敗回報端點不結束工作階段 | `UploadSessionApiTests` 失敗 |
| 上傳管理不在導向登入前拿掉 `beforeunload` | **L4-07 仍通過** |

最後一項的原因：Playwright 下導覽不會跳 `beforeunload` 對話框，端對端驗不到。這段只有單元測試保護，驗的是「401 導向前會先發出通知」。

驗完都已還原。全套單元／API 與端對端照跑。
