# WASM 遷移 M4：AI 呼叫者歸屬修正（1.1.27 → 1.1.28）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：1.1.28
- 首次實作版本：1.1.28
- 最後核對日期：2026/11/11

使用者要求：

> 開始 M4，另開分支。

---

## 一、原因

開始做 M4 的使用說明 API 時，發現 M3 留下的缺陷：**經 API 呼叫 AI 時，用量帳本記不到是誰用的**。

- 服務層取 AI 呼叫者只看 `CurrentUserService`，它只有 Blazor 頁會填，API 請求時是空的；
- M3 起會議頁、專案頁都是 WASM，AI 問答、待辦抽取、重新轉錄、產生會議紀錄都改走 API，所以：
  - 用量帳本、AI 對話紀錄的「使用者」是空的；
  - **每人每月額度擋不住**（額度依帳本的使用者加總，記不到人就永遠是 0）；
  - Token 用量報表的「依使用者」看不到這些用量；
  - AI 問答訊息的作者名稱是空的。
- 稽核已經在 1.0.34 改用 `IAuditActorProvider` 從 claims 取操作者，所以稽核本身沒有受影響。

已在 L2 重現：經 API 提問後，帳本的使用者編號是 null（預期是呼叫者）。

## 二、修改

- **新增 `IAiCallerProvider`**（Business）與實作 `AiCallerProvider`（`Web/Auth`）：
  - Blazor 頁、背景工作：照舊看 `CurrentUserService`；
  - API 請求：從 claims 取編號；名稱優先序同 `AiUsageAttribution`（姓名 → 帳號）。Cookie 帶姓名；JWT 只有帳號，就記帳號。
- **`AiUsageAttribution.Resolve(user, caller)`**：有 provider 就問它，沒有（直接 new 服務的單元測試）才只看 `CurrentUser`。
- **改用它的服務**（建構子多一個選用參數，DI 會注入）：
  - `AiChatService`：帳本與訊息作者；
  - `TodoExtractionService`：帳本；
  - `MeetingService`：重新轉錄、產生會議紀錄入列時帶的觸發者，以及入列前的額度預檢。
- **這版沒改的**：
  - `HelpAssistantService`：還沒有 API，1.1.29 開使用說明 API 時一起改；
  - `DiagnosticAiService`、`AiConnectionTestService`：只在 Server 監控頁用，M5 搬頁開 API 時一起改。
- 文件：開發慣例與限制速查、Token 用量 PRD、架構總覽、09 號（§4.2 與「十、之五」）。
- 版本 1.1.27 → 1.1.28。

## 三、外部可見的行為變更

| 項目 | 以前（M3 起經 API） | 現在 |
|---|---|---|
| 用量帳本與 AI 對話紀錄的使用者 | 空的 | 呼叫者（Cookie：姓名；JWT：帳號） |
| 每人每月 AI 額度 | 經 API 的呼叫不計入、也不會被擋 | 計入，達上限就擋 |
| AI 問答訊息的作者名稱 | 空的 | 呼叫者 |

1.1.28 以前已經寫進帳本、沒有使用者的紀錄不回補：無從得知是誰。

## 四、測試

- **單元 `AiCallerProviderTests`**：Blazor 使用者優先、Cookie 用姓名、沒有姓名退回帳號、JWT 用帳號、未登入回空、沒有 provider 時照舊只看 `CurrentUser`。
- **L2**：
  - `AiChatApiTests.Ask_ShouldAttributeUsageToTheCaller`：經 API 提問，帳本的使用者是呼叫者，名稱不是空的。修正前失敗（null）。
  - `ProjectMeetingApiTests.TodoExtraction_…`：抽待辦後帳本的使用者是呼叫者。
- **抓錯檢查**：暫時讓待辦抽取不經 provider → L2 失敗（null）；已還原。
- 全套單元／API 與端對端照跑。
