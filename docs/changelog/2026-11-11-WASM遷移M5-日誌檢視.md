## 二、修改

### 2.1 API（加在 `MonitoringController`，`api/v1/monitoring`，整個 Controller `[AdminOnly]`）

| 端點 | 說明 |
|---|---|
| `GET logs/meta` | AI 日誌分析能不能用與原因 |
| `POST logs/query` | 依條件查日誌（`LogQueryRequest`），回時間正序；條件被夾住時回實際查詢的區間，讀檔失敗時結果帶訊息 |
| `POST logs/export` | 匯出 .log：伺服器依同一組條件**重查**、組原文（UTF-8 含 BOM），內容與畫面「複製」相同；沒有日誌 400；寫稽核 |
| `POST logs/ai-analysis` | **AI 日誌分析**，串流回應（`delta`／`done`／`error`） |
| `POST logs/ai-analysis/pdf` | 匯出分析 PDF，寫稽核 |

**AI 日誌分析**：
- 伺服器依同一組條件重查，取最新 100 筆組成送出內容（`AiLogPromptBuilder`），**不收前端給的日誌**。
- 前端關掉視窗＝中斷請求，AI 呼叫跟著停（帳本記 Cancelled）。
- 稽核同畫面：成功記筆數、字數、模型、耗時；取消記「使用者取消」；失敗記例外型別。
- AI 未設定、沒有日誌、第一段文字前就失敗，都回一般的 400。

**PDF**：結果與說明行由前端帶，附錄「實際送出的日誌」由伺服器依同一組條件重查重組，操作者是 API 呼叫者。

**稽核**：目標 `LogQuery`、編號是實際查詢的區間（同畫面），另加 `via=Api`；不記日誌內容。

### 2.2 頁面搬到 WASM

- `LogViewerView` 用 `git mv` 搬成 `Web.Client/Pages/Monitoring/LogViewerPage.razor(.cs/.css)`；Server 的頁面外殼刪除。
- Server 的 `Components/Views/Monitoring` 已清空，`Components/_Imports.razor` 拿掉對應的 `using`。
- `MonitoringApi` 加 5 個方法，`ClientJsonContext` 補型別，`WasmRoutes` 加 `/logs`。
- 管理者判斷改用 `PermissionView.IsAdmin`。
- 查詢、匯出、AI 分析、PDF 走 API，稽核由伺服器寫。
- 複製（點列、全部）留在前端。
- AI 確認窗的筆數與字數用畫面上的結果算（同一套組字）。
- 文字、按鈕、class 都不變。

### 2.3 共用

- **`AiLogPromptBuilder`** 從 `Web/Diagnostics` 搬到 `Dtos/Diagnostics`：前端算確認窗、伺服器組送出內容都用它。
- **`LogAiFailure`**（`Web/Diagnostics`）：失敗訊息從畫面搬到伺服器。
- **AI 分析串流的 DTO 改成通用名稱**：1.1.40 取名 `ExceptionAi…` 的三個型別改成 `DiagnosticAiStreamEventDto`、`DiagnosticAiMetaLineDto`、`DiagnosticAiPdfRequestDto`，搬到 `Dtos/Diagnostics/DiagnosticAiDtos.cs`，例外分析與日誌分析共用。新增 `LogAiPdfRequestDto`、`LogViewerMetaDto`。
- **Client 端讀串流抽成 `DiagnosticAiStream`**：`ExceptionLogApi` 與 `MonitoringApi` 共用。
