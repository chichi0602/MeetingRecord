## 一、原因

M5 第二頁：日誌等級設定 `/log-level-setting` 搬到 WASM。這頁的特點：
- 只限管理者；
- 動作只有「套用」與「還原」，都會改伺服器記憶體中的 NLog 規則並寫稽核。

## 二、修改

### 2.1 API（加在 `MonitoringController`，`api/v1/monitoring`，`[AdminOnly]`）

| 端點 | 說明 |
|---|---|
| `GET log-level` | 現況：是否可調整、目前生效等級、系統預設等級、是否有執行期覆寫 |
| `PUT log-level` | 內容 `{ level }`，只接受 TRACE～FATAL；「不限」與「無法解析」回 400。成功回新的現況 |
| `POST log-level/restore` | 還原為系統預設等級，回新的現況 |

- 套用、還原失敗（NLog 設定讀不到）回 500，訊息同畫面：「套用失敗，請確認 NLog 設定。」。
- **稽核改由伺服器寫**：`LogLevel.Apply`／`LogLevel.Restore`，目標 `NLog`／`logger:*`，內容同以前，另加 `via=Api`。
- 套用 TRACE／DEBUG 前的確認框留在畫面上。

### 2.2 型別搬到 Dtos

`LogModels.cs` 整檔從 `Web/Diagnostics` 搬到 `Dtos/Diagnostics`，包含：
- `LogLevelRank`、`LogLevelRankHelper`、`LogTimeRanges`；
- `LogQueryRequest`、`LogEntry`、`LogQueryResult`。

後面的系統健康、日誌檢視頁也會用到。另新增 `LogLevelStateDto`、`LogLevelApplyRequestDto`。

### 2.3 頁面

- `LogLevelSettingView.razor(.cs/.css)` 搬到 `Web.Client/Pages/Monitoring/LogLevelSettingPage.*`，`@page "/log-level-setting"`；刪掉 Server 的頁面。
- 畫面、文字、按鈕不變。
- 管理者判斷用 `PermissionView.IsAdmin`。
- 每次操作後以伺服器回傳的現況為準。
- `WasmRoutes` 加 `/log-level-setting`。
