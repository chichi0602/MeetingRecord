## 一、原因

稽核紀錄頁 `/audit-logs` 是**最後一個應用程式的 Blazor Server 頁**。搬完之後，應用程式的頁面全部在瀏覽器（WASM）執行；伺服器只剩：
- 首頁 `/`（開場畫面）；
- `/not-found`、登入登出；
- 範本留下的 `/counter`、`/weather`。

端對端 L4-05、L4-08 一直借用「還沒遷移的 Server 頁」，這版一起改寫。

## 二、修改

### 2.1 新 `AuditLogController`（`api/v1/audit-logs`，整個 Controller `[AdminOnly]`）

| 端點 | 說明 |
|---|---|
| `GET meta` | 自動清除天數、手動清除天數、CSV 上限 |
| `GET actions` | 動作下拉：資料庫裡出現過的動作代碼 |
| `POST search` | 清單一頁（`AuditLogQuery`），回 `PagedResult` |
| `POST export/csv` | 伺服器產生 CSV（最多 10,000 筆），寫稽核 |
| `POST purge` | 清除 N 天前（N 由伺服器設定決定），稽核在刪除**之後**寫 |
| `POST clear-all` | 清空全部，稽核在刪除**之後**寫（這筆是清空後的第一筆） |

- 同畫面：刻意沒有單筆刪除。
- 稽核目標 `AuditLog`，另加 `via=Api`。

### 2.2 頁面搬到 WASM

- `AuditLogView` 用 `git mv` 搬成 `Web.Client/Pages/Admins/AuditLogPage.razor(.cs/.css)`；Server 的頁面外殼刪除。
- 新 `Web.Client/Api/AuditLogApi.cs`；`ClientJsonContext` 補型別；`Program.cs` 註冊；`WasmRoutes` 加 `/audit-logs`。
- 管理者判斷改用 `PermissionView.IsAdmin`。
- 查詢、動作選項、匯出、清除都走 API，稽核由伺服器寫。
- 「按查詢才凍結條件」的做法照舊，文字、按鈕、class 都不變。

### 2.3 型別搬到 Dtos

- `AuditLogAdapterModel`、`AuditLogQuery` 從 Models 搬到 `Dtos/AuditLogs`；顯示用的計算屬性標 `[JsonIgnore]`。
- 新 `AuditLogMetaDto`、`Web/Export/AuditLogCsv`（從 `AuditLogView.CsvColumns` 搬來）。

### 2.4 端對端 L4-05、L4-08 改寫

**L4-05**：
- 以前：驗 Blazor Server 斷線重連，借用還沒遷移的 Server 頁。
- 現在：名稱改成「斷網 10 秒後自動恢復，頁面沒有重新載入、仍可操作」，在 WASM 版稽核紀錄頁斷網 10 秒。
  - 斷網中按「查詢」只跳「載入稽核紀錄失敗」，頁面不會重新載入；
  - 恢復後同一頁用不存在的關鍵字查詢，清單變成空的（走 API）。
- 推播通道的斷線重連仍由 L4-10 驗。

**L4-08**：
- 上傳中往「舊版頁」要先確認，目標改成仍由伺服器處理的 `/not-found`。
- 確認框在導覽之前出現、選「留下」不會真的離開。

## 三、外部可見的行為變更

| 項目 | 以前 | 現在 |
