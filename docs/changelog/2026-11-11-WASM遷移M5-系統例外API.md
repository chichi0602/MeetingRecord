## 一、原因

系統例外頁 `/system-exceptions` 除了清單、堆疊、複製、CSV、刪除與清除，還有**會花錢的 AI 例外分析**（串流、關窗取消、PDF）。比照 Token 用量與 AI 對話紀錄拆成兩版：這版先開 API，1.1.41 再搬頁面。這版頁面仍是 Server 頁，畫面不變。

## 二、修改

### 2.1 新 `ExceptionLogController`（`api/v1/exception-logs`，整個 Controller `[AdminOnly]`）

| 端點 | 說明 |
|---|---|
| `GET meta` | 自動清除天數、手動清除天數、上限 5,000、AI 能不能用與原因 |
| `POST search` | 清單一頁（`ExceptionLogQuery`），回 `PagedResult`；「複製全部」用同一支、頁大小帶上限 |
| `GET {id}/stack-trace` | 堆疊全文（檔案不存在時 null）與 AI 分析會送出的字數；這一列不存在 404 |
| `POST stack-traces` | 一次讀多列的堆疊（「複製全部」用，最多 5,000 列） |
| `POST export/csv` | 伺服器產生 CSV，寫稽核 |
| `DELETE {id}` | 刪除一列與堆疊檔，不存在 404，寫稽核 |
| `POST purge` | 清除「最後發生」早於 N 天前的紀錄（N 由伺服器設定決定），寫稽核 |
| `POST clear-all` | 清空全部與堆疊檔目錄，寫稽核 |
| `POST {id}/ai-analysis` | **AI 例外分析**，串流回應（一行一筆 JSON：`delta`／`done`／`error`） |
| `POST {id}/ai-analysis/pdf` | 匯出分析 PDF，寫稽核 |

**AI 例外分析**：
- 送出的內容由伺服器依例外編號用 `AiExceptionPromptBuilder` 組（不含帳號），**不收前端的值**。
- 前端關掉視窗＝中斷請求，AI 呼叫跟著停（帳本記 Cancelled）。
- 稽核同畫面：成功記字數、模型、耗時；取消記「使用者取消」；失敗記例外型別。
- 第一段文字前就失敗（例如已達用量上限）回一般的 400；AI 未設定也回 400。

**PDF**：結果與說明行由前端帶（剛收到的），附錄「實際送出的例外內容」由伺服器重組，操作者是 API 呼叫者。

**稽核**：動作代碼與內容同畫面，目標 `ExceptionLog`，另加 `via=Api`；不記例外內容。

## 四、測試

- **L2 `ExceptionLogApiTests`**（假 AI、假 PDF 的測試主機，例外經真的 `ExceptionLogService.RecordAsync` 寫入）：
  - 未登入 401；非管理者打設定、清單、堆疊、刪除、全部清除、AI 分析都是 403，也沒有花到 AI。
  - 清單依關鍵字；堆疊與送出字數；找不到 404；一次讀多列；CSV 由伺服器產生並寫稽核 `via=Api`。
  - AI 分析：串流 `delta` 後 `done`；用量帳本記在呼叫的管理者身上；送出的內容含例外訊息、**不含帳號**；稽核成功；PDF 由伺服器產生並寫稽核。
  - 讀到第一段就中斷：帳本記 Cancelled，稽核「使用者取消」。
  - 刪除後再刪 404；清除 N 天前會刪掉舊列；都寫稽核。
- **L2 `ExceptionLogApiWithoutAiTests`**：沒設定 AI 時設定標成不能用，AI 分析回 400。
- **抓錯檢查**：
  - 拿掉 `[AdminOnly]` → 非管理者那則失敗；
  - `DiagnosticAiService` 改回只看 `CurrentUserService` → AI 分析那則失敗（帳本記不到人）。
  - 都已還原。
- **全套**：單元／API 與端對端照跑；系統例外頁仍是 Server 頁，MON-01／02 照過。
