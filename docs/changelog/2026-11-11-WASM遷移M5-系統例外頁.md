## 一、原因

1.1.40 已開好 `api/v1/exception-logs`。這版把系統例外頁 `/system-exceptions` 搬到 WASM，畫面不變。

## 二、修改

### 2.1 頁面搬到 WASM

- `ExceptionLogView` 用 `git mv` 搬成 `Web.Client/Pages/Monitoring/ExceptionLogPage.razor(.cs/.css)`；Server 的 `Pages/Monitoring/ExceptionLogPage.razor` 外殼刪除。
- 新 `Web.Client/Api/ExceptionLogApi.cs`；`ClientJsonContext` 補 8 個型別；`Program.cs` 註冊；`WasmRoutes` 加 `/system-exceptions`。
- 管理者判斷改用 `PermissionView.IsAdmin`，被拒時 `PageAccessApi.RecordPageDeniedAsync`。
- 以下全部改走 API，稽核都由伺服器寫，頁面不再寫：
  - 清單、設定（保留天數、AI 能不能用）；
  - 明細的堆疊、點列複製、複製全部（先查清單、再一次讀多列堆疊）；
  - 匯出 CSV、刪除（含多選，逐筆呼叫）、清除 N 天未再發生、全部清除。
- **AI 例外分析**：
  - 確認窗的字數由伺服器算好，隨堆疊一起回來。
  - 按「開始分析」後讀串流，邊收邊顯示；關掉視窗＝中斷請求，伺服器停止呼叫 AI。
  - 送出的內容由伺服器依例外編號組（不含帳號），頁面不再組。
  - 「匯出 PDF」由伺服器產生。
  - 「已等待 N 秒」的計時留在前端。
- 文字、按鈕、class 都不變。

### 2.2 剪貼簿組字搬到 Dtos

`ExceptionLogClipboardText`（點列複製、複製全部的文字）從 Server 的 `Views/Monitoring` 搬到 `Dtos/Diagnostics`，WASM 頁與單元測試共用；`ExceptionLogClipboardTextTests` 只改引用。

### 2.3 文件與版本

- 文件：
  - 系統例外紀錄 PRD、PRD 索引、畫面與欄位字典、對話窗 UI 設計規範；
  - 開發慣例速查、測試指南；
  - 09 號「十、之六」。
- 版本 1.1.40 → 1.1.41。

## 三、外部可見的行為變更

| 項目 | 以前 | 現在 |
|---|---|---|
| 系統例外頁 | Server 頁 | WASM 頁，畫面不變，資料走 API |
| 匯出、刪除、清除、AI 分析的稽核 | 畫面寫 | 伺服器寫，另加 `via=Api` |
| AI 分析送出的內容 | 畫面組 | 伺服器依例外編號組（同樣不含帳號） |
