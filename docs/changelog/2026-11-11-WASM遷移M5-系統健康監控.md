## 一、原因

M5 第三頁：系統健康監控 `/system-health` 搬到 WASM。這頁有三件事要在伺服器做：
- 跑全部健康檢查；
- 讀最近 24 小時的警告日誌；
- 管理者手動的「測試 AI 連線」，會產生費用。

## 二、修改

### 2.1 API（加在 `MonitoringController`，`api/v1/monitoring`，`[AdminOnly]`）

| 端點 | 說明 |
|---|---|
| `GET health` | 跑一輪全部檢查，回 `SystemHealthReport`（分數、燈號、各項佐證）。失敗回 500，訊息同畫面「讀取系統健康狀態失敗：例外型別。」 |
| `GET logs/recent-warnings` | 最近 24 小時警告以上的日誌，最新 200 筆，時間正序（畫面自己反轉成最新在前）。讀檔失敗時結果帶訊息，同畫面 |
| `POST ai-connection-test` | 實際呼叫一次文字生成與語音轉錄。**會產生費用**，確認框在畫面上。回兩個探測結果 |

- **稽核改由伺服器寫**：`AiConnection.Test` 由伺服器寫，內容同以前，另加 `via=Api`。
- **AI 呼叫者**：`AiConnectionTestService` 改經 `IAiCallerProvider`（同 1.1.28），用量帳本記到呼叫的管理者。以前只看 `CurrentUserService`，經 API 會記不到人。

### 2.2 型別搬到 Dtos

- `SystemHealthReport`、`SystemHealthItem`、`SystemHealthStatus`、`SystemHealthLight`、`SystemHealthGroups` 從 `Web/Health` 搬到 `Dtos/Diagnostics`；
- `AiConnectionProbeResult` 從 Business 搬到 `Dtos/Diagnostics`。

### 2.3 頁面

- `SystemHealthView.razor(.cs/.css)` 搬到 `Web.Client/Pages/Monitoring/SystemHealthPage.*`，`@page "/system-health"`；刪掉 Server 的頁面。
- 畫面、文字、按鈕、分組都不變。
- 管理者判斷用 `PermissionView.IsAdmin`。
- `WasmRoutes` 加 `/system-health`。

### 2.4 文件與版本

- 文件：
  - 系統健康監控 PRD 與機制文件、Web API 端點目錄；
  - 畫面與欄位字典、架構總覽、介面視覺設計規範；
  - 09 號「十、之六」。
- 版本 1.1.34 → 1.1.35。

## 三、外部可見的行為變更

| 項目 | 以前 | 現在 |
|---|---|---|
| 系統健康監控頁 | Blazor Server 頁 | WASM 頁，畫面不變 |
| 測試 AI 連線的用量歸屬 | 記到操作的管理者（Blazor 頁） | 同左（經 API 也記得到） |
| 測試 AI 連線的稽核 | 由畫面寫 | 由伺服器寫，內容另加 `via=Api` |

## 四、測試

- **L2 `MonitoringApiTests`**：
  - `health`、`logs/recent-warnings`：未登入 401，非管理者 403 並留稽核；
  - 管理者拿到完整報告（各項都在、權重合計 100、分組正確）；
  - 警告日誌最多 200 筆、都是 WARN 以上；
  - `ai-connection-test`：非管理者 403；管理者執行後稽核由伺服器寫、`via=Api`。測試主機沒設定 AI，不會真的花錢。
- **單元**：`SystemHealthChecksTests`、`SystemHealthTests`、`LoggingPipelineHealthTests`、`AiConnectionTestServiceTests` 照過，只改 using；`ApiIntegrationTests` 未登入開 `/system-health` 不外洩那則照過。
- **端對端**：MON-01、MON-02 的 `/system-health` 一行不改照過，全套照跑。
- **抓錯檢查**：暫時讓 AI 連線測試寫錯稽核動作 → L2 失敗；已還原。
