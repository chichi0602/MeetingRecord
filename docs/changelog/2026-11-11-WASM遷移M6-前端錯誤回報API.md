# WASM 遷移 M6：前端錯誤回報改走 API（1.1.46 → 1.1.47）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：1.1.47
- 首次實作版本：1.1.47
- 最後核對日期：2026/11/11

使用者要求：

> 需要做 M6 並且一次性做完。

---

## 一、原因

瀏覽器端錯誤（JS 的 `error`／`unhandledrejection`）以前經 Blazor Server 的 circuit 回報。頁面搬到 WASM 後就沒有這條路了，**WASM 頁的瀏覽器錯誤一直送不出去**，只暫存在記憶體後丟掉。M1 時因為要「依帳號限流」而延後，這版補上。

## 二、修改

### 2.1 新 API：`POST api/v1/client-errors`（`ClientErrorController`）

- 任何登入者都能回報自己頁面上的錯誤；匿名者 401，無從灌資料。
- 內容（`ClientErrorReportDto`）：種類、訊息、堆疊、腳本位置、頁面路徑。
- 記進日誌檔與系統例外紀錄：
  - 來源「瀏覽器」，帳號是呼叫者；
  - 頁面只留路徑（查詢字串與錨點可能含權杖）；
  - 長度伺服器再截一次。
- 回傳是否記下（停用或超過上限是 `false`，前端不必處理）。

### 2.2 伺服器：`BrowserErrorReporter`

- 改成 Singleton，**依帳號限流**：每個帳號每分鐘最多 `ClientErrorReporting:MaxPerCircuitPerMinute` 筆（預設 10），一個人洗版不會擋到別人。
- 設定名稱沿用 Blazor Server 時代的，避免改到已部署的設定檔。
- 帳號從 API 請求取（`IAuditActorProvider`），不再讀 `CurrentUserService`。

### 2.3 WASM 端

- 新 `Web.Client/Services/ClientErrorReporter`（JS 可呼叫），把錯誤轉送到 API；回報失敗一律吞掉，不會自己觸發自己。
- `WasmLayout` 在登入狀態確認後註冊一次。註冊前發生的錯誤由 JS 暫存（上限 20 筆），註冊時一次送出。
- `client-error-reporter.js` 的捕捉與過濾不變（略過外掛腳本、ResizeObserver），只改說明。

### 2.4 文件與版本

- 文件：
  - 系統例外紀錄 PRD、架構總覽、日誌與設定檔說明、正式部署與安全檢查清單；
  - Web API 端點目錄、測試指南；
  - 09 號「十、之七」。
- 版本 1.1.46 → 1.1.47。

## 三、外部可見的行為變更

| 項目 | 以前 | 現在 |
|---|---|---|
| WASM 頁的瀏覽器錯誤 | 送不出去 | 記進系統例外紀錄（來源「瀏覽器」） |
| 回報上限 | 每條 Blazor 連線每分鐘 10 筆 | 每個帳號每分鐘 10 筆 |

## 四、測試

- **L2 `ClientErrorApiTests`**（新）：
  - 未登入 401；
  - 登入者回報後，系統例外紀錄出現一筆，來源「瀏覽器」、帳號與使用者 Id 是呼叫者、頁面只留路徑；
  - 同一帳號連送 12 筆只記 10 筆。
- **單元 `BrowserErrorReporterTests`**：改成新的簽章，新增「依帳號限流」：一個帳號超過上限不擋另一個帳號。
- **端對端 ERR-01**（新）：在 WASM 頁丟一個 JS 錯誤，系統例外紀錄出現那一筆。
  - 第一次跑沒過：瀏覽器 `error` 事件的訊息會帶「Uncaught Error: 」前綴，測試改成比對包含。
- **抓錯檢查**：
  - 限流改成所有人共用一個時間窗 → 依帳號那則失敗；
  - 拿掉 `WasmLayout` 的註冊 → ERR-01 失敗。
  - 都已還原。
- **全套**：單元／API 與端對端全綠。
