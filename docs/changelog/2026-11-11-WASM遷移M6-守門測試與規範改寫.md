# WASM 遷移 M6：守門測試補強與規範改寫（1.1.47 → 1.1.48）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：1.1.48
- 首次實作版本：1.1.48
- 最後核對日期：2026/11/11

使用者要求：

> 需要做 M6 並且一次性做完。

---

## 一、原因

Blazor Server 頁拆除後（1.1.46），有兩類東西要跟上：

1. **掃原始碼的守門測試**：資料夾搬走或掃描範圍寫錯時，掃到零個檔案也會「通過」，等於沒在守。
2. **開發規範**：開發慣例速查、架構總覽、CLAUDE.md 還寫著只適用 Blazor Server 的規則，例如：
   - DbContext 每條連線共用、編輯前 `Clone()`；
   - 頁面用 `CheckIsAdmin` 守門、`CurrentUserService` 由 Blazor 頁填；
   - 追蹤碼與 IP 由 circuit 給。

照著寫會寫錯。

## 二、修改

### 2.1 守門測試加下限

| 測試 | 新增的檢查（1.1.48 的實際數量） |
|---|---|
| `HoverTipUsageTests` | 至少掃到 40 個 razor 檔（56）、30 個可排序欄位（43） |
| `TableSelectionColumnTests` | 至少掃到 8 個勾選欄（10）；只認 `PermissionView.Can`，Server 頁的 `CheckAccessAction` 寫法不再放行 |
| `ModalVisibleBindingTests` | 至少掃到 8 個有確定鈕的 WASM 視窗（11） |
| `PageAccessDeniedAuditTests` | 1.1.46 已改成只掃 `Web.Client`，下限 17 加上說明 |

CSRF（Cookie 登入但寫入沒帶 `X-MeetingRecord-Client` 被擋）既有 `CookieApiTests.CookieWrite_WithoutClientHeader_ShouldBeRejectedAsCsrf` 守，不另寫。

### 2.2 規範改寫

**開發慣例速查**：
- 頁面與共用元件都在 `Web.Client`；
- 元件的資料來源只剩 API 實作；
- 頁面拒絕稽核走 `PageAccessApi`；
- 往伺服器頁（登出等）才整頁載入；
- `PermissionView` 規則同 `AuthenticationStateHelper.CanAccessPage`／`CanDoAction`；
- 前端參考不到 `BackendDBContext`；
- `Clone()` 只是畫面層的事、DbContext 一個請求一個；
- 登入狀態與權限鍵來自 Session API；
- 上傳的開始、完成、取消經 API；
- 服務層不可平行（同一個請求共用 DbContext），WASM 頁同時打兩支 API 沒問題；
- 追蹤碼與 IP 走 HTTP 請求；
- 中文輸入法那節加註（WASM 後理論上不再發生，但沒重新實測，規則維持）。

**架構總覽**：
- 專案職責（Web 不再是 Blazor Server 宿主、Web.Client 是全部的頁面）；
- 「監控與診斷」「AI 管理」頁的守門方式；
- 例外情境與追蹤碼不再提 circuit；
- 服務清單（`AuthenticationStateHelper` 只剩純函式、加上 `UserSessionService`）；
- **請求生命週期 4.1 改成 WASM 頁 → API**；4.2 的 Repository 改成 Service；
- 分層慣例表。

**CLAUDE.md**（專案根目錄）：
- 分層依賴補上 `Web.Client` 的規則；
- 網頁用登入 Cookie 打 API；
- 資料權限「API Repository」改成服務層（Repository 1.1.24 已沒有）；
- 編輯前複製與清追蹤的新說法；
- 新增頁面要有 API Controller、授權測試、`PermissionView` 與拒絕稽核。

**其他**：docs 索引（測試報告說明）、測試指南（掃描測試的下限）、09 號「十、之七」。
