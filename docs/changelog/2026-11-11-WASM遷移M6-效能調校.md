# WASM 遷移 M6：效能調校（1.1.48 → 1.1.49）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：1.1.49
- 首次實作版本：1.1.49
- 最後核對日期：2026/11/11

使用者要求：

> 需要做 M6 並且一次性做完。

---

## 一、原因

09 號文件的 L5 門檻：有快取的再次載入要在 1.5 秒內。M1～M5 的報告都記錄超過門檻，這版先做低風險的調整並量測。

## 二、修改

### 2.1 調整

- **登入狀態與選單同時發出**（`WasmLayout`）：以前先等 `api/v1/session` 回來，才發 `session/menu`。選單 API 對須改密碼的人也開放，登入狀態不通過時選單結果直接丟掉。
- **AntDesign 的樣式與腳本走 `@Assets`**（`App.razor`）：取得指紋網址與永久快取，不必每次向伺服器確認有沒有更新。
- **字型網域預先連線**：Google Fonts 的兩個網域加 `preconnect`。
- **請求日誌略過靜態檔**（`UseHttpRequestLogging`）：`/_framework`、`/_content` 每次載入幾十個，以前逐一記 Information；API、頁面與推播照記。

### 2.2 量測（WASM-06，Playwright 從重新載入到登入者名稱出現，各 3 次）

| | 首次載入（門檻 4 秒） | 有快取再次載入（門檻 1.5 秒） |
|---|---|---|
| 調整前 | 1.94～2.64 秒 | 1.63～1.88 秒 |
| 調整後 | 1.85～2.44 秒 | 1.77～1.98 秒 |

**沒有明顯改善**。用瀏覽器的資源時間軸追了一次有快取的重新載入：

| 時間點 | 發生的事 |
|---|---|
| 0～140 ms | 所有快取檔案讀完（傳輸量 0） |
| 約 940 ms | 第一支 API 才發出 |
| 940～980 ms | session 與 menu 已同時發出（相差 10 ms），各 20～30 ms |
| 約 1.4 秒 | 頁面出現（Playwright 自己量會再多 0.3～0.5 秒） |

所以時間主要花在 **.NET WASM 執行環境啟動**（約 0.9 秒），不在網路或 API。再往下要動 AOT 編譯或修剪模式：前者下載量會變大（已貼近 5 MB），後者有破壞 AntDesign 的風險。下一版（1.1.50）以真正門檻量測後，交給使用者決定。

`System.Private.Xml` 也在啟動時載入，但應用程式本身沒用到 XML，是框架帶進來的，不動。

### 2.3 文件與版本

- 文件：日誌與設定檔說明（請求日誌略過靜態檔、追蹤碼不再有 circuit）、架構總覽、09 號「十、之七」。
- 版本 1.1.48 → 1.1.49。
