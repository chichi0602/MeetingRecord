# 程式註解更新到遷移後現況（1.1.54 → 1.1.55）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：1.1.55
- 首次實作版本：1.1.55
- 最後核對日期：2026/11/12

使用者要求：1.1.53 核對時發現的程式碼歷史註解、`CurrentUserService` 的說明要整理（「都要」；`CurrentUserService` 選「只改註解」）。

---

## 一、原因

文件在 1.1.53 更新到遷移後的現況，但程式碼的註解還有約 190 處停在遷移前或遷移中，例如：

- 「比照 Server 頁」「1.1.x 搬到 WASM，以前…」；
- 「在 Blazor Server 上 circuit 會斷」；
- 提到 `MainLayout`、`CheckAccessAction`、Repository 等已移除的東西；
- `CurrentUserService` 的說明還寫「Blazor 用它、由 `AuthenticationStateHelper.Check` 填入」。

1.1.53 的回報說「`CurrentUserService` 已經沒有地方寫入值」，這不對：背景上傳工作（`MeetingMediaUploadJobs`）自開 scope 時會把上傳者填進去，後續的服務、稽核與 AI 計費靠它知道是誰觸發的。API 請求時它是空的，`AuditActorProvider`／`AiCallerProvider`／`RecordAccessScopeProvider` 改從 HTTP 的 claims 取。所以它仍在用，這版只更正說明，不動程式。

## 二、修改

**只改註解**（`//`、`///`、`/* */`、Razor `@* *@`、CSS／JS 註解），程式邏輯、識別名稱、日誌樣板都不動：

| 範圍 | 檔案 | 處數（約） |
|------|------|-----------|
| `MeetingRecord.Web.Client` | 73 | 115 |
| `Web`、`Business`、`Share`、`Dtos`、`Models`、`AccessDatas`（含 `wwwroot/app.css` 與 js） | 121 | 150 |
| `MeetingRecord.Tests`、`MeetingRecord.E2ETests` | 66 | 105 |

- **只描述現況**：
  - 拿掉「WASM 遷移 Mx」「從 Blazor Server 的 XxxView 搬來」「同 Server 頁」等說法；
  - 已移除的元件改指現在的對應：`AppShell`／`WasmLayout`、`PermissionView`、`[AdminOnly]`、`PageAccessApi`、`HelpPage` 等；
  - 「circuit／Blazor 連線」改成 API 請求、scope 或背景服務。
- **保留**：功能起始版本「（x.y.z）」，以及說明為什麼這樣寫的踩雷教訓，必要時改成現在式。例如：
  - 背景 scope 的 `CurrentUserService` 是空白物件，要由呼叫端傳入使用者；
  - 1.1.39 的查詢字串無限重載；
  - 注音選字的 Enter。
- **`CurrentUserService`**：所有說明改成「只由背景工作填入上傳者；API 請求時是空的，改從 claims 取」。
- **順手更正兩處本來就錯的註解**：
  - `TextSearchHelper` 的命名空間是 `Share.Helpers`；
  - `ClientRoutes` 列的伺服器頁補上等待核准。

**註解以外的少數文字**（都是現況描述，不影響行為）：

- 端對端測試標題（會出現在測試報告）：
  - NAV-01「全程沒有 Blazor Server 連線」→「全程不建立 `/_blazor` 連線」（測試斷言的就是這件事）；
  - 5 個標題拿掉多餘的「（WASM 頁）」：AI-、AIM-01、AIM-02、EXC-01、LOG-01；
  - L4-09「換到其他 WASM 頁」→「換到其他頁面」。
- `/wasm` 預覽頁的說明文字：原本是「遷移期間其他頁面仍是原本的版本，從選單點過去會整頁載入」，改成說明這頁的用途。
- **AI 例外分析的系統提示詞**：原本告訴 AI「你是 ASP.NET Core／Blazor Server／EF Core 工程師」，改成「ASP.NET Core Web API／Blazor WebAssembly／EF Core」，讓 AI 用正確的架構分析。這會送給 AI，所以列在這裡。
- 版本 1.1.54 → 1.1.55。

## 三、外部可見的行為變更

- `/wasm` 預覽頁的一行說明文字。
- AI 例外分析時，提示詞裡的架構描述改成現況。

## 四、核對時發現、這版沒處理的事

- `wwwroot/app.css` 的 `.app-error-banner-overlay` 已經沒有任何頁面使用（死樣式）。
- `Profile.razor` 存檔後仍以整頁載入回 `/meetings`。原本的理由（會議頁是舊版頁面）已不成立，可能可以改成一般導覽。
- `BackgroundJobBoard`／`ProjectAccessService.LoadAsync` 為了「背景事件觸發的面板」另開短命 scope，現在唯一的呼叫端是 `JobController`，另開 scope 可能已不需要。
- 幾個 JS 互動類別的 catch 註解寫「預先算繪階段沒有 JS」，但系統關閉了預先算繪（`prerender: false`）。catch 實際還會接到什麼沒有確認，所以先不動。

以上都是程式改動，不在這次「只改註解」的範圍。
