# 腳本更新到遷移後架構（1.1.51 → 1.1.52）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：1.1.52
- 首次實作版本：1.1.52

使用者要求：

這一版處理**腳本**（文件的全面核對在下一版）。

---

## 一、原因

WASM 遷移（1.1.51）完成後，`scripts/` 裡的腳本還停在遷移前或遷移中：

- `New-CrudModule.ps1` 產生的是 Blazor Server 的 Page＋View＋Repository，用 JWT 而且沒有 `[HasPermission]`。
- `New-TestReport.ps1`：
  - L2 寫死成 5 個類別，之後新增的 28 個 `*ApiTests` 都被算成 L1；
  - 不帶參數產生「M0 基準報告」；
  - 留著遷移最終報告用的 `-WasmE2ETrx` 並列模式（M6 改用 `-Milestone M6`，這個模式從沒用過）。
- `New-StarterProject.ps1` 改名時漏了 `.cmd`、`.mjs`，`run.cmd` 與 `Backfill-AiUsageCost.mjs` 裡的專案名稱不會換掉。
- `Test-DocsEncoding.ps1` 只能在 repo 根目錄執行。

## 二、修改

### 2.1 `New-TestReport.ps1`、`Run-E2E.ps1`

- **L1／L2 依「有沒有啟動測試主機」分**：腳本掃 `MeetingRecord.Tests` 原始碼，標了 `[Collection(nameof(ApiHostCollection))]` 的類別（目前 32 個）是 L2，其餘是 L1。新的 API 測試類別照慣例標上集合就自動算進 L2。
  - `ApiResultTests`、`JwtTokenServiceTests`、`ApiAuthorizationConventionTests` 不啟動主機，改算 L1。
  - 第四節的「授權守門掃描」改從全部單元結果找，不受分層影響。
- **預設產生一般測試報告**：
  - 不帶參數時，標題「測試報告」，涵蓋 L1～L5，檔名「日期-測試報告-版本.md」，沒有 L6 人工驗收一節。
  - `-Milestone Mx` 是里程碑報告，多一節 L6，檔名「日期-Mx-里程碑測試報告-版本.md」。
  - `-Milestone M6` 保留遷移最終報告的格式。
  - `Run-E2E.ps1` 的 `-Milestone` 預設改成空值。
- **拿掉並列模式**：刪除 `-WasmE2ETrx` 參數與 Server／WASM 兩欄。摘要一律寫「版本」與「頁面全部在瀏覽器執行；伺服器只靜態算繪登入、登出、等待核准與錯誤頁」（補上等待核准）；第三節改名「端對端情境矩陣（L3～L5）」，只有一個結果欄。
- 兩支腳本的表頭說明改成現況。

### 2.2 `New-CrudModule.ps1` 重寫

直接在方案裡產生一組照現在架構的 CRUD 模組：

- 實體；
- DTO：新增修改輸入、輸出（有 `Clone()`）、搜尋條件；
- 服務：篩選、排序、分頁、名稱重複檢查，寫入前後清除追蹤；
- API Controller：`ApiScheme`＋每個動作一個 `[HasPermission]`，回傳 `ApiResult<T>`／`PagedResult<T>`，名稱重複 409、找不到 404；
- WASM 端的 API 包裝；
- WASM 頁：`PermissionView`、擋下時記稽核、編輯前 `Clone()`、`FormSubmitGate`、`FormKeyboardHelper`、放棄修改確認；
- L2 授權測試：5 支端點各測未登入 401、沒權限 403，有權限時 CRUD 走一輪。

腳本不改既有檔案，最後列出要手動登錄的 8 處，並附上要貼的程式碼：

- 權限鍵常數、權限目錄、`Menu.json`、`MenuPermissionMap`；
- `DbSet` 與 migration；
- 服務與 API 包裝的 DI 註冊；
- `ClientJsonContext`。

已有檔案時整組不寫，除非帶 `-Force`。
