## 一、修改

### 1. 拿掉沒人用的樣式

`wwwroot/app.css` 的 `.app-error-banner-overlay` 是給以前錯誤邊界「渲染在頁面最底、固定在視窗下緣」的錯誤畫面用的，那個錯誤邊界已經移除，現在沒有任何頁面用到。連同說明一起刪除；`.app-error-banner` 本身仍由 `WasmLayout` 使用，保留。

### 2. 「設定 API 密碼」頁（`/Profile`）不再整頁重新載入

- **以前**：存檔成功與按「取消」都以 `forceLoad: true` 回 `/meetings`。理由是會議頁還是舊版頁面，要整頁載入才換得過去。
- **現在**：所有頁面都在同一個前端，而且 API 密碼不在外框用的登入資料（Session）裡，不必整頁重新載入。改成一般的頁內切換：比較快，也不會重新下載與啟動整個前端。
- 須改密碼的帳號會先被 `WasmLayout` 導到變更密碼頁，進不了這一頁，所以不影響「須改密碼」旗標的處理。

### 3. 背景工作進度不再另開 scope 查資料範圍

- **以前**：`BackgroundJobBoard` 查「呼叫者看得到哪些會議」時，自己開一個短命的 DI scope、拿另一個 `DbContext` 查。理由是以前右下角的面板可能被背景事件觸發，會和同一個 context 上正在跑的查詢撞在一起。
- **現在**：唯一的呼叫端是 `JobController`，一個 API 請求只依序呼叫一次，不會並行。改成直接注入請求的 `ProjectAccessService`、呼叫 `GetAsync()`。
- `ProjectAccessService.LoadAsync(context, scope)` 已經沒有外部呼叫端，改成 private。
- 〈開發慣例與限制速查〉對應那條規則同步更新：一律經請求的 `ProjectAccessService`，真的要並行才自開 scope。

### 4. 前端 JS 互動的錯誤處理

- **拿掉 5 段 `catch (JSDisconnectedException)`**（`AiChatModal` 2 段、`TextEditorInterop`、`HelpViewInterop`）：這個例外只有 Blazor Server 在連線中斷時才會丟，WASM 不會發生，是死碼。
- **`catch (InvalidOperationException)` 保留**：對還沒綁上的 `ElementReference` 呼叫 JS 會丟這個例外，例如區塊因權限沒有渲染時（`ProjectPage` 的 `FocusAsync` 就是實例）。原本的註解寫「預先算繪階段沒有 JS」是錯的（系統關閉了預先算繪），改成「元素還沒綁上或元件已經被處置：略過即可」。
- `TodoAutoFit.FallbackRows` 的說明拿掉「預先算繪」。
