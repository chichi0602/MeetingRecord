# 頁面上的 .NET 例外送到系統例外紀錄（1.1.53 → 1.1.54）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：1.1.54
- 首次實作版本：1.1.54
- 最後核對日期：2026/11/12

使用者要求：1.1.53 核對時發現的缺口要處理（「都要」）。

---

## 一、原因

瀏覽器端只攔 JavaScript 的 `error`／`unhandledrejection`（`client-error-reporter.js`）。但 WASM 頁上的 .NET 例外不會觸發這兩個事件：

- 被 `WasmLayout` 的 `ErrorBoundary` 接住的例外，畫面顯示「這個頁面發生未預期的錯誤…」；
- 算繪時沒人接住的例外（外框、通知鈴、進度面板等）。

這兩種 Blazor 都只用 `ILogger` 寫到瀏覽器主控台，所以**使用者看到錯誤畫面，系統例外紀錄卻什麼都沒有**。遷移前由伺服器的錯誤邊界記錄，遷移時沒補上。

## 二、修改

- **WASM 端** `Services/DotNetErrorForwarder.cs`（新）：
  - `ClientErrorLoggerProvider` 只轉送 Blazor 元件框架（類別 `Microsoft.AspNetCore.Components*`）記下、Error 以上、帶例外的記錄。
  - 頁面自己記的錯誤（例如 API 失敗）不轉送，那些在伺服器端已有紀錄。
  - `DotNetErrorForwarder` 經既有的 `ClientErrorReporter` 送到 `POST api/v1/client-errors`：
    - 種類 `dotnet`；
    - 訊息是「例外型別: 訊息」（最多 1000 字）；
    - 堆疊用 `exception.ToString()`（最多 4000 字）；
    - 頁面是當下路徑。
  - 登入狀態確認前發生的先暫存，最多 20 筆；`WasmLayout` 接上時一次送出，跟 JS 端同一套做法。
  - 送出失敗一律吞掉。
- **註冊**：`Web.Client/Program.cs` 註冊 forwarder 與記錄器提供者；`WasmLayout` 在登入狀態確認後 `Attach`。
- **伺服器**：
  - `BrowserErrorReporter` 接受 `dotnet` 種類，其他不認得的仍當 `error`。
  - 照舊依帳號限流（每分鐘 `MaxPerCircuitPerMinute` 筆）、截斷長度、只留路徑，來源「瀏覽器」。
- **`ApiClient` 收到 401 只導向登入頁一次**：
  - 登入一失效，同時進行中的請求（上傳分塊、查進度、錯誤回報）會各自拿到 401。以前每個都整頁導向，後一次打斷前一次（瀏覽器回 `net::ERR_ABORTED`）。
  - 這次的全套測試裡 L4-07（上傳途中登入失效）因此偶發失敗：單獨跑 3 次都過，多了錯誤回報這個請求來源之後更容易撞上。
  - 改成第一次 401 才通知、才導向，其餘只回 401 結果；整頁載入後重新建立，旗標自然歸零。
- **系統例外紀錄頁的提示**：原本是「使用者回報的『錯誤追蹤碼』可以直接貼進關鍵字查詢」，但使用者已經看不到追蹤碼。改成「用帳號與時間找來源『瀏覽器』的那筆；逐行日誌以明細裡的『最後追蹤碼』查」。
- **文件**：
  - 系統例外紀錄 PRD、PRD 索引、架構總覽、日誌與設定檔說明、測試指南（ERR-02）、畫面與欄位字典；
  - 使用說明的 FAQ 改成「錯誤已經自動記錄下來了…管理者可以依你的帳號與時間找到這筆錯誤」。
- 版本 1.1.53 → 1.1.54。

## 三、外部可見的行為變更

- 頁面出錯時，系統例外紀錄會多一筆來源「瀏覽器」、訊息以 .NET 例外型別開頭的紀錄。同一個錯誤在同一頁重複發生，依既有的簽章規則合併計次。
- 錯誤畫面的文字不變。

## 四、測試

- **L1** `DotNetErrorForwarderTests`（5 則）：
  - 元件框架的 Error（`ErrorBoundary`）、Critical（renderer）會轉送；
  - 其他類別、Warning、沒有例外物件的不轉送；
  - 接上前暫存 20 筆、接上時送出並帶當下路徑；
  - 過長訊息截斷。
- **L1** `BrowserErrorReporterTests`：`unhandledrejection`、`dotnet` 照原樣保留。
- **L1** `WasmApiClientTests.ManyUnauthorized_ShouldRedirectToLoginOnlyOnce`：同時 3 個 401 只導向一次、只通知一次（改之前實測導向 3 次，測試失敗）。L4 十則重跑全過。
- **端對端 ERR-02**：
  - 讓儀表板 API 回傳格式正確、但卡片清單是 null 的資料，頁面算繪時丟 `NullReferenceException`；
  - 驗證畫面出現錯誤提示，而且系統例外紀錄出現 `/dashboard`、訊息含 `System.NullReferenceException`、來源「瀏覽器」、帳號是登入者的那一筆。
  - 抓錯檢查：暫時拿掉 `WasmLayout` 的接線，ERR-02 失敗（「.NET 例外沒有記進系統例外紀錄」），還原後通過。
- 全套 `Run-E2E.ps1 -NoReport`（1.1.54，含 401 只導一次的修正）全部通過：單元／API 2218 則、端對端 126 過 1 略過（同 M0 起的既有略過）。
