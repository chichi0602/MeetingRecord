# 第一次開啟的載入畫面（1.1.57 → 1.1.58）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：1.1.58
- 首次實作版本：1.1.58
- 最後核對日期：2026/11/13

使用者回報：在一台沒開過系統的瀏覽器第一次開網址，畫面空白很久才出現登入頁；開過一次之後再開就很快。空白期間使用者分不出是系統壞了還是自己操作錯了。希望至少有一段文字或簡單的動畫，讓人知道系統正在載入。

---

## 一、原因

- 除了登入、登出、等待核准、錯誤頁，所有頁面都是瀏覽器端的 WASM 頁，而且不預先算繪（`InteractiveWebAssemblyRenderMode(prerender: false)`）。伺服器只送出一個空的標記，要等瀏覽器下載完約 4.8 MB 的執行環境並啟動，畫面才有內容。
- 未登入的人更慢：WASM 跑起來後，`WasmLayout` 問 Session API 拿到 401，這時 `ApiClient` 才導去登入頁。等於先下載完整個 WASM，只為了被導去登入頁。
- 第二次開時這些檔案都在瀏覽器快取裡，所以很快。

## 二、修改

### 1. 未登入時，伺服器直接導到登入頁

- `Web/Components/App.razor.cs`：WASM 頁遇到未登入，直接 302 到 `/Auths/Login?ReturnUrl=<原網址>`，不送 WASM；登入後回到原網址。
- 缺檔的 404 重新執行到 `/not-found` 時不導（看 `IStatusCodeReExecuteFeature`），維持 404。

### 2. 載入畫面

- `App.razor` 在每個 WASM 頁先送出純 HTML／CSS 的載入畫面 `#app-loading`（那時還沒有 AntDesign 可用），內容是：
  - 系統名稱（`SystemSettings.SystemInformation.SystemName`）；
  - 轉圈動畫；
  - 「系統載入中，第一次開啟需要較長時間，請稍候…」；
  - 下載百分比（`blazor.web.js` 寫在 `<html>` 的 `--blazor-load-percentage-text`）。
- `wwwroot/js/app-loading.js`：
  - 超過 20 秒還沒載完，顯示「載入時間比平常久，請確認網路連線；若一直沒有反應，請重新整理頁面或聯絡系統管理員。」和「重新整理」按鈕；
  - 提供 `meetingRecordAppLoading.hide()`。
- `Web.Client/Layout/WasmLayout.razor`：外框（或「無法取得登入狀態」訊息）畫好後才拿掉載入畫面，中間不會閃一下空白。要整頁導走的（登入失效、須改密碼、停用）不拿，留到換頁。
- 樣式放 `app.css` 的 `.app-loading*`，配色沿用全站的燕麥奶茶色；`prefers-reduced-motion` 時轉圈放慢（不停止，免得看起來像當掉）。

### 3. 登入頁在背景預先載入 WASM

- 原本計畫「先實測，有效才加」。實測後登入頁完全沒有預先下載（停 5 秒只有 `blazor.web.js` 一個請求），登入後還要等約 14 秒，所以加上。
- 登入頁放了瀏覽器端、什麼都不畫的元件 `Web.Client/Components/WasmWarmup.razor`，由 Blazor 用它自己的資源清單，趁使用者輸入帳密時在背景下載並啟動 WASM。
- WASM 頁的 `<head>` 只預載了 `dotnet.js`，完整的清單包在 `dotnet.js` 裡，伺服器端拿不到準確的清單，所以不用 `<link rel="prefetch">`。
- 這個元件不打 API；WASM 的 `Program.cs` 啟動時也只註冊服務。登入頁沒登入，打 API 拿到 401 會被導回登入頁，一直重新載入。端對端 LGN-09 檢查登入頁沒有任何 `/api/` 請求。

### 4. 其他

- 更正 1.1.57 `Program.cs` 在 `UseWebAssemblyDebugging()` 上方的註解：舊註解寫「沒掛的話 VS 只能用內建代理」，這是後來已推翻的推論。
- 版本 1.1.57 → 1.1.58。

## 三、外部可見的行為變更

- 未登入開任何 WASM 頁，會立刻被導到登入頁，網址多了 `?ReturnUrl=…`；登入後回到原本要去的網址（以前一律到 `/meetings`）。
- WASM 頁下載、啟動期間顯示載入畫面，不再一片空白。
- 登入頁在背景下載約 4.8 MB（第一次開啟時；之後都在瀏覽器快取裡）。

## 四、實測（親自體驗）

做法：
- 用 Edge 無頭瀏覽器，每次開全新的瀏覽器內容（沒有快取）；
- 用 CDP 限速，延遲 40 ms；
- 網站以 Release 發佈、E2E 環境啟動；
- 依序截圖並看過。

| 情境（4 Mbps，512 KB/s） | 修改前 | 修改後 |
|---|---|---|
| 開網址到出現登入頁（停用快取） | 空白 12.95 秒 | 0.43 秒 |
| 登入後到畫面出現第一個東西（停用快取） | 空白約 13 秒 | 0.43 秒出現載入畫面，百分比一路往上跳 |
| 登入後到會議紀錄頁畫好（停用快取，等於每次都重新下載） | 14.05 秒 | 14.09 秒（一樣要下載，但看得到進度） |
| 登入後到會議紀錄頁畫好（全新快取，在登入頁停 15 秒，大約是輸入帳密的時間） | 約 14 秒 | 2.51 秒 |

- 網路很慢（96 KB/s）時，登入後約 20 秒出現提示與「重新整理」按鈕，載完後載入畫面消失、外框正常。
- 登入頁本身會不會被背景下載拖慢（128 KB/s，各兩次，看瀏覽器記錄的首次繪製 FCP）：修改前 7.57／7.44 秒，修改後 7.68／7.59 秒，主要都花在等樣式檔，差距約 0.1 秒。
- 「停用快取」是照使用者描述的方式重現；一般使用者不會停用快取，背景預先載入的效果以「全新快取」那列為準。
