# 轉錄改用 diarize、逐字稿顯示講者（1.1.62 → 1.1.63）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：1.1.63
- 首次實作版本：1.1.63
- 最後核對日期：2026/11/13

使用者需求：

> 現在這個系統 可以判斷人聲嗎 想看誰講了甚麼
>
> 我剛剛在模型上下載了 gpt-4o-transcribe-diarize，我想讓這個系統改用這個模型轉錄

使用者決定：逐字稿要顯示講者，**每 5 分鐘那一段各自標 A／B／C**，跨段不對齊同一人。

---

## 一、為什麼不能只改設定

1. diarize 模型的輸入超過 30 秒時，**`chunking_strategy` 是必填**，不帶會直接回 400。我們每段約 5 分鐘，一定會遇到。
2. 原本送的是 `response_format=text`，拿不到講者，要改成 `diarized_json`，再把 JSON 轉成文字。

## 二、修正

- `AzureOpenAiTranscriptionProvider`：部署名稱含 `diarize`（不分大小寫，`IsDiarizeModel`）時，改送 `response_format=diarized_json`＋`chunking_strategy=auto`。其他部署照舊送 `text`，舊部署的行為不變。
- 新增 `DiarizedTranscriptFormatter`：把 `segments[].speaker／text` 轉成一行一位講者的「講者 A：……」，相鄰的同一講者合併成一行。沒有 segments 時退回 `text`，不是 JSON 時原樣回傳，寧可沒有講者也不要整段不見。
  - 講者之間用 `\n`，**不用 `\n\n`**：`\n\n` 是轉錄分段的邊界，`TranscriptChunker` 和 `TranscriptionNoiseFilter` 都靠它切段。
- 新增 `Share.Helpers.TranscriptSpeakerLabels`：統一管理代號的格式、判斷（`HasLabels`）和去除（`Strip`），Business 和 Web.Client 共用。
- `TranscriptionSegmentPlanner.EstimateTokens` 先去掉代號再估算。代號是系統自己加的，不是模型的輸出；講者輪替多的段落會被代號灌水，誤判成截斷而對半重轉，重轉要再付錢。
- 產生會議紀錄：逐字稿有代號時，map 和 reduce 的提示詞最前面加上 `NameGuidancePromptHelper.SpeakerLabelNote`，說明代號不是人名、每段重新編號、判斷不出就寫「未標示」。沒有代號的舊逐字稿，提示詞逐字元不變。這段說明不併進人名名單，以免觸發名單的尾部提醒。
- 逐字稿頁籤（`MarkdownEditorModal`）：有代號時，上方顯示一行灰字說明。
- 設定：`appsettings.json` 單價表新增 `gpt-4o-transcribe-diarize`（每分鐘 0.006 美元）；`appsettings.Development.json` 的 `TranscriptionModel` 改成 `gpt-4o-transcribe-diarize`。

## 三、部署時要做的事

- `LlmSettings:Providers:AzureOpenAI:TranscriptionModel` 填 Azure 上的**部署名稱**，**名稱要保留 `diarize`**，系統靠這個字判斷要不要送講者參數。
- 單價表的鍵要跟部署名稱一模一樣。部署名稱不是 `gpt-4o-transcribe-diarize` 的話，要另外加一筆。
- ⚠️ 單價 0.006 美元／分鐘是依 OpenAI 價目先填的，要對照 Azure 價目表確認。
- 轉錄的 api-version 預設是 `2025-03-01-preview`。如果「系統健康監控 → 測試 AI 連線」回 400、說 api-version 不支援，改 `TranscriptionApiVersion` 設定就好，不用改程式。

## 四、已知限制

- 代號**每段（約 5 分鐘）重新編號**，前後兩段的「講者 A」不一定是同一人。跨段對齊要用 `known_speaker_references`（最多 4 人），這次沒做。
- 代號不是人名，系統不會自動對應到與會人員。
- **舊逐字稿不會有講者**，要按「重新轉錄」，而且會再計費一次。
- diarize 模型自己的輸出上限、JSON 會不會吃掉輸出額度，都還沒實測。1.1.61 的截斷保險還在，可以兜底。

## 五、驗證

- 相關測試（`DiarizedTranscriptionTests`、`TranscriptionRequestTests`、`AzureDeploymentErrorsTests`、`SystemHealthChecksTests`、`MeetingDraftJobRunnerTests`、`TranscriptionJobRunnerTests`、`TranscriptionSegmentPlannerTests`、`NameGuidancePromptHelperTests`、`RazorMarkupTests`）共 157 個全部通過；`MeetingRecord.Web.Client` 建置成功。依專案規定，這次沒有跑全套測試。
- 實機待驗：
  1. 改好設定後，到「系統健康監控 → 測試 AI 連線」，語音轉錄要顯示成功。
  2. 上傳一段超過 30 秒的多人錄音：逐字稿應該是一行一位「講者 X：」，頁籤上方有灰字說明，Token 用量有金額。
  3. 用這份逐字稿產生會議紀錄：出席人員不應該出現「講者 A」。
  4. 挑一個長會議重新轉錄，確認每段結尾都是完整的句子。
