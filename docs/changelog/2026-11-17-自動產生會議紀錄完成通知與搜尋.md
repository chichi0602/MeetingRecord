# 自動產生會議紀錄、完成通知與搜尋（1.1.68 → 1.1.69）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：1.1.69
- 首次實作版本：1.1.69
- 最後核對日期：2026/11/17

使用者問「還有哪裡可以更優化使用者體驗」。子代理查了主流程後發現：
- 從上傳到看到會議紀錄要約 8 次點擊、4～5 個對話框、兩段等待。
- 工作完成沒有任何通知。
- 搜尋只搜標題、描述、檔名。

使用者挑了三項：
1. **轉錄完自動產生會議紀錄**。使用者問：自動產生的話，要怎麼先看對話紀錄、選擇誰是講者 1～4？決定的做法：轉完先等標示講者，存檔就自動產生。
2. **完成通知**。
3. **搜尋會議紀錄內容＋逐字稿搜尋**。

---

## 一、轉錄完自動產生會議紀錄

**上傳**
- 選了檔案後多一個「轉錄完自動產生會議紀錄」下拉，選提示詞，預設不自動產生。
- 值經上傳工作階段帶進 `SaveMediaAsync`，存成 `Meeting.AutoDraftPromptTemplateId`。
  - 只有真的上傳檔案才會設定，不經會議表單。
  - 提示詞不存在或停用時，當成不自動產生。
- 上傳的確認框多一句「轉錄完會再自動產生會議紀錄（另計費用）」。

**轉錄完成時**
- 有「講者 1～4」：
  - `AwaitingSpeakerNames = true`，進度面板顯示「已完成，請標示講者」。
  - 清單顯示「待標示講者」，操作欄多一顆「標示講者並產生會議紀錄」。
- 沒有講者：
  - `AutoDraftStarter` 替上傳者排入產生。背景沒有登入使用者，不能走 `RequestDraftAsync` 的資料範圍，所以自己檢查提示詞、轉錄狀態、是否產生中、封存專案、額度。
  - 排不進去只寫 `DraftError`，轉錄仍是「已完成」。

**標示講者視窗**
- 在等標示時有三顆按鈕：
  - 「儲存並產生會議紀錄」
  - 「跳過，直接產生」
  - 「只儲存」
- 前兩者打 `PUT …/speakers?generate=true` → `NameSpeakersAndGenerateAsync`：存名字後用上傳時選的提示詞走 `RequestDraftAsync`，與會人員就是填的講者名字。會議紀錄直接用真名，只付一次產生費用。

**其他**
- 任何路徑排入產生時，都清掉這兩欄，避免重新轉錄又自動產生一次。
- migration `AddMeetingAutoDraft`：`AutoDraftPromptTemplateId`（int?）、`AwaitingSpeakerNames`（bool）。

## 二、順手修：改會議資料會清掉講者名字（1.1.64 起）

- 問題：`MeetingService.UpdateAsync` 把 AdapterModel 轉回實體，AdapterModel 上沒有的欄位會變成預設值。1.1.64 新增的 `SpeakerNames` 沒有放進「沿用資料庫既有值」那段，所以**在會議頁改個標題，就會把標示好的講者名字清掉**。
- 修法：這次連同兩個新欄位一起補上，並新增回歸測試。

## 三、完成通知

- 右下角進度面板比對前後兩次清單。**自己上傳的**工作從進行中變成完成或失敗時，跳一則提示，點了直接打開那一筆：
  - 「轉錄完成」
  - 「轉錄完成，請標示講者」
  - 「會議紀錄已產生」
  - 失敗時附原因
- 頁面在背景時，分頁標題前加「(✓) 」，回到分頁就拿掉（`js/tab-alert.js`）。
- 已完成那一列的標題可以點。
- `BackgroundJobDto` 新增 `ProjectId`、`IsMine`、`NeedsSpeakerNames`。進度項目新增 `Note`，用來顯示「請標示講者」。
- 點了之後的落點：
  - 有專案：`/projects?projectId=&meetingId=`（1.1.67 的深連結）。
  - 沒有專案：新的 `/meetings?meetingId=`，打開「會議紀錄與逐字稿」；加 `&speakers=1` 改開標示講者。
- 只提示自己的工作，同團隊別人的不打擾。

## 四、搜尋

- 會議清單的關鍵字也搜 `DraftContent`，頁面與 API 搜尋兩處都改了。
  - 逐字稿存在磁碟上，不做跨會議的逐字稿搜尋。
- 逐字稿頁籤加搜尋框：
  - 即時把找到的字標黃，顯示「第 i／共 n 筆」，有上一筆、下一筆，Enter 跳下一筆。
  - 找字用 `TextSearchHelper`，JS 只負責捲動（`scrollToMark`）。
  - 輸入框不綁 value，避免中文輸入法組字時被回寫。
- 專案頁歷史清單加關鍵字篩選（標題、提示詞），純前端。

## 五、驗證

- 新增測試：
  - `TranscriptionJobRunnerTests`：
    - 沒有講者 → 自動排入，歸屬上傳者。
    - 有講者 → 等標示、沒有排入。
    - 提示詞停用 → 轉錄仍完成，`DraftError` 寫原因。
    - 沒選自動產生 → 都不做。
  - `MeetingServiceTests`：
    - 改標題不會清掉講者名字與新旗標（回歸）。
    - `NameSpeakersAndGenerateAsync` 存名字＋排入，與會人員是講者名字。
    - 沒設自動產生時只存名字。
    - 搜尋會比對會議紀錄內容。
  - `JobApiTests`：`ProjectId`、`IsMine`。
- 相關測試全部通過（轉錄、會議服務、會議／專案 API、授權、通知器、Razor 標記、前端架構等）。依專案規定，這次沒有跑全套測試。
- 實機待驗：
  1. 上傳時選提示詞，用有分講者的檔案。轉完應跳「轉錄完成，請標示講者」，點開填名字，按「儲存並產生會議紀錄」，完成後跳「會議紀錄已產生」，打開確認是真名。
  2. 用沒分講者的檔案，轉完應自動產生。
  3. 切到別的分頁等完成，分頁標題應出現 (✓)。
  4. 在逐字稿頁籤搜尋，用上一筆、下一筆跳轉；用會議紀錄裡的字搜尋清單。
