# 轉錄比較工具（1.1.71 → 1.1.72）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：1.1.72
- 首次實作版本：1.1.72
- 最後核對日期：2026/11/20

## 為什麼做

1. **品質問題**：有人反映 `gpt-4o-transcribe-diarize` 轉出來的逐字稿比會議實際內容精簡，還夾了不少奇怪的英文。不過用它產生的會議紀錄整理是對的。
2. **模型要下線**：OpenAI 公告 `gpt-4o-transcribe-diarize` 將在 **2027/02/26 下線**，官方建議改用 `gpt-transcribe`。但 `gpt-transcribe` 不分講者，官方也還沒有分講者的替代模型。
3. **兩個可能的原因**：
   - 正式轉錄**沒有帶 `language`，也沒有帶 `prompt`**。
   - diarize 模型本身不支援 `prompt`；也有人回報它會忽略 `language`。

使用者決定先做比較工具，拿實際會議比較之後，再決定正式轉錄怎麼改、講者怎麼分。

## 做了什麼

新頁「系統管理 → AI 管理 → **轉錄比較**」（`/transcription-compare`，選單 id 64，只限管理者）：

- **挑片段**：挑一場有影音檔的會議，選一段片段（起點以分鐘計，長度 30 秒～5 分鐘）。
- **比較條件**最多 4 組：部署名稱、語言（不指定／zh）、提示詞（diarize 會停用）。
  - 預設兩組：目前設定，以及 `gpt-transcribe`＋zh。
- **費用確認**：按「開始比較」先估價，用各部署在 Pricing 的單價，再跳確認框。
- **結果**：每完成一組顯示一欄，有逐字稿、字數、英文占比（≥10% 標橘）、耗時、費用，可以複製；上方有片段原音可以邊聽邊對照。
- **停止**：按「停止」或離開頁面就中斷，還沒跑的組不送出。
- **不碰會議本身**：不改狀態、不存逐字稿、不進進度面板。

## 實作

- **`AzureOpenAiTranscriptionProvider.WithOverrides(TranscriptionOverrides)`**：回傳新實例，換部署、加 `language`／`prompt`。
  - `ModelName` 跟著換，帳本記的模型與單價都是實際打的部署。
  - diarize 一律不送 `prompt`。
  - 正式轉錄不帶覆寫，送出的表單和以前完全一樣。
- **`IMediaExcerptCutter`**（`FfmpegMediaConverter.CutMp3ExcerptAsync`）：剪出和正式轉錄同規格的 mp3（16kHz 單聲道 32kbps）。實際長度取 FFmpeg 結尾的 `time=`，取不到時用位元組推估。
- **`TranscriptionComparisonService`**：
  - 依序呼叫每一組，不平行，因為帳本共用同一個 DbContext。
  - 同一時間只跑一趟。
  - 後處理和正式轉錄一樣：指令外洩、轉繁體。
- **`AiUsageFeature.TranscriptionComparison = 10`**（「轉錄比較」），以音訊時長計費，已加進 `IsTokenBased` 的排除清單。
- **`TranscriptionCostEstimator.EstimateTwd(seconds, model)`**：可以指定部署估價。
- **API**（`MonitoringController`，`[AdminOnly]`）：`GET transcription-compare/meta`、`POST transcription-compare/estimate`、`POST transcription-compare`（NDJSON 串流）。
- **稽核** `Ai.TranscriptionCompare`：記會議、片段與各組部署，不記逐字稿內容。

## 怎麼用來決定下一步

1. 在 Azure 建好 `gpt-transcribe` 部署，名稱要和 Pricing 的鍵一致，單價已經設好。
2. 挑一場被反映的會議，取 5 分鐘片段，比較以下三組，邊聽原音邊對照：
   - 目前設定，不指定語言
   - diarize＋zh
   - gpt-transcribe＋zh
3. 依結果再決定：
   - 只要加上 `language=zh` 就夠了嗎？
   - 要不要改用 `gpt-transcribe`？
   - 講者分離怎麼做：diarize 切講者＋gpt-transcribe 轉文字，或改用其他服務？
