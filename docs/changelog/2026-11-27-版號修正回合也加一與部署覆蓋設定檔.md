# 版號修正回合也加一與部署覆蓋設定檔（1.1.73 → 1.1.74）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：1.1.74
- 首次實作版本：1.1.74
- 最後核對日期：2026/11/27

## 為什麼做

- **修正後版號沒動**：規則寫「每次產生建置內容 Patch +1」，但實際上只在一輪功能做完時加一次，使用者回報問題、修正的回合常漏加（所以有時一個 commit 跳兩號、有時只跳一號）。
- **日期沒跟著改**：1.1.73 的 commit 在 11/25，版號卻寫 `1.1.73 (2026/11/24)`。
- **「關於」顯示舊版號**：版號放在 `appsettings.json`，網站啟動時讀一次。部署時沒覆蓋這個檔案、或從舊的發佈輸出執行（本機 `bin\Release\net10.0\publish` 還停在 1.1.59），畫面就停在舊版號。

## 改了什麼

只改規則與文件，程式沒動，也沒加腳本、hook 或 CI 檢查（使用者決定只靠 CLAUDE.md）。

- `CLAUDE.md`（跟著 repo 走，任何人用 Claude Code 開發都會讀到）：寫明「修正回合也算」「日期一起改成當天」「回覆前先確認版號」，速查區加「部署一定要覆蓋 `appsettings.json`」。
- [維護規範](../operations/維護規範.md) §1：§1.2 加「修正回合也算」，§1.3 日期改成「異動當天」，新增 §1.4「部署要帶到新版號」。
- [開發慣例與限制速查](../architecture/開發慣例與限制速查.md) §8：同步。
- [正式部署與安全檢查清單](../operations/正式部署與安全檢查清單.md)「部署設定」：新增「部署一定要覆蓋 `appsettings.json`、重啟後開『關於』確認版號」。

## 限制

- 這仍是給 Claude 的規則，不是自動機制：不用 Claude 的開發者要自己記得 +1、改日期。
- 兩個人同時開發可能改成同一個版號，合併時 `appsettings.json` 會衝突，合併的人要再 +1。
