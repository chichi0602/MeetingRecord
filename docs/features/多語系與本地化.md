## 文件目的

說明本專案如何處理 .NET 在地化、瀏覽器語系自動偵測，以及 AntDesign Blazor 元件的本地化字串覆寫。

> ⚠️ **適用範圍**：第 1～3 節是 `MeetingRecord.Web`（伺服器）的設定，只影響伺服器算繪的頁面——登入、登出、帳號待審核與錯誤頁。
> 應用程式的頁面在瀏覽器執行（`MeetingRecord.Web.Client`，Blazor WebAssembly），Web.Client **沒有任何在地化設定**：
> 文化跟著瀏覽器語系，AntDesign 元件用它內建、對應該文化的字串，第 3 節的 zh-TW 覆寫不會套用到這些頁面。

---

## 1. 支援文化

目前內建兩種文化：

| Culture | 顯示 | 預設 |
|---------|------|------|
| `zh-TW` | 繁體中文（台灣） | ✅ 預設 |
| `en-US` | 英文（美國） | |

設定位置：[`src/MeetingRecord/MeetingRecord.Web/Extensions/ServiceCollectionExtensions.cs`](../../src/MeetingRecord/MeetingRecord.Web/Extensions/ServiceCollectionExtensions.cs) 的 `AddConfiguredLocalization()`；`Program.cs` 只在 `#region 系統使用服務` 內呼叫 `builder.Services.AddConfiguredLocalization()`。

## 2. .NET RequestLocalization

```csharp
// ServiceCollectionExtensions.AddConfiguredLocalization()
services.AddLocalization();

var supportedCultures = new[] { new CultureInfo("zh-TW"), new CultureInfo("en-US") };
var defaultCulture = supportedCultures[0];

services.Configure<RequestLocalizationOptions>(options =>
{
    options.DefaultRequestCulture = new RequestCulture(defaultCulture);
    options.SupportedCultures = supportedCultures;
    options.SupportedUICultures = supportedCultures;
    options.RequestCultureProviders = new List<IRequestCultureProvider>
    {
        new AcceptLanguageHeaderRequestCultureProvider()
    };
});
```

關鍵點：

- 採用 `AcceptLanguageHeaderRequestCultureProvider`，**根據瀏覽器 `Accept-Language` 標頭自動切換文化**。
- 移除預設的 Cookie / Query 文化提供者，避免使用者手動鎖定文化。
- 中介軟體啟用：`Extensions/ApplicationBuilderExtensions.cs` 的 `UseConfiguredLocalization()` 從 DI 取出 `IOptions<RequestLocalizationOptions>` 後呼叫 `app.UseRequestLocalization(localizationOptions)`；`Program.cs` 於 `#region 註冊中介軟體` 內呼叫 `app.UseConfiguredLocalization()`。

> 若日後要支援使用者手動切換語系（例如下拉式選單），需另行加入 Cookie / Query Provider，並提供切換 UI。

## 3. AntDesign 元件本地化

AntDesign Blazor 內建多語字典，但部分字串（例如表格排序、過濾、確認）需要客製。本專案以 `AntDesignLocaleFactory` 集中覆寫（同樣在 `AddConfiguredLocalization()` 內設定）：

```csharp
LocaleProvider.SetLocale("zh-TW", AntDesignLocaleFactory.Create("zh-TW"));
LocaleProvider.DefaultLanguage = defaultCulture.Name;
```

檔案：`src/MeetingRecord/MeetingRecord.Web/Localization/AntDesignLocaleFactory.cs`

工廠職責：

1. 取得 AntDesign 內建 `Locale`（依 culture 名稱）。
2. 覆寫需要客製的字串（例：表格欄位排序提示、確認對話框預設文字）。
3. 回傳客製後的 `Locale` 物件交給 `LocaleProvider`。

新增覆寫項目時請集中於此檔，避免散落於各元件。

## 4. 在元件中使用本地化

### 4.1 使用 `IStringLocalizer<T>`

於需要翻譯的元件以 DI 注入：

```razor
@inject IStringLocalizer<MyComponent> Localizer

<h1>@Localizer["Welcome"]</h1>
```

對應字串需放在 `Resources/MyComponent.zh-TW.resx`、`Resources/MyComponent.en-US.resx`（資料夾結構需與元件命名空間對齊）。

> 本專案目前全是硬編碼的繁體中文字串，沒有任何 `.resx` 資源檔（也沒有 `Resources/` 資料夾）。若要導入 IStringLocalizer：伺服器頁的資源檔放在 `MeetingRecord.Web`；應用程式頁面在 `MeetingRecord.Web.Client`，資源檔與 `AddLocalization()` 等註冊也要放在 Web.Client。

### 4.2 AntDesign 元件自動套用

`<Table>`、`<DatePicker>`、`<Modal>` 等元件會自動使用 `LocaleProvider.CurrentLocale`，無須手動傳入 `Locale` 屬性（伺服器頁依第 3 節的設定；應用程式頁面依瀏覽器語系對應的內建字串）。

## 5. 文化切換驗證

可用瀏覽器設定變更語系驗證：

1. Chrome → 設定 → 語言 → 將想測試的語言（例如 English (United States)）拉到第一順位。
2. 重新整理頁面，AntDesign 表格、按鈕等預設字串會切換到 `en-US` 對應翻譯。

伺服器頁也可以用 PowerShell 直接送出帶 `Accept-Language` 標頭的請求（`Accept-Language` 只影響伺服器算繪的頁面）：

```powershell
Invoke-WebRequest -Uri "https://localhost:5001/Auths/Login" -Headers @{ "Accept-Language" = "en-US" }
```
