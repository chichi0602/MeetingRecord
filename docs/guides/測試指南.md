本專案以 **xUnit** 撰寫單元與整合測試，測試專案為 `src/MeetingRecord/MeetingRecord.Tests`，並納入 CI 自動執行（見 [CI-CD 與品質檢查](../operations/CI-CD與品質檢查.md)）。

---

## 1. 測試框架與套件

`MeetingRecord.Tests` 使用：

- **xUnit** — 測試框架（`[Fact]` / `[Theory]`）。
- **Microsoft.AspNetCore.Mvc.Testing** — 以 `WebApplicationFactory` 啟動整個 Web API 做整合測試。
- **Microsoft.NET.Test.Sdk** — 測試執行器。
- **coverlet.collector** — 程式碼覆蓋率蒐集。

實際版本以 `src/MeetingRecord/MeetingRecord.Tests/MeetingRecord.Tests.csproj` 為準。

## 3. 在本機執行

```powershell
# 執行整個方案的所有測試
dotnet test src/MeetingRecord/MeetingRecord.slnx

# 只跑測試專案
dotnet test src/MeetingRecord/MeetingRecord.Tests/MeetingRecord.Tests.csproj

# 以單一測試類別或方法過濾
dotnet test src/MeetingRecord/MeetingRecord.slnx --filter "FullyQualifiedName~ApiIntegrationTests"
dotnet test src/MeetingRecord/MeetingRecord.slnx --filter "Name=GetProvider_ShouldThrow_WhenUnknown"
```

CI 以 Release 組態執行：`dotnet test src/MeetingRecord/MeetingRecord.slnx --configuration Release --no-build`（先經 restore/build 階段）。

## 4. 覆蓋率

`coverlet.collector` 已隨測試專案引入，可於執行時蒐集覆蓋率：

```powershell
dotnet test src/MeetingRecord/MeetingRecord.slnx --collect:"XPlat Code Coverage"
```

報表（Cobertura XML）會輸出至各測試專案的 `TestResults/` 下，可再以報表工具轉檢視。

## 5. 撰寫新測試的慣例

- 整合測試走 `WebApplicationFactory`，驗證對外 **`ApiResult` 合約**（狀態碼 + 信封結構），不依賴內部實作細節；需觸發 403／500 等情境時，透過測試專案的 probe controller 製造，**不新增正式 API contract**。
- 單元測試針對 Service / Helper 的純邏輯，必要時以 in-memory 或測試替身隔離資料庫。
- 新增 / 修改 API 時，請補對應整合測試；新增 Entity 或密碼／權限邏輯時，補單元測試。對照 [維護規範](../operations/維護規範.md) 的 commit 前檢查清單。
