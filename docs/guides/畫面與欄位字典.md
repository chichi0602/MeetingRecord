## 摘要

把系統的**每一個畫面、每一個欄位**講清楚：這一頁在做什麼、這個欄位是什麼意思、對應哪個程式屬性、有哪些限制與容易踩的坑。
讀者是**接手開發的人與測試人員**；給終端使用者看的操作說明在另一份文件。

### 與其他文件的分工

| 文件 | 回答的問題 |
|------|-----------|
| [`docs/prd/`](../prd/README.md) 各份 PRD | 「**為什麼**要這樣做、需求是什麼、**怎麼運作**」—— 能力範圍、流程、權限、設計決策、驗收條件 |
| [`docs/guides/系統使用說明.md`](系統使用說明.md) | 「**使用者要怎麼操作**」—— 給終端使用者的說明，也是系統內 `/help` 頁的內容來源 |
| **本文件** | 「這個**欄位是什麼**」—— 意思、對應程式屬性、限制、預設值、選項清單、容易誤解的地方 |

三者都會提到欄位名，但角度不同：要改功能看 PRD，要教使用者看使用說明，要搞懂某一欄、寫測試案例看這裡。

### 怎麼讀

每個畫面固定三段：

1. **一段白話** —— 這頁做什麼、什麼時候用、誰看得到。
2. **這一頁可以做什麼** —— 工具列與列上動作，含權限鍵與確認視窗。
3. **欄位對照** —— 給開發者的表：欄位 ↔ 對應屬性 ↔ 意義 ↔ 用途 ↔ 坑或限制。

對話窗（新增／修改表單、檢視視窗、AI 問答、抽出待辦、會議紀錄編修器）放在**開啟它的畫面底下**。
程式位置一律以檔名、類別、屬性名稱標示，不寫行號（行號一改就過期）。⚠️ 標記代表「這一欄的字面意思會誤導你」。

## 0. 先讀這段：全站共通概念

這幾組概念跨越多個畫面，先在這裡講一次，各畫面不再重複。

### 0.1 角色＝能做什麼，團隊＝誰的資料，分類＝什麼資料 ⚠️

0.4.102 起三者徹底分工，**不要混用**：

| 概念 | 決定什麼 | 設定位置 | 程式權威 |
|------|---------|---------|---------|
| 角色 | 能進哪些頁、能按哪些按鈕（檢視／新增／編輯／刪除／匯出） | 使用者管理（主要角色＋額外角色）、角色管理（權限矩陣） | `IPermissionChecker`、`AuthenticationStateHelper.CheckAccessPage`／`CheckAccessAction` |
| 團隊 | 看得到哪些專案（以及跟著專案走的會議、待辦、附件、AI 問答） | 使用者管理「團隊」、團隊清單「成員」、專案「主責團隊／協作團隊」 | `ProjectAccessService` → `ProjectAccess` |
| 分類 | 這筆資料的性質標籤，只用來篩選 | 專案、會議、提示詞的「分類」欄 | 無（**不影響可見性**） |

**角色不帶任何團隊**（0.4.101 起角色的預設團隊欄位已刪除）；**分類也不帶團隊**（分類清單的「負責團隊」只是參考）。

### 0.2 資料可見範圍（`ProjectAccessService`）

| 資料 | 誰看得到 |
|------|---------|
| 專案 | 管理者全部；其他人：自己所屬團隊（`UserTeam`）與專案的**主責＋協作團隊**（`ProjectTeam`）有交集。**沒有公開專案**——沒掛團隊的專案只有管理者看得到 |
| 會議（已歸屬專案） | 跟著專案走 |
| 會議（未歸屬專案） | **只有上傳者**（`Meeting.CreatedByUserId`）與管理者；上傳者為 null 的舊資料只有管理者看得到 |
| 待辦 | 跟著專案走（待辦一定有專案）；來源會議看不到時，「來源會議紀錄」欄會是空的（`ProjectAccess.HideInvisibleSourceMeetings`） |
| 專案附件、AI 問答對話 | 跟著專案（或會議）走；問答對話是**共用**的，看得到那個專案／會議的人都看得到所有對話 |
| 儀表板 | **刻意的例外**：登入即可看、全公司彙總、不放任何明細 |

看不到的資料一律當成不存在（UI 找不到、API 回 404），服務層與 API Repository 都要套。

### 0.3 權限有三層

| 層 | 欄位 | 行為 |
|----|------|------|
| 管理者 | `MyUser.IsAdmin`（使用者管理的「管理者」勾選） | 短路所有頁面與動作檢查，不受團隊過濾。**不是一個角色**——角色管理裡那個叫「管理者」的預設角色只是「勾滿所有權限的角色」，不會讓人變成 `IsAdmin` ⚠️ |
| 角色 | 主要角色 `RoleViewId` ＋ 額外角色 `AdditionalRoleIds` | 權限鍵取**聯集**。裸頁面鍵（例如 `專案項目`）＝該頁全部動作；動作鍵 `頁面:動作`（`PermissionKey.For`）＝只給那個動作 |
| 團隊 | 使用者的團隊 | 決定看得到哪些**資料列**，與能做哪些**動作**是兩回事 |

`CheckAccessPage(頁面)`：有裸頁面鍵**或** `頁面:view` 就能進頁面（0.4.109）。`CheckAccessAction(頁面, 動作)`：有 `頁面:動作` **或**裸頁面鍵就放行。動作代碼見 `PermissionActions`：`view`／`create`／`edit`／`delete`／`export`。

### 0.4 側邊選單與權限鍵

選單結構在 `MeetingRecord.Web/Datas/Menu.json`（每項唯一 `id`），`SidebarMenuService.MenuPermissionMap` 以 `id` 對應到 `MagicObjectHelper` 的權限鍵常數。選單項目的權限檢查走 `CheckAccessPage`；群組只要底下有任一子項目看得到就會顯示。

### 0.5 共通 UI 行為

- **每頁筆數**：清單預設 8 筆（`MagicObjectHelper.PageSize`）；待辦事項頁會依畫面高度自動調整（`TodoAutoFit`）。
  ⚠️ 會議紀錄、使用者、角色、分類、團隊這幾頁的服務層只在 `DataRequest.Take != 0` 時才截斷，而畫面一律傳 `Take = 0`——實際上第 N 頁會回「第 N 頁之後的全部資料」。待辦（`TodoService`）與提示詞（`PromptTemplateService`）已修正，其餘尚未。
- **未儲存提示**：表單開啟時以 `FormDirtyHelper.Capture` 拍快照，取消時有變更會問「是否放棄變更」；預設值不算變更。
- **Enter 送出**：表單的 Enter 一律走 `FormKeyboardHelper.IsSubmit`（中文輸入法組字中的 Enter 不算）。下拉、日期、常用名詞等欄位外層有 `@onkeydown:stopPropagation`，避免在下拉搜尋框按 Enter 被當成送出。
- **會產生費用的動作**（轉錄、AI 轉會議紀錄、抽出待辦、重新產生 AI 答案）一律先跳確認窗；確認按鈕只有在「會覆蓋既有內容」時才是紅色（Danger 跟著「覆蓋」走、不跟著「花錢」走）。AI 問答的一般提問不跳確認，改為常駐費用提示。
- **時間欄位**（建立時間、更新時間）都是系統自動寫入，沒有任何畫面可以修改。
- **狀態膠囊**（`StatusToggleTag`）：清單上的「啟用／停用」膠囊有編輯權限時可直接點擊切換（0.4.105），會跳確認窗；停用的確認按鈕是紅色。

## 一、登入與帳號

### 1.1 登入

網址：`/Auths/Login`（靜態 SSR，`[ExcludeFromInteractiveRouting]`；版面 `NoFooterLayout`；類別 `Login`）

沒登入的人會被導到這裡。輸入帳號、密碼與畫面右側的 4 位數驗證碼即可進入系統；有設定 Google OAuth 時也可以用 Google 帳號登入。
登入成功預設導向 `/meetings`（有 `ReturnUrl` 時導回原頁）。

**這一頁可以做什麼**：登入（按鈕「登入系統」）、勾選「記住我」、使用 Google 登入（`GoogleOAuthSettings.IsConfigured` 為真才出現）。

| 欄位 | 對應屬性 | 意義 | 用途 | 坑或限制 |
|---|---|---|---|---|
| 帳號 | `InputModel.Account` | 系統帳號（`MyUser.Account`） | 識別使用者 | 空白時訊息「請輸入帳號」。帳號不存在與密碼錯誤回**同一句**「帳號或者密碼不正確」，不讓人試探帳號是否存在 |
| 密碼 | `InputModel.Password` | 登入密碼，PBKDF2 雜湊比對（`SecurePasswordHasher`） | 驗證身分 | 連續錯 **5 次**鎖定 **15 分鐘**（`MyUserServiceLogin.MaxFailedAccessAttempts`／`LockoutMinutes`），鎖定中訊息「帳號已鎖定，請稍後再試。」；舊雜湊登入成功會自動升級 |
| 驗證碼 | `InputModel.CaptchaInput`（比對隱藏欄位 `CaptchaCode`） | 4 位數字（`CaptchaLength`），前後空白會去掉 | 防自動化嘗試 | 驗證碼錯誤或登入失敗都會**重新產生**，不能沿用上一組 |
| 記住我 | `InputModel.RememberMe` | 勾選時 `AuthenticationProperties.IsPersistent = true` | 關掉瀏覽器仍維持登入 | — |

- ⚠️ **停用帳號**在密碼驗證成功之後才擋（0.4.113），訊息「此帳號已停用，請聯絡管理者。」；密碼錯誤時一律回同一句，不透露帳號狀態。
- 登入成功後若 `MustChangePassword` 為真或密碼仍是 `123456`，下一個頁面會被強制導到 1.4。
- 預設開發帳號是 `support`（`MagicObjectHelper.開發者帳號`），它被禁止在任何畫面改密碼。

### 1.2 帳號待審核

網址：`/Auths/Pending`

第一次用 Google 登入時，系統會依序以 GoogleId、Email 比對既有帳號，都找不到就**自動建立一個停用中的帳號**（`ExternalLoginService`，`Status = false`、角色為預設角色），再導到這一頁告訴使用者「等管理者啟用」。純說明頁，沒有欄位，只有「返回登入頁」連結。

### 1.3 登出

網址：`/Auths/Logout`（選單「登出」或右上角使用者選單「登出」）

沒有畫面：清除 Cookie（`CookieAuthenticationScheme`）後導回 `/Auths/Login`。驗證狀態異常（帳號被刪、停用、沒有角色）時系統也會自動導到這裡。

### 1.4 變更密碼頁與首次登入強制改密碼

網址：`/ChangePassword`（類別 `ChangePassword`，`Pages/ChangePassword.razor`）

改自己的登入密碼。**主要用途是被強制導來**：

- `AuthenticationStateHelper.Check` 每次進頁面都會呼叫 `MyUserService.NeedChangePasswordAsync`，條件是 **`MyUser.MustChangePassword` 為真，或密碼等於 `123456`**（`MagicObjectHelper.NeedChangePassword`）。成立時除了 `/ChangePassword` 本身，所有頁面都會被導來這裡。
- `MustChangePassword`（0.4.113）由**管理者**設定：在使用者管理**新增帳號**時一律設為真；**替別人重設密碼**時設為真（改自己的不設、`support` 一律不設——它被禁止改密碼，設了會卡在這頁出不去）。
- 本人從任何一個改密碼入口（本頁、1.5 對話窗、1.6 API 密碼頁）改完就清掉旗標。
- API 端也會擋：`/api/v1/auth/login` 遇到 `MustChangePassword` 或密碼是 `123456` 回 401「請先登入網頁變更密碼後，再使用 API。」；換發權杖（`refresh`）也會因為待改密碼而拒絕（0.4.115）。

**這一頁可以做什麼**：儲存（成功顯示「密碼已變更。」並導到 `/meetings`）、取消（導到 `/meetings`，被強制時會再被導回來）。
`support` 帳號只會看到黃色提示「系統預設開發帳號 support 禁止變更密碼」，沒有表單。

| 欄位 | 對應屬性 | 意義 | 用途 | 坑或限制 |
|---|---|---|---|---|
| （帳號） | `currentAccount` | 目前登入的帳號，唯讀顯示於標題下 | 確認改的是誰 | — |
| 目前密碼 | `InputModel.CurrentPassword` | 必填（`[Required]`） | 驗證是本人 | 錯誤時訊息「目前密碼不正確。」（`MyUserService.ChangeOwnPasswordAsync`） |
| 新密碼 | `InputModel.NewPassword` | 必填 | 新的登入密碼 | ⚠️ **沒有長度或複雜度規則**，也不擋與目前密碼相同。⚠️ 若新密碼設成 `123456`，`NeedChangePasswordAsync` 仍為真，會一直被導回這一頁 |
| 確認新密碼 | `InputModel.ConfirmPassword` | 必填，`[Compare(NewPassword)]` | 防打錯 | 不一致：「新密碼與確認密碼不一致」 |

### 1.5 變更密碼對話窗

開啟方式：右上角使用者選單「變更密碼」（`MainLayout`，`ChangePasswordForm`）

與 1.4 做同一件事，但是對話窗、走的是另一支服務方法 `MyUserService.ChangePasswordAsync`。按「確認變更」或 Enter 送出，成功提示「密碼變更成功！」。有填內容時取消會問是否放棄。

| 欄位 | 對應屬性 | 意義 | 坑或限制 |
|---|---|---|---|
| 目前密碼 | `ChangePasswordForm.CurrentPassword` | 必填 | 錯誤訊息「目前密碼輸入錯誤。」（與 1.4 的措辭不同） |
| 新密碼 | `ChangePasswordForm.NewPassword` | **至少 6 個字元**（只在畫面檢查） | ⚠️ 1.4 的頁面沒有這條長度限制，兩個入口規則不一致 |
| 確認新密碼 | `ChangePasswordForm.ConfirmPassword` | 須與新密碼相同 | — |

⚠️ `support` 判斷：對話窗讀設定 `BootstrapSettings:SupportAccount`（預設 `support`，大小寫敏感），1.4／1.6 用常數 `MagicObjectHelper.開發者帳號`（不分大小寫）；`ChangePasswordAsync` 本身在服務層**沒有** support 防護。

### 1.6 設定 API 密碼

網址：`/Profile`（類別 `Profile`；瀏覽器分頁標題「設定 API 密碼」）

## 二、核心功能

### 2.1 儀表板

網址：`/dashboard`（`DashboardPage` → `DashboardView`；資料來源 `DashboardService.GetSummaryAsync`）

全公司的營運概況：專案、會議、逐字稿、待辦、提示詞、儲存空間與處理效能的**彙總數字與圖表**。
**登入即可看，不檢查頁面權限、不套團隊過濾**（0.4.97），所以刻意只放數字、不列任何專案名稱或待辦明細（唯一例外是「各專案的會議紀錄份數」長條圖的專案名稱）。本頁不寫入任何資料。

**這一頁可以做什麼**：重新整理。沒有篩選、沒有期間選擇。

**數字卡**（`DashboardService.BuildCards`，`StatCardItem`）

| 卡片 | 主數字 | 副標 | 坑或限制 |
|---|---|---|---|
| 專案總數 | 全部專案數 | 進行中 N | — |
| 會議紀錄 | 全部會議數 | 本月新增 N | 「本月」以 `Meeting.CreatedAt` 判斷 |
| 逐字稿完成 | `TranscriptionStatus.Completed` 的數量 | 處理中 N（待處理＋處理中） | 有處理中時副標變警示色 |
| 待辦未完成 | 狀態不是「已完成」的待辦數 | 有逾期時「已逾期 N」（紅），否則「共 N 筆」 | 完成判斷只看 `Status == "已完成"` |
| 儲存空間 | 影音檔＋逐字稿＋專案附件合計 | 截至今天 | 與下方「儲存空間」區塊同源（`StorageSummary.TotalBytes`） |
| AI 問答次數 | 累計提問數 | 累計提問 | — |

**圖表**：專案狀態分布、逐字稿轉錄狀態、會議紀錄生成狀態、未完成待辦優先度（圓餅）；各專案的會議紀錄份數（前 8 名，未歸屬的歸到「未歸屬」）、提示詞範本使用次數（長條）。

**指標區塊**

| 區塊 | 指標 | 意義與坑 |
|---|---|---|
| 待辦概況 | 已逾期／7 天內到期／進行中／由會議擷取 | 「由會議擷取」＝有 `MeetingId` 的占比；沒有任何待辦時顯示「—」而不是 0% |
| 專案概況 | 進行中平均完成度／已過結束日／14 天內到期／暫緩／等待 | 「已過結束日」只算尚未「已完成」的 |
| 提示詞範本 | 範本總數／啟用中／已停用／啟用但未使用 | ⚠️ 「未使用」比對的是 `Meeting.DraftPromptTemplateName`（生成當下的**名稱快照**）而非外鍵，**改過名的範本會被算成未使用** |
| 儲存空間 | 影音檔／逐字稿／專案附件／合計 | 影音檔取 `Meeting.MediaFileSize`、附件取 `ProjectFile.FileSize`；⚠️ 逐字稿**沒有容量欄位**，是實際掃目錄量的，孤兒檔也會算進去 |
| 會議時數 | 累計／本月／平均每場／有時長紀錄 N／M 場 | 時長取自 AI 用量帳本的轉錄音訊秒數，**0.4.80 之前轉錄的會議沒有時長**，不計入時數 |
| 處理效能 | 平均轉錄耗時／平均生成耗時／轉錄失敗率／未歸屬逐字稿 | 失敗率超過 20% 標紅（`FailureRateWarningThreshold`），沒有資料時「—」；「未歸屬逐字稿」＝已轉錄完成、未歸屬**且尚未產生會議紀錄**的份數 |

### 2.2 會議紀錄

網址：`/meetings`（`MeetingPage` → `MeetingViewView`；服務 `MeetingService`）
權限鍵：`會議紀錄`（頁面 `CheckAccessPage`；新增 `create`、修改／歸屬／轉錄／產生 `edit`、刪除 `delete`、匯出 PDF 與 AI 問答下載 `export`）

上傳會議影音檔、自動轉成逐字稿、再用 AI 整理成會議紀錄的地方。一筆會議只搭配**一個**影音檔。
會議可以先不歸屬專案（「— 未歸屬」）：未歸屬時**只有上傳者與管理者看得到**；歸屬到專案後就跟著專案的團隊走（見 0.2）。
已歸屬專案的會議，編修與匯出 PDF 都集中到「專案項目」頁（那裡才有專案脈絡，PDF 表頭也要帶專案名稱）。

**這一頁可以做什麼**

- 工具列：新增（`create`）、重新整理、分類過濾（多選，只列**啟用中**的分類；符合任一即可）、關鍵字搜尋（Enter 或「搜尋」）、清空搜尋（有輸入時才出現）。
- 關鍵字比對**標題、描述、影音檔原始檔名**（`MeetingService.GetAsync`），不比對分類（用分類過濾）。
- 預設依更新時間新到舊排序；可排序欄位：會議標題、會議日期、轉錄狀態、更新時間（「會議紀錄」欄不能排序，服務層白名單沒有 `DraftStatus`）。
- 轉錄與生成進度由 `TranscriptionProgressNotifier`／`MeetingDraftProgressNotifier` 即時推送，狀態欄旁顯示百分比；工作結束時清單自動重載。

**列上動作**（依條件顯示）

| 動作 | 顯示條件 | 行為 |
|---|---|---|
| 檢視會議紀錄 | `HasDraft` | 開唯讀的會議紀錄編修器（2.2.4）。已歸屬的會議底部會提示「編修與下載 PDF 請到『專案項目』頁」 |
| AI 轉會議紀錄 | `edit` 且 `CanGenerateDraft`（逐字稿完成、不在待處理／生成中） | 開 2.2.2 對話窗 |
| 編修會議紀錄 | `edit` 且 `HasDraft` 且**未歸屬** | 開可編輯的編修器 |
| AI 問答 | `HasDraft` 或 `HasTranscript` | 開 AI 問答視窗（2.3.3），範圍是這一場會議 |
| 歸屬到專案 | `edit` 且未歸屬 | 開 2.2.3 對話窗 |
| 重新轉錄 | `edit` 且 `CanRetryTranscription`（有影音檔、不在待處理／處理中；已取消可重跑） | 費用確認後重新排入轉錄；已完成者會**覆蓋**逐字稿（紅色確認鈕「覆蓋並重新轉錄」） |
| 修改 | `edit` | 開 2.2.1 表單 |
| 刪除 | `delete` | 確認「影音檔與逐字稿會一併刪除，此操作無法復原」 |

- ⚠️ 「抽出待辦」0.4.83 起**只在專案項目頁**（待辦一定要有專案），「匯出 PDF」0.4.82 起不放在列上。
- ⚠️ 刪除：轉錄或生成進行中會被擋「這筆會議正在轉錄或產生會議紀錄，請等它完成，或從右下角的進度面板取消後再刪除。」；刪除會一併刪掉影音檔、逐字稿檔與這場會議的 AI 問答對話檔；**由它產生的待辦保留**，只是失去來源。

| 欄位 | 對應屬性 | 意義 | 用途 | 坑或限制 |
|---|---|---|---|---|
| 會議標題 | `Title`；第二行 `ProjectTitleText` | 標題＋所屬專案名稱 | 辨識會議與歸屬 | 未歸屬顯示「— 未歸屬」（`IsUnassigned`）；專案名是服務層另外填的跨物件欄位 `ProjectTitle` |
| 會議日期 | `MeetingDate` | 開會日期，`yyyy/MM/dd` | 排序、辨識 | 可空 |

| 影音檔 | `MediaOriginalFileName`、`MediaFileSize` | 原始檔名與大小 | 確認上傳了什麼 | 沒有時顯示「尚未上傳」（`HasMedia` 以 `MediaRelativePath` 判斷） |

#### 2.2.1 新增／修改會議紀錄（對話窗）

標題「新增會議紀錄」／「修改會議紀錄」，類別 `meeting-view-modal`，`MaskClosable = false`。模型 `MeetingAdapterModel`。

| 欄位 | 對應屬性 | 意義 | 用途 | 坑或限制 |
|---|---|---|---|---|
| 會議標題 | `Title` | 必填，最多 200 字（`[StringLength(200)]`） | 辨識 | 「會議標題 不可為空白」 |
| 會議日期 | `MeetingDate` | 選填 | 記錄開會日 | — |
| 分類 | `Categories` | 多選，選項為啟用中的分類（`CategoryService.GetAllEnabledNamesAsync`） | 描述會議性質 | ⚠️ 選項**沒有**補回已停用的分類（專案表單有補），編輯掛著已停用分類的會議時要留意被拿掉 |
| 描述 | `Description` | 選填，最多 2000 字 | 補充說明 | — |
| 影音檔 | 待上傳檔（`pendingMediaFile`）／`MediaOriginalFileName` | 拖放或點選，**一次一個** | 上傳並觸發轉錄 | 單檔上限 **1 GB**（`MeetingMediaPolicy.MaxUploadFileSize`）；副檔名白名單 `MeetingMediaPolicy.AllowedExtensions`：mp3、wma、wav、m4a、aac、flac、ogg、opus、amr、mp4、m4v、mov、avi、wmv、mkv、webm（影片只取聲音軌）。不合格時選檔當下就擋，並清掉先前選的檔 |

**儲存流程**：表單驗證 → 有待上傳影音檔時跳「確認上傳並開始轉錄（會產生費用）」——說明音檔每 N 分鐘一段（`FfmpegMediaConverter.SegmentSeconds`）逐段送 Azure OpenAI；**替換既有檔案**時說明「現有音檔與逐字稿會被刪除且無法復原」並改為紅色按鈕 → 存檔 → 上傳（顯示進度條）→ 自動排入背景轉錄。
新增時 `CreatedByUserId` 記為上傳者（未歸屬時的可見範圍就靠它）。轉錄或生成進行中不能替換影音檔。

#### 2.2.2 AI 轉會議紀錄（對話窗）

把一份已完成的逐字稿，用選定的提示詞交給 AI 整理成會議紀錄。按「開始產生」或 Enter 後一定再跳費用確認。

| 欄位 | 對應變數 | 意義 | 坑或限制 |
|---|---|---|---|
| 來源逐字稿 | `draftRequestMeetingTitle` | 唯讀，會議標題 | — |
| 提示詞 | `draftRequestPromptTemplateId` | 必選，選項為**啟用中**的提示詞（`PromptTemplateService.GetEnabledSelectableAsync`）；只有一個時自動帶入 | 沒選：「請選擇提示詞。」 |
| 所屬專案（選填） | `draftRequestProjectId` | 選看得到的專案（`ProjectService.GetSelectableAsync`）；可不指定 | 已歸屬的會議**預選並鎖住**（`draftRequestLockedProject`），重新產生不會改歸屬。指定專案＝同時把會議歸屬過去，並套用該專案的常用名詞校正 |
| 與會人員 | `draftRequestAttendees` | 從所選專案的「常用與會人員」名冊多選 | 沒選專案或名冊是空的時停用；換專案會清空已選；存為 `Meeting.DraftAttendees` 快照，最多 50 人（`MeetingService.MaxDraftAttendees`） |

- 已有會議紀錄時，確認窗改為「確認重新產生（會產生費用）」、紅色「覆蓋並重新產生」：**人工編修過的內容也會被覆蓋**，不保留版本。
- 生成當下的提示詞名稱存成快照 `DraftPromptTemplateName`，範本日後改名或刪除仍看得出當初用了什麼。

#### 2.2.3 歸屬到專案（對話窗）

只變更 `Meeting.ProjectId`，**不重新產生、不產生費用**。已產生的會議紀錄內容不會因此套上該專案的常用名詞（要套用請歸屬後重新產生）。歸屬後才能在專案頁抽出待辦。

| 欄位 | 對應變數 | 坑或限制 |
|---|---|---|
| 會議紀錄 | `attachMeetingTitle` | 唯讀 |
| 歸屬到 | `attachProjectId` | 必選，「請選擇要歸屬的專案。」；生成中不能歸屬；已歸屬別的專案的會議要先在專案頁「從專案移除」 |

⚠️ 歸屬後可見範圍立刻改變：原本只有上傳者看得到，歸屬後換成該專案主責＋協作團隊的人看得到（上傳者若不在那些團隊裡，自己反而看不到了）。

#### 2.2.4 會議紀錄編修器（對話窗）

元件 `MarkdownEditorModal`（`Components/Commons`），會議紀錄頁與專案項目頁共用；「檢視」與「編修」是同一個視窗，差別只在 `CanEdit`。

| 模式 | 畫面 | 行為 |
|---|---|---|
| 唯讀（`CanEdit = false`） | 只有右邊的 Markdown 預覽 | Esc 與點遮罩可關閉；按鈕「關閉」 |
| 編修（`CanEdit = true`） | 左邊原始 Markdown（原生 `<textarea>`）、右邊即時預覽，左右**同步捲動**（0.4.100） | Esc 與點遮罩**都關不掉**，只能按「取消」，有改過會再問一次；按鈕「儲存」 |

| 欄位／控制 | 意義 | 坑或限制 |
|---|---|---|
| 搜尋（`SearchTerm`） | 常駐搜尋列，不分大小寫，顯示「第幾個／共幾個」 | Enter 下一個、Shift+Enter 上一個；刻意不綁 Ctrl+F |
| 取代為（`replaceTerm`） | 「取代」目前這一個、「全部取代」 | — |
| 內容（`editingText`） | 會議紀錄 Markdown 全文（存回 `Meeting.DraftContent`） | 存檔走 `MeetingService.UpdateDraftAsync`；重新產生中不能存；元件本身不存檔，存檔後要做什麼由父頁決定 |
| 下載 PDF | `CanExport` 為真時出現 | ⚠️ 匯出的是**視窗裡當下的內容**（含尚未儲存的修改），不是資料庫裡的版本。會議紀錄頁只有**未歸屬**的會議能在這裡下載（表頭專案欄為「未指定」） |
| 底部說明（`Notice`） | 例如已歸屬會議的「請到專案項目頁」提示 | — |

### 2.3 專案項目

網址：`/projects`（`ProjectPage` → `ProjectViewView`；服務 `ProjectService`）
權限鍵：`專案項目`（頁面；新增 `create`、編輯專案與 AI 生成區塊 `edit`、刪除專案與「從專案移除」`delete`、匯出 PDF 與問答下載 `export`）；「抽出待辦」看的是 `待辦事項:create`。

以「一次看一個專案」的方式工作：上方選專案，下方是專案摘要、用 AI 把逐字稿整理成會議紀錄的操作區，以及這個專案的歷史會議紀錄。
只列得出你看得到的專案（主責或協作團隊有你的團隊；管理者全部）。

**這一頁可以做什麼**

- 工具列左側：專案下拉（可搜尋）、新增專案（`create`）、編輯專案（`edit`，需先選專案）、刪除專案（`delete`）、AI 問答（不需動作權限，就整個專案提問）。
- 工具列右側三個篩選：**團隊**（列全部啟用中的團隊；符合主責或協作任一）、**分類**、**狀態**。三者同時成立、同一個篩選內選多個時符合任一即可。⚠️ 篩選只縮小上方的專案下拉，**不影響誰看得到**。
- 刪除專案：確認文字會講清楚「專案底下的**待辦事項會一併刪除**（Cascade）；N 份會議紀錄**不會被刪除，只會解除歸屬**（SetNull）」。

**專案摘要**（選了專案後顯示）

| 協作團隊 | `CollaboratorTeamNames` | 0～多個，以「、」串接 | 決定可見範圍 |

| 狀態 | `Status` | 五選一 | — |

| 附件 | `projectFiles.Count` | 可點開「專案附件」視窗（0 份時不可點） | — |

**AI 生成區塊**（需 `edit`）——「用 AI 把逐字稿整理成會議紀錄」

| 欄位 | 對應變數 | 意義 | 坑或限制 |
|---|---|---|---|
| 選擇逐字稿 | `selectedTranscriptId`（選項 `MeetingService.GetSelectableTranscriptsAsync`） | 轉錄完成的逐字稿 | 每項顯示歸屬：「未歸屬」「本專案」「已屬：其他專案」；**已被其他專案取用的不可選**（`IsTranscriptDisabled`）；已有會議紀錄的會註明「重新產生將覆蓋既有會議紀錄」。下方提示共幾份、幾份未歸屬 |
| 與會人員 | `selectedAttendees` | 從本專案「常用與會人員」名冊勾選本次到場的人 | 名冊空時停用，提示「可在『修改專案』中設定名冊」；每次換專案都重來，不持久化（生成後才快照進 `Meeting.DraftAttendees`） |
| 提示詞 | `selectedPromptTemplateId` | 啟用中的提示詞 | — |
| AI 轉會議紀錄 | — | 送出生成 | 三者都選且逐字稿 `CanGenerateDraft` 才可按（`CanSubmitDraft`）；一定跳費用確認，覆蓋時紅色按鈕；成功後「已排入生成佇列，可在右下角看到進度」。選了未歸屬的逐字稿會把它歸屬到本專案 |

**歷史會議紀錄**（`projectMeetings`，不分頁）

| 欄位 | 對應屬性 | 意義 | 坑或限制 |
|---|---|---|---|
| 來源逐字稿 | `Title` | 會議標題 | — |
| 使用提示詞 | `DraftPromptTemplateName` | 生成當下的名稱快照 | 沒有時「—」 |
| 狀態 | `DraftStatus` | 會議紀錄生成狀態，生成中顯示百分比 | 失敗時圖示提示 `DraftError` |
| 產生時間 | `DraftCompletedAt` | `yyyy/MM/dd HH:mm` | — |

列上動作：檢視會議紀錄（`HasDraft`）、編修會議紀錄（`HasDraft`＋`edit`，開 2.2.4 可編輯模式）、匯出 PDF（`HasDraft`＋`export`，表頭帶專案名稱）、抽出待辦（`HasDraft`＋`待辦事項:create`，見 2.3.4）、AI 問答（範圍是這一場會議）、**從專案移除**（`delete`，紅色）。

⚠️ 「從專案移除」**不是刪除**：解除歸屬並**刪掉已產生的會議紀錄**（無法復原），但影音檔與逐字稿保留，逐字稿會回到可選清單，可以指定到正確的專案重跑——不必重新上傳、不會再付轉錄費。生成中不能移除。真正的整筆刪除只在會議紀錄頁。

#### 2.3.1 新增／修改專案（對話窗）

標題「新增專案」／「修改專案」，類別 `form-modal-large`。模型 `ProjectAdapterModel`（實作 `IValidatableObject`）。

**新增時的預設值**：狀態「未開始」、完成百分比 0、**主責團隊不預設**（0.4.114 起一定要自己選；以前預設帶第一個團隊卻沒顯示，專案會默默存到使用者沒選的團隊）。

| 欄位 | 對應屬性 | 意義 | 用途 | 坑或限制 |
|---|---|---|---|---|
| 標題 | `Title` | 必填 | 專案名稱 | 可以同名（新增後以 Id 切換選取） |
| 負責人 | `Owner` | 必填，純文字 | 描述誰負責 | **不是系統帳號**，打錯不會有人提醒 |
| 主責團隊 | `PrimaryTeamId` | 必填（`[Required]`），單選 | 決定誰看得到 | 選項（`GetSelectablePrimaryTeamsAsync`）：管理者列全部啟用中團隊，**一般使用者只列自己所屬的**；編輯時原主責不是自己的團隊也會補進選項，**主責沒改就原樣保留**（協作團隊的人也能存檔）。改成非自己的團隊：「主責團隊只能選擇自己所屬的團隊。」（`ProjectAccess.ResolveProjectTeams`） |
| 協作團隊 | `CollaboratorTeamIds` | 0～多個 | 拉別的部門進來看 | 任何人可選任何啟用中團隊；編輯時已掛著但已停用的團隊也列出來，免得一動就被拿掉；主責不會重複列在協作 |
| 分類 | `Categories` | 多選標籤 | 描述性質（例如 .NET、成大） | 選項＝啟用中分類＋專案已掛著的已停用分類（`FormCategoryOptions`）；**不影響誰看得到** |
| 開始日期 | `StartDate` | 選填 | 期程 | — |
| 結束日期 | `EndDate` | 選填 | 期程 | 不可早於開始日期（`Validate`）：「結束日期 不可早於開始日期」 |
| 狀態 | `Status` | 必填，五選一 | 進度狀態 | `ProjectAdapterModel.StatusOptions`：未開始／進行中／已完成／暫緩／等待；服務層另驗合法值 |
| 完成百分比 | `CompletionPercentage` | 必填，0～100 整數（滑桿，步進 1） | 進度 | `[Range(0, 100)]` |
| 常用名詞 | `GlossaryTerms` | 術語、產品名清單 | 生成會議紀錄時餵給 AI 校正聽錯的同音字 | 輸入框＋「新增」鈕（刻意不用 Tags 模式，中文輸入法會殘留注音）；Enter **不會**新增；空白與重複（不分大小寫）略過；存成 `TagStringHelper` 換行包夾字串。名詞表是長期資料，重跑時用最新版 |
| 常用與會人員 | `Participants` | 專案的長期名冊 | 生成時從這裡勾選本次到場的人 | 同上 |
| 專案附件 | 待上傳（`pendingUploadFiles`）／已上傳（`Files`） | 可一次選或拖入多個檔 | AI 問答的專案範圍會讀附件 | 每檔上限 **1 GB**（`ProjectService.MaxUploadFileSize`），超過時選檔當下就擋「{檔名} 超過 1GB 限制」；附件**沒有副檔名白名單**。已上傳檔可點檔名下載、按「移除」標記刪除（存檔時才生效）。附件讀取中不能存檔 |

**儲存流程**：防重複送出 → 表單驗證（錯誤逐條通知）→ `BeforeAddCheckAsync`／`BeforeUpdateCheckAsync`（日期、狀態、百分比、附件大小、附件根目錄）→ 存檔並同步 `ProjectTeam`（`ProjectTeamWriter.Apply`）→ 上傳附件。新增時專案已建好、只有附件失敗，視窗會切成編輯模式，重送就是修改這一筆而不是再建一筆。

#### 2.3.3 AI 問答（視窗）

元件 `AiChatModal`（`Views/Projects`），專案項目頁與會議紀錄頁共用；差別在 `Scope`（`AiChatScope.Project`／`Meeting`）與 `TargetId`。服務 `AiChatService`，對話存在檔案系統（`AiChatStore`，一段對話一個 JSONL 檔）。

| 範圍 | 從哪裡開 | AI 讀什麼 |
|---|---|---|
| 整個專案 | 專案項目頁工具列「AI 問答」 | 本專案所有會議紀錄與附件 |
| 單一會議 | 會議紀錄頁或專案頁歷史會議紀錄的列上「AI 問答」 | 該會議的會議紀錄與逐字稿 |

⚠️ 對話是**共用**的：看得到這個專案／會議的人都看得到底下所有對話（左欄每列標示建立者）。權限依開啟的頁面而定——從會議紀錄頁開用 `會議紀錄` 的動作鍵，從專案頁開用 `專案項目` 的動作鍵，所以同一段會議對話從兩頁進去能做的事可能不同。

**左欄：對話紀錄**

| 控制 | 意義 | 坑或限制 |
|---|---|---|
| 開新對話 | 建一段新對話 | 目前那段還沒問過問題時停用（提示「目前已經是一段空白的新對話」） |
| 對話列 | 標題、更新時間、建立者 | 標題自動取第一個問題前 20 字（`AiChatStore.AutoTitleMaxLength`） |
| 重新命名 | 需 `CanEdit`（`edit`） | 最多 60 字；Enter 存、Esc 取消 |
| 刪除這段對話 | 需 `CanDelete`（`delete`），紅色 | 「所有人都會看不到，且無法復原」 |

**右側：問答區**

| 欄位／控制 | 意義 | 坑或限制 |
|---|---|---|
| 來源說明（`sourceNotice`） | 「本次讀取了 N 份資料」，並列出被截斷或跳過的來源 | 脈絡上限 60000 字元（`ChatContextBuilder.DefaultMaxChars`），依序截斷，**絕不無聲截斷** |
| 問題輸入框（`question`） | Enter 送出、Shift+Enter 換行 | 每次送出都計費（常駐提示），不跳確認；送出時帶最近 6 輪歷史（`AiChatService.MaxHistoryTurns`） |
| 附件（迴紋針、貼上、拖放） | 隨問題附上圖片或文件 | 每題最多 **5** 個（`AiChatAttachmentPolicy.MaxAttachmentsPerQuestion`）；圖片 png／jpg／jpeg／gif／webp 每個 ≤ 10 MB；文件 pdf／docx／txt／md／csv 每個 ≤ 20 MB；附件也計費 |
| 訊息工具：複製內容 | 所有人 | — |
| 訊息工具：編輯 | 需 `CanEdit` | 「儲存」只改文字、不重跑 AI；提問另有「重新產生答案」（費用確認，覆蓋下方回答） |
| 訊息工具：下載這則 PDF | 需 `CanExport` | — |
| 下載整段對話 PDF | 需 `CanExport` | — |
| 清空這段對話 | 需 `CanDelete` | — |

回答以 Markdown 渲染（`MarkdownRenderer`，擋掉原始 HTML 與危險連結）；串流中以純文字顯示。任一耗時動作進行中，所有按鈕共用同一個停用閘門（`IsBusy`）。

#### 2.3.4 抽出待辦（視窗）

元件 `TodoExtractionModal`，從專案頁歷史會議紀錄的列上「抽出待辦」開啟（需 `待辦事項:create`）。服務 `TodoExtractionService`。

開啟前先跳「確認抽出待辦（會產生費用）」：會議紀錄全文送 AI 分析，**每次抽取固定一次呼叫**；關閉後再開會重抽、再計費。確認後視窗一開啟就呼叫 AI（確認不能放進視窗裡，否則視窗出現時 API 已經打出去了）。
抽出來的只是**候選**，要勾選並按「加入 N 條待辦」才會真的建立待辦（`ProjectId` 為本專案、`MeetingId` 為這場會議）。

| 欄位 | 對應屬性（`Candidate`） | 意義 | 坑或限制 |
|---|---|---|---|
| 勾選 | `Selected` | 是否加入；有「全選」與「已選 N / M 條」 | 一條都沒勾時「加入」鈕停用 |
| 已加入過 | `AlreadyAdded` | 標題與這場會議既有待辦相同（去頭尾空白比對） | 預設**不勾**但仍列出，可自己勾回；頂部說明這次有幾條重複 |
| 待辦標題 | `Title` | 可改，必填，最多 200 字 | — |
| 描述 | `Description` | AI 摘錄，**唯讀** | 要改請進待辦頁 |
| 負責人 | `Owner` | 可改，最多 50 字，空白＝未指定 | — |
| 截止日 | `DueDate` | 可改 | — |
| 優先度 | `Priority` | 低／中／高，預設依 AI 結果 | 選項 `TodoAdapterModel.PriorityOptions` |

部分加入失敗時會列出哪些沒加入與原因。抽不到東西是正常結果，顯示中性提示而非錯誤。

### 2.4 待辦事項

網址：`/todos`（`TodoPage` → `TodoViewView`；服務 `TodoService`）
權限鍵：`待辦事項`（頁面；新增 `create`、修改與勾選完成 `edit`、刪除 `delete`）

追蹤會議裡講好要做的事。待辦**一定隸屬於一個專案**（看得到專案的人就看得到它的待辦），可以手動新增，也可以從專案頁的會議紀錄「抽出待辦」。
左邊是待辦清單，右邊是「負責人工作量」面板。沒有任何可存取的專案時，頁面提示先去建專案，「新增」鈕停用。

**這一頁可以做什麼**

- 工具列左側：新增（`create`）、重新整理。右側：專案過濾（單選）、狀態過濾（單選）、關鍵字搜尋、清空搜尋。
- 關鍵字比對**標題、描述、負責人、狀態、優先度、專案名稱**（`TodoService.GetAsync`）。
- 預設排序：**有截止日的在前、越早到期越前面**，未指定截止日的墊底；可排序欄位：待辦事項、所屬專案、負責人、截止日、優先度、狀態。
- 每頁筆數依畫面高度自動調整（`TodoAutoFit`，0.4.86）。
- 列上「完成」勾選框：需 `edit`。勾選＝狀態改「已完成」；**取消勾選退回「進行中」而不是「待辦」**（`TodoService` 的完成切換）。
- 刪除：確認「確定要刪除這筆待辦事項嗎？此操作無法復原。」

**清單欄位**

| 欄位 | 對應屬性 | 意義 | 用途 | 坑或限制 |
|---|---|---|---|---|
| 完成 | `IsCompleted`（`Status == "已完成"`） | 勾選框 | 快速標記完成 | 沒有 `edit` 時停用 |
| 待辦事項 | `Title` | 單行省略 | 辨識 | 有描述時旁邊多一顆「檢視完整內容」（開 2.4.2）；完成的加刪除線 |
| 所屬專案 | `ProjectTitle` | 專案名稱 | 辨識 | 服務層另外填的跨物件欄位 |
| 來源會議紀錄 | `MeetingTitle` | 由哪場會議抽出 | 回溯來源 | 空白顯示「— 手動新增」。⚠️ 來源會議你看不到時（例如會議被改歸屬到別的專案）也會是空白 |
| 負責人 | `Owner` | 純文字姓名 | 分派 | 空白顯示「未指定」；**不是系統帳號** |
| 截止日 | `DueDate` → `DueDateOnlyText` | `yyyy/MM/dd` | 期限 | 逾期（有截止日、未完成、早於今天）標紅並顯示「逾期 N 天」（`IsOverdue`／`OverdueDays`） |
| 優先度 | `Priority` | 低／中／高 | 排序 | — |
| 狀態 | `Status` | 待辦／進行中／已完成 | 進度 | 完成判斷只看這一欄 |
| 操作 | — | 修改（`edit`）、刪除（`delete`） | — | 固定在右側 |

**負責人工作量面板**

- ⚠️ 只跟「專案過濾」連動，**不跟狀態過濾與關鍵字連動**（`TodoService.GetOwnerSummariesAsync`）：它顯示的就是狀態分布，再被狀態過濾一次會得到「每個人都 100%」這種看似合理的錯誤數字。標題旁顯示目前範圍（專案名稱或「全部專案」）。
- 負責人下拉：「姓名（總數）」，依待辦數多到少排序；負責人空白的歸成「未指定」（`OwnerKey`）。
- 選定後顯示完成度（已完成／總數）與四顆膠囊：**待辦、進行中、已完成、逾期**（`OwnerTodoFilter`）。點膠囊只篩面板下方的小清單，左邊表格不動；膠囊上的數字一律維持未篩選。0 筆的膠囊不可點。
- 「逾期」不是 `Status` 的值，是「有截止日、未完成、早於今天」的衍生條件。
- 面板可收合，收合時仍保留一行摘要。

#### 2.4.1 新增／修改待辦事項（對話窗）

標題「新增待辦事項」／「修改待辦事項」。模型 `TodoAdapterModel`。開表單前會重新載入可選專案（0.4.115）。

|---|---|---|---|---|
| 待辦標題 | `Title` | 必填，最多 200 字 | 要做的事 | — |
| 所屬專案 | `ProjectId` | 必填（`[Range(1, int.MaxValue)]`），選項為看得到的專案 | 決定誰看得到 | ⚠️ **改到別的專案會清掉來源會議**（`MeetingId` 設 null，0.4.115）——來源會議屬於原專案，留著的話新專案的人會看到他們看不到的會議標題 |
| 負責人 | `Owner` | 選填，最多 50 字 | 分派 | 純文字 |
| 截止日 | `DueDate` | 選填 | 期限 | — |
| 優先度 | `Priority` | 必填，低／中／高 | — | `TodoAdapterModel.PriorityOptions` |
| 狀態 | `Status` | 必填，待辦／進行中／已完成 | — | `TodoAdapterModel.StatusOptions`；`CompletedStatus = "已完成"` |
| 來源會議紀錄 | `MeetingTitle` | 唯讀，只有從會議抽出的待辦才出現 | 回溯 | 不開放從畫面修改 |
| 描述 | `Description` | 選填，最多 2000 字 | 補充 | — |

#### 2.4.2 檢視完整內容（視窗）

唯讀，標題為待辦標題，內容是描述全文（以 `<pre>` 保留換行）。

### 3.1 使用者管理

網址：`/myusers`（`MyUserPage` → `MyUserView`；服務 `MyUserService`）
⚠️ 頁面實際要求 **`IsAdmin`**（`AuthenticationStateHelper.CheckIsAdmin`），不是看 `使用者管理` 權限鍵：角色勾了 `使用者管理`（例如「管理者」預設角色）的非管理者，選單看得到這一項，點進去卻是「你沒有權限存取此頁面」。新增、修改、刪除按鈕本身沒有再做動作權限檢查。

**這一頁可以做什麼**

- 狀態膠囊點擊切換啟用／停用（確認「停用後這個帳號無法登入」）。
- 刪除：確認「確定要刪除這筆紀錄嗎？此操作無法復原。」。⚠️ 服務層沒有擋刪除自己或 `support`。

**清單欄位**

| 欄位 | 對應屬性 | 意義 | 坑或限制 |
|---|---|---|---|
| 帳號 | `Account` | 登入帳號 | 預設排序 |

| 團隊 | `TeamNamesText` | 直接所屬的團隊 | 沒有時「—」：**看不到任何專案**，只看得到自己上傳、尚未歸屬的會議 |

### 3.2 角色管理

⚠️ 與 3.1 相同，頁面實際要求 **`IsAdmin`**。

## 四、資料定義

### 4.1 分類清單

網址：`/categories`（`CategoryPage` → `CategoryViewView`；服務 `CategoryService`）
權限鍵：`分類清單`（頁面；新增 `create`、修改與狀態切換 `edit`、刪除 `delete`）

維護「分類」這個標籤的選項。分類＝**什麼資料**，貼在專案、會議、提示詞上用來篩選，**不影響誰看得到**。

**這一頁可以做什麼**：新增、重新整理、關鍵字搜尋（比對名稱與描述）、點狀態膠囊啟用／停用、修改、刪除。

| 欄位 | 對應屬性 | 意義 | 用途 | 坑或限制 |
|---|---|---|---|---|
| 名稱 | `Name` | 必填，最多 100 字 | 分類標籤文字 | 不可重複：「分類名稱已存在，無法新增。」 |
| 描述 | `Description` | 選填，最多 2000 字 | 說明 | — |
| 負責團隊（參考） | `TeamIds`／`TeamNamesText` | 通常由哪些團隊負責這類資料（`CategoryTeam`） | **只是參考** | 不會帶進專案、不影響誰看得到 |
| 啟用狀態 | `IsEnabled` | 預設啟用 | 停用後不出現在各頁的分類下拉 | 已貼在資料上的分類不會被移除 |
| 更新時間 | `UpdatedAt` | 自動 | 預設排序（新到舊） | — |

⚠️ 專案、會議、提示詞上存的是分類**名稱字串**（`TagStringHelper` 格式），不是外鍵：**改名或刪除分類不會同步**到已貼上的資料，舊名稱會留在資料上（也就無法再用新名稱篩到）。

### 4.2 團隊清單

網址：`/teams`（`TeamPage` → `TeamViewView`；服務 `TeamService`）
權限鍵：`團隊清單`（頁面；新增 `create`、修改與狀態切換 `edit`、刪除 `delete`）。預設角色中「主管」只有檢視（0.4.114），一般使用者預設沒有。

維護團隊與成員。團隊＝**誰的資料**：專案的主責或協作團隊有你所屬的團隊，你就看得到那個專案。團隊通常就是部門。

**這一頁可以做什麼**：新增、重新整理、關鍵字搜尋（比對名稱、代號、描述）、點狀態膠囊啟用／停用、修改、刪除。

| 欄位 | 對應屬性 | 意義 | 用途 | 坑或限制 |
|---|---|---|---|---|
| 名稱 | `Name` | 必填，最多 100 字 | 團隊名稱 | 不可重複：「團隊名稱已存在…」。使用者管理的團隊下拉以**名稱**對應 |
| 代號 | `Code` | 選填，最多 50 字 | 給人看的備註 | 有填則需唯一：「團隊代號已存在…」 |
| 描述 | `Description` | 選填，最多 2000 字 | 說明 | — |
| 成員數 | `MemberCount` | 清單顯示 | — | — |
| 成員 | `MemberIds`（表單） | 多選帳號，選項為**啟用中**的帳號「名稱（帳號）」 | 寫入 `UserTeam`（`TeamService.SyncMembersAsync`） | 管理者不受團隊限制，不必加進來 |
| 啟用狀態 | `IsEnabled` | 預設啟用 | 停用後不出現在團隊下拉 | ⚠️ **停用不等於收回權限**：已設定的成員與專案團隊不受影響 |
| 更新時間 | `UpdatedAt` | 自動 | 預設排序 | — |

⚠️ **刪除**：團隊還是某些專案的**主責團隊**時，非管理者不能刪（`ProjectTeamWriter.PrimaryInUseMessageAsync`），訊息列出你看得到的專案名稱，看不到的只給數量；管理者照刪（0.4.104），受影響的專案就沒有主責，之後編輯時要補。只當協作的團隊可以刪。

### 4.3 提示詞清單

網址：`/prompttemplates`（`PromptTemplatePage` → `PromptTemplateViewView`；服務 `PromptTemplateService`）
權限鍵：`提示詞清單`（頁面；新增與內建範本 `create`、修改與狀態切換 `edit`、刪除 `delete`）

維護「AI 轉會議紀錄」時要套用的提示詞範本。提示詞是生成會議紀錄的**必要輸入**，清單空著等於核心功能不能用。

**這一頁可以做什麼**

- 新增、**建立內建範本**（一次建立全部，已存在同名者略過）、選一個內建範本再按「新增此範本」（刻意做成兩步式，避免誤觸就多一筆）、重新整理、關鍵字搜尋（比對名稱、內容、描述）。
- 內建範本（`PromptTemplatePresets.All`）：標準會議紀錄、逐字稿重點條列、決議與待辦事項、客戶訪談紀要、一頁摘要。
- 啟用狀態欄：有 `edit` 時是可點的按鈕，沒權限時是純文字。

**清單欄位**：名稱（`Name`）、內容預覽（`ContentPreview`，單行、最多 60 字後加「…」）、描述（`Description`）、啟用狀態（`IsEnabled`）、更新時間（`UpdatedAt`，預設排序）。

#### 4.3.1 新增／修改提示詞（對話窗）

| 欄位 | 對應屬性 | 意義 | 用途 | 坑或限制 |
|---|---|---|---|---|
| 名稱 | `Name` | 必填，最多 100 字 | 下拉顯示名稱 | 不可重複（不分大小寫）：「提示詞名稱已存在，無法新增。」。⚠️ 會議記的是生成當下的名稱快照，**改名後儀表板會把它算成「啟用但未使用」** |
| 啟用狀態 | `IsEnabled` | 預設啟用 | 停用後不出現在 AI 轉會議紀錄的提示詞下拉 | 選了已停用的範本送出會被擋「找不到指定的提示詞，或該提示詞已停用。」 |
| 分類 | `Categories` | 多選標籤 | 描述用途 | 選項只列啟用中分類（同 2.2.1 的坑） |
| 描述 | `Description` | 選填，最多 2000 字 | 用途說明 | — |
| 提示詞內容 | `Content` | 必填，最多 20000 字 | 生成會議紀錄時送給模型的指令 | 支援變數（`PromptVariableHelper.KnownVariables`）：`{{transcript}}`、`{{meetingTitle}}`、`{{meetingDate}}`，不分大小寫、大括號內可有空白。**未知變數不阻擋儲存**，只跳警示通知，生成時原樣輸出 |

## 五、沒有網址、但也是畫面

| 畫面 | 位置 | 內容與坑 |
|---|---|---|
| 啟動頁 | `/`（`Home` → `SplashView`） | 驗證通過後導向 `/meetings` |
| 右上角使用者選單 | `MainLayout` | 顯示名稱（沒有時用帳號），管理者加「管理員」徽章；項目：變更密碼（1.5）、關於、登出。⚠️ 沒有「設定 API 密碼」（1.6）的入口 |
| 「關於」對話窗 | `MainLayout.OnAboutClick` | 系統名稱、系統描述、系統版本（`SystemSettings.SystemInformation.SystemVersion`）、執行環境、.NET 版本、啟動時間、已運作時間（開啟當下計算） |
| 頂欄頁面標題 | `MainLayout.CurrentPageTitle` | 取自 `Menu.json` 中與目前網址相符的項目名稱，找不到時顯示「系統首頁」（例如 `/ChangePassword`、`/Profile`） |
| 右下角背景工作進度面板 | `BackgroundJobProgressPanel` | 轉錄與會議紀錄生成的即時進度；「取消」才會真的停止工作，「關閉」只是移除通知、工作照跑；「全部關閉」同理 |
| 側邊選單 | `NavMenu`、`SidebarMenuService` | 依權限過濾（見 0.4），可收合；收合鈕在側欄外緣 |
| 頁面拖放保護 | `MainLayout` 外層 `@ondragover:preventDefault`／`@ondrop:preventDefault` | 檔案拖到拖放區以外的地方不會讓瀏覽器導航去開檔案（否則 Blazor 連線中斷、表單內容全失） |
