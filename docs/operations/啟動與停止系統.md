## 一、先確認有沒有已經在跑的實例

```powershell
netstat -ano | Select-String ":5189.*LISTENING"
```

**有輸出就代表系統已經開著，直接開瀏覽器即可，不要再啟動第二個。**
兩個實例會共用同一個 SQLite 檔（`C:\temp\MeetingRecord\DB\BackendDB.db`），
會互相干擾；而且第二個會因為埠被佔用而啟動失敗。

## 二、需要停掉時

改了 `.cs` / `.razor` 要重新編譯，就得先把舊的停掉。

最乾淨的方式是**回到那個 console 視窗按 `Ctrl+C`**（Visual Studio 則按停止偵錯）。

找不到視窗時才用 PID：

```powershell
netstat -ano | Select-String ":5189.*LISTENING"   # 最後一欄就是 PID
tasklist /FI "PID eq <PID>"                       # 確認真的是 MeetingRecord.Web.exe
taskkill /PID <PID> /F
```

> ### ⚠️ 絕對不要用映像名稱砍行程
>
> ```powershell
> taskkill /IM MeetingRecord.Web.exe /F   # ← 不要這樣做
> ```
>
> 本專案曾因此**連帶砍掉開發者正在使用的 Visual Studio**。
> Visual Studio 偵錯中的宿主行程會匹配到同樣的映像名稱。
>
> **一律先用 `netstat` 由埠找到單一 PID，`tasklist` 確認過再砍那一個。**

## 三、啟動（三選一）

| 方式 | 指令 | 適用時機 |
|------|------|----------|
| **A. `run.cmd`** | `.\run`（或 `.\run https`）| 日常最快。從哪個目錄呼叫都可以，也可在檔案總管按兩下 |
| **B. Visual Studio** | 開 `src/MeetingRecord/MeetingRecord.slnx` → F5 | 要下中斷點除錯時 |
| **C. 手動** | 見下方 | 前兩者出問題時的退路 |

方式 C：

```powershell
cd src/MeetingRecord
dotnet run --project MeetingRecord.Web/MeetingRecord.Web.csproj --launch-profile http
```

`launchSettings.json` 的兩個 profile：

| profile | 網址 |
|---------|------|
| `http`（預設）| <http://localhost:5189> |
| `https` | <https://localhost:7044>（同時也聽 5189）|

兩者都是 `ASPNETCORE_ENVIRONMENT=Development` 且 `launchBrowser: true`，會自動開瀏覽器。

> ### ⚠️ A 與 B 不能同時用
>
> Visual Studio 會佔住 5189，而且會**鎖住 `bin\Debug` 的 DLL**，
> 讓 `dotnet run` 連編譯都過不了（錯誤訊息是檔案被另一個處理程序使用）。
> `run.cmd` 在非零結束碼時會提示這個可能性。
>
> 需要在 VS 執行的同時另外建置（例如跑測試），把輸出導到別的目錄：
>
> ```powershell
> dotnet build src/MeetingRecord/MeetingRecord.slnx -p:BaseOutputPath=./.tmp-build-out/
> ```
>
> 輸出目錄要放在**倉庫樹內**——放到 `%TEMP%` 會讓
> `MeetingRegistrationTests` / `MenuIconTests` 假性失敗 6 筆（它們會去讀相對路徑的檔案）。

## 五、什麼時候一定要重新編譯

改了 `.cs` / `.razor` / `.razor.css` **一定要重新編譯**才會生效，
**新增的 `@page` 路由尤其**（例如 0.4.54 的 `/dashboard`）。

但有兩個例外容易讓人誤判：

| 檔案 | 行為 |
|------|------|
| `MeetingRecord.Web/Datas/Menu.json` | 走 `ContentRootPath`，Development 下讀的是**原始碼目錄**，改了立刻生效 |
| `MeetingRecord.Web/appsettings.json` | 同上 |

**這個落差在 0.4.54 造成過一次誤判**：`Menu.json` 加了儀表板選單、不重編就出現在側邊欄，
但點下去是 Not Found——因為 `@page "/dashboard"` 這個新路由還沒被編譯進組件。
側邊欄看得到不代表頁面存在。

## 六、啟動失敗的常見原因

| 症狀 | 原因與處理 |
|------|-----------|
| 埠已被使用 | 已經有實例在跑，見第一節 |
| DLL 被另一個處理程序使用 | Visual Studio 開著並鎖住 `bin\Debug`，見第三節 |
| 啟動時就中止並抱怨 FFmpeg | `StartupSafetyValidator` 找不到 `ffmpeg`。`winget install --id Gyan.FFmpeg -e` 後**開新的終端機**讓 PATH 生效 |
| LLM 設定驗證失敗 | Azure OpenAI 的金鑰放在 `dotnet user-secrets`，不在 git 追蹤的 `appsettings.json` 裡。用 `dotnet user-secrets list`（在 `MeetingRecord.Web` 目錄下）確認 |
