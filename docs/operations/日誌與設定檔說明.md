## 1. 日誌方案：NLog

採 `NLog.Web.AspNetCore 6.1.2`，於 [`src/MeetingRecord/MeetingRecord.Web/Program.cs`](../../src/MeetingRecord/MeetingRecord.Web/Program.cs) 的 `#region NLog 相關設定` 完成設定（`NLog.BasePath` 留空時只做第 5 步，不建目錄、不設變數）：

1. 從 `appsettings.json` 讀取 `NLog.BasePath`（預設 `C:\temp\Logs`）。
2. 在 `BasePath/MeetingRecord.Web/` 下建立日誌目錄。
3. 設定 NLog Internal Logger 寫入 `MeetingRecord.Web-nlog-internal.log`。
4. 將 `BasePath` 與 `LogFilenamePrefix` 變數寫入 NLog 設定，供 `nlog.config` 內 `${var:BasePath}` 引用。
5. `builder.Logging.ClearProviders()` 清除預設 Provider，由 `builder.Host.UseNLog(Program.NLogOptions)` 接管。
   - 0.4.123 起 `NLogOptions` 把 `LoggingConfigurationSectionName` 設為空字串：NLog 設定**只來自 `nlog.config`**，不會把 appsettings 的 `NLog` 區段當成 NLog 設定載入。
   - 那個區段只放本專案自己的 `BasePath`。之前在 NLog 設定被清空時（例如整合測試另一個主機 `LogManager.Shutdown()`），NLog 會去解析它，並拋 `Unrecognized value 'BasePath'`。
6. （0.4.122）`AddApplicationServices` 在 `ClearProviders()` **之後**再加上 `ExceptionLogProvider`（`ILoggerProvider`），與 NLog 並存：凡是帶例外物件的 `LogError`／`LogCritical` 都會另外寫進「系統例外紀錄」（`ExceptionLog` 表，見 [系統功能總覽](../architecture/系統功能總覽.md)）。⚠️ 註冊在 `ClearProviders()` 之前會被清掉，例外紀錄就靜靜地一筆都沒有。

`nlog.config` 位於 `MeetingRecord.Web/` 根目錄，定義具體 Target / Rule。

**錯誤追蹤碼（0.4.122）**：每個 HTTP 請求（`UseHttpRequestLogging`）與每一次 Blazor 互動（`ApplicationCircuitHandler`）都有一組 8 碼追蹤碼（`Diagnostics/TraceCode`，Crockford Base32，放在 NLog `ScopeContext`）；HTTP 請求的追蹤碼會**取代 `HttpContext.TraceIdentifier`**，所以 `ApiResult.TraceId` 與框架自己的日誌都是同一個碼。file 與 console 目標的第 2 欄因此由 `${aspnet-TraceIdentifier}` 改成 `${scopeproperty:item=TraceCode:whenEmpty=${aspnet-TraceIdentifier}}`（欄數不變）。錯誤畫面會顯示「（錯誤追蹤碼：XXXXXXXX）」，使用者回報的碼可在日誌檢視與系統例外紀錄查到。

**日誌檢視（0.4.121）**：管理者可在「系統管理 → 監控與診斷 → 日誌檢視」（`/logs`）查詢檔案目標的內容（`LogQueryService`，含當天的封存檔）。0.4.122 起 TraceId 篩選查的就是錯誤追蹤碼（第 2 欄）。⚠️ 解析依賴檔案目標的 7 欄 layout `${longdate}|${scopeproperty:item=TraceCode:whenEmpty=${aspnet-TraceIdentifier}}|${level:uppercase=true}|${threadid}|${logger}|${message}|${exception:...}`——改 layout（欄位順序、分隔字元、時間格式）會讓等級、記錄器等欄位解析錯欄（原文仍可展開與匯出）。console 目標的欄位順序不同，但不會被讀取。

**執行期調整等級（0.4.120）**：管理者可在「系統管理 → 監控與診斷 → 日誌等級設定」（`/log-level-setting`）暫時調整 `<logger name="*">` 規則的最低等級（`LogLevelRuntimeState`），重新啟動即回到 `nlog.config` 的值，不寫任何檔案；`Microsoft.*`／`System.*` 規則是 `final`，不受影響。`LogLevelRuntimeState.Initialize()` 在啟動時訂閱 `nlog.config` 的重新載入（`autoReload`），重新載入後會補回 `BasePath`／`LogFilenamePrefix` 變數並重新套用執行期等級。

`/system-health`（系統健康監控）人工巡檢頁的「日誌」項目以 `NLogFilePathResolver`（與日誌檢視同一套路徑推導）定位今日日誌檔，只看目錄與檔案狀態、不讀檔內容，證據列出今日檔大小與目前生效等級（註明是否為日誌等級設定的執行期覆寫）。頁尾「最近 24 小時警告以上日誌」以日誌檢視同一個查詢服務（`ILogQueryService`）讀取 WARN 以上、最新 200 筆，預設收合、**第一次展開才讀檔**。「近期錯誤」項目 0.4.123 起改看「系統例外紀錄」最近 24 小時發生過的例外，不再掃今日日誌的 ERROR／FATAL 行數；0.4.122 以前頁尾是「最後 100 筆原始日誌」。0.4.120 起整頁**只限管理者**（不能再開給其他角色）；日誌本身仍不應寫入密碼、token 或完整連線字串。

## 2. 何時使用何種等級

| 等級 | 使用時機 | 範例 |
|------|----------|------|
| `Trace` | 細節最高的逐步追蹤；通常不啟用。 | 內部演算法每一步狀態。 |
| `Debug` | 流程關鍵節點、輸入參數、查詢條件。 | `logger.LogDebug("Received task search request. Keyword={Keyword}", request.Keyword);` |
| `Information` | 商業流程成功完成、啟動 / 關閉、Seed 完成。 | `logger.LogInformation("Application startup completed.");` |
| `Warning` | 找不到資源、業務驗證未通過、可恢復例外。 | `logger.LogWarning("Task get request could not find record. TaskId={TaskId}", id);` |
| `Error` | 例外、外部資源失敗、重要流程中斷。 | `logger.LogError(ex, "Failed to search tasks");` |
| `Critical` | 系統幾乎無法繼續運作。 | DB 連線完全失敗、執行階段崩潰。 |

撰寫原則：

- 訊息以英文 + 結構化參數（`{Name}` 佔位）為主，方便日後檢索。
- 使用者面向訊息（中文）保留在 `ApiResult.Message` / `Notification`，不要混入日誌訊息。
- 例外請使用 `logger.LogError(ex, "...")` 寫入完整堆疊。

## 3. 全域請求日誌

`Program.cs` 於 `#region 註冊中介軟體` 呼叫 `app.UseHttpRequestLogging<Program>()`，由 `Extensions/ApplicationBuilderExtensions.cs` 的 `UseHttpRequestLogging<TProgram>()` 註冊一個自訂 middleware：

- 對每筆 HTTP 請求記錄 `Method`、`Path`、`StatusCode`、`ElapsedMilliseconds`。
- 例外發生時改寫為 `Error`，並重新拋出讓上層 ExceptionHandler 處理。
- （0.4.122）給請求一組錯誤追蹤碼並取代 `TraceIdentifier`；同時設定系統例外紀錄的情境（路徑以 `/api` 開頭為「WebAPI」，其餘為「畫面」）。驗證之後由 `UseExceptionContextUser()`（必須在 `UseAuthorization()` 之後）補上使用者帳號與路由樣板。

由此可在不額外加程式的情況下取得每個 endpoint 的響應耗時。

### 4.1 `Logging`

.NET 預設記錄等級。NLog 啟動後會接管實際輸出，但此區段仍影響 `Microsoft.*` 等內建類別的 Filter。

### 4.2 `NLog.BasePath`

NLog 寫檔的根目錄；專案會在其下建立 `MeetingRecord.Web` 子目錄。若不存在會被 NLog 自動建立。

### 4.3 `Swagger` / `Security` / `Cors`

| 欄位 | 用途 |
|------|------|
| `Swagger.EnabledInProduction` | Production 是否開啟 Swagger UI；Production 必須明確設定。 |
| `Security.ReturnExceptionDetails` | 是否在 API 500 回應填入完整 `Exception`；未設定時 Development 才會回傳。 |
| `Cors.AllowedOrigins` | 允許跨來源呼叫的 origin 清單；空陣列代表不開放。 |

`JwtSettings`（Web API 的 JWT 簽發與驗證）與 `BootstrapSettings`（啟動時自動建立／校正的 `support` 管理帳號）屬安全設定，欄位說明與正式環境要求見 [認證授權與權限機制](../security/認證授權與權限機制.md) 與 [正式部署與安全檢查清單](正式部署與安全檢查清單.md)。

### 4.3.0 `CookieSettings`（0.4.119）

Blazor UI 登入 Cookie 的效期，綁定 `MeetingRecord.Web.Auth.CookieSettings`（`ValidateDataAnnotations` ＋ `ValidateOnStart`，超出範圍啟動即失敗）。之前沒有這一段，吃框架隱藏預設 14 天。

| 欄位 | 預設 | 用途 |
|------|------|------|
| `ExpireMinutes` | 480 | 沒勾「記住我」的效期（分鐘，1～43200）；此時 Cookie 也是 session cookie，關瀏覽器就沒了。 |
| `RememberMeDays` | 30 | 勾了「記住我」與 Google 登入的效期（天，1～365），登入時以 `ExpiresUtc` 明寫。 |
| `SlidingExpiration` | `true` | 滑動續期：用掉超過一半效期時的那一次 HTTP 請求才續，並從那一刻重新算滿；`false` 則到期就是到期。 |

Cookie 名稱（`.MeetingRecord.Auth`）與加密金鑰（`SystemSettings:ExternalFileSystem:DataProtectionKeyPath`）見 [記住我登入原理說明](../security/記住我登入原理說明.md)。

### 4.3.0.1 `LogRetentionSettings`（0.4.122；1.0.29 新增 `AiUsageLogDays`；1.0.32 新增 `AuditLogDays`）

系統例外紀錄、AI 用量帳本與稽核紀錄的保存期限，綁定 `MeetingRecord.Models.Systems.LogRetentionSettings`（`ValidateDataAnnotations` ＋ `ValidateOnStart`）。日誌檔的保存由 `nlog.config` 的 `maxArchiveDays` 管，不在這裡。

| 欄位 | 預設 | 用途 |
|------|------|------|
| `ExceptionLogDays` | 90 | 「最後發生」超過幾天的例外紀錄自動刪除（連同堆疊檔；0～36500）。**0＝不自動清理**。`ExceptionLogRetentionBackgroundService` 啟動時跑一次、之後每 24 小時一次，有刪到才記稽核 `ExceptionLog.AutoPurge`。「系統例外紀錄」頁的「清除 N 天未再發生」也用這個天數（設 0 時退回 90）。 |
| `AiUsageLogDays` | 0 | AI 用量帳本（`AiUsageLog`）超過幾天自動刪除（1.0.29）。**0＝永久保留**；要啟用時**至少 62 天**（「本月 vs 上月同期」與每月用量上限都要讀到上個月初），設 1～61 啟動即失敗。由 `AiLogRetentionBackgroundService` 每天執行一次（啟動時先跑一次），有刪到才記稽核 `AiUsage.AutoPurge`。會議時長已改存在 `Meeting.MediaDurationSeconds`，清帳本不會讓儀表板「會議時數」變少。1.0.31 起「Token 用量」頁的說明列會顯示目前的保留天數（或「永久保留」），管理者也可在該頁手動刪除單筆、清除此日之前或全部清除（稽核 `AiUsage.Delete`／`Purge`／`ClearAll`）；⚠️ 刪掉本月的紀錄會讓本月用量上限的已用額度變少。 |
| `AuditLogDays` | 365 | 稽核紀錄（`AuditLog`）超過幾天自動刪除（1.0.32；0～36500）。**0＝不自動清理**。預設比例外紀錄長，因為稽核是追究責任的證據。`AuditLogRetentionBackgroundService` 啟動時跑一次、之後每 24 小時一次，門檻以 UTC 計算，有刪到才記稽核 `Audit.AutoPurge`。「稽核紀錄」頁（`/audit-logs`）的「清除 N 天前」也用這個天數（設 0 時退回 365）。 |

### 4.3.0.1.1 `AiCallLogSettings`（1.0.29）

AI 對話紀錄（每次付費 AI 呼叫的送出內容與回應，由 `AiCallGateway` 寫入），綁定 `MeetingRecord.Models.Systems.AiCallLogSettings`（`ValidateDataAnnotations` ＋ `ValidateOnStart`）。內容檔位置見 §4.6 `AiCallLogPath`。1.0.30 起管理者可在「系統管理 → AI 管理 → AI 對話紀錄」（`/ai-call-logs`）查看、匯出與手動清除，頁面說明列會顯示目前的 `RetentionDays` 與是否停用記錄；設計見 [AI 對話紀錄 PRD](../prd/AI對話紀錄-prd.md)。

| 欄位 | 預設 | 用途 |
|------|------|------|
| `Enabled` | `true` | 是否記錄送出內容與回應。關掉後不再寫新的對話紀錄（用量帳本照記），既有紀錄保留期限照常清除。 |
| `RetentionDays` | 90 | 保留天數（1～3650）。內容含逐字稿等敏感資料，**沒有「永久保留」**。`AiLogRetentionBackgroundService` 每天清一次（停用記錄時照樣清），有刪到才記稽核 `AiCallLog.AutoPurge`。 |

### 4.3.0.1.2 `AiQuotaSettings`（1.0.29）

AI 用量上限，綁定 `MeetingRecord.Models.Systems.AiQuotaSettings`（`ValidateDataAnnotations` ＋ `ValidateOnStart`，範圍 0～100,000,000），以 `IOptionsMonitor` 讀取，**改設定檔即生效、不必重啟**。

| 欄位 | 預設 | 用途 |
|------|------|------|
| `GlobalMonthlyTwd` | 0 | 全系統每月上限（新台幣整數）。**0＝不限制**。 |
| `PerUserMonthlyTwd` | 0 | 每位使用者每月上限（新台幣整數）。**0＝不限制**。 |

用量＝本月用量帳本的估算金額，依每一列自己的匯率換算成新台幣後加總（沒有匯率的列用目前匯率；未設定單價的呼叫算 0 元；讀不到帳本時放行）。達上限時擋下新的 AI 呼叫並記稽核 `Ai.QuotaBlocked`（Warning，不進系統例外紀錄）；背景工作（轉錄、會議紀錄生成）只在開始時檢查一次，被擋就標為失敗並寫原因，一旦開始就做完。多個呼叫同時進行時實際用量可能略超過上限。系統健康監控的「AI 用量上限」會依此亮燈；1.0.31 起「Token 用量」頁最上方的上限列也會顯示全系統已用／上限、每人上限與本月用最多的前 5 人（達 80%、達上限各有標示）。改了上限後按該頁的「重新整理」即可看到新值。

| `MaxPerCircuitPerMinute` | 10 | 每個 circuit 每分鐘最多收幾筆（1～1000），超過的丟棄並計數。 |

| 欄位 | 用途 |
|------|------|
| `Provider` | 快取提供者，支援 `Memory`（預設，單機記憶體）與 `Redis`（分散式）。空字串會回退為 `Memory`，未知值在啟動時拋出例外。 |
| `RedisConnection` | `Provider=Redis` 時的連線字串（如 `localhost:6379`）；`Redis` 時不可留空，Production 會被啟動安全檢查阻擋。 |
| `InstanceName` | Redis 鍵前綴，用於隔離同一 Redis 實例上的多個應用。 |
| `DefaultExpirationMinutes` | 未指定過期時間時套用的預設絕對過期（分鐘）。 |

呼叫端統一透過 `ICacheService`（`Get/Set/GetOrCreateAsync<T>/Remove`，內含 JSON 序列化），切換 provider 不需改任何使用端程式。完整說明見 [分散式快取機制](../features/分散式快取機制.md)。

### 4.3.3 `LlmSettings`

大語言模型（LLM）與語音轉錄（STT）供應商設定，0.4.26 起存在，0.4.27 補上轉錄欄位並由 `AzureOpenAiTranscriptionProvider` 實際使用。以 `Providers` 字典依**供應商名稱**分組。

| 欄位 | 用途 |
|------|------|
| `DefaultProvider` | 文字生成的供應商名稱，對應 `Providers` 的鍵。**留空代表未啟用 LLM 功能**，啟動驗證與 Production 安全檢查都會整段跳過。 |
| `TranscriptionProvider` | 語音轉錄的供應商名稱。**留空時沿用 `DefaultProvider`**，讓轉錄端與生成端可以是不同廠商。 |
| `Providers.<名稱>.Endpoint` | 該供應商的 API 端點，例如 `https://<resource>.openai.azure.com/`。 |
| `Providers.<名稱>.ApiKey` | API 金鑰。**機敏值**，版控內只放開發預設值，正式環境請用 user-secrets／環境變數。 |
| `Providers.<名稱>.Model` | 文字生成用：Azure OpenAI 為 deployment 名稱；其他廠商為 model id。 |
| `Providers.<名稱>.TranscriptionModel` | 語音轉錄用的 deployment／model 名稱，例如 `gpt-4o-transcribe`。**留空代表未啟用轉錄功能。** |
| `Providers.<名稱>.TranscriptionApiVersion` | **選填**（1.0.28）。語音轉錄用的 api-version，留空時用內建的 `2025-03-01-preview`；只有 Azure 淘汰這個版本時才需要填。 |
| `Currency` | **定價**幣別代碼（0.4.80），預設 `USD`——Azure 的公告價與帳單都是美金。0.4.88 起畫面上的**顯示**幣別另由 `ExchangeRateSettings` 決定，資料庫兩者都存。 |
| `Pricing.<deployment>.InputPerMillionTokens` | 每百萬**輸入** token 的單價（0.4.80，用量分析頁估算金額用）。 |
| `Pricing.<deployment>.OutputPerMillionTokens` | 每百萬**輸出** token 的單價。通常是輸入的 3～4 倍，所以與輸入分開設。 |
| `Pricing.<deployment>.AudioPerMinute` | 每分鐘音訊的單價（語音轉錄用）。 |

⚠️ **`Pricing` 的鍵是 deployment／model 名稱**，與 `Model`／`TranscriptionModel` 設的是同一個字串
（用量帳本記的也是它，三者對得起來）。

⚠️ **查不到單價時，帳本的金額欄位是空白而不是 0**——0 與「真的沒花錢」看起來一模一樣，
會讓總額靜靜地少報。「Token 用量」頁（1.0.30 前名為「AI 用量分析」）會在頂端提示「有 N 次呼叫的模型未設定單價」。
**換 deployment 時記得補一筆，否則那段期間的金額全部不會被統計。**

⚠️ 單價設成負數會在**啟動時**被擋下：負成本在圖表上只是看起來「這個月比較省」，沒有任何跡象。

⚠️ **`gpt-5.6-sol` 的 $4／$20 是 promo 價**（OpenAI 公告至少到 2026/11/21）。JSON 不能寫註解，
所以記在這裡：promo 結束後要回來更新，否則那之後的金額會低估。

⚠️ **快取輸入單價目前不支援**（已知限制，0.4.88）。`gpt-5.6-sol` 的 cached input 是 $0.40，
與一般輸入的 $4.00 差十倍；帳本已經有 `CachedInputTokens` 欄位，但 `LlmPricingSettings` 沒有對應的單價，
所以快取命中的 token 目前一律以一般輸入價計算。實測目前快取命中數是 0，因此不影響現有數字；
日後命中率上升時，這裡會**高估**成本（高估比低估安全，但仍不準）。

⚠️ **API 版本（1.0.28）**：1.0.28 起**文字生成走 Azure OpenAI v1 API**（`{Endpoint}/openai/v1/chat/completions`，部署名稱放在 body 的 `model`），不再需要 `ApiVersion`；`openai.azure.com` 與 `services.ai.azure.com` 兩種端點都可以。**語音轉錄仍走 `/openai/deployments/{TranscriptionModel}/audio/transcriptions?api-version=…`**：實測 v1 的轉錄路徑打 `gpt-transcribe` 部署一律回 404 DeploymentNotFound。轉錄的 api-version 內建 `2025-03-01-preview`（`LlmProviderSettings.DefaultTranscriptionApiVersion`），設定檔不必填。
舊設定檔或 user-secrets 若還留著 `ApiVersion` 鍵，會被直接忽略，不會報錯；可以刪掉。
文字生成仍送 `stream_options: {"include_usage": true}` 取得 token 用量，v1 支援（1.0.28 實測）。

新增第二家供應商只需在 `Providers` 多一個物件（例如 `GoogleGemini`）並改 `DefaultProvider` 或 `TranscriptionProvider`，**既有設定鍵不需變動**。用字典而非陣列，是為了讓環境變數覆寫有穩定的鍵路徑：

```
LlmSettings__Providers__AzureOpenAI__ApiKey  →  LlmSettings:Providers:AzureOpenAI:ApiKey
```

`appsettings.Production.json` 已把 `DefaultProvider`、`TranscriptionProvider` 與 `AzureOpenAI.ApiKey` 清空——正式環境預設「未啟用」，要用必須顯式以環境變數指定。

`StartupSafetyValidator` 在 Production 啟動時的檢查：

- 指定了 `DefaultProvider` → 要求該供應商的 `ApiKey` 非空且非開發預設值、`Endpoint` 非空且不含範例值 `your-resource`。
- **啟用了轉錄**（明確指定 `TranscriptionProvider`，或沿用 `DefaultProvider` 且該供應商填了 `TranscriptionModel`）→ 額外要求 `TranscriptionModel` 非空、`MediaSettings:FfmpegPath` 非空；轉錄供應商若與生成端不同，另外檢查它自己的 `ApiKey` 與 `Endpoint`。
- **只用 LLM、不用轉錄的部署不受轉錄檢查影響**，不會被擋住上線。

服務端一律以 `IOptions<LlmSettings>` 取值，**禁止**直接從 `IConfiguration` 讀字串。

> 呼叫端：語音轉錄由 `AzureOpenAiTranscriptionProvider` 使用 `TranscriptionModel`／`TranscriptionApiVersion`；文字生成由 `AzureOpenAiTextGenerationProvider`（`ITextGenerationProvider`）使用 `Model`（v1 API），供會議紀錄草稿生成（`MeetingDraftJobRunner`）、AI 問答（`AiChatService`）與抽出待辦（`TodoExtractionService`）共用。每次呼叫的用量與依 `Pricing` 算出的金額由 `AiUsageRecorder` 寫入 `AiUsageLog`。詳見 [會議紀錄產生流程 PRD](../prd/會議紀錄產生流程-prd.md)。

### `ExchangeRateSettings`（0.4.88）

把用量金額從定價幣別（`LlmSettings:Currency`）換算成顯示幣別。對應 `MeetingRecord.Models/Systems/ExchangeRateSettings.cs`，於 `Program.cs` 的 `#region 加入設定強型別注入宣告` 以 `ValidateDataAnnotations().ValidateOnStart()` 綁定；背景抓取由 `ExchangeRateBackgroundService` 執行（`ServiceCollectionExtensions.AddExchangeRateServices()` 註冊），結果放在 Singleton 的 `ExchangeRateCache`。`Enabled = false` 時其餘欄位都不驗證。

| 設定鍵 | 說明 |
| --- | --- |
| `Enabled` | 是否啟用換算。`false` 時完全不會有背景抓取，用量分析頁**整頁**維持定價幣別顯示。 |
| `SourceUrl` | 匯率來源，預設 `https://open.er-api.com/v6/latest/USD`（免金鑰、每日更新）。`Enabled = true` 時不可空白，且必須是 http／https 絕對網址（啟動時驗證；不驗證連不連得上）。 |
| `TargetCurrency` | 換算目標幣別代碼（三碼），預設 `TWD`。 |
| `RefreshIntervalHours` | 重抓間隔（小時），預設 24；必須介於 1～168，否則啟動時被擋下。 |
| `FallbackRate` | 保底匯率，目前設 `32.0`。只在「連一次都沒抓成功、資料庫也沒有任何歷史匯率」時才會用到，所以刻意用整數，讓「這是估的」一眼看得出來。可留空（代表沒有保底匯率）；有填則必須大於 0。 |

⚠️ **`Enabled = false` 時整頁退回定價幣別**，不是「有匯率的顯示台幣、沒有的顯示美金」——
那會讓總額變成兩種幣別相加。

⚠️ **`FallbackRate` 是離線時的最後手段，會帶 1～3% 的系統性誤差而且畫面上看不出來。**
留空的話該筆不換算、顯示「—」並跳提示——那比較誠實，但畫面上會出現一片「—」。
目前選擇給值（32.0），是刻意拿一點準確度換可讀性。

⚠️ **`SourceUrl` 結尾的幣別要與 `LlmSettings:Currency` 一致**。程式會拿回應的 `base_code` 交叉比對，
對不上就整批不換算（畫面顯示「—」），而不是算出錯好幾 % 卻看起來很正常的金額。

⚠️ **`TargetCurrency` 寫成 `"TWD "`（尾隨空白）之類的 typo 會在啟動時被擋下**——
不擋的話系統會完全正常啟動，然後永遠查不到匯率，只在 log 裡留一行 warning。

⚠️ **正式部署若無法對外連 `open.er-api.com`**，請設 `FallbackRate` 或把 `Enabled` 設為 `false`，
否則所有紀錄都不會有台幣金額。

### 4.3.4 `MediaSettings`

影音處理設定，0.4.27 起存在。語音轉錄前一律以 FFmpeg 將上傳的影音檔轉成 mp3 並切段。

| 欄位 | 用途 |
|------|------|
| `FfmpegPath` | FFmpeg 執行檔完整路徑；若已加入 `PATH` 也可以只填 `ffmpeg`（0.4.29 起為預設值）。 |

以 `IOptions<MediaSettings>` 注入 `FfmpegMediaConverter`。

**0.4.29 起會在啟動時驗證存在性**，不再等到轉錄失敗才發現。判斷由 `FfmpegPathResolver.Exists` 負責：帶目錄資訊的路徑直接檢查檔案，純檔名則沿 `PATH` 搭配 `PATHEXT` 搜尋，與 `Process.Start` 的解析方式一致。

| 環境 | 轉錄已啟用且 FFmpeg 找不到時 |
|------|------|
| Production | `StartupSafetyValidator` 累積錯誤後擲例外，**中止啟動**（留空與路徑不存在都算） |
| 其他環境 | `Program.cs` 記一則 `Startup configuration warning.` 的 WARN，**照常啟動**——沒在用轉錄的開發者不該被擋 |

若仍在未安裝的狀態下執行轉錄，`FfmpegMediaConverter` 會失敗並在會議紀錄上留下明確指出設定鍵的錯誤訊息。

### 4.3.5 `ExportSettings`

匯出設定，0.4.40 起存在。會議紀錄匯出 PDF 是以**系統既有的瀏覽器無頭列印**產生的。

| 欄位 | 用途 |
|------|------|
| `BrowserPath` | 產生 PDF 用的瀏覽器執行檔（Edge 或 Chrome）完整路徑；已加入 `PATH` 也可只填檔名。**留空即自動偵測**——依序試 Edge 的兩個標準安裝位置與 Chrome 的兩個，Windows 內建 Edge 因此通常不必設定。 |

以 `IOptions<ExportSettings>` 注入 `HeadlessBrowserPdfRenderer`。存在性判斷與 FFmpeg 共用 `ExecutablePathResolver.Exists`。

**設定值優先且不回退**：填了但找不到檔案時直接報錯，不會靜默改用自動偵測到的其他瀏覽器——設錯路徑要讓人看得見。

| 環境 | 找不到瀏覽器時 |
|------|------|
| 任何環境 | 啟動時記 WARN（不中止），匯出當下回明確錯誤訊息並提示可設定 `ExportSettings:BrowserPath` |

> 為什麼不用純 .NET 的 PDF 套件：中文 PDF 必須嵌入 CJK 字型（TrueType subsetting、CID font、CMap），要嘛把 10MB 以上的字型檔放進版控，要嘛買商業授權，而且表格等複雜排版還得自己寫。交給瀏覽器則三者全免。代價是依賴機器上裝有 Edge 或 Chrome。

## 6. 一次性維運腳本：`scripts/Backfill-AiUsageCost.mjs`

0.4.88 上線「AI 用量台幣換算」時附帶的**手動、一次性**回填腳本，補 `AiUsageLog` 舊紀錄的空欄位。**不是新慣例**：帳本的設計是「金額、單價與匯率在寫入當下算好存起來，之後不再回填」，自動路徑（`AiUsageRecorder`、EF migration）一律不回填，只有這支腳本會。

**做兩件事（都只補「還是空的」欄位，已有值的一律不動）：**

| 選項 | 補什麼 | 適用情境 |
|------|--------|----------|
| `--model <名稱> --input-per-million <美金> --output-per-million <美金>` | 該模型 `EstimatedCost IS NULL` 且有 token 用量的列，寫入 `EstimatedCost`、`InputPricePerMillion`、`OutputPricePerMillion`（算式與 `AiUsagePricing` 相同，輸入輸出分開計價） | 換了 deployment 卻忘了在 `LlmSettings:Pricing` 補單價，那段期間金額全是空白 |
| `--rate <數字> [--target-currency TWD]` | 所有 `ExchangeRate IS NULL` 的列，寫入 `ExchangeRate`、`ConvertedCurrency` | 0.4.88 之前的舊紀錄沒有匯率欄位 |

⚠️ **補匯率填的是「執行當天」的匯率，不是呼叫發生當天的匯率**，與本功能「當時匯率」的賣點相牴觸；腳本動手前會再提示一次。只在確實需要讓舊資料顯示台幣時才補。

**前置條件：**

- **Node.js 24 以上**（使用內建 `node:sqlite`，不需安裝任何套件）。之所以不是 `.ps1`：Windows PowerShell 5.1 載不了 .NET 10 版的 `Microsoft.Data.Sqlite`。
- 資料庫位置：未給 `--db` 時讀 `src/MeetingRecord/MeetingRecord.Web/appsettings.json` 的 `SystemSettings:ExternalFileSystem:DatabasePath`，再接 `BackendDB.db`。正式環境的路徑若以環境變數覆寫，請用 `--db <完整路徑>` 指定。
- 建議先停止系統或選離峰時段：資料庫為 WAL 模式，同時寫入不會壞資料，但邊操作邊回填會讓「異動列數」對不上。

**用法（於 repo 根目錄執行）：**

```powershell
node scripts/Backfill-AiUsageCost.mjs --rate 31.863639 `
     --model gpt-5.6-sol --input-per-million 4.0 --output-per-million 20.0
```

執行流程：列出將異動的列數 → 要求輸入 `yes` 確認（`--yes` 可跳過）→ 先 `wal_checkpoint` 並把 `BackendDB.db`（連同 `-wal`／`-shm`）備份成 `BackendDB.db.bak-before-backfill-<時間戳>` → 以單一交易更新 → 印出各模型「筆數／無金額／無匯率」統計。出錯會整批 ROLLBACK；要還原就把備份檔改回原檔名。

背景與當時的執行紀錄見 [AI 用量台幣換算](../changelog/2026-09-18-AI用量台幣換算.md)。
