## 目標
- [x] 建立腳手架上線前必查項目，避免開發用設定被複製到正式環境。

## JWT 與認證
- [ ] 將 `JwtSettings:SigningKey` 改由 secret manager、環境變數或部署平台 secret 提供。
- [x] Production 啟動時若仍使用開發用 signing key，會直接中止啟動。
- [ ] 確認 signing key 長度、亂數強度與輪替流程。
- [ ] 確認 access token 與 refresh token 有效期符合系統風險等級。
- [ ] 記錄 refresh token 採 stateless signed JWT，無法可靠撤銷單一 token；若需要撤銷能力，需改成落庫或加入 token version 機制。
- [ ] 確認 `ApiResult.Exception` 正式環境完整回傳的資訊揭露風險已被接受，或另開需求改成依環境遮蔽。

## 預設帳號
- [ ] 部署前停用、刪除或透過 `BootstrapSettings` / 環境變數重新設定預設 `support` 帳號。
- [x] Production 啟動時若仍使用 `support` 預設密碼，會直接中止啟動。
- [ ] 若系統需要保留預設管理者，必須將 `BootstrapSettings:SupportPassword` 改由部署 secret 提供；首次啟動強制改密碼可另開功能化任務。
- [ ] 檢查文件、seed、測試資料中沒有可被正式環境沿用的密碼。

## Swagger 與 API
- [ ] 正式環境確認 Swagger UI 是否關閉，或限制在內網/VPN/授權後使用。
- [x] Production 必須明確設定 `Swagger:EnabledInProduction`，預設範本為 `false`。
- [ ] 確認所有 CRUD API 均需要 Bearer token。
- [ ] 確認受保護 API 具**動作級授權**（`[HasPermission]`）：以無對應權限的使用者實測 create/edit/delete 回 **403（非 200）**，view/search 回 200。
- [ ] 確認 API validation、401、403、404、500 都維持 `ApiResult<T>` 格式。
- [ ] 確認檔案下載成功時維持原生 File stream，錯誤才回 `ApiResult<T>`。
- [ ] 確認新用戶端使用 `/api/v1/...`，既有 `/api/...` 僅作相容路由。

## 快取
- [ ] 確認 `CacheSettings:Provider`：單機可用 `Memory`，多節點部署應改 `Redis` 以共享快取。
- [x] Production 若 `Provider=Redis` 但 `RedisConnection` 留空，會直接中止啟動。
- [ ] 將 `CacheSettings:RedisConnection` 改由部署 secret / 環境變數提供，勿進版控。

## LLM 設定
- [x] `appsettings.Production.json` 已清空 `LlmSettings:DefaultProvider`、`LlmSettings:TranscriptionProvider` 與 `LlmSettings:Providers:AzureOpenAI:ApiKey`；正式環境預設為「未啟用 LLM 與語音轉錄」。
- [ ] 不使用文字生成能力時，保持 `LlmSettings:DefaultProvider` 留空（0.4.27 現況：文字生成端仍無任何呼叫端，設定值不會產生外部請求）。
- [ ] 要啟用時，以部署 secret／環境變數提供 `LlmSettings__Providers__<供應商>__ApiKey` 與 `__Endpoint`，**勿進版控**。
- [x] Production 一旦指定 `DefaultProvider`，`ApiKey` 留空或沿用開發預設值、`Endpoint` 留空或含 `your-resource`，都會被啟動安全檢查中止。
- [ ] 串接外部 LLM 前，先評估會議逐字稿外送第三方的合規、資料保留與跨境政策。

## 語音轉錄與影音處理（0.4.27 起）
- [ ] 不使用語音轉錄時，保持 `LlmSettings:TranscriptionProvider` 與 `Providers:<供應商>:TranscriptionModel` 皆留空；啟動檢查會整段跳過。
- [ ] 要啟用時：在 Azure OpenAI 另外部署轉錄模型（例如 `gpt-4o-transcribe`），把 deployment 名稱填入 `TranscriptionModel`。
- [ ] 確認 `TranscriptionApiVersion` 為目標 Azure 資源實際可用的版本——轉錄端點需要比文字生成的 `ApiVersion` 更新的版本。
- [ ] **安裝 FFmpeg** 並設定 `MediaSettings:FfmpegPath`。這是本專案唯一的外部執行檔相依，沒有它所有轉錄都會失敗。
- [x] Production 啟用轉錄後，`TranscriptionModel` 或 `MediaSettings:FfmpegPath` 留空會被啟動安全檢查中止；轉錄供應商與生成端不同時，另檢查它自己的 `ApiKey` 與 `Endpoint`。
- [ ] 規劃 `MeetingMediaPath` 的儲存容量與備份策略——原始影音檔會持續累積，系統**沒有**自動清理政策。
- [ ] 決定 `MeetingTranscriptPath` 的保留期限。逐字稿是高敏感內容，且目前沒有自動清理機制。
- [ ] 確認 `MeetingMediaPath` 與 `MeetingTranscriptPath` **不在** `DownloadPath` 之下——它們不應被 `/UploadFiles` 靜態路由對外服務。
- [ ] 評估轉錄的成本上限與速率限制：目前沒有配額控管，每次「重新轉錄」都會重新計費。
- [ ] 確認轉錄工作是單一 worker、佇列不持久化：重啟會把「處理中」判為失敗，需由使用者手動重跑。若部署為多節點，這個假設不成立，須先改設計。
